# U12 커버리지 측정 범위 (새 연습 흐름, 작업 기록 261017-u12-practice-flow · J137)
# -PcoverageScope=practice-flow일 때 JaCoCo가 이 목록의 운영 소스(.java)만 잰다. 한 줄에 저장소 루트 기준 경로 하나.
# 내용은 U12가 만든 realtime-activity 운영 Java 파일이다(설정 yml · SQL · 계약 문서 제외).
# 이 목록은 구현 묶음마다 자랐다. 묶음 A(V7 · 저장소 · 삭제 참여자 · 정산 복구 분기 · 설정 값 · 대본 읽기 · 시작 패키지 해석 · 다음 목표 대본 요청),
# 묶음 B(전이표 · 흐름 상태 · 상태 기계 · 라우터 · 역할 정책 · 지시문 · 기록 포트 · 설정 빈), 묶음 D(운영 기록기 PracticeFlowRecorder)의 새 클래스가 들어 있다.
# 묶음 C(생성형 슬롯 · 제브 연결)는 새 파일 없이 SessionExecutor · GuardrailCoordinator · PracticeSpeech의 호출 지점만 더했다(아래 이유로 목록 밖).
# 진행 단계 6값 접기(progress)는 PracticeConversation 안에 있어 따로 새 클래스가 없다.
# 정직하게 적은 목록이다:
#  - SessionExecutor(약 4,250줄, 앞 유닛 코드가 대부분)와 SessionInternalController · StartSessionHandler · PracticeSessionExtension은 U12가 호출 지점 · 한 필드만
#    더한 앞 유닛 파일이라 뺀다(U13과 같은 이유: 목록에 넣으면 practice-flow 태그 시험만으로 재는 이 범위가 파일 전체를 분모로 삼아 낮게 나온다).
#    그 변경은 PracticeStartPathIT · PracticeStartBodyTest(practice-flow 태그)가 실행하고, 파일 전체 커버리지는 모듈 전체 80%(태그 없는
#    -Pmujoong.test.db=docker check)로 본다.
#  - runtime/PracticeRecoveryRouter는 두 복구(새 흐름 · 레거시 U5b)를 잇는 한 곳이라 넣었다. 레거시 복구 자체(practice/ 패키지)는 목록에 없다.
# test-support 가짜 공급자와 contract-model은 이 목록에 넣지 않는다(u9 · u11 · u13과 같은 이유: 모듈 전체 80%로 잰다).
