### 2. 시험 가능성 — 가짜 공급자(R-F1)와 증거 분리(R-M11)

AC2.1.1~2.1.7, AC3.1.7, AC3.1.8(의미 반복), AC4.5.1(Luna가 기록에서 후보를 "만든다")은 **모델의 판단 품질**을 말한다. 시험 · CI · `verify.sh`에서는 가짜 공급자만 쓰므로(R-F1), 자동 시험은 "가짜 제브가 `BLOCK`을 주면 재생되지 않는다" 같은 **배선**만 증명한다. "능력 단정 문장이 실제로 `BLOCK`된다"는 실호출(FR12.1, 합성 자료)에서만 나오는 증거다.

제안:
- AC마다 증거 수준 꼬리표를 단다: `[자동-대역]`(가짜 공급자 · 가짜 시계로 CI에서 합격/불합격) · `[실호출-합성]`(FR12.1, 합성 자료, 별도 보고) · `[실기기]`(FR12.3, 사람 실행).
- 2절 대상 AC는 둘로 쪼갠다. (a) `[자동-대역]`: 해당 정책 문장이 버전 고정된 시스템 프롬프트(FR6.10)에 들어 있고, 픽스처 후보 문장 + 가짜 판정 → 기대 송신 결과. 1차 사전(대역)으로 잡히는 표현은 대역 단독으로도 확인. (b) `[실호출-합성]`: 같은 픽스처 문장으로 실제 제브 결과를 기록하되 **합격 기준이 아니라 관측값**으로 보고한다.
- AC2.1.7(프롬프트 주입)의 `[자동-대역]` 부분: 맥락이 지시 영역이 아닌 데이터 필드(구분자 안)로만 실리는지 요청 구조를 단언한다.
- C §8.4에 따라 `REPORT_FULL_2026-10-15.html` 같은 합성 대화 결과는 픽스처로만 쓰고 정확도 근거로 쓰지 않는다는 문장을 스토리 머리말이나 의존 절에 한 줄 넣는다. `boundary_timeout`이 '성공'으로 찍힌 사례를 픽스처로 쓸 때 기대 결과를 독립적으로 다시 정한다는 것도 함께.

### 3. 기본값의 구체성

구체적인 것: 0.6 · 0.15 · 2초 · 10초 · 800ms · 최근 3턴 · 다시 설명 1회 · 다시 해 보기 2회 · 90초 · 10분 · 15초 · 그래프 2초 · 재시도 3회(5 · 15 · 30초) · 5글자.

빠진 것:
- AC3.1.4 "허용 횟수 안이면 다시 생성" — 횟수 없음(AC3.2.3은 "2회 규칙"을 참조만 함).
- AC1.9.1 "대기 시간 안에 발화가 없으면" — 무응답 대기 시간 값 없음.
- AC1.6.1 · AC1.6.2 "참여 의사가 있고" — 무엇으로 판정하는지(J 판정? 명시 거절 없음?) 없음.
- AC2.3.1 "아동 서비스는 시작을 거부" — 앱 기동 실패(컨텍스트 시작 실패)인지, 세션 시작 거부(오류 코드)인지 정해야 시험을 쓸 수 있다.

R-M5 주의: 새 시간 값(판정 2초 · 응답 준비 10초 · 제브 800ms · 집중 90초 · 목표 10분 · 그래프 2초 · 무응답 대기)은 `mujoong.timing.*` 세 곳 동기화 대상이다. AC의 [기본값]은 "설정 키의 기본값"이라고 적어 두면 `TimeLiteralScanTest` · `ConfigKeyContractTest`와 바로 이어지고, 시험은 `MujoongClock` 가짜 시계로 판정한다. 0.6 · 0.15는 시간 값이 아니라 일반 설정값이다.

## Positions

- AGREE: Q3-A대로 C §8.1~§8.3을 AC로 옮긴 틀과 (C §8.1-n) 표기는 추적에 좋고, 확인한 36개 중 18개는 그대로 대응되고 판정 가능하다.
