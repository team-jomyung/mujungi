# 접근성 점검표

> 기준: 보호자 앱은 WCAG 2.1 AA이고, 이번에 바뀌는 곳만 점검한다(Q2-A). 아이 기기는 음성 중심이라, 상태를 색만으로 구분하지 않는지만 확인한다.
> 점검 방법: 자동 검사(axe / Lighthouse) + 키보드만으로 조작 + 화면 읽기 프로그램(TalkBack · VoiceOver) + 200% 확대. Build and Test에서 실행한다.

## 1. 보호자 앱 — 17 종료 사유 줄 (EndReasonLine)

- [ ] 종료 사유를 글자로 보인다(아이콘 · 색만으로 구분하지 않음) — 1.4.1
- [ ] 글자 대비 4.5:1 이상 — 1.4.3
- [ ] 판정으로 끝난 경우 시각만 보이고, 화면 읽기 프로그램이 "민준이 끝내자고 했어요, 10시 52분"처럼 읽는다 — 1.3.1
- [ ] 200% 확대에서 사유 줄이 잘리지 않는다 — 1.4.4

## 2. 보호자 앱 — 27 연습 목표 칸 (GoalCandidateCard)

- [ ] [담기] · [담김 ✓] 단추가 키보드로 닿고(Tab), Enter · Space로 토글된다 — 2.1.1
- [ ] 포커스 표시가 보인다(2px 이상, 3:1) — 2.4.7
- [ ] 단추 이름에 목표 이름이 들어간다(`aria-label`), 토글 상태가 `aria-pressed`로 전달된다 — 4.1.2
- [ ] 터치 대상 44×44px 이상 — 2.5.5(권장) · 프로젝트 기준
- [ ] 목표 이름 12자 · 근거 문구 40자 한도로 줄바꿈이 깨지지 않는다(320px 폭) — 1.4.10
- [ ] '후보 없음' · '정리 중' · '정리 실패' 상태가 글자로 안내된다 — 4.1.3
- [ ] 근거 문구에 진단 · 점수 · 단정 표현이 없다(금지 표현 검사 통과분만 표시) — 서비스 안전 기준(NFR-01)

## 3. 보호자 앱 — 12 활동 진행 말풍선 (ActivityTranscriptBubbles)

- [ ] 새 말풍선이 `aria-live="polite"`로 안내되고 지나치게 자주 끊어 읽지 않는다 — 4.1.3
- [ ] 화자(아이/무중)를 색만이 아니라 글자로도 구분한다 — 1.4.1
- [ ] 글자 대비 4.5:1 — 1.4.3
- [ ] 막힌 · 버린 발화가 화면 읽기 프로그램에도 나오지 않는다(DOM에 없음) — 서버 필터 확인

## 4. 보호자 앱 — 27 장면 칩 (표시 유지)

- [ ] 이번 작업 뒤에도 27 표시가 바뀌지 않았다(회귀 확인, Q5-A)
- [ ] 칩이 그려지는 곳에서 색만으로 구분하지 않는다 — 1.4.1

## 5. 아이 기기 — T19 상태 화면

- [ ] 상태(대기 · 듣는 중 · 생각 중 · 말하는 중 · 마무리 · 연결 끊김)를 표정 그림 + 글자로 함께 보인다(색만으로 구분하지 않음) — 1.4.1
- [ ] 판정 턴 · 제브 재시도 중에 '생각 중'이 유지되고, '듣는 중'으로 잠깐 깜빡이지 않는다(AC1.10.4)
- [ ] 상태 글자 대비 4.5:1 — 1.4.3
- [ ] 켜기 · 끄기 단추 44×44px 이상

## 6. 점검 범위 밖 (이번 작업)

- 보호자 앱의 바뀌지 않은 화면 전체 재점검(Q2-A로 제외)
- 아이 기기의 음성 경험 자체에 대한 접근성 평가(청각 · 발화 장애 등)는 이번 범위 밖이다. 열린 항목으로 남긴다.
