# 다듬은 화면 시안 — 문서 기반 코드 갱신

> 근거: `../user-stories/stories.md`, `../requirements-analysis/requirements.md`, 화면 설계 v1.5j(`aidlc/spaces/default/knowledge/documents/10_화면설계_v1.5j/`, 가장 앞섬), 질문지 Q1-B · Q2-A.
>
> 거친 시안(Ideation)은 없다. classic 범위라 거친 시안 단계를 건너뛰었다. 그래서 스토리 · 요구사항과 화면 설계 v1.5j를 바로 근거로 삼고, 없는 거친 시안의 내용을 지어내지 않는다.
>
> 원칙
> - 이번 작업은 **새 화면을 만들지 않는다.** 화면 설계 v1.5j의 화면 · 상태 · 분기 · 문구 ID를 그대로 쓴다.
> - 정본에 없는 문구 · 상태가 필요한 곳은 끝의 **「화면 설계 v1.5j 개정안」**(RP-1~RP-7)에 적는다(Q1-B). 개정안은 제안이다. 정본 파일(`knowledge/documents/`)은 사람이 승인한 뒤 고친다. 이 단계는 정본을 고치지 않는다.

## 2. 화면별 시안

### 2.1 T19 아이 기기 · 상태 화면 — 판정 턴

```
┌──────────────────────────────┐
│                              │
│        (무중 캐릭터 그림)      │   ← C.D-19.31.1 · 상태마다 표정이 바뀜
│          생각하는 표정         │
│                              │
│          생각 중              │   ← C.D-19.31.4 (글자 + 표정, 색만으로 구분하지 않음)
│                              │
│                       [끄기] │   ← C.D-19.31.8
└──────────────────────────────┘
```

상태 흐름(판정 턴)

```
듣는 중 ──(아이 말 끝)──▶ 생각 중 ──(지시 뒤 응답이 게이트 · 제브 통과, 재생 시작)──▶ 말하는 중
                         │
                         ├─(판정 턴 중 자동 응답 도착 → 버림)──▶ 생각 중 유지   (AC1.10.1 · AC1.10.4)
                         ├─(제브 BLOCK · 시간 초과 → 같은 지시 1회 재시도)──▶ 생각 중 유지  (AC2.1.3)
                         ├─(재시도도 막힘 → 장면 정리 · 다음 단계 지시)──▶ 생각 중 → 말하는 중
                         ├─(아이 말 끝 뒤 10초 안에 응답 없음 → 무난한 되묻기 지시)──▶ 생각 중 → 말하는 중 (AC1.8.4)
                         └─(종료 표현 인식)──▶ 마무리 → 대기 (AC1.7.1 · AC1.7.2)
```

- 화면 요소는 v1.5j 그대로다. 새 상태 이름을 만들지 않는다. '쉬는 중' 상태도 만들지 않는다(AC1.7.6).
- '생각 중'이 길어질 때의 상한은 따로 두지 않는다. 판정 2초 · 응답 준비 10초 · 제브 800ms · 재시도 1회 규칙이 끝을 낸다.

### 2.2 12 활동 진행 · 연습 중 (보호자 앱)

```
┌────────────────────────────────────┐
│ 연습 · 1/2번째 목표 · 친구에게 부탁하기 │  ← C.S-12.19.1
│ 민준이 연습하고 있어요               │  ← C.S-12.19.2
│ 10:40 시작 · 3분째                  │  ← C.S-12.19.3
├────────────────────────────────────┤
│ (무중) 무중이 블록 성을 쌓고 있어.    │  ← 장면 설명 · 기회 문장(재생된 것만)
│        나도 하나 줄래?              │
│ (아이) 그거 줘                       │
│ (무중) 어느 색?                      │  ← 친구 역할 되묻기(제브 ALLOW 뒤 재생된 것만)
│ (아이) 파란색                        │
│ (무중) 응, 여기 있어.                 │
│ ┄┄┄ 10:43 ~ 10:43 끊김 ┄┄┄            │  ← 기존 끊김 점선
├────────────────────────────────────┤
│            [연습 끝내기]             │  ← C.S-12.19.7
│  홈 · 자유대화 · 연습 · 기록           │
└────────────────────────────────────┘
```

- 말풍선에는 **아이가 실제로 들은 무중이 말만** 나온다. 다음은 말풍선에 넣지 않는다(AC1.10.1 · AC2.1.9).
  - 판정 턴 중 버린 출력
  - 제브가 막은 발화
  - 늦게 와서 무효가 된 `ALLOW`의 발화
- 위 예시 대화는 새 흐름(되묻기로 해결)을 보이는 시안이다. 문구표 C.S-12.19.4 · C.S-12.19.5의 예전 예시(메타 질문 · 정답 제시)를 바꾸는 개정은 RP-4.

### 2.3 17 활동 끝 · 아이가 끝냄 (판정으로 알아들은 경우)

등록 표현과 일치해 끝났을 때(지금과 같음)

```
연습 · 목표 2개
오늘 연습이 끝났어요
10:40 ~ 10:52 · 목표 2개
민준이 끝내자고 했어요                 ← C.S-17.72.4
"무중아 그만할래" · 10:52             ← C.S-17.72.5 (일치한 등록 표현을 따옴표로)
기록을 정리하고 있어요
[오늘 기록 보기]  [홈으로]
```

Luna 판정(J6 '종료 명확')으로 끝났을 때(AC1.7.5, 개정 RP-3)

```
연습 · 목표 2개
오늘 연습이 끝났어요
10:40 ~ 10:52 · 목표 2개
민준이 끝내자고 했어요                 ← C.S-17.72.4 그대로
10:52                               ← RP-3 제안: 따옴표 문구 없이 시각만
기록을 정리하고 있어요
[오늘 기록 보기]  [홈으로]
```

- 판정으로 알아들은 아이 말을 따옴표로 옮기지 않는다. 아이가 실제로 한 말과 판정 해석이 다를 수 있고, 판정 결과를 보호자에게 보이지 않는 원칙(FR3.6)을 지키기 위해서다.

### 2.4 18 내 연습 목표

- 바뀌지 않는다.
- 상황 생성 · 자체 검토 · 서버 검사가 끝내 실패하면(`SCENARIO_GEN_FAILED`), 기존 분기 "연습 · 상황 생성 실패 → 18 (이유 표시)"를 그대로 쓴다(AC3.1.4).

### 2.5 27 활동 기록 상세 · 연습 기록 (표시 유지)

```
← 10월 7일 연습                          ← C.S-27.26.1
10:40 ~ 10:52 · 목표 2개                 ← C.S-27.26.2
18에서 고른 목표                          ← C.S-27.26.3 (판정 글 없음 — v1.5j)
  친구에게 부탁하기                        ← C.S-27.26.4
  차례 기다리기                            ← C.S-27.26.5
[대화 기록] [생활 팁 1] [연습 목표 1]       ← C.S-27.26.6~8
```

- **이번 작업에서 27 표시는 바꾸지 않는다**(Q5-A). '되묻기 뒤 전달'(`AFTER_REASK`) 값은 API · 리포트 집계에만 더한다(AC4.1.1).
- 지금 코드는 27에 장면 칩을 그린다(`RecordDetail27.tsx` → `SceneChip`). 이것은 v1.5j('판정 글 없음')와 어긋나는 기존 편차다. 새 값이 27에 그대로 흘러가면 표시가 바뀌거나 깨질 수 있다(사용자 스토리 검토 R-01). 그래서 Functional Design에서 다음 중 하나를 정해야 한다.
  - (a) 27 표시용 값은 기존 5종으로 접는다. 예: `AFTER_REASK` → 기존 '바로 전달'이 아닌 별도 접기 규칙.
  - (b) 27 칩을 숨긴다.
  - 화면 설계 쪽 결정은 RP-1.

### 2.6 27 활동 기록 상세 · 연습 목표 칸 (Luna가 만든 후보)

```
[대화 기록] [생활 팁 2] [연습 목표 3]            ← C.S-27.25.3~5 (탭 n = 후보 수, 최대 3)
┌──────────────────────────────────────────┐
│ 친구에게 부탁하기                    [담기] │  ← 목표 이름(최대 12자) · C.S-27.25.10
│ 근거 · "빌려줘" 대신 손으로 가져갔어요 (10:36) │  ← 화면용 근거 문구(최대 40자) + 시각
├──────────────────────────────────────────┤
│ 차례 기다리기                       [담김 ✓] │  ← C.S-27.25.7
│ 근거 · 무중이 말하는 중에 끼어들었어요 (10:38) │
└──────────────────────────────────────────┘

후보 없음일 때: 기존 '후보 없음' 상태 문구(v1.5j 27 상태) 그대로
정리 중 · 실패: 기존 상태 그대로
```

- 보이는 것은 v1.5j에 있는 항목뿐이다(AC4.5.5): 목표 이름 · 근거 문구 · 시각 · [담기]/[담김 ✓] · 후보 없음.
- 추천 이유 · 4요소 · `skill_ref` · 근거 발화 원문은 보이지 않는다(내부용).
- 근거 문구는 아이 말을 그대로 옮긴 것이 아니라 관찰을 짧게 적은 문장이다(C.S-27.25.8과 같은 형식). 글자 일치로 검증하는 '근거 발화'와 따로 저장한다(AC4.5.6).
- 길이 · 개수 한도(목표 이름 12자, 근거 문구 40자, 후보 3개)는 정본에 없어 RP-5로 올린다.
