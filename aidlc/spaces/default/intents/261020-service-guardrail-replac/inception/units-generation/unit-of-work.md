## U16 — 서비스 정책·세션 정합성

### 책임과 경계

- **ServicePolicyCatalog / PolicyBundle**: 앱 포함 자원, 원본/적용본 버전·해시, 세션에 고정한 모드별 정책 선택, 누락/빈 자원 실패.
- **DialoguePolicy**: 자유대화 초기/후속/교정/재시도 정책 일치, 기존 최소 아이 문맥/이스케이프, 거절·정정·휴식·도움 사용·명확/모호한 종료의 규칙.
- **SessionLifecycle / SessionConversation / NoticeDeliveryEvidence**: 실제 안내 재생 증거, 안내 뒤 현재 참여 확인, 조기/중복/지난 결과 차단, 단일 actor 상태/세대/시간/기록 소유.
- **OutputGuard / OutputCandidateBinding**: 기존 JEV·음성/전사 대응·미승인 보류 및 현재 상태 재확인 연결. 새 분류기/범주·공급자·추가 호출 루프를 만들지 않는다.
- **서버 사실 투영**: 거절/무응답/기술 실패, 확인된 종료 표현, 실제 승인 인사 재생과 기기 종료 확인. actor 종료/재조회에도 근거/unknown을 보존하는 기존 스냅숏 경계를 설계한다.
- **기존 서비스 통합**: Core↔Realtime의 기존 HTTP·기기 WS·보호자 REST 계약과 Java 모델/어댑터가 필요한 만큼 변경된다. 다른 앱 코드/DB의 직접 참조는 없다.

### 파일 소유

아래는 변경이 필요한 경우의 소유 경계이며 모두 바꾼다는 파일 목록이 아니다. 세부 파일/변경 규모는 Code Generation의 실제 계획에서 확정한다.

| 영역 | U16 소유 | U17과의 경계 |
|---|---|---|
| 정책/지시 | realtime의 정책 자원·적재 코드, dialog의 DialogInstructions/InstructionTemplates/StopIntentJudge/StopConfirmFlow 관련 변경 | 프런트에 정책 본문·해시 실행 권한을 넣지 않음 |
| 공급자 연결 | voice의 ProviderRequestFactory/ProviderClient/ProviderPort에서 필요한 모드/허용 문맥 연결 | 공급자 wire 형식/모델 유지 |
| 세션/검수 | SessionExecutor/SessionContext/JoinFlow/EndingFlow/GuardrailCoordinator와 필요한 기존 시계·조회 경계 | 프런트는 직접 상태 승인/수정하지 않음 |
| 기존 판정 | J1/J6 요청 구성·고정 정책 자원·결과 매핑 관련 서버 변경 및 요청 경계 시험 | 새 외부 판정기 없음 |
| 공개 계약 | 필요한 contracts/ 문서·스키마·contract-model Java DTO, Core 조회 어댑터 및 서버 검증 | U17은 프런트 타입·파싱과 화면 소비만 소유 |
| 승인 안내 | 기존 승인 콘텐츠/시드 연결 및 텍스트·음성 버전/실제 확인의 일치 | U17은 기기 웹의 수신/재생 확인 소비만 소유 |
| 시험 | 해당 Java/정책/요청·상태/검수/계약 대역 시험과 기능 이름 범위 파일 | 프런트 컴포넌트/기기 웹 시험은 U17 |

### 산출과 단위 완료 기준

1. 새 자유대화 정책을 포함한 실제 초기/후속 요청을 가짜 공급자로 확인한다. 기존 연습 정책과 요청 whitelist는 유지한다.
2. 실제 안내 확인 전/조기 응답·실패/기한·중복/지난 결과에서 일반 출력을 열지 않는다. 참여 거절과 기술 실패 원인을 구분한다.
3. 현재 세대·모드·출력 목적 재확인과 기존 JEV/시계/원음·전사 정책의 회귀 증거를 남긴다.
4. R-01은 로컬 종료 규칙과 실제 J6 요청에 등록 표현 외 종료·인용·화제 거절·모호함 기준이 전달되는지 대역으로 검증하는 항목으로 상세 설계에 넣고 구현/시험한다. 판정 결과 주입만으로 이 검증을 대체하지 않는다.
5. U17에 필요한 사실/unknown·호환성 계약과 대표 대역 응답을 제공한다. 자연어 종료에 기본 문구를 거짓 인용하거나 인사 없음에 재생 중이라고 표시하게 만드는 기본값을 내보내지 않는다.
6. 새 안내 음성이 실제 서비스 자원으로 준비됐는지와 정책 텍스트/버전 일치를 별도 확인 항목으로 남긴다. 제공 패키지는 음성 파일을 포함하지 않으며 시험 톤/무음은 실제 안내 청취 증거가 아니다. 자원이 없으면 실패 보류를 지키며 기능 완료/실기기 성공으로 보고하지 않는다. 기존 승인 음성 갱신 경로와 필요한 실제 자원 확보는 Functional Design에서 구체화한다. 유료 공급자 호출은 이번 자동 시험에 넣지 않는다.

### 단위 안 구현 순서

기존 기준선 확인 → 정책 자원/모드·최소 문맥 및 해당 층 시험 → 실제 안내/참여·대화/종료와 검수 상태 및 시험 → 조회/계약·기존 연습/저장/시간 회귀. 이는 U16 내부의 test-after 순서이며 단위 사이 경제적 우선순위가 아니다.

### 제외

프런트 copy/화면 변경, 새 저장/계정/권한 정책, 전체 기억·PDF·리포트 개편, 신규 JEV 제안 축, 새 AI 공급자·배포. 프런트 표시를 바꾸려고 백엔드 실제 사실을 왜곡하지 않는다.

## U17 — 사실 기반 화면·기기 웹

### 책임과 경계

- **ConversationPresentation**: 기존 S-08/S-12/S-17, P-01/P-03, D-19의 배치와 조작을 유지한다.
- **RP-1**: 같은 승인 안내 자원/버전의 재생·표시 소비. 화면의 말풍선 존재나 서버 전송을 실제 안내 완료로 승인하지 않는다.
- **RP-2**: 명확한 거절, 무응답, 기술 실패의 제목/이동을 서버 사실에 맞춘다. 사유가 없으면 추측하지 않는다.
- **RP-3/4**: 실제 확인된 종료 표현만 인용하고, 확인된 승인 인사 재생 동안만 인사 중 줄을 표시한다. 기기 미확인 상태와 종료 원인을 구분한다.
- **기기 웹 소비**: U16의 기존 기기 계약을 따른 수신/재생 확인·세션/재생 식별 매칭이 필요한 경우 이 단위가 소유한다. 새 장치 프로토콜/런타임을 별도로 만들지 않는다.
- **접근성/호환성**: 기존 토큰/copy·프런트 import 경계, 키보드/초점/상태 알림·반응형·긴 한국어를 유지하고 바뀐 표면을 점검한다.

### 파일 소유

프런트의 parent/features/live 및 done의 표시/훅, 필요한 common/api 타입·파싱/상태 표현, shared/copy/ko.ts·activity.ts, device의 현재 WS/runtime/재생 확인 소비와 StatusView의 필요한 변경, 해당 프런트 시험을 소유한다. 모든 해당 폴더를 재작성하지 않는다. 서버/contract-model/공개 contracts 파일은 U16, 프런트 내부 타입과 소비는 U17이다. 소유를 넘겨야 하면 계획을 명시적으로 조정한다.

### 산출과 단위 완료 기준

1. RP-1–RP-4의 확인된 값/없음/미확인/구버전 응답 조합을 컴포넌트/파싱 대역으로 검증한다. 값이 없을 때 실제 발화/인사/성공을 채우지 않는다.
2. 보호자 P-01은 유지하고 아이의 명확한 음성 종료에는 추가 확인 UI를 붙이지 않는다. 두 경로가 같은 완료 사실을 거짓으로 확정하지 않는다.
3. 안내 중 수락·중단/지난 재생 확인·중복 통지에 대해 기기 웹이 현재 확인만 전송/적용하는 경계를 확인한다. 실제 서비스 기기 성공과 웹 대역을 구분한다.
4. 기존 레이아웃·연습·준비/진행/마무리/미확인·stale/복구를 유지한다. 변경된 조작의 초점/상태 낭독·기존 크기 하한·확대를 점검한다.
5. U16의 실제 대역 서버와 기존 전체 흐름을 연결해 최종 Build and Test의 회귀 대상으로 넘긴다. UI의 대역 응답만 통과한 상태를 전체 교체 완료로 표시하지 않는다.

### 단위 안 구현 순서

기존 프런트 기준선 → 계약 타입/파싱과 층 시험 → copy/사유/인용/인사 매핑과 컴포넌트 시험 → 필요한 기기 웹 수신/확인과 해당 시험 → 변경 표면 키보드/확대/연습 회귀. U16 구현 내용이나 배포 방식을 대신 정하지 않는다.

### 제외

새 페이지/정책 대시보드·새 보호자 동의 UI·메모리/리포트 기능·서비스 전체 접근성 재설계. UI에서 서버 상태·권한·기기 멈춤을 자체 승인하지 않는다.

## 공통 품질·인계

- 각 단위는 자신의 책임과 스토리 부분의 완료를 증명한다. 두 단위에 걸친 사용자 결과는 모든 해당 부분과 최종 통합 회귀가 있어야 전체 완료다.
- 기존 기능 이름 시험 태그·커버리지 파일을 사용한다. 예시는 service-guardrail, guardrail-presentation이며 U16/U17 번호를 새 시험 경로 규칙으로 강제하지 않는다.
- 합의한 test-after·줄 80%·계약 대조/ArchUnit·전체 verify.sh와 개인정보/수동 스택 보호를 유지한다.
- NFR1–NFR6의 세부 설계와 검증은 두 단위의 적용 표면 및 후속 NFR/Build and Test에서 추적한다. 새 제품 요구사항으로 확장하지 않는다.
- 이번 단위는 기존 실행 산출물의 변경 묶음이며 독립적인 새 배포 제품이 아니다. 최종 서비스 교체 완료는 서버와 UI의 결합 결과로 검증한다.

## Assumptions & Open Questions

- 실제 변경 파일 수·자료형/API/DB 필드·승인 안내 음성 확보 방법·호환성 세부는 다음 Contract/Functional Design에서 확정한다. 자원 부재·미확인을 성공으로 덮지 않는다.
- 원본/라이선스·실제 모델 품질 미확인은 상위 요구사항을 승계한다. 자동 대역 검증을 실공급자/실기기 성공으로 표시하지 않는다.
- 이 문서는 단위 책임을 정한다. 경제적 우선순위·Bolt·일정·최종 병합 계획은 Delivery Planning에서 정한다.
