## ADR-001: 정책·판단·실행·검수·표시 책임 분리

### Context

기본 지시와 첫 질문·휴식·교정·종료 판단은 다른 경로에서 구성된다. 본문만 추가하면 서로 반대 지시를 내릴 수 있으며, 기존 실행기는 mailbox로 상태·세대를 직렬 관리한다. [FR1, FR3, FR4, FR7]

### Decision

Q1-A에 따라 ServicePolicyCatalog, DialoguePolicy, SessionLifecycle, OutputGuard, ConversationPresentation의 5개 논리 책임을 명시한다. 기존 앱/패키지 안에서 필요한 경계만 구현하며 새 원격 정책 서비스는 만들지 않는다. 세션 상태를 바꾸는 소유자는 기존 실행기 하나다.

### Consequences

버전/지시/상태/검수/표시를 독립 시험할 수 있다. 내부 값과 호출 경계의 비용은 생기지만 기존 실행기를 전면 재작성하지 않는다. 클래스 수·파일/Unit 경계는 다음 설계에서 정한다.

### Alternatives Rejected

기존 클래스마다 자원/지시/상태를 한꺼번에 구현하는 안은 초기에 경계를 덜 만들지만 정책 변경 시 회귀 범위가 커져 선택하지 않았다. 별도 원격 정책 서비스는 버전 조정·네트워크 실패·배포를 추가하므로 범위에 맞지 않는다.

## ADR-002: 세션 시작에 고정한 모드별 정책 묶음

### Context

지시문 출처와 적용본 해시를 추적해야 하며, 현재 초기 요청 팩토리에는 모드 입력이 없다. 자유대화 전체 정책을 공용 경로에 넣으면 연습 지침을 침범한다. [FR1, FR7.1, FR7.3, NFR5]

### Decision

앱 산출물의 PolicyBundle을 적재/검증하고 세션 시작에 모드별 묶음을 고정한다. 자유대화는 새 서비스 본문, 연습은 기존 지침 경계다. 초기/후속/판단 요청은 같은 묶음의 기준을 사용한다. sourceHash와 appliedHash를 구분하고 현재 세션에서 정책을 자동 hot reload하지 않는다.

### Consequences

정책 출처·실제 전송·세션 증거의 귀속을 재현할 수 있다. 잘못된/빈 자원으로 일반 대화를 시작할 수 없고 조용한 이전 정책 대체도 없다. 변경 정책의 적용에는 새 실행 산출물/세션이 필요하며 이미 살아 있는 세션의 버전 전환 기능은 제공하지 않는다.

### Alternatives Rejected

원본 knowledge 파일을 실행 시 읽는 안은 문서 변경/경로/배포 의존이 생긴다. 모든 모드에 같은 새 본문을 쓰는 안은 연습 보존 요구에 맞지 않는다. 버전만 남기고 실제 적용본 해시를 생략하는 안은 사실 안내 조정의 추적이 약해진다.

## ADR-003: 실제 전달 증거와 참여·출력 허가의 단일 소유

### Context

기존 JoinFlow는 안내가 없거나 보내지 못해도 재생 완료로 진행하고 안내 중 대답을 곧바로 분류한다. 새 요구는 매 세션 실제 안내 완료 후 현재 참여 확인이다. 비동기 검수·기기 확인과 종료가 경합할 수 있다. [FR2, FR4.3, NFR2]

### Decision

SessionLifecycle이 NoticeDeliveryEvidence와 참여/세대/종료 상태를 소유한다. 인증된 현재 기기의 확인을 예상 세션/재생/정책/현재 상태에 묶어 검증하고, 리소스/말풍선/전송을 증거로 사용하지 않는다. 판단/검수는 결과만 반환하며 actor가 현재 허가를 재확인한다. 기기 큐/재생 경계도 기존 세대·중단 확인을 유지한다.

### Consequences

조기/중복/지난 확인과 실패가 ACTIVE/일반 출력을 열지 않는다. 확인 지연/실패에서는 일반 대화를 보류하므로 가용성보다 확인된 참여를 우선하는 기존 승인 선택을 따른다. 실제 안내 자원·기기 완료 표식·마감의 세부 계약을 확인해야 한다.

### Alternatives Rejected

모델이 ‘안내했다’고 말하거나 UI에 말풍선을 그린 것으로 완료를 추정하는 안은 실제 전달을 증명하지 못한다. DialoguePolicy/프런트/OutputGuard가 각각 참여 상태를 바꾸는 안은 권위가 나뉘어 경합을 만든다. 매번 새로운 AI 분류기를 추가하는 안은 필요 없고 기존 호출 예산을 바꾼다.

## ADR-004: 판단 의미와 실행 효과를 분리하고 기존 종료 경로를 검증

### Context

명확한 전체 종료·화제 거절·인용·모호함을 구분해야 하며, 현재 로컬 종료 규칙과 기존 J6가 있다. User Stories R-01은 판정 결과를 주입한 시험만으로 실제 판단 요청의 정책 전달이 검증되지 않는다는 위험이다. [FR3, FR4, US1.6]

### Decision

DialoguePolicy가 모드별 지시·로컬 규칙·기존 J6 요청의 정책 의미를 담당하고 SessionLifecycle이 전이/재생/시계를 실행한다. 명확한 전체 종료는 반복 확인 없이 종료, 모호함만 한 번 확인, 인용/화제 거절은 전체 종료와 분리한다. R-01은 로컬 규칙과 실제 J6 요청 구성→결과 매핑→효과의 대역 경계 시험으로 Functional Design에 인계한다.

### Consequences

새 AI 공급자 없이 기존 판단 경로를 재사용한다. 정책의 실제 전달과 서버의 결과 처리를 별도로 검증할 수 있지만 실제 모델 정확도 보장은 하지 않는다. 같은 정보 도움/화제 거절 범위의 세션 상태 상세는 후속 기능 설계가 필요하다.

### Alternatives Rejected

GPT-Live 본문만 바꾸고 종료/J6 요청을 두는 안은 R-01 위험을 남긴다. 등록 문구만 종료로 인정하는 안은 자연스러운 종료 존중에 부족하다. 모든 애매한 말마다 새 외부 분류 호출을 추가하는 안은 기존 경계/예산을 넓힌다.

## ADR-005: 사실의 투영과 화면 매핑 분리

### Context

P-03 무응답 제목, 고정 기본 종료 인용, 항상 인사 중이라는 S-17 설명은 거절·자연어 종료·즉시 음소거 상황에서 사실과 다를 수 있다. 새 전체 UI나 저장 정책을 만들 필요는 없다. [RP-2–RP-4, FR5]

### Decision

SessionLifecycle은 참여 원인·확인된 종료 표현·실제 승인 인사 재생·기기 확인 사실을 기존 계약으로 투영하고 ConversationPresentation은 그 범위만 표시한다. 정보가 없으면 확정적인 사유를 추측하지 않고 인용/인사 줄을 숨긴다. 필요한 최소 계약 확장은 후속 Contract Design에서 정하며 actor 종료 후 조회에도 사실/unknown이 보존되는 방법을 확인한다.

### Consequences

원문/프런트 기본값으로 하지 않은 말을 채우지 않고 기존 화면을 재사용한다. 조회 스냅숏의 새 사실 표현과 이전 응답의 호환성 설계가 필요할 수 있다. 표현을 숨기는 것이 새 기록 삭제·보관 정책 변경을 뜻하지 않는다.

### Alternatives Rejected

프런트가 DECLINED를 모두 무응답으로 보거나 기본 종료 문구를 자동 인용하는 안은 오해를 지속한다. UI가 새 상태 권위를 갖는 안은 서버와 불일치한다. 새 대시보드·전면 기록 재설계는 승인 범위를 벗어난다.

## 범위와 인계

자료형·검증·허용값·API/DB 스키마·Unit/배포 묶음·NFR 패턴은 후속 단계에서 다룬다. 기존 시간·원음/전사 보관·JEV 범주·연습·공급자를 보존하며 배포/유료 실호출은 하지 않는다. ADR은 이 작업의 선택을 기록하며 이전 승인 문서를 덮어쓰지 않는다.
