## 계획과 검증 기준

8개 스토리는 승인된 Must 요구사항을 구체화하므로 모두 **Must Have**다. 최종 구현 묶음과 순서는 Delivery Planning에서 정한다. 기능별 파일 소유를 미리 확정하지 않으며, 승인된 요구사항의 ID와 범위를 바꾸지 않는다.

모든 AC는 자동 시험 가능한 서버 동작/출력 경계와 공급자에 전달되는 지시를 검증한다. `[자동-대역]`은 가짜 공급자/기기 재생 대역을 사용한다. 모델이 항상 문구를 지킨다는 품질 보장은 하지 않는다. 실제 모델이 맥락·감정·종료를 올바르게 판단하는지는 별도 실호출 관측 대상이며 이번에는 실행하지 않는다. 새로운 화면 문구나 API 형식은 이 문서에서 확정하지 않는다.

## US1.1 — 나에게 맞는 자유대화 정책

아이(P1)로서, 서비스에서 정한 일관된 방식으로 대화하고 싶다. 그래야 오래된 시험 지시나 다른 아이의 정보가 내 대화를 바꾸지 않는다.

- **Priority**: Must Have
- **근거**: FR1, FR1.1–FR1.3, FR5.2, FR7.1.
- **의존**: 기존 자유대화 세션 기반. 새 스토리 의존 없음.
- **AC1.1.1 [자동-대역]** Given 사용 가능한 새 정책 자원과 자유대화 시작 요청, When 초기 공급자 요청을 만들면, Then service-0.1 기반 적용본을 한 번만 포함하고 기존 역할/시험 지시와 최초 관심사 질문 강제를 중복하지 않는다.
- **AC1.1.2 [자동-대역]** Given 누락·빈 값·읽기 실패 중 하나인 적용 자원, When 일반 대화를 시작하려 하면, Then 명시적 오류로 일반 대화를 열지 않고 옛 템플릿으로 조용히 대체하지 않는다.
- **AC1.1.3 [자동-대역]** Given 한글·따옴표·역슬래시·줄바꿈·제어 문자·상한 초과 문맥, When 허용된 아이 정보를 전달하면, Then 기존 상한/이스케이프를 적용하고 이를 지시와 구분하며 내부 ID·키·타인 정보를 추가하지 않는다.
- **AC1.1.4 [자동-대역]** Given 깨끗한 빌드의 실행 산출물, When 정책 자원을 읽으면, Then knowledge/Windows 경로 없이 같은 적용 버전·해시를 식별하고 원본과 적용본 차이를 추적할 수 있다.
- **AC1.1.5 [자동-대역]** Given 구현 계약 JSON과 기존 GPT-Live 요청 형식, When 새 지시문을 연결하면, Then 모델/공급자를 교체하지 않고 애플리케이션 계약 필드를 공급자 API 필드로 복사하지 않는다.
- **INVEST**: 하나의 사용자 결과인 올바른 정책 적용으로 묶는다. 지시문 저장 위치·메타데이터 방법은 설계에서 협의하며, 자원/요청 대역으로 독립 검증한다. 크기는 구현 분해 시 다시 확인한다.

## US1.2 — 매 세션 실제로 듣는 안내

아이(P1)로서, 대화 전에 AI와 기록·열람 사실을 안내받고 싶다. 그래야 무엇을 알고 참여할지 결정할 수 있다.

- **Priority**: Must Have
- **근거**: FR2.1, FR2.2, FR2.5.
- **의존**: US1.1. 참여 수락 결과는 US1.3이 다룬다.
- **AC1.2.1 [자동-대역]** Given 새 자유대화 세션, When 시작 안내를 제공하면, Then AI임·대화 글/아이 음성 저장·보호자 열람/수동 공유 가능·말하지 않거나 그만둘 수 있음을 실제 기능과 맞는 승인 안내로 제공한다.
- **AC1.2.2 [자동-대역]** Given 현재 세션/안내 재생/정책에 묶인 유효한 완료 확인, When 완료 이벤트를 처리하면, Then 그 안내만 완료로 표시하고 모델이 같은 안내/참여 질문을 중복 시작하지 않도록 확인된 상태만 전달한다.
- **AC1.2.3 [자동-대역]** Given 안내 리소스 누락·전송 실패·재생 확인 만료, When 시작 처리가 진행되면, Then 완료로 추정하지 않고 오류/기술 종료 경로로 처리하며 일반 대화를 열지 않는다.
- **AC1.2.4 [자동-대역]** Given 이전 세션·이전 정책·다른 재생·중단된 재생의 확인, When 완료 이벤트가 오면, Then 현재 안내를 대신하지 못하고 일반 대화는 잠긴다.
- **AC1.2.5 [자동-대역]** Given 같은 세션의 중복 완료 확인 또는 완료 확인과 종료가 경합, When 이벤트를 처리하면, Then 현재 완료를 중복 적용하지 않고 이미 끝난 세션의 대화를 되살리지 않는다.
- **INVEST**: ‘실제로 안내받음’ 한 결과와 실패 경계로 제한한다. 완료 확인의 전송 구현은 설계에서 정하며, 정상/누락/틀린 확인 대역으로 검증한다.

## US1.3 — 내가 고르는 참여

아이(P1)로서, 안내를 들은 뒤 내가 이야기할지 고르고 싶다. 그래야 보호자의 동의나 우연한 발화가 내 참여로 대신 처리되지 않는다.

- **Priority**: Must Have
- **근거**: FR2.3, FR2.4, FR2.5, FR6.1, FR6.3.
- **의존**: US1.2. 안내 완료를 대역으로 제공해 이 결과를 독립 검증한다.
- **AC1.3.1 [자동-대역]** Given 현재 안내 완료 후의 유효한 참여 수락, When 이를 처리하면, Then ACTIVE 전환·원음 기록 시작·일반 대화 시작은 각각 필요한 동작을 한 번만 수행한다. 보호자 동의만으로는 전환하지 않는다.
- **AC1.3.2 [자동-대역]** Given 안내 도중의 조기 응답, When 아이가 수락처럼 들리는 말을 해도, Then 해당 응답만으로 참여를 확정하지 않고 안내 완료 뒤 현재 참여 의사를 다시 확인한다.
- **AC1.3.3 [자동-대역]** Given 명확한 참여 거절, When 이를 처리하면, Then 만류·반복 대안 없이 기존 DECLINED 정리로 연결하고 정상 활동/참여 기록으로 꾸미지 않는다.
- **AC1.3.4 [자동-대역]** Given 참여 전 대기·불명확 답 또는 무응답, When 기존 20초/재안내 뒤 20초 창과 기술 일시정지 규칙을 적용하면, Then 실제 불명확함만 짧게 확인하고 기존 무응답 정리 규칙을 유지한다. 참여 전 전사는 분류에만 사용하며 원음 영속 기록을 새로 시작하지 않는다.
- **AC1.3.5 [자동-대역]** Given 같은 수락의 중복 또는 종료/이전 세대의 늦은 판정, When 이를 처리하면, Then 중복 ACTIVE·첫 응답 시작이 없고 끝난 세션을 다시 활성화하지 않는다.
- **INVEST**: ‘안내 이후 내 선택’으로 한정한다. 안내·전사·기기를 대역으로 제공해 테스트할 수 있으며 기존 기록 정책은 바꾸지 않는다.

## US1.4 — 내가 고르는 이야기

아이(P1)로서, 내가 꺼낸 경험·질문·화제를 따라 대화하고 싶다. 그래야 미리 정한 질문에 끌려가거나 거절한 이야기를 계속 요구받지 않는다.

- **Priority**: Must Have
- **근거**: FR3.1, FR3.2.
- **의존**: US1.3. ACTIVE 대역으로 독립 시험한다.
- **AC1.4.1 [자동-대역]** Given 아이가 이미 질문/경험을 말한 상태, When 첫 응답/일반 응답을 지시하면, Then 그 내용을 먼저 따르며 관심사 질문으로 덮거나 답 뒤 새 질문을 항상 붙이라고 강제하지 않는다.
- **AC1.4.2 [자동-대역]** Given 아이가 참여 중이지만 다음 말이 막힌 상태, When 대화를 돕는 지시를 보내면, Then 지금 맥락의 주요 질문/설명 요청 하나만 허용하며 주변 정보를 계속 채우도록 강제하지 않는다.
- **AC1.4.3 [자동-대역]** Given 화제 거절과 대안 없음, When 후속 지시를 선택하면, Then 수용 후 질문 없이 기다리도록 하며 표현만 바꿔 같은 화제를 다시 요구하지 않는다.
- **AC1.4.4 [자동-대역]** Given 아이가 다른 화제를 제안하거나 스스로 거절한 화제를 다시 엶, When 후속 지시를 보내면, Then 아이가 선택한 새 맥락을 따르며 서버의 이전 강제 첫 질문이 이를 뒤집지 않는다.
- **AC1.4.5 [자동-대역]** Given 실제 경험과 상상 또는 보호자 보고가 섞인 문맥, When 지시문을 구성하면, Then 그 출처를 같다고 단정하거나 실제 경험 수집을 성공 조건으로 강제하지 않는 새 정책을 유지한다.
- **INVEST**: 화제 선택이라는 한 사용자 결과로 묶는다. 모델 품질은 별도이며, 서버의 강제 질문 제거와 전달 정책은 자동 대조한다.

## US1.5 — 정정하고 이해받기

아이(P1)로서, 내가 고친 말을 기억하고 모르는 부분만 확인받고 싶다. 그래야 능력 시험처럼 반복 질문을 받거나 취소한 질문을 다시 듣지 않는다.

- **Priority**: Must Have
- **근거**: FR3.3, FR3.4.
- **의존**: US1.3. 후속 지시·재시도 경계를 대역으로 검증한다.
- **AC1.5.1 [자동-대역]** Given 아이의 정정/끼어들기와 취소된 응답, When 다음 지시를 구성하면, Then 정정과 발언권을 존중하고 취소한 말/질문을 다시 잇지 않는 정책을 보존한다.
- **AC1.5.2 [자동-대역]** Given 같은 정보 요구에서 최초 요청 뒤 한 차례 도움/재설명이 사용됨, When 여전히 어렵거나 싫다는 맥락이면, Then 같은 정보를 표현만 바꿔 다시 요구하도록 지시하지 않는다.
- **AC1.5.3 [자동-대역]** Given 실제 이해 실패 근거가 없는 판정 보류·교정·재시도, When 후속 지시를 보내면, Then 일부러 못 알아들은 척하거나 의무 새 질문을 강제하지 않는다.
- **AC1.5.4 [자동-대역]** Given 공급자 세션에 남는 이전 후속 지시, When 새 지시를 추가하면, Then 적용 범위를 닫아 다음 턴의 화제·휴식·정정 정책을 덮지 않게 한다.
- **AC1.5.5 [자동-대역]** Given 아이가 말하는 중/느린 응답/침묵, When 서버의 응답 지시를 만들면, Then 모든 발화에 고정 맞장구를 의무화하거나 이를 즉시 답변 실패로 단정하는 지시를 보내지 않는다.
- **INVEST**: 정확한 이해와 제한된 확인이라는 결과로 한정한다. 반복 요구의 문맥 연결 방법·판정 구현은 후속 설계에서 정한다.

## US1.6 — 쉬거나 끝내는 선택

아이(P1)로서, 쉬거나 그만두겠다는 말을 존중받고 싶다. 그래야 재개를 설득받거나 끝낸 대화가 다시 재생되지 않는다.

- **Priority**: Must Have
- **근거**: FR3.2, FR4, FR4.1–FR4.3, FR6.1–FR6.2.
- **의존**: US1.3. ACTIVE·기기 재생/확인 대역으로 독립 검증한다.
- **AC1.6.1 [자동-대역]** Given 휴식/생각할 시간 요청, When 후속 지시를 보내면, Then 짧게 수용하고 기다리며 ‘잠깐 뒤 이어 하자’는 재개 압박이나 자동 새 질문을 강제하지 않는다.
- **AC1.6.2 [자동-대역]** Given 현재 전체 대화의 명확한 종료 의사, When 종료로 분류된 의사를 처리하면, Then 재확인·이유 질문·만류 없이 CHILD_STOP으로 연결하고 승인된 짧은 인사는 최대 한 번만 허용한다. 즉시 음소거/서버 중단이면 추가 발화 0회다.
- **AC1.6.3 [자동-대역]** Given 정말 모호한 종료 의사, When 확인을 시작하면, Then 일반 대화를 보류하고 한 번만 짧게 확인한다. 명확한 종료 답에는 다시 묻지 않는다. 단순 무응답은 종료 동의로 꾸미지 않고 기존 20초 확인 대기 동작을 유지한다.
- **AC1.6.4 [자동-대역]** Given 이야기 속 인용된 종료 표현 또는 화제만 거절한 판정, When 서버가 그 판정을 처리하면, Then 현재 전체 종료와 구분한다. 종료/끼어들기 이후 늦은 결과·음성·재생 확인이 와도 지난 세대를 재생/재활성화하지 않는다.
- **AC1.6.5 [자동-대역]** Given 공백·입력 연결 장애·기술 일시정지·재생 또는 기기 종료 확인 누락, When 기존 시계를 적용하면, Then 4분 안내/6분 종료·40초 재연결·30초 종료 확인과 기존 제외/리셋 의미를 유지하고 입력 장애를 아이 침묵으로 바꾸지 않는다. 실제 확인 전에는 기기 중단 완료를 말하지 않는다.
- **INVEST**: 휴식/종료 모두 아이가 발언권을 거두는 결과다. 늦은 결과·시계 경합은 같은 종료 경계로 검증하며, 세부 구현은 설계에서 협의한다. 실제 모호한 발화를 분류하는 모델 품질은 자동 판정 성공으로 표시하지 않는다.

## US2.1 — 사실에 맞는 서비스 설명

보호자(P2)로서, 아이가 듣는 저장·열람·공유·삭제 설명이 실제 기능과 같기를 원한다. 그래야 서비스가 하지 않은 일을 했다고 믿거나 비밀이 보장된다고 오해하지 않는다.

- **Priority**: Must Have
- **근거**: FR5.1, FR5.3, FR6.3.
- **의존**: US1.1, US1.2. 정책 사실·동작 결과 대역으로 독립 검증한다.
- **AC2.1.1 [자동-대역]** Given 현행 저장/보호자 열람/수동 공유/삭제의 확인된 사실, When 안내·기본/후속 지시를 만들면, Then 그 범위만 설명하고 원본과 적용본에 차이가 있으면 근거를 추적한다.
- **AC2.1.2 [자동-대역]** Given 삭제 접수·대기만 확인되거나 원음 재생/외부 PDF 삭제/긴급 연락/모드 전환 완료가 확인되지 않음, When 모델에 사실 문맥을 제공하면, Then 완료·가능을 꾸미도록 지시하지 않으며 더 적게 저장/공유된다고 약속하지 않는다.
- **AC2.1.3 [자동-대역]** Given 아이의 비밀 보장/삭제 요청 또는 보호자가 알고 싶다는 내용, When 새 지시문을 제공하면, Then 비밀 보장·권한 변경·정보 조사 강요를 하지 않는 정책을 포함한다. 대화 안의 요청만으로 서버 기능이 실행됐다고 처리하지 않는다.
- **AC2.1.4 [자동-대역]** Given 과거 기억이 제공되지 않았거나 보호자 보고/아이 경험/미확인 추정이 섞임, When 정책/허용 문맥을 전달하면, Then 이를 구분하고 새 장기 기억·임상 진단·점수·고정 성격을 만들어 제공하지 않는다.
- **AC2.1.5 [자동-대역]** Given 교체 전의 동의·전사/원음·계정 삭제·보호자 권한 경계, When 새 대화 정책을 적용하면, Then 저장/삭제/PDF/관찰 결과를 전면 변경하지 않고 기존 회귀를 유지한다. 실제와 맞추려면 새 제품 정책이 필요한 차이는 자동으로 범위를 넓히지 않는다.
- **INVEST**: ‘실제 기능과 같은 설명’으로 좁힌다. 저장 기능 자체의 신규 구현은 제외하고 사실 문맥/지시와 기존 회귀로 확인한다.

## US2.2 — 정책 교체 후에도 유지되는 연습과 검수

보호자(P2)로서, 자유대화 정책을 바꿔도 기존 연습과 출력 검수가 유지되길 원한다. 그래야 교체 때문에 아이가 다른 모드의 지시나 미검사 음성을 듣지 않는다.

- **Priority**: Must Have
- **근거**: FR7, FR7.1–FR7.3, FR6.3.
- **의존**: US1.1. 나머지 스토리의 모드·출력 회귀 경계로 함께 검증한다.
- **AC2.2.1 [자동-대역]** Given 기존 연습 세션, When 공용 요청/지시 코드를 사용하면, Then 자유대화용 전체 지시문을 무조건 넣지 않고 기존 연습 역할·판정·시작·종료 동작을 유지한다.
- **AC2.2.2 [자동-대역]** Given 자유대화의 JEV 검사 요청/응답, When 새 정책을 연결하면, Then 기존 어댑터·범주·결과 검증을 유지하고 진단/점수/압박 등 기존 금지를 완화하지 않는다.
- **AC2.2.3 [자동-대역]** Given 미검사·실패·타임아웃·불완전/음성-텍스트 정렬 미확인 후보, When 출력 경계를 통과하려 하면, Then 기존 보류/폐기 경계를 유지해 미승인 모델 음성을 재생하지 않는다.
- **AC2.2.4 [자동-대역]** Given 이전 세대 결과 또는 현재 상태/출력 목적과 맞지 않는 후보, When 검사/출력 허가를 재확인하면, Then 늦은 결과가 멈춘 세션이나 다른 모드의 일반 대화를 열지 않는다.
- **AC2.2.5 [자동-대역]** Given 새 계약의 제안 JEV 축·기억·관찰 상태, When 교체 결과를 검증/보고하면, Then 이를 신규 구현하거나 모두 탐지됐다고 주장하지 않고 기존 공급자·저장 경계의 회귀 증거만 표시한다.
- **INVEST**: ‘기존 서비스 결과를 보호’하는 호환성 스토리다. 모드/검사 대역으로 독립 회귀하며 구체적인 코드 변경이 불필요한 부분은 유지 증거로 닫는다. 신규 제브 분류기나 연습 기능을 더하지 않는다.

## 스토리 밖 추적

| 상위 요구사항 | 추적 방식 | 후속 단계/검증 |
|---|---|---|
| NFR1 | 운영 로그의 비밀/원문 금지는 새 사용자 동작을 만들지 않는다. US1.1/US2.1의 모델 문맥 보호와 구분해 Deferred 추적 | nfr-requirements, nfr-design, functional-design, build-and-test의 허용 로그 항목 시험 |
| NFR2 | US1.2/US1.3/US1.6/US2.2의 실패·중복·지난 세대 AC에 연결 | functional-design, code-generation, build-and-test |
| NFR3 | 시험 순서·줄 80%·기존 검사·전체 verify.sh는 개발 품질 조건 | code-generation 및 build-and-test |
| NFR4 | 모든 AC의 대역 표기와 실제 공급자 품질 구분은 증거 조건 | build-and-test 보고, 실호출은 이번 범위 밖 |
| NFR5 | 정책 자원/해시/문자 보존은 US1.1에 연결 | functional-design, code-generation, build-and-test |

FR 묶음 머리와 모든 하위 ID를 traceability.json에 별도 나열한다. 새 요구사항/권한을 추가하지 않고, NFR의 Deferred는 ‘나중에 잊음’이 아니라 위 이름 붙인 단계에서 세분화할 항목이다.

## Assumptions & Open Questions

- 승인된 요구사항과 Q1의 분해 방식 외에 새 제품 결정은 없다. 사용자 역할/빈도/임상 분류를 창작하지 않는다.
- 정책 사실·승인 안내 자원·재생 일치 확인의 구체적인 방법은 기존 요구사항대로 후속 설계에서 정한다. 권한/저장 정책을 새로 결정해야 하는 차이는 사람에게 되묻는다.
- 실제 모델의 질문 수·정정 이해·종료/인용 분류 품질은 대역 AC 통과와 별개다. 새 동작이 필요한데 실제 모델만으로 강제할 수 없는 규칙은 설계에서 상태/출력 경계를 명시한다.
- 문서 원본/라이선스 미확인, 실제 기기/유료 AI/배포/저장 전면 개편 제외는 상위 요구사항 그대로다.
