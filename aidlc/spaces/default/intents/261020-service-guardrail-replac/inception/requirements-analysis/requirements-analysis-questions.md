## Q1 — 이번 교체의 범위

새 패키지는 자유대화 지시문과 서버 구현 계약을 나눈다. GPT-Live 기본 지시문과 서버가 보내는 첫 질문·휴식·종료 후속 지시가 별도로 있으므로, 지시문만 바꾸면 서로 충돌할 수 있다. JEV 출력 검사는 별도 구현이고 새 문서는 대체 구현을 제공하지 않는다.

이번에는 어디까지 바꿀까요?

- A. 새 지시문 + 충돌하는 대화 흐름 조정 (추천): GPT-Live 자유대화 지시문을 교체하고 첫 질문·휴식·종료 등 직접 충돌하는 서버 지시·상태 처리를 함께 맞춘다. 기존 JEV 검사와 연습 모드의 별도 지침을 유지한다. 저장·PDF·기억·리포트 기능의 전면 재구축은 제외한다.
- B. 지시문만 교체: GPT-Live 기본 지시문만 바꾸고 기존 서버 흐름을 유지한다. 문서와 다른 서버 동작을 편차·잔여 위험으로 명시하며 새 계약 전체 준수로 표시하지 않는다.
- C. 서비스 계약 전체 반영: 안내·참여·종료·저장/삭제·동의·기기·기록 등 계약 전체를 현행 코드와 대조하고 필요한 변경을 범위에 포함한다. 미정 정책은 추가 질문으로 정한다. 제안 기능(JEV 확장·기억·관찰 결과)의 신규 구현 여부도 별도 결정한다.
- X. Other (please specify)

[Answer]: A. 새 지시문 + 대화 흐름 조정 (Recommended)

## Q2 — 아동 안내의 반복 시점

기존 서버는 세션을 시작할 때 승인된 시작 안내를 재생한다. 새 지시문은 실제 안내 전달 및 현재 세션의 아이 참여 확인 없이는 일반 대화를 시작하지 않으며, 확인되지 않은 안내를 완료로 추정하지 않는다. 정책 버전과 세션에 묶인 실제 재생 확인을 사용하고, 안내 누락·전송 실패·확인 만료 때는 일반 대화로 넘어가지 않는다.

- A. 매 세션 안내 + 참여 확인 (추천): 기존 세션별 시작 흐름을 유지하면서 새 서비스 안내로 맞춘다. 현재 세션에서 확인된 안내를 모델이 다시 읽지 않게 한다.
- B. 최초·정책 변경 때 안내, 매 세션 참여 확인: 같은 아이의 유효한 이전 안내 기록이 있을 때만 안내를 생략한다. 이전 안내의 정책 버전·출처·유효성 저장이 추가로 필요하다.
- X. Other (please specify)

[Answer]: A. 매 세션 안내 + 참여 확인 (사용자 원문: Q2 - 1, Q3 - 1)

## Q3 — Assumption Confirmation

Q1에서 선택한 범위에 맞춰, 문서와 기존 코드가 뒷받침하는 다음 내용을 함께 적용한다. 서로 다른 제품 선택이 필요한 부분은 개별 질문으로 전환할 수 있다.

1. 자유대화의 기본·후속 지시만 새 정책에 맞추고 연습의 기존 전용 지시·판정·UI는 유지한다. 공용 코드가 바뀌면 연습 회귀를 확인한다.
2. GPT-Live 공급자·모델·호출 형식을 바꾸지 않는다. 서비스 계약 JSON은 공급자 API 필드로 보내지 않는다. JEV 어댑터·현재 판정 범주·검사 실패 시 출력 보류 경계를 유지하며 새 제안 축 전체 검출을 달성했다고 표시하지 않는다.
3. 첫 응답에서 이미 한 아이 말을 관심사 질문으로 덮지 않는다. 휴식·화제 거절에는 이어 하기를 압박하지 않는다. 명확한 전체 종료는 재확인 없이 마무리하고, 모호한 경우만 한 번 확인한다. 인용한 종료 표현은 구분한다.
4. 기존 참여 대기 20초(재안내 뒤 20초), 공백 안내 4분/종료 6분, 재연결 40초, 기기 종료 확인 30초 및 기술 일시정지·재생 제외 의미를 유지한다. 총 대화 시간·턴 수·시험 예산 제한을 새로 넣지 않는다.
5. 참여 전 저장 정책을 새로 만들지 않는다. 현재 구현은 WAITING_CHILD 전사를 분류에만 쓰고 ACTIVE 진입 때 원음 기록을 시작한다. 안내 미전달 상태의 발화로 참여를 확정하거나 이를 기록 완료로 꾸미지 않는다.
6. 새 지시문의 저장·열람·공유·삭제 안내를 현행 서비스의 검증된 사실에 맞춘다. 전면 저장/삭제·PDF·관찰 결과·기억 개편은 제외하고, 확인되지 않은 원음 재생·삭제 완료·긴급 연락·모드 전환을 약속하지 않는다.
7. 원본 문서와 Windows Zone.Identifier 파일은 변경하지 않는다. 지시문을 앱 자원으로 반영할 때 버전·해시를 추적하고, 개인 문맥은 데이터로 구분해 기존 이스케이프·상한을 유지한다. 일반 운영 로그에 원문·음성·키를 남기지 않는다.
8. 시험은 합의한 가짜 공급자로 검증하고 실제 모델의 행동 품질과 구분한다. 이번에는 배포·유료 AI 호출·수동 스택 변경을 하지 않는다.

- A. Accept assumptions
- B. Convert to follow-up questions
- X. Other (please specify)

## Assumptions & Open Questions

- Q1-A, Q2-A, Q3-A를 선택했다. 자유대화 지시문과 직접 충돌하는 대화 흐름을 조정하고 매 세션 안내·참여 확인을 적용한다. 기본안 8개는 Accept assumptions로 확인했다.
- 지시문의 저장·열람·공유·삭제 설명은 실제 서버 정책과 맞아야 한다. 차이가 있으면 확인 없이 기능 완료를 약속하는 문구를 넣지 않는다.
- 안내 전달 확인을 강화하고 명확한 종료는 재확인하지 않는다. 첫 참여 대기·공백·재연결·기기 종료 확인 시간과 기존 저장 정책은 유지한다.
- ZIP의 참조 원본 화면설계 HTML/v03_full.txt와 라이선스 선언은 앞선 분석에서 미확인이다. 이 폴더의 자료 확인만으로 권리·원본 일치가 인증된 것으로 기록하지 않는다.
- Guide me 방식으로 질문했다. 별도 요약 확인은 이번 작업에서 꺼져 있으므로 응답에 따라 요구사항을 생성한다. 단계 승인은 별도다.
