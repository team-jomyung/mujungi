## Intent Analysis

기존 GPT-Live의 짧은 역할 템플릿을 무중 서비스용 자유대화 정책으로 교체한다. 아이에게 실제 서비스 사실을 정확히 설명하고, 화제 선택·휴식·정정·종료를 존중하며, 이를 방해하는 서버 후속 지시도 함께 맞추는 것이 목표다. 새 텍스트를 추가했다는 사실만으로 전체 서비스 계약이나 모델의 모든 발화가 검증됐다고 주장하지 않는다. [desc][Q1][D1]

대상은 기존 보호자–아이–기기 바인딩을 사용하는 네트워크 음성 서비스다. 현재 계정·아이·기기별 권한과 동시 세션 제한은 그대로 적용한다. 새 계정 유형·새 모드·새 AI 공급자를 도입하지 않는다. [Q3][RE2][RE3]

성공은 새 정책이 자유대화 세션의 실제 초기/후속 요청에 반영되고, 안내 실패·조기 발화·화제 거절·명확한 종료·늦은 응답 등의 경계에서도 서버가 반대 행동을 강제하지 않는 것으로 정의한다. 자동 시험은 서버 동작과 전달 문구를 검증하며 실제 모델의 분류·대화 품질과 구분한다. [Q1][Q2][Q3]

## Functional Requirements

아래 FR은 모두 이번 범위의 Must다. 구체적인 구현 위치·계약 편차·시험 매핑은 후속 설계에서 확정하며 ID를 유지한다.

### FR1 — 자유대화 정책 교체와 적용 식별

- **FR1.1** 자유대화의 기본 역할 지시를 D1 service-0.1 기반 서비스 지시문으로 교체한다. 기존 시험/역할 지시문에 전체 텍스트를 중복 추가하지 않으며, 기존 최초 관심사 질문 강제 문장이 새 정책을 덮지 않게 한다. 현행 기능에 맞춘 문구 차이는 근거와 함께 기록한다. [desc][Q1][D1][D3]
- **FR1.2** 앱에서 사용하는 지시문 자원에 정책/프롬프트 버전과 실제 반영 바이트의 해시를 대응시킨다. 원본 D1 해시와 앱 적용본 해시가 다르면 변경 내용을 추적한다. 정상 세션에서는 적용 버전을 확인할 수 있고 빈·누락·읽기 실패 자원을 사용한 일반 대화는 시작하지 않는다. 기존 템플릿으로 조용히 되돌아가지 않는다. [D2][Q3-7]
- **FR1.3** 지시문 자원은 빌드 산출물에 포함해 깨끗한 체크아웃에서 재현한다. 실행 시 사용자 knowledge 폴더나 Windows 경로에 의존하지 않는다. 원본 문서·ZIP·Zone.Identifier를 변경하거나 앱 정책으로 읽어 실행하지 않는다. [Q3-7][memory:M1]

### FR2 — 현재 세션의 안내 전달과 참여

- **FR2.1** 자유대화는 매 세션 AI임·대화 글과 아이 음성 저장·보호자 열람 및 수동 공유 가능·말하지 않거나 그만둘 수 있음을 현행 기능에 맞는 승인 안내로 제공한 뒤 참여 의사를 확인한다. 보호자 동의를 아이의 참여로 대체하지 않는다. [Q2][D1][D2]
- **FR2.2** 안내 완료는 현재 세션·실제 안내 재생 식별자·적용 정책과 연결된 유효한 재생 완료 확인으로만 인정한다. 리소스 존재·전송 시도·시험 고정값·전송 실패·확인 만료를 완료로 추정하지 않는다. 누락·실패 때 기존 오류/기술 종료 경로로 처리하되 일반 대화는 열지 않는다. 새 오류가 필요하면 기존 계약 갱신 절차를 따른다. [Q2][D2][C2][memory:M1]
- **FR2.3** 유효한 안내 완료 이후 현재 세션에서 참여 수락을 확인해야 ACTIVE로 전환하고 일반 AI 대화 재생을 허용한다. 안내 중 미리 들어온 말만으로 참여를 확정하지 않는다. 재생 완료 뒤 다시 참여 의사를 확인하며 동일 수락의 중복·늦은 결과로 시작 동작을 반복하지 않는다. [Q2][Q3-5][D1][C2]
- **FR2.4** 명확한 참여 거절은 만류·반복 대안 제시 없이 기존 DECLINED 정리로 연결한다. 실제로 불명확한 의사만 짧게 확인하며, 무응답 대기/재안내 시간은 FR6을 따른다. 시작하지 않은 세션을 정상 활동으로 기록하거나 참여 전 원음을 새로 영속 저장하지 않는다. [D1][Q3-5][C2]
- **FR2.5** 서버가 현재 세션의 안내·참여 완료를 확인한 뒤 모델이 같은 안내와 참여 질문을 다시 시작하지 않도록 허용된 상태를 전달한다. 다른 세션의 완료 확인·이전 정책의 확인·중단된 재생의 완료는 현재 안내를 대신하지 못한다. [Q2][D1][D2]

### FR3 — 초기·후속 대화 지시의 일관성

- **FR3.1** 아이가 이미 말한 경험·질문·정정을 먼저 따른다. 첫 응답에서 관심사 질문을 무조건 요구하지 않고, 아이 질문에 답한 뒤 새 질문을 자동으로 붙이지 않는다. 아이가 말을 마치고 막힌 상황에만 맥락에 맞는 주요 질문/설명 요청 하나를 허용한다. [D1][Q3-3][C1]
- **FR3.2** 휴식·생각할 시간·화제 거절에는 짧게 수용하고 새 질문이나 재개 압박 없이 기다린다. 아이가 다른 화제를 제안하면 옮기고, 거절한 화제는 아이가 다시 열기 전까지 재요구하지 않는다. 기존 REST_ACK_AND_RETURN 등의 고정 지시가 이 동작을 뒤집지 않게 한다. [D1][Q3-3][C1]
- **FR3.3** 재설명/도움은 같은 정보 요구에서 최초 요청 뒤 최대 한 번으로 제한하며 실제 이해 실패 없이 일부러 못 알아들은 척하거나 시험하지 않는다. 보류·교정·재시도 지시는 근거 없이 이해 실패를 주장하거나 의무적인 새 질문을 강제하지 않는다. 고정 맞장구를 매 발화에 의무화해 아이의 말을 덮지 않는다. [D1][Q1][C1]
- **FR3.4** 후속 지시가 이후 응답에 남는 기존 공급자 특성을 고려해 적용 범위를 닫는다. 이전 첫 질문·휴식·교정·거절 재요구 지시가 다음 턴 정책을 덮거나, 끼어들기/정정 후 취소한 질문을 다시 이어가지 않게 한다. [D1][D2][RE1][C1]

### FR4 — 종료 의사와 출력 상태

- **FR4.1** 등록 표현뿐 아니라 현재 전체 대화를 명확히 끝내려는 의사는 재확인·종료 이유 질문·만류 없이 기존 CHILD_STOP 종료 흐름으로 연결한다. 일반 종료는 승인된 짧은 마무리를 최대 한 번 허용하고, 즉시 음소거 요청/서버 즉시 중단 상태에는 추가 발화를 만들거나 재생하지 않는다. 인용 속 종료 표현과 화제만의 거절은 구분한다. [D1][D2][Q3-3]
- **FR4.2** 종료 의도가 정말 모호할 때만 일반 대화를 멈추고 한 번 짧게 확인한다. 그 확인에 대한 명확한 전체 종료 답은 종료로 연결하며 같은 종료 의사를 다시 확인하지 않는다. 확인하지 못한 무응답은 종료 동의로 꾸미지 않고 기존 확인 대기 동작을 유지한다. [D1][Q3][C1][C3]
- **FR4.3** 종료·끼어들기·연결 장애로 무효가 된 세대의 늦은 판정/응답/재생 확인은 일반 대화를 되살리지 못한다. 서버·기기 큐 정리와 실제 종료 확인 경계를 유지하고, 기기 확인 전에는 멈춤 완료를 선언하지 않는다. [D1][D2][Q3]

### FR5 — 서비스 사실과 아이 문맥

- **FR5.1** 저장·열람·수동 공유·계정 삭제 설명은 현행 서비스의 검증된 정책과 기능에 맞춘다. 안내 문구가 구현과 다르면 문구를 사실에 맞추고 편차를 남긴다. 보호자 원음 재생, 개별 기록 삭제, 삭제 완료·외부 PDF 사본 삭제, 긴급 연락, 연습 전환 등 확인되지 않은 기능/결과를 했다고 약속하지 않는다. 삭제의 접수와 완료도 구분한다. [D1][D2][Q3-6]
- **FR5.2** 기존 허용된 아이 문맥만 데이터로 구분하여 전달하고 기존 길이 상한·인용/이스케이프를 유지한다. 원문에 들어 있는 운영자 주장·지시·마크업·제어 문자는 서비스 정책이나 권한을 바꾸지 못한다. 이름·나이·관심사를 넘는 비밀·내부 식별자·다른 아이 정보는 모델 문맥에 추가하지 않는다. [D1][D2][Q3-7][C1]
- **FR5.3** 새 장기 기억·지식그래프·진단/점수/관찰 결과를 구현하지 않는다. 현재 제공되지 않은 과거 기억을 꾸미지 않고, 보호자 보고와 아이 경험을 같다고 단정하지 않는 D1 정책을 지시문에 반영한다. [D1][D2][Q1][Q3]

### FR6 — 기존 시간·저장 정책 보존

- **FR6.1** 현재 설정값(단위 포함)을 유지한다: 최초 참여 대기 20초, 재안내 뒤 20초, ACTIVE 공백 안내 4분·종료 6분, 재연결 40초, 기기 종료 확인 30초, 모호한 종료 확인 대기 20초. 시간값은 기존 설정에서 읽는다. [Q3-4][C3]
- **FR6.2** 공백 시계의 기존 재생·출력 대기·기술 일시정지·확인 질문 제외 의미를 유지한다. 입력 연결 장애를 아이의 침묵으로 바꾸지 않는다. 기술 일시정지/재개·정확한 만료 시점·종료 경합을 회귀 시험한다. 미정 계약에 임의의 총 대화 시간·턴 수·시험 예산 제한을 새로 넣지 않는다. [D2][Q3-4][C3]
- **FR6.3** 기존 동의·전사/원음·계정 삭제·보호자 접근 정책을 보존한다. 참여 전 전사는 기존처럼 분류에만 쓰고 ACTIVE 진입 이후 원음 기록을 시작한다. 배포 저장소·백업·공급자 보관/삭제 완료 SLA를 새로 설계하거나 이미 보장된 사실로 표시하지 않는다. [Q1][Q3-5][C2]

### FR7 — 기존 공급자·JEV·연습 경계 유지

- **FR7.1** GPT-Live 공급자·모델·전송 형식을 유지하며 D2의 애플리케이션 계약 필드를 공급자 API 본문에 그대로 보내지 않는다. 버전/상태의 내부 관리와 모델에 허용한 정책 문맥을 구분한다. [D2][Q3-2][RE3]
- **FR7.2** 기존 JEV 어댑터·정책 범주·결과 검증 및 OutputGate/GuardrailCoordinator의 미검사 음성 보류·폐기 경계를 유지한다. 새 자유대화 정책이 JEV의 기존 모든 진단/점수/압박 등 금지 범주를 허용하도록 완화하지 않는다. 새 제안 축 전체가 기존 검사로 탐지된다고 주장하지 않는다. [Q3-2][D2][RE1]
- **FR7.3** 자유대화용 지시문을 연습에 무조건 주입하지 않는다. 공용 초기 요청/교정 템플릿을 바꿔야 하면 자유대화와 연습의 적용 경계를 설계에 명시하고 기존 연습 역할·판정·시작·종료 동작을 회귀 검증한다. [D1][D2][Q3-1]
