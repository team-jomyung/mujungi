## 음성 자원과 호출 범위

- 현재 infra/seed-audio WAV와 tools/seed/gen-session-wav.mjs, gen-approved-wav.mjs는 실제 안내 말소리가 아닌 톤/무음 자리다.
- 사용자는 현재 기존 파일을 활용하고 후속 구현 필요 사항을 정리하도록 했다. 기존 파일은 재생/표식·실패 연결 대역에 활용하되 새 안내를 실제 전달한 증거로 승격하지 않는다. 실제 음성 미준비를 전체 교체 완료로 보고하지 않는다.
- 사용자는 .env에 GPT-Live 키가 있으며 낭독 후 파일로 추출할 수 있는지 질문했다. 기존 session.instructions.append와 session.output_audio.delta 수신 경로, OpenAI 공식 문서로 기술적 가능을 확인했다.
- 안내 문구별 독립 GPT-Live 제작 세션 → PCM 조각 수집/WAV → 전사/청취·잘림/추가 발화·PCM16LE24kHz모노·20초 한도 확인 → 승인 콘텐츠 새 버전 등록 경로를 후속 항목으로 설계했다.
- 실제 유료 호출/음성 생성·키 접근 권한/생성 품질 검증은 아직 하지 않았다. 키 값은 출력하지 않았다. 가능 여부 질문을 실제 유료 생성 실행 승인으로 기록하지 않았다.

## 고정된 계약·검증

- C1/C2: 기존 보호자/내부 조회에 선택 guardrail 사실 객체. 거절/무응답·실제 인사/기존 확정 전사 참조·unknown을 표현한다. Core fallback은 stale=false여도 guardrail=null, 새 UI는 null을 이전 값으로 채우지 않는다.
- C3: 기존 기기 WS/재생ID·승인 콘텐츠 버전/실제 PLAYBACK_MARK를 사용, 새로운 wire 필드 없음. ACK는 완료가 아니다.
- C4–C6: 기존 GPT-Live 모델·4개 송신 type·J1/J6/JEV 경계 유지. 서비스 프롬프트 판과 기존 JEV 판을 구분한다. 연습/시간/저장/삭제·권한 회귀를 유지한다.
- 각 단위 완료의 사용자 승인 검증 명령은 verification-command.txt에 있고 전용 설정 반영 완료:

`(cd backend && ./gradlew --no-daemon clean check -Pmujoong.test.db=docker) && (cd frontend && npm run lint && npx vitest run tests --coverage && npm run build)`

- 최종 Build and Test에서 기존 전체 bash scripts/verify.sh 및 변경 경계 대역 통합을 수행한다. 실제 실행/테스트 PASS는 아직 없다.
- 실제 배포·main 병합·유료 호출·수동 mujoong-manual 스택 변경을 자동 실행하지 않는다. JDK21/Node22/Docker 등 검증 준비는 실행 전에 확인해야 한다.

- infra/compose.demo.yml은 /srv/mujoong/approved-audio 읽기 전용 경로를 사용한다. infra/compose.ci.yml은 ./seed-audio를 그 경로에 읽기 전용으로 연결한다.
