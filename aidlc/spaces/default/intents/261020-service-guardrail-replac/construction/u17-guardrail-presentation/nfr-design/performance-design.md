## P1 — 현재 세션 조회와 정규화

기존 조회/캐시 갱신 경계에 현재 로그인 세대·sessionId·요청 발행 순서를 귀속한다. 완료/취소/화면 이탈 뒤 응답을 적용할 때 이 귀속을 먼저 확인한다. 폴링과 수동 새로 읽기·끝내기 뒤 재조회 등 같은 캐시를 갱신하는 모든 경로에 같은 적용 규칙을 사용한다. 낮은 statusVersion은 버리고 같은 판의 더 최신 요청 facts는 적용한다. 요청 취소만으로 격리를 보장하지 않고, 취소되지 못한 오래된 응답도 적용 경계에서 거른다.

정규화된 guardrail은 이번 응답의 단일 snapshot이며 null을 포함해 교체한다. items만 기존 같은 세션 seq 병합을 사용한다. 다른 응답의 상태와 facts를 합성하거나 이전 PLAYING을 복원하지 않는다. 구조 실패는 선택 객체만 null, 미래 문자열 enum은 필드 UNKNOWN으로 낮추며 기존 기본 응답 오류·세션 식별 검증을 유지한다. 표시 selector는 유효성·현재 모드·오류/stale/오프라인·서버 상태와 facts를 함께 읽는다.

대응: NFR2.1, NFR2.2, NFR6.1, NFR6.2.

## P2 — 추가 호출 없는 표시·기기 소비

현재 병합 items를 순번으로 찾고 실제 인용만 생성한다. 참조가 없는 경우 빈 표시를 반환하며 추가 전사 요청/원문 복제 캐시를 만들지 않는다. 일반 마무리/사유/인용/인사 줄을 서로 다른 표시 값으로 구성하여 한 조건의 누락이 다른 확인된 상태를 지우지 않게 한다. 인사는 같은 상태판의 변경과 오류 신호에서 즉시 재계산하고 별도 브라우저 성공 타이머를 만들지 않는다.

기기 웹의 현재 세션/연결/재생 수명과 기존 중복 제거를 사용한다. 플레이어 중단은 재생 상태를 먼저 무효화하고 늦은 종료 콜백이 완료 표식을 내지 못하게 한다. 실제 COMPLETE·STOPPED·FAILED를 구분하고, 종료 확인은 입력·출력·대기열 정리 뒤에 보낸다. 이미 충족된 경로는 변경하지 않고 회귀 시험으로 보존한다.

기존 2초 폴링·진행 요청 공유·retry:false·시간 설정·no-store·출력 큐와 기기 마감은 그대로다. 새로운 요청·가용성 SLA·처리량 계층·장기 facts 캐시를 만들지 않는다. 현재 query cache의 기존 세션별 수명은 유지하되 로그아웃/세션 전환의 기존 정리를 빠뜨리지 않는다.

대응: NFR2.3, NFR6.1, NFR6.2.

## P3 — 품질 검증과 재현

계약 파싱/병합 → 표시/copy·컴포넌트 → 필요한 기기 소비 → 접근성/연습 순서의 test-after를 따른다. 각 구현 층 직후 시험과 결과를 기록한다. 기능 범위 파일은 실제 수정 운영 소스 전체와 대응하고 빈/없는 범위를 실패시킨다. 모듈/기능 LINE80% 및 기존 단언/계약/import 경계는 입력 하한이다. lint·전체 프런트 coverage·production build와 최종 verify.sh/실제 대역 서버 통합은 서로 다른 증거로 남긴다.

기기 실제 오디오 대역, 컴포넌트 가상 환경, 브라우저 점검·실기기/실공급자 성공을 섞지 않는다. 320px/200%·긴 한글/인용·초점/낭독은 가능한 브라우저 점검과 컴포넌트 시험의 범위를 구분해 보고한다. 기존 말풍선 양/길이 제한을 새로 바꾸거나 단위를 임의로 잘라 커버리지 분모를 줄이지 않는다.

대응: NFR3.1, NFR3.2, NFR3.3, NFR4.1, NFR4.2, NFR5.1, NFR5.2.

## 인계와 미해결 조건

U16의 늦은 안내 이전 전사 항목 재수락은 최종 통합 검증에 별도 실행기 회귀로 연결해야 한다. U17의 보수적 표시가 서버 허가 오류를 치유하지 않는다. 운영 말소리 부재는 실패 보류를 유지하며 대역 음성을 운영 승인 자산이라고 하지 않는다. 두 항목을 UI 검증 PASS로 닫지 않는다. 별도 서버 확장/백업/복구·CDN·재시도/차단기를 추가하지 않는다.
