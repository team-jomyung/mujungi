## 책임과 데이터 흐름

기존 보호자 진행 조회 한 응답에서 상태와 guardrail을 함께 읽어 표시한다. 서버의 참여·종료·저장 권한을 브라우저가 생성하지 않는다. 같은 세션의 기존 공개 말풍선만 순번으로 병합하며, guardrail은 매 응답의 값으로 교체한다. 안내 원문/정책 해시를 새 API나 브라우저 저장소에 복제하지 않는다.

새 엔티티·영속 저장·라우트·공급자·호출 루프를 추가하지 않는다. 내부 상태는 현재 세션 조회값, 기존 말풍선 집합, 요청 귀속, UI 팝업/요청 진행 여부뿐이다. rules.md의 표시 규칙은 서버 업무 규칙을 대체하지 않는다.

## F1 — 계약 파싱과 현재 응답 적용

1. 기존 인증·세션 소유 확인을 거친 진행 응답의 sessionId가 요청과 같은지 검증한다. 다른 세션 응답은 기존 응답 오류로 거절한다.
2. guardrail 속성 없음 또는 null은 null이다. schemaVersion=1인 객체에는 notice, participation, goodbye, confirmedStopBubbleSeq가 모두 필요하다. 구조·필수 타입·지원 판이 잘못되면 이 객체 전체만 null로 낮추고 나머지 유효한 진행 정보를 유지한다.
3. 세 상태 필드는 문자열이어야 한다. 지원하지 않는 미래 문자열 enum은 해당 필드 UNKNOWN이다. 알려지지 않은 추가 속성은 실행/표시 근거로 쓰지 않는다. 참조 순번은 null 또는 양의 안전한 정수만 허용한다. 문자열·분수·0·음수·안전 범위 밖이면 객체 구조 실패다.
4. 세션/로그인 전환 때 이전 말풍선·사실과 대기 요청 귀속을 비운다. 취소 또는 이전 요청 순번의 늦은 응답이 현재 값을 덮지 못하게 한다. FREE_TALK에도 낮은 statusVersion의 역행을 막는다. 같은 statusVersion의 새 응답은 재생 사실이 달라질 수 있으므로 적용한다.
5. 이번 null/누락을 이전 guardrail로 채우지 않는다. Core fallback은 stale=false라도 null을 유지한다. 상태와 facts를 서로 다른 응답에서 조합하지 않는다.
6. 새 선택 객체의 실패는 새로운 자동 재시도를 만들지 않는다. 기존 요청 오류·연속 실패/다시 시도·권한 만료 처리를 따른다.

## F2 — 안내와 미참여 표시

1. S-08의 기존 시작 요청과 S-12 준비/대기 화면을 유지한다. WAITING_CHILD, 말풍선 존재, 안내 송신·ACK·시각 경과만으로 안내 완료나 참여 수락을 만들지 않는다.
2. notice COMPLETED도 일반 대화 권한이 아니다. ACTIVE는 서버 상태만으로 결정되며, 화면은 자체 참여 수락·원음 저장 시작 요청을 보내지 않는다.
3. 서버 DECLINED를 받으면 같은 응답의 participation으로 P-03 제목만 선택한다. REFUSED는 ‘아이가 지금은 이야기하지 않기로 했어요’, NO_RESPONSE는 기존 ‘아이가 대답하지 않아 시작하지 못했어요’, 나머지/null은 ‘이야기를 시작하지 않았어요’로 구분한다.
4. 확인 버튼 후 기존 홈 이동을 유지하며 자동 재권유·활동 완료/정상 활동 표시를 만들지 않는다. 기술 FAILED는 failureCode와 기존 시작 실패/진행 실패 경로를 유지하며 참여 거절/무응답으로 바꾸지 않는다.
5. P-03 열린 뒤 더 최신 사실이 들어오면 제목은 최신 유효 값으로 갱신하되 팝업을 반복 열거나 초점을 매 폴링마다 이동하지 않는다. 오류/빈 값은 일반 미참여 문구다.

## F3 — 종료 인용과 실제 인사

1. 보호자 끝내기는 기존 P-01의 취소 기본 초점·진행 중 이중 제출 차단·동일 requestId 재시도 의미를 유지한다. 요청 실패를 종료 접수/기기 정지로 바꾸지 않는다.
2. 아이의 서버 확정 전체 종료에는 P-01 등 추가 확인 UI를 열지 않는다. 서버의 CLOSING/종료 흐름으로 이동한다. 모호한 의사의 판단/음성 질문은 서버 책임이다.
3. CHILD_STOP의 인용은 현재 guardrail.confirmedStopBubbleSeq와 정확히 같은 순번의 같은 세션 공개 items 행이 있을 때만 만든다. CHILD, final=true, uncertain=false, 비어 있지 않은 기존 text를 모두 요구한다. 숨김/삭제·다른 화자·미완성·없음이면 생략한다. 기본 등록 종료 표현이나 마지막 CHILD 행으로 대체하지 않는다.
4. 인용 텍스트는 기존 안전한 텍스트 표시와 줄바꿈을 쓴다. 시각은 해당 행의 유효한 시각만 표시하며 세션 종료 시각을 발화 시각처럼 붙이지 않는다. 인용 때문에 추가 전사 조회를 하지 않는다. 끝내자고 했다는 원인 제목과 실제 발화 인용 줄은 구분한다.
5. S-17의 일반 ‘마무리 중’ 제목은 CLOSING을 설명한다. ‘무중이 마무리 인사를 하고 있어요’ 줄은 FREE_TALK의 최신 유효 응답에서 CLOSING이고 goodbye=PLAYING이며 stale·오프라인·확인된 연결/기술 장애가 없을 때만 표시한다.
6. NONE/PENDING/UNKNOWN/null 및 COMPLETED/STOPPED/FAILED에는 인사 재생 중 줄을 숨긴다. 종결 상태·로그아웃·세션 변경·조회 오류/연결 단절을 알게 된 때도 숨긴다. 같은 statusVersion의 PLAYING→완료/실패/null 갱신을 반영한다. 이전 PLAYING을 캐시로 복원하지 않는다.
7. 로딩·조회 오류·미확인·CLOSING·종결은 별개다. 최초 미조회 상태에 ‘인사 중’을 채우지 않는다. 실제 기기 confirmed 이전에 정지 완료를 표시하지 않는다. 결과 작업의 정리 중/완료/실패와 기기 확인도 기존처럼 별도다.

## F4 — 기기 재생과 종료 확인 소비

기기 웹은 C3의 기존 메시지·세션/재생 식별·중복 제거를 그대로 소비한다. 승인 자원 수신/프리패치/재생 요청/화면 상태는 완료가 아니다. 실제 오디오가 시작한 뒤 STARTED, 끝까지 종료한 뒤 COMPLETED, 끄기·STOP_OUTPUT·연결 해제·실패는 STOPPED/FAILED 의미를 유지한다. 중단 뒤 늦은 오디오 종료 콜백으로 COMPLETED를 다시 내보내지 않는다.

현재 연결/세션이 아닌 재생 콜백과 오래된 명령은 현재 상태를 바꾸지 못한다. 재연결 때 기존 중단 재생을 완료로 복구하지 않는다. CLOSE_TRANSPORT는 입력·재생·대기열 정리 뒤 현재 VOICE_SESSION_CLOSED를 보낸다. 기기 웹의 대역 완료 보고는 아이 청취/이해나 실제 기기 성공을 증명하지 않는다. 이미 충족한 구현은 시험으로 유지하고 필요한 소비 수정만 한다.

## F5 — 화면 전이와 접근성

| 현재 상태/사건 | UI 결과 | 금지되는 추정 |
|---|---|---|
| 첫 조회/빈 대화/조회 실패 | 각각 로딩·빈 전사·기존 오류/다시 시도 | 안내/참여/인사 완료 |
| 준비/WAITING_CHILD | 기존 준비·대기와 끝내기 권한 | 브라우저 참여 허가 |
| ACTIVE | 기존 자유대화/연습 진행 | 연습에 자유대화 사실 표시 |
| DECLINED | 사유별 P-03 → 확인 → 홈 | 정상 활동 완료, unknown→무응답 |
| CLOSING | S-17 일반 마무리·조건부 인사 줄 | 기기 정지 확인 |
| terminal/미확인 종료 | 기존 종료 사유·결과 정리·미확인 줄 | 이전 인사 재생 중 유지 |
| 로그아웃/다른 세션 | 기존 이동·캐시/귀속 정리 | 다른 아이 전사 재사용 |

기존 한 열 배치·토큰·버튼·탭·상태 문구를 사용한다. P-03의 접근 가능한 제목·확인 초점·Tab 가두기를 보존하고, 기존 P-01의 취소 기본 초점과 복귀를 지킨다. 상태는 색 외 텍스트로 전달한다. 동일 상태를 폴링마다 다시 낭독하거나 인용 전체를 자동 낭독하지 않는다. 긴 한글·연속 문자열·마크업·따옴표·역슬래시·줄바꿈은 안전한 텍스트와 줄바꿈으로 표시한다. 키보드·확대·좁은 화면·기기 라벨/끄기 버튼·reduced-motion을 변경 표면에서 확인한다.

## 검증과 인계

합의한 test-after·Standard·모듈 및 기능 줄80%를 유지한다. 계약 파서/병합 → 사유·인용·인사 순수 매핑/컴포넌트 → 필요한 기기 소비 → 접근성/연습 순서로 구현 후 해당 층 시험을 수행한다. 최종 실제 대역 서버 통합과 전체 verify.sh는 Build and Test로 연결한다. 아래 추적은 UI가 담당하는 부분이며 모델 정책/서버 권한 전체를 U17이 검증했다고 하지 않는다.

U16 code-generation R-01의 늦은 이전 전사 항목 재수락은 미해결 서버 지적이다. 최종 통합 합격 전에 해당 실행기 순서의 WAITING_CHILD/원음 시작0 및 새 항목 수락을 따로 확인해야 한다. UI가 서버 ACTIVE를 받아 표시한다고 이 문제를 해결하지 않는다. 운영 승인 말소리 부재도 그대로 승계하며 생성·청취 승인·배포·실공급자/실기기 실행은 수행하지 않는다.

## Assumptions & Open Questions

None.

이 명세의 UI 보수적 표시는 승인된 C1–C3와 RP-1–RP-4의 적용이다. 서버 소유·저장 정책·시간값을 바꾸는 새 제품 가정은 없다. 새로운 서버 계약 충돌이 발견되면 추정으로 보완하지 않고 해당 경계의 차이를 기록한다.
