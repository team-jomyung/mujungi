| ID | 요구와 합격 기준 | 위협/검증 |
|---|---|---|
| NFR1.1 | 현재 인증/세션 소유·쿠키/CSRF·no-store를 유지. 로그아웃/권한 실패/다른 세션 전환 뒤 이전 아이 facts/인용/말풍선의 새 세션 재사용0회. 서버 소유 확인을 클라이언트 검증으로 대체하지 않음 | 교차 세션 응답·캐시/로그인 전환·기존401/403 시험 |

| NFR1.3 | UI는 참여·원음 시작·기기 정지·삭제/공유 완료 권한을 만들지 않음. 승인 정보 부재 때 완료를 표시0회. 기존 수동 스택/배포/실제 아동 입력·유료 공급자 호출은 수행하지 않음 | 응답/기기 소비 시나리오 및 실행 증거 |

정확한 인용은 동일 세션의 공개 허용 CHILD 최종·확실 행만 대상으로 한다. 참조가 없거나 삭제/비공개·불확실이면 인용 줄을 생략한다. 현재 보기 자료 외 전사 조회나 캐시 검색으로 채우지 않는다. 보호자 끝내기의 기존 CSRF·동일 requestId 의미와 권한 거절을 유지한다.

## 인증·저장·실패 설계 제약

새 자격 증명/권한/계정 종류/장기 저장소를 추가하지 않는다. 선택 객체의 구조 오류를 완화하는 것은 그 객체의 미확인 처리일 뿐이며, 다른 세션 ID·인증 실패·잘못된 기본 응답의 기존 거절을 완화하지 않는다. 익숙하지 않은 필드는 표시/실행 권한의 근거로 사용하지 않는다.

소유/동의/보존/계정 삭제의 서버 정책과 실제 모델 약관·법률 판단은 이번 UI 작업에서 새로 인증하지 않는다. 원문 정책 자원/안내 음성의 권한·청취 승인 미확인은 별도 후속이다. 프런트 로그에서 실패 원문 전체를 덤프하는 진단 기능을 추가하지 않는다.

## 연관 요구 추적

NFR2.1–NFR2.3은 안전한 실패/현재성, NFR5.1–NFR5.2는 텍스트/접근성, NFR6.1–NFR6.2는 기존 호출/모드 경계와 연결된다. 자세한 합격 기준은 performance-requirements.md를 따른다. 접근성/종료 인용은 개인정보 제한보다 우선하지 않는다.
