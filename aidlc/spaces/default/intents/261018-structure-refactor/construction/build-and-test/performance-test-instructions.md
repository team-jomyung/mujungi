# 성능 시험 지침 — 구조 · 이름 리팩토링

> 이 작업은 동작을 바꾸지 않는 이동 · 이름 변경 · 분리라서 새 성능 요구(NFR 성능 항목)가 없다.

## 적용 여부

- `nfr-requirements/` · `nfr-design/` 산출물이 이 작업 기록에 없다(refactor 범위가 두 단계를 건너뜀). 따라서 측정 가능한 성능 목표가 없다.
- 성능 시험 지침은 만들지 않고 이 문서로 "해당 없음"을 기록한다(Minimal 전략).

## 지연 회귀를 볼 수 있는 곳

- `verify.sh`의 C 단계가 음성 1턴의 `LATENCY_TURN` 로그 키를 단언한다(P2.latency PASS). 이는 키 존재 확인이지 지연 목표 검증이 아니다.
- 실제 지연 측정(`probe-three` 등)은 이 작업의 범위 밖이다. 필요하면 별도 작업으로 연다. 측정 도구를 돌릴 때는 GNU date를 앞에 둔다(project 규칙).
