# 무중 접근성 점검표 (WCAG 2.1 AA)

> Refined Mockups(2.5) · 2026-10-09 · 입력: mockups.md · interaction-spec.md(같은 폴더), `../user-stories/stories.md`의 접근성 AC(AC1.4.15 · AC2.1.14 · AC3.2.20 · AC4.1.13 · AC5.1.10 · AC5.3.14 · AC6.2.13 · AC1.3.5 · AC1.6.9), `../requirements-analysis/requirements.md`(NFR1 · NFR2 · NFR10)
> 수준: WCAG 2.1 AA(refined-mockups-questions.md Q5). 화면 설계 v1.5j는 모든 상태에 색 + 상태명 + 사유 글을 함께 쓰는 설계라 대부분 그대로 만족하고, 아래는 구현에서 지켜야 할 것과 시험 방법이다. 체크는 Build and Test(3.6)에서 한다.

## 1. 인지 가능 (Perceivable)

| # | 항목 | 적용 | 시험 |
|---|---|---|---|
| P1 | 상태를 색만으로 전하지 않는다 — 04 · 05 상태 카드 · 판정 카드(초록 · 노랑 · 빨강 · 회색)에 상태명 글 + 사유 문장 + 아이콘 | StatusCard · VerdictCard(AC1.4.15 · AC2.1.14) | 흑백 캡처에서 상태 구분 가능 |
| P2 | 글 대비 4.5:1 이상, 큰 글(≥ 24px 또는 18px 굵게) · UI 요소 3:1 이상 — 특히 노랑(불안정) · 회색(응답 없음) 글 | 토큰 `color.status.*`는 글이 아니라 점 · 배경에만 쓰고 글은 `color.text.*`(design-system-mapping §2) | axe · Lighthouse 대비 검사 |
| P3 | 말풍선 발화자(무중 · 아이)를 위치 · 색 외에 보조기기용 이름으로 구분 | TranscriptList 숨김 접두 "무중:" / "{아이}:"(AC3.2.20) | 스크린리더로 12 · 27 읽기 |
| P4 | 달력 점 · 기간 칠하기는 글로도 드러난다 — 날 칸 `aria-label="m월 d일 · 활동 n개"`, 기간은 요약 줄 글 | Calendar · RangeSummary(AC5.1.10 · AC5.3.14) | 스크린리더로 26 · 28 |
| P5 | 아이콘 · 캐릭터 그림에 대체 텍스트 — T19 캐릭터는 상태 라벨이 대체 텍스트, 장식 아이콘은 `alt=""` | DeviceStateView · 아이콘 | 마크업 검사 |
| P6 | 글자 확대 200%에서 가로 스크롤 · 겹침 없음, 400%에서 내용 잃지 않음 | 모든 /parent 화면(상대 단위 rem) | 브라우저 확대 시험 |
| P7 | 자동 갱신 콘텐츠(12 폴링 말풍선)는 조용히 알린다(`aria-live=polite`) · 초점 · 스크롤 위치를 빼앗지 않는다 | TranscriptList(AC3.2.20) | 스크린리더 + 폴링 주입 |
| P8 | 움직임 최소화 — `prefers-reduced-motion`이면 전환 · 교차 페이드 즉시 | interaction-spec §2 | 설정 켜고 확인 |
| P9 | PDF는 텍스트 PDF(선택 · 검색 가능), 한글 폰트 내장, 제목 구조 태그 | ReportPdf(AC5.5.5 · 5.5.6) | PDF 글자 선택 · 검색 |

## 2. 조작 가능 (Operable)

| # | 항목 | 적용 | 시험 |
|---|---|---|---|
| O1 | 모든 조작이 키보드로 가능, 보이는 초점 표시(2px · 3:1) | 전체 | 마우스 없이 전 화면 순회 |
| O2 | 터치 영역 44×44 CSS px 이상, 이웃 조작 간 8px — 18 줄의 세 조작(선택 · ★ · ×), 05a 코드 칸, 달력 날 칸, 하단 탭 | ActivityRow · CodeInput · Calendar · BottomTabBar(AC4.1.13 · AC5.1.10) | 크기 측정 |
| O3 | 아이 기기 「켜기」 · 「끄기」는 화면에서 가장 큰 터치 영역(≥ 72px), 「끄기」는 캐릭터와 떨어진 자리 | DeviceStateView(AC6.2.13) | 레이아웃 검사 |
| O4 | 팝업 · 시트는 초점 가둠, Escape로 닫힘(P2 · P3 제외), 닫히면 열었던 단추로 초점 복귀 | ConfirmDialog · BottomSheet | 키보드 시험 |
| O5 | 조작이 달린 토스트는 최소 3초이고 초점이 가면 사라지지 않는다(「되돌리기」 · 「다시 시도」) | Toast(B25) | 초점 두고 5초 대기 |
| O6 | 시간 제한이 있는 상호작용은 사용자 조작이 아니라 활동 규칙(공백 4분/6분 · 참여 대기 40초)이며 보호자 화면 조작에는 시간 제한이 없다 | — | 설계 확인 |
| O7 | 잠긴 탭은 초점을 받고 누르면 이유가 글(토스트)로 나온다(`aria-disabled`, `disabled` 아님) | BottomTabBar(AC1.4.11 · 1.4.15) | 키보드로 잠긴 탭 활성 |
| O8 | 드래그에 의존하지 않는다 — 28 기간은 두 번 누르기로 같은 결과, 18 삭제는 「×」 단추(길게 누르기 없음) | Calendar · ActivityRow(AC5.3.14) | 드래그 없이 시험 |
| O9 | 번쩍임 없음(초당 3회 초과 금지) — T19 표정 전환 · 12 점선 | DeviceStateView · TranscriptList | 애니메이션 검사 |
| O10 | 제목 구조 — 화면마다 h1 하나(머리 제목), 구역은 h2 | 전체 | 제목 순회 |

## 3. 이해 가능 (Understandable)

| # | 항목 | 적용 | 시험 |
|---|---|---|---|
| U1 | `lang="ko"` 선언, 문구는 문구표의 해요체 | 전체 | 마크업 |
| U2 | 입력 라벨은 보이는 글(`<label for>`), placeholder만으로 라벨을 대신하지 않음 — 03 "이름 또는 별명" · "나이" · "관심사", 08 네 칸, SET-01 "새 표현" | TextArea · 입력 | 마크업 |
| U3 | 오류는 글로 식별 · 설명 · 교정 안내, 칸 바로 아래(빨간 테두리만 아님) — 03 나이, SET-01 2~20자 · 중복 · 5개, 05a 코드 | AC1.3.5 · AC2.3.6 · AC2.2.3 | 오류 주입 |
| U4 | 되돌릴 수 없는 작업은 확인 + 결과 설명 — P7 계정 삭제(본문에 "되돌릴 수 없어요 · 남길 리포트는 먼저 저장"), 기본 초점 「아니오」, 「삭제」는 위험 단추 | ConfirmDialog(AC1.6.9) | 시나리오 |
| U5 | 같은 조작은 같은 자리 · 같은 라벨 — 머리 「←」, 하단 탭 4개 순서, 「다시 시도」 라벨 | 전체 | 화면 대조 |
| U6 | 사용자 언어 — 화면 번호 · 상태 enum · 오류 코드가 사용자 글에 나오지 않는다 | 문구표 · mockups §9 | 문구 전수 검토 |
| U7 | 예상치 못한 문맥 변화 없음 — 폴링 갱신 · 재조회가 화면을 바꾸지 않고(04 → 12 이동은 사용자 누름으로만, 알림 진입 제외) | StatusCard · TranscriptList | 폴링 중 조작 |
| U8 | 재촉 · 만류 · 보상 문구 없음(NFR2) — 재안내 · 종료 확인 질문 · 공백 경고 · 토스트 전부 | mockups §9 제안 문구 · 승인 콘텐츠 | NFR2 체크리스트(stories 품질 기여 §5) |

## 6. 시험 방법 요약

1. 자동: axe DevTools · Lighthouse 접근성 — 보호자 23 화면 + 아이 2 화면 전부, 오류 0.
2. 키보드만으로 시연 네 경로(US1~US5 Must) 완주.
3. 스크린리더(TalkBack Android Chrome · 데스크톱 NVDA/Chrome)로 04 · 12 · 26 · 28 · T19 읽기.
4. 확대 200% · 400%에서 04 · 12 · 28 레이아웃.
5. 색각 시뮬레이션(적록 · 청황)에서 04 · 05 상태 구분.
6. `prefers-reduced-motion` 켜고 전환 확인.
7. PDF: 글자 선택 · 검색 · 폰트 내장 확인.
