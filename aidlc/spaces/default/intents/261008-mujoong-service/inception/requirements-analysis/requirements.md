## 의도 분석

6~12세 아이가 집에서 AI '무중'과 음성으로 자유대화·연습을 하며 화용 능력(상황과 상대에 맞게 말하기)을 연습하고, 보호자는 폰 웹에서 활동을 준비·관찰·기록한다 `[desc]`. 서비스가 하려는 것은 세 가지다.

- **아이가 말로만 참여하는 안전한 대화 상대**: 아이는 기기 「켜기」만 누르고, 승인된 문구로 시작 안내를 듣고, "무중아 그만할래"로 끝낸다. AI 출력은 게이트를 거쳐 승인된 말만 기기로 간다.
- **보호자가 준비·관찰·기록하는 한 화면 흐름**: 홈(아이 · 대화 기기 · 지금 활동) → 자유대화/연습 시작 → 진행(12) → 끝(17) → 기록(26·27) → 상담용 원문 PDF(28·30).
- **판단하지 않는 기록**: 진단·치료 효과·점수·등급을 어디에도 만들지 않는다. 결과는 대화 기록 · 생활 팁 · 연습 목표 후보로만 돌아온다.

제출물이다. 2026-11-05 제출, 구현 10/15~27(7일), 팀 5인(A 계정 / B 음성 / C 연습 / D AI / E 결과) `[desc]`. 그래서 요구사항의 우선순위는 11/5 시연 경로(Q6)를 Must로, 나머지를 Should로 둔다 `[Q6]`.

## 기능 요구사항

우선순위는 MoSCoW. **Must** = 11/5 시연에서 끝까지 보여 줄 네 경로(처음 한 번 · 자유대화 1회 · 연습 1회 · 기록·리포트)와 그 경로를 지탱하는 서버 기능 `[Q6]`. **Should** = 구현하되 시연 필수가 아닌 것(장애 경로 · 푸시 · 설정 · 삭제). **Could** = 되면 좋은 것.

### FR1 계정 · 동의 · 아이 정보 (담당 A)

**FR1.1 구글 로그인** — Must · 화면 01 · 출처 FR-A01, G1
- 보호자는 구글 계정 하나로만 로그인한다. 자체 회원가입 · 아이디/비밀번호 · 카카오 · 네이버는 없다.
- 로그인 상태는 유지된다. 유지 토큰이 만료되면 01에서 다시 로그인하고 04로 간다(진행 중 활동이 있으면 지금 활동 칸에 보인다).
- 분기: 첫 로그인(동의 없음) → 02, 동의 있음 · 아이 등록됨 → 04, 동의 있음 · 아이 없음 → 03.
- 완료 기준: 01에는 「구글로 시작」만 있다. 취소 · 실패 시 인증되지 않은 상태로 01에 남고 다시 시도할 수 있다. 02 · 03을 끝내지 않고 종료하면 다음 실행은 01부터다. 인증 뒤에는 그 보호자의 데이터에만 접근한다.

**FR1.2 필수 동의 4항목** — Must · 화면 02 · 02-1 · P5 · 출처 FR-A03, G3
- 처음 한 번 네 항목(음성 수집 · 글 저장 / 보호자 열람 / 리포트 생성 · 외부 전달 / 원음 보관)에 전부 동의해야 쓸 수 있다. 항목별 「자세히 보기」는 02-1 약관 시트(수집 · 목적 · 보관 · 거부 시 영향)를 연다.
- 동의를 바꾸거나 거두는 화면은 없다. 거두려면 계정 삭제(FR1.6)다.
- 동의 전 「←」는 P5(로그아웃 / 계속 동의하기).
- 완료 기준: 네 개 다 체크하기 전엔 「동의하고 계속」이 꺼져 있다. 항목별 동의 상태와 약관 버전이 저장된다. 동의 범위 밖 수집 · 저장 · 이용이 없다. 02를 끝내지 않고 종료하면 다음 실행은 01 → 02다.

**FR1.3 생성형 AI 사전 고지** — Must · 화면 02-1 · 출처 FR-A04, NFR-03, `[Q3]`
- 02-1 약관 시트 각 항목 본문에 "무중은 생성형 AI와 대화하는 서비스" 고지 문장을 넣는다. 01 · 02 화면에는 추가 요소를 두지 않는다(화면 v1.5e 결정).
- 아이에게는 기기 시작 안내(FR5.2)로 알린다.
- 완료 기준: 네 약관 항목 본문 모두에 고지 문장이 있다. 법적 적합성 검토는 범위 밖이다.

**FR1.4 아이 정보 등록 · 보기 · 수정** — Must · 화면 03 · 출처 FR-A02, G2
- 계정당 아이 하나. 03은 아이 정보 한 화면이다: 처음엔 빈 입력 카드(이름 · 나이 · 관심사, 뒤로 없음), 그 뒤엔 보기 카드 + 기기 상태 줄 + 「정보 수정」(카드 안 편집). 아이 선택 · 추가 · 삭제는 없다. 아이를 바꾸려면 계정 삭제 뒤 새로 한다.
- 완료 기준: 이름이 비면 「확인」이 꺼진다. 나이가 6~12 밖이면 오류 글이 뜨고 입력 상태가 유지된다. 처음 등록을 마쳐야 04로 간다. 수정 「취소」는 원래 내용으로, 저장 실패는 토스트와 이전 값 유지. 수정으로 기존 활동 · 기록의 대상 아이가 바뀌지 않는다. core_child는 guardian과 1:1이다.

**FR1.5 홈과 설정** — Must · 화면 04 · SET0 · 출처 FR-A07, G8
- 홈은 늘 같은 세 구역(아이 · 대화 기기 · 지금 활동)이고 구역마다 상태가 바뀐다. 하단 탭은 홈 · 자유대화 · 연습 · 기록.
- 아이 구역: 이름 · 나이 · 「수정」 → 03. 대화 기기 구역: FR2.2의 상태와 「기기 상태 보기」 → 05, 기기 없음이면 「기기 등록」 → 05a. 지금 활동 구역: 없음 / 진행 중(활동 종류 · 경과 · 「진행 화면 보기」 → 12) / 조회 실패(마지막 확인 시각 · 미확인 · 「다시 확인」).
- 활동 진행 중이면 자유대화 · 연습 탭은 새 시작 대신 12로 간다. 「⚙」은 설정 시트(로그아웃 → 01, 계정 삭제 → P7).
- 완료 기준: 재진입 시 최신 세션을 조회해 진행 · 종료 확인 상태를 반영한다. 조회 실패 시 마지막 확인 시각을 유지하고 현재 상태로 단정하지 않는다. 종료 확인 없는 세션을 종료 완료로 표시하지 않는다. 앱 닫힘은 장애 · 종료 요청이 아니다.

**FR1.6 계정 삭제** — Should · 화면 P7 · 출처 FR-A08 재정의, G3, `[Q4]`
- 설정 시트 「계정 삭제」 → P7 확인 → 「삭제」. 요청 즉시 접근을 차단하고 로그아웃해 01로 보낸다. 백그라운드 작업이 기록 · 리포트 · 동의 · 기기 등록 · 원음 파일을 영구 삭제한다(core_data_deletion_request). 되돌리기는 없다.
- 완료 전 같은 구글 계정으로 다시 로그인하면 "삭제 처리 중"을 보여 주고 아무 데이터에도 접근할 수 없다. 완료 뒤 로그인하면 새 계정(02부터)이다.
- 진행 중 세션이 있으면 종료 요청을 먼저 보내고(종료 사유 CONSENT_WITHDRAWN) 삭제를 진행한다.
- 완료 기준: 삭제 요청 뒤 어떤 API도 그 보호자의 데이터를 돌려주지 않는다. 삭제 완료 뒤 DB · 파일 저장소에 그 계정의 원음 · 전사 · 기록 · 리포트 · 기기 행이 없다. 삭제 요청 뒤 늦게 도착한 자료는 저장되지 않는다. 동의 철회의 유일한 경로이므로 Should이지만 Delivery Planning에서 앞쪽에 둔다.

### FR2 기기 연결 (담당 A · B)

**FR2.1 아이 기기 코드 등록** — Must · 화면 05 · 05a · D0 · 출처 FR-A06 재정의, D-04, 점검표 1, G6
- 아이 기기 웹(D0)을 처음 켜면 서버가 발급한 8자리 코드를 보여 주고 등록을 기다린다. 보호자가 05a에 코드를 넣으면 우리 집 기기로 묶이고(계정당 기기 하나) 기기는 「등록되었어요」(3초) 뒤 T19 대기로 간다.
- 등록된 기기는 기기 토큰으로 Realtime에 WSS 접속한다. 기기 검색 · 페어링 · 운영자 사전 시드 · 기기 해제 기능은 없다. 기기 브라우저 데이터가 지워지면 새 코드가 뜨고 보호자가 다시 등록한다(옛 Device 행 해제).
- 완료 기준: 없는 코드 · 이미 등록된 코드는 05a 빨간 카드로 거절된다. 등록 성공 시 05 기기 등록 줄이 「완료 (코드 앞 4자리)」가 된다. 등록되지 않은 기기 · 만료된 토큰으로는 WSS 접속과 활동 참여가 거부된다. 데모에서도 시드 대신 서버 발급 코드 + 05a 입력을 쓴다.

**FR2.2 기기 상태 판정 · 표시** — Must · 화면 04 · 05 · 출처 FR-A06, D-18, D-21, 점검표 7, G7
- 기기 상태는 5단계: 안정(초록) · 불안정(노랑) · 끊김(빨강) · 응답 없음(회색) · 연결된 기기 없음.
- 판정 규칙(Realtime heartbeat 기준): 지연 1초 초과 또는 5분 안 끊김 2회 이상 → 불안정, 40초 무응답 → 끊김(진행 중이면 P2 재연결 대기), 시작 요청 때 기기 응답 없음 20초 → 시작 실패(FAILED).
- 05는 서로 독립인 두 줄(기기 등록 · 기기 네트워크 현황)과 둘을 합친 판정 카드(등록 없음 → 「기기 등록」 / 안정 → 시작할 준비 / 그 밖 → 지금은 시작할 수 없어요 + 사유)를 보여 준다. 네트워크 줄은 안정 · 지연 n초 / 불안정 · 끊김 n회 / 끊김 · hh:mm부터 / 응답 없음 · 마지막 hh:mm을 적는다.
- 보호자 폰 인터넷 문제는 따로 표시하지 않고 공통 오류 토스트로만 알린다.
- 완료 기준: 기기 연결 장애 · 음성 모델 연결 장애 · 보호자 서버의 상태 미수신 · 보호자 폰만 오프라인을 각각 주입하면 서로 다른 상태 · 문구가 나온다. 「연결됨/안정」은 기기 연결이 실제로 유지되는 동안만 표시된다. 원인 불명 시 단독 "연결 끊김"을 쓰지 않는다.

**FR2.3 활동 시작 조건과 잠금** — Must · 화면 04 · 05 · 08 · 18 · 출처 FR-B05, FR-C05 공통규칙, G7, G13
- 새 활동은 기기 상태 안정 · 필수 동의 완료 · 진행 중 세션 없음(종료 확인됨)일 때만 시작한다. 계정당 진행 세션은 하나다.
- 기기가 안정이 아니면 자유대화 · 연습 탭이 잠기고, 잠긴 탭을 누르면 이유 토스트 뒤 05로 간다. 17 마무리 중에도 두 탭이 잠긴다(토스트 「끝나는 중이에요」).
- 시작 요청 전송 중엔 단추가 꺼진다(중복 시작 방지). 서버 수락과 기기 실행 확인을 구분해 표시한다.
- 완료 기준: 조건 하나라도 빠지면 시작 요청이 서버에서도 거절된다. 오래된 준비 상태 · 종료 미확인 세션으로 중복 시작되지 않는다.

**FR2.4 아이별 종료 표현 설정** — Should · 화면 SET-01 · 출처 FR-A09, 점검표 14, G14
- 05의 종료 표현 「설정」 → SET-01. 기본 표현 "무중아 그만할래"는 파란 카드로 고정(수정 · 삭제 불가). 추가 표현은 문장 전체 2~20자, 최대 5개(차면 「+ 표현 추가」 꺼짐), 같은 화면 입력 칸에서 추가 · 수정 · 삭제, 「저장」 · 「취소」(변경 버림) → 05.
- 완료 기준: 빈 값 · 중복은 저장되지 않는다. 저장 완료 · 실패를 구분하며 실패를 성공으로 표시하지 않는다. 저장한 표현은 다음 활동부터 종료 의도 인식(FR5.4)의 보조 정보로 쓰이고 진행 중 활동에는 적용되지 않는다. 종료 표현은 정확 일치를 요구하는 암호가 아니다.

### FR3 자유대화 (담당 A · B)

**FR3.1 배경 네 칸 입력과 시작** — Must · 화면 08 · 출처 FR-B01, FR-B02, FR-B03, FR-B05, G9
- 자유대화 탭(08)은 네 칸(보호자가 알고 있는 내용 · 관련 상황 유형 · 정보 출처 · 궁금한 내용)을 받는다. 모두 선택 사항이고 비워도 「자유대화 시작」으로 바로 12에 간다. 목적 선택 · 확인 · 녹음 첨부 화면(07 · 09 · 10)은 없다.
- 네 칸은 결과 구조화(경험 · 목표 후보)의 입력이며 대화 모델에는 전달하지 않는다(FR7.4, NFR3). 평가 · 판단 표현을 유도하는 입력란은 두지 않는다.
- 완료 기준: 서술 칸은 200자를 넘기면 입력이 막힌다. 빈 입력으로 시작하면 기기는 관심사 · 일상 질문으로 대화를 시작한다(FR5.3). 요청 전송 중 단추가 꺼진다.

**FR3.2 활동 진행 화면** — Must · 화면 12 · 출처 FR-B06, FR-C06, D-15, 점검표 9, G10
- 12는 자유대화 · 연습 공통이다. 머리에 활동 종류(연습이면 n/N번째 목표), 시작 시각 · 경과, 실시간 말풍선(승인된 AI 말 + 아이 전사), 끊김 점선 · 미확인 구간, 「끝내기」(P1).
- 상태: 대화 중 / 연습 중 / 참여 기다리는 중 / 공백 4분 경고 / 잠깐 끊김 · 미확인 구간 / 종료 처리 중.
- 보호자 앱은 세션 조회 API를 1~2초 간격으로 폴링해 상태와 전사를 받는다(SSE · 푸시 스트림 아님). 실시간 발화 · 부모 마이크 · 다음 질문 버튼은 없다.
- 완료 기준: 앱만 오프라인인 동안 기기 대화가 계속된 경우 재조회 뒤 실제 기록으로 이어지고 임의의 중단 구간이 생기지 않는다. 음성 대화 장애 확인("대화 연결 복구 중")과 보호자 서버의 상태 미수신("기기 상태 확인 불가" + 마지막 확인 시각)은 구분된다. 침묵만으로 장애 · 거부 · 실패로 판정하지 않는다. 탭을 눌러도 진행 중엔 12가 유지된다.

**FR3.3 보호자 끝내기** — Must · 화면 P1 · 17 · 출처 FR-B07, D-08, 점검표 5, G11
- 12 「끝내기」 → P1(네, 끝낼게요 / 아니오). 「네」면 바로 17 마무리 중으로 간다.
- 서버는 기기에 종료를 보내고 기기는 일반 출력을 멈춘 뒤 승인된 마무리 인사 1회(1~3초)를 재생하고 멈춘다. 기기 멈춤이 확인되면 17 정리 중으로 넘어간다. 30초 안에 기기 확인이 없으면 서버가 ENDED_UNCONFIRMED(사유: 기기 응답 없이 끝냄)로 처리하며 보호자 단추는 없다.
- 완료 기준: 앱만 오프라인이면 요청을 "전송하지 못함"으로 알리고 종료 요청됨으로 표시하지 않는다. 요청 중복 · 재시도 · 재연결 · 중복 응답으로 다른 세션이 종료되지 않는다. 종료 확정 뒤 이전 응답이 이어서 재생되지 않는다. 종료와 기록 삭제는 별개다.

**FR3.4 활동 끝 화면** — Must · 화면 17 · 출처 FR-B08, FR-C07, FR-B10, FR-C08, G11
- 끝내기 · 종료 표현 · 자동 종료 · 연결 끊김 모두 17로 온다. 상태는 마무리 중 → 정리 중 → 정리 끝(「오늘 기록 보기」 → 27) / 정리 실패(「기록에서 다시 시도」 → 27). 머리에 활동 종류와 종료 사유 한 줄(보호자 끝냄 · 아이가 끝냄 · 자동 종료 · 연결 끊김 · 기기 응답 없이 끝냄).
- 17에는 결과 · 해석 · 추천 · 판정을 직접 보여 주지 않는다. 「홈으로」 · 하단 탭 홈 · 기록은 언제든 가능하고 정리는 서버에서 계속된다. 마무리 중엔 자유대화 · 연습 탭이 잠긴다.
- 완료 기준: 종료 직후 상세 결과가 표시되지 않고 「오늘 기록 보기」는 정확히 이 활동의 27로 간다. 같은 날 여러 활동이 있어도 해당 세션으로 연결된다. 준비 중인 기록은 준비 상태로 표시된다. 종료 사유 · 종료 확인 여부 · 기록 확보 범위가 구분된다.

**FR3.5 예상치 못한 종료 · 아이 무응답 안내** — Should · 화면 P2 · P3 · 출처 FR-B10, FR-B11, FR-E02, `[Q7]`
- 진행 중 연결 끊김이 40초 안에 복구되지 않으면 P2(예상치 못한 종료) → 「확인」 → 17(사유: 연결 끊김 · 끊기기 전까지 기록).
- 시작 뒤 아이가 참여 질문에 답하지 않으면 P3(아이 무응답 · 시작하지 못함 · 기록 없음) → 「확인」 → 04. 기준 시간은 FR5.2.
- 시작 때 기기 응답이 없으면(20초) 08 · 18로 돌아가 이유를 표시한다. 연습 상황 생성 실패도 18로 돌아가 이유를 표시한다.
- 완료 기준: 기기 종료 확인 미수신을 종료 완료로 표시하지 않는다. 앱 연결 장애 · 조회 불가를 아이 종료 · 대화 중단으로 표시하지 않는다. 미참여(P3) 세션은 종료 사실 · 시각만 남기고 원문을 저장하지 않는다. 안내 문구는 아이를 다그치지 않는다.

### FR4 연습 (담당 C)

**FR4.1 내 연습 목표 목록** — Must · 화면 18 · 출처 FR-C01, FR-C02, FR-C03, D-14, D-23, G16, `[Q2]`
- 18은 담은 목표 목록이다(★ 즐겨찾기 묶음이 맨 위, 그 아래 담은 순). 줄을 눌러 여러 개를 선택 · 해제하고(단추에 N 갱신, 0개면 꺼짐) 「연습 시작」 → 12. 별 「☆/★」로 즐겨찾기 토글. 별 옆 「×」로 바로 삭제하고 토스트 「되돌리기」(3초)로 복구.
- 비어 있으면 "먼저 자유대화를 해 보세요" + 「자유대화 하러 가기」 → 08. 다른 목표 선택 화면(19) · 연령 기반 추천 목록은 없다.
- 완료 기준: 선택만으로 활동이 시작되지 않는다. 즐겨찾기 · 담은 순서가 저장된다(is_favorite · sort_order). 선택 가능한 모든 목표는 상황 생성 · 판정 기준이 갖춰진 것만이다(FR7.5, FR7.6).

**FR4.2 연습 세션 진행** — Must · 화면 12 · 출처 FR-C05, FR-C06, D-05, G15, `[Q2]`
- 선택한 여러 목표를 ★ 즐겨찾기 · 담은 순 가중 랜덤 순서로 차례로 연습한다(세션–목표 연결 realtime_session_goal). 12 머리에 n/N번째 목표. 목표 하나가 끝나면 다음 목표가 있으면 12(다음 목표), 마지막이면 17.
- 목표마다 2안(상황 반응 조절형) + 제브 판정 흐름을 따른다: 상황 생성 → 첫 반응(Cue 금지) → 필요하면 도움 동의 → Cue 1회 → 도움 후 반응 1회 → 새 상황(Cue 금지) → 판정(FR7.6). 실제 현재 단계를 12에 보여 주되 고정 순서 표시나 부모의 다음 단계 · 건너뛰기 버튼은 없다.
- 상황 생성이 두 번 실패하면 연습을 시작하지 않고 18로 돌아가 이유를 표시한다(FR7.5). 개별 상황 본문은 보호자에게 미리 보여 주지 않는다.
- 완료 기준: 서버 수락과 기기 안내 실행 확인을 구분한다. 보호자 서버의 상태 미수신 · 앱 조회 불가를 연습 멈춤 · 단계 실패로 바꾸지 않는다. 단계 값(current_practice_stage) 목록은 AI 입출력 계약(WBS 1.7.3)에서 확정한다.

**FR4.3 연습 기록 표시와 4단계 분리 저장** — Must · 화면 27 · 출처 FR-F09, FR-C07, FR-C08, D-05
- 연습 세션의 27은 맨 위에 18에서 고른 목표 이름만 보여 주고 판정 글 · 단계 결과를 보여 주지 않는다. 그 아래는 자유대화와 같은 세 칸(FR6.2).
- 서버는 목표마다 첫 반응 · 도움(내용 · 종류 · 순서 · 시각 · 동의 응답) · 도움 후 반응 · 새 상황 반응(추가 도움 여부)을 분리해 저장하고 당시 상황 · 상대 역할 · 제공 발화 맥락에 연결한다. 미실시 단계는 null과 미실시 사유로 구분한다.
- 완료 기준: 도움 후 반응이 첫 반응을 덮어쓰지 않는다. 같은 기회의 재시도가 독립 성공으로 바뀌지 않는다. 기록된 도움 내용에서 정답 문장 포함 여부를 확인할 수 있다. 판정값은 저장되지만 27 · 17 · PDF 어디에도 노출되지 않는다.

**FR4.4 연습 목표 후보 담기** — Must · 화면 27 · 18 · 출처 FR-C01, FR-D04, FR-F06, 점검표 21, G16
- 자유대화 · 연습 결과에서 서버가 만든 연습 목표 후보(행동 정의 · 기회 조건 · 상황 생성 조건 · 판정 기준 4요소를 갖춘 것만)를 27 세 번째 칸에 보여 준다. 보호자가 「담기」를 누르면 18 목록에 쌓이고(화면 이동 없음), 「담김 ✓」을 다시 누르면 취소되어 18에서도 빠진다.
- 후보 생성 · 등록은 자동이지만 연습할 것을 고르는 것은 보호자다. 후보가 없으면 후보 없음 상태를 보여 준다.
- 완료 기준: 담기 · 취소가 18에 즉시 반영된다. 근거 없는 개인화 이유나 지원되지 않는 목표가 노출되지 않는다. 추천 근거가 있으면 실제 기록과 연결된다.

### FR5 아이 기기 (담당 B · D)

**FR5.1 기기 웹 상태와 조작** — Must · 화면 D0 · T19 · 출처 FR-E11 일부, D-16, G19
- 아이 기기는 웹(/device)이다. 클릭 요소는 「켜기」(마이크 · 소리 허용 → 기기 연결 → 대기, 화면 켜짐 유지 Wake Lock)와 「끄기」(기기 연결 끊김 → 꺼짐)뿐이다.
- 상태: 꺼짐 · 대기 · 듣는 중 · 생각 중 · 말하는 중 · 마무리(→ 대기 자동) · 연결 끊김/다시 연결 중 · 마이크 허용 안 됨(→ 「켜기」 다시).
- 탭이 뒤로 가거나 화면이 꺼지면 연결 유지를 시도하고 끊기면 다시 연결 중으로 간다. 브라우저 데이터 삭제 · 다른 기기면 D0(다시 등록). `?debug=1`이면 상태 로그를 보인다.
- 완료 기준: 보호자가 활동을 시작하면 대기 → 듣는 중으로 바뀐다. 아이 종료 표현 · 보호자 끝내기 · 자동 종료 모두 마무리 → 대기로 간다. 마이크 거부 시 연결하지 않고 안내만 한다.

**FR5.2 시작 안내와 참여 확인** — Must · 화면 12(참여 기다리는 중) · P3 · 출처 FR-E01, FR-E02, 점검표 6, `[Q7]`
- 보호자가 시작을 요청하면 기기는 승인된 음성 문구로 AI와 대화한다는 사실 · 오늘 활동(자유대화/연습) · 기록과 보호자 열람 · 그만하고 싶을 때 말할 "무중아 그만할래"를 안내하고 참여 의사를 묻는다. 자유대화와 연습의 시작 안내 문구는 다르다. 쉬기 · 건너뛰기 · 재개 명령은 안내하지 않는다.
- 참여 대기: 20초 무응답 → 승인 문구로 재안내 1회 → 20초 더 무응답 → 시작하지 않고 종료(DECLINED, 기록 없음, 보호자 P3). 합계 40초를 시간 계약(WBS 1.7.6)에 넣는다.
- 참여 질문을 명시적으로 거부하면 다른 선택지를 1회 제안하고 다시 거부하면 마무리한다(DECLINED). 특정 주제만 거부하면 다른 주제를 제안하고 종료로 혼동하지 않는다.
- 완료 기준: 재권유가 1회를 넘지 않는다. 무응답 · 쉬고 싶다는 말만으로 종료 의도를 확정하지 않는다. 미참여 기록은 종료 사실 · 시각만 남긴다.

**FR5.3 자유대화 대화 규칙** — Must · 화면 12 · 출처 FR-E03, FR-F03, FR-F15
- 보호자 입력을 직접 언급하지 않고('엄마가 그러던데' 류 금지) 일상 질문으로 시작해 후속 질문으로 이어간다. 한 번에 질문 하나, 과도한 칭찬 · 추궁 금지. 입력한 사건이 나오지 않아도 계속 유도하지 않는다.
- 배경 정보가 없거나 아이가 다른 이야기를 하면 프로필 관심사 · 활용 가능한 이전 기록 · 승인된 일상 질문 은행으로 이어간다.
- 대화 역할에는 판정 기준 · 보호자 입력 원문 · 이전 판정 결과를 전달하지 않는다(NFR3).
- 완료 기준: 합성 시험 세트에서 보호자 입력 직접 언급 · 역할 지식 누출이 0건이다. 입력 없이 시작한 세션이 마무리까지 진행된다.

**FR5.4 아이 종료 의도 인식과 마무리** — Must · 화면 12 · 17 · 출처 FR-E05, FR-E10, FR-F14, G14
- Realtime이 GPT-Live 전사와 대화 맥락에서 실제 종료 의도를 인식한다. 기본 표현 "무중아 그만할래"와 아이별 추가 표현은 보조 정보이며 정확 일치 · 호출어+명령어 조합을 유일 조건으로 두지 않는다. 미등록 표현도 종료 의도가 명확하면 처리하고, 역할 속 대사 · 상대 발화 · 주제 거부 · 기기 재생 음성과 구분한다. 불명확하면 종료라고 단정하지 않고 짧게 확인한다.
- 종료 의도를 확인하면 대기 중 응답을 취소하고 승인된 마무리 인사 1회를 재생한 뒤 멈춘다(사유 CHILD_STOP). 종료 처리 중엔 새 대화 응답을 생성 · 재생하지 않는다.
- 완료 기준: 20회 시험에서 오인식 0 · 미인식 1 이하(TS-N05). 종료 확정 뒤 이전 응답이 이어서 재생되지 않는다. 기기 재생 음성을 아이의 종료 요청으로 취급하지 않는다.

**FR5.5 연습 음성 흐름** — Must · 화면 12(연습) · 출처 FR-E06, FR-E07, FR-E08, FR-E09, FR-E10, D-05
- 만들어진 상황임과 AI의 역할을 음성으로 안내하고 상황과 상대 역할의 말을 제공한다. 기회 트리거(예: 상대의 중단 요청)는 승인 대본으로 출력한다.
- 첫 반응 전에는 힌트 · 정답 · 시범(Cue)을 주지 않는다. 같은 말 반복 · 속도 조절은 할 수 있다(FR5.6).
- 첫 반응이 목표 행동과 연결되지 않으면 아이 동의("같이 살펴볼까?")를 구한 뒤 상대의 말을 다시 짚어주는 단서(Cue)를 실시간으로 만들어 준다(5초 예산). 정답 문장은 알려주지 않는다. 거부하면 이어가지 않는다. 도움 후 재시도는 1회.
- 새 상황은 같은 활동 안에서 소재만 다르고 목표 행동 · 상대 관계 · 기회 조건은 같은 상황을 추가 도움 없이 제시한다.
- 정상 마무리 음성은 승인 목록을 쓰고 1회만 재생한다.
- 완료 기준: 첫 반응 · 새 상황 단계에서 Cue 출력이 차단된다. 제공한 도움 내용과 동의 응답이 기록되고 정답 문장 포함 여부를 확인할 수 있다. 같은 활동 안에서 같은 상황이 재사용되지 않는다.

**FR5.6 다시 듣기 · 속도 조절 · 설명 요청** — Should · 화면 12 · 출처 FR-E04
- 아이가 요청하면 같은 내용 반복 · 속도 조절을 한다. 목표 행동의 판단 단서를 추가하는 설명은 도움(Cue) 제공으로 기록하고 FR5.5의 동의 원칙을 적용한다.
- 완료 기준: 단서를 추가하지 않은 반복 · 속도 조절은 Cue로 집계되지 않는다. 요청 문구만으로 분류하지 않고 실제 제공 내용으로 구분한다.

**FR5.7 연결 장애 대응과 복구** — Should · 화면 12 · P2 · 17 · 출처 FR-E11, FR-F18, FR-F14, G7
- 기기 연결 · 음성 모델 연결 장애가 확인되면 Realtime이 기술적 일시 정지를 기록하고 12에 "대화 연결 복구 중"과 끊김 점선을 표시한다. 기기는 다시 연결 중으로 간다.
- 40초 안에 복구되면 종료 요청이 없고 상태 · 맥락을 복원할 수 있을 때만 재개한다(이전 응답 · Cue 재재생 없음). 복구 실패면 P2 → 17(사유 DISCONNECT, 끊기기 전 기록 보존).
- 완료 기준: 기기 연결 장애 · 음성 모델 장애 · 보호자 서버 상태 미수신 · 앱만 오프라인을 각각 주입하면 구분된 표시가 나오고, 복구 뒤 확보 기록으로만 타임라인이 보완되며 증거 없는 구간은 미확인으로 남는다. 종료 요청 중이거나 종료된 세션은 복구만으로 재개되지 않는다.

### FR6 기록 · 리포트 (담당 E)

**FR6.1 기록 달력과 그날 목록** — Must · 화면 26 · 출처 FR-D01, D-14, G17
- 기록 탭(26)은 달력(활동한 날 점)이다. 날을 누르면 그날 활동 목록(시각 · 종류)이 아래에 뜨고, 활동 한 줄을 누르면 27. ‹ ›로 달을 넘긴다. 활동 없는 날은 「활동이 없어요」 한 줄. 상단에 「상담용 리포트 다운」 → 28. 활동 종류 필터는 없다.
- 완료 기준: 날짜가 같아도 서로 다른 세션이 구분되고 선택한 기록과 상세의 세션이 일치한다. 미참여(DECLINED) 세션은 종료 사실 · 시각만 표시하고 상세로 연결하지 않는다. 27에서 「←」는 보던 날을 유지한다.

**FR6.2 활동 기록 상세** — Must · 화면 27 · 출처 FR-D02, FR-F05, FR-F12, D-14, G17
- 27은 세 칸이다: 대화 기록(아이 전사 · 승인된 AI 말 인용, 보호자 입력 배경, 보호자 입력/아이 회상 출처 구분, 아직 확인되지 않은 내용) · 생활 팁(FR6.3) · 연습 목표 후보 담기(FR4.4). 연습 세션은 맨 위에 고른 목표 이름(FR4.3).
- 정리 중 · 정리 실패(「다시 시도」 → 팁 · 목표 다시 정리) · 후보 없음 · 자료 부족을 구분한다. 기술 문제가 있으면 종료 확인 여부와 확보된 기록 범위 · 미확인 구간을 따로 보여 준다.
- 완료 기준: 모든 인용 · 출처 · 미실시가 실제 저장 기록과 일치하고 서버 집계에 없는 수치 · 판단 · 점수 · 성공률이 없다. 기록 수신 공백을 아이의 침묵 · 거부 · 실패로 해석하지 않는다. 앱 연결 복구 후 실제 수신한 기록만 갱신한다.

**FR6.3 생활 팁(일상 지원)** — Must · 화면 27 · 출처 FR-C09, FR-F13
- 승인된 지원 목록(Support Library)에서 이번 목표 행동 · 적용 조건에 맞는 항목을 골라 적용 조건 · 한계와 함께 보여 준다. 초기 목록은 개발팀이 제공한다. 맞는 항목이 없거나 목록이 비면 '추가 관찰 필요'를 표시한다.
- 완료 기준: 미승인 항목과 검색 점수가 노출되지 않는다. 표현 제한(NFR1)을 따른다.

**FR6.4 리포트 범위 선택과 생성** — Must · 화면 28 · 출처 FR-D05 재정의, D-13, D-22, G18
- 28에서 범위를 고른다: 빠른 선택 3개(최근 2주 — 기본 · 이번 달 · 전체/직접), 달력(첫 탭 시작일 · 둘째 탭 끝일 · 드래그 · 달 넘겨도 이어짐 · 미래 날 불가 · 세 번째 탭은 새로 시작), 기간 안 활동 목록(줄 체크로 빼기 · 넣기, 진행 중 활동 제외). 날 토글은 없다.
- 「활동 N개로 리포트 만들기」 → 만드는 중(몇 초, 화면 머무름, 「취소」 · 「←」로 중단 · 범위 유지) → 성공 시 30. 실패 시 「다시 시도」 · 「범위 다시」 · 「←」(26).
- 서버가 저장된 전사로 날짜별 대화 원문 PDF를 만든다. AI 요약 · 평가 · 판정값은 들어가지 않는다.
- 완료 기준: 기간 안 활동 0건이면 단추가 꺼지고 안내가 뜬다. 생성은 60초 안에 READY, 실패는 재시도 뒤 FAILED로 구분된다(NFR8). 리포트 기간(period_from · period_to)이 저장된다.

**FR6.5 PDF 확인 · 저장 · 공유** — Must · 화면 30 · R-PDF · 출처 FR-D06, D-13, G18
- 30은 저장 전 확인(기간 · 아이 · 대화 원문 건수) → 「PDF 저장」 → 저장했어요 → 「공유하기」(OS 공유 시트) · 「파일 열기」 · 「기록으로」. 「나중에」 · 저장 전 「←」는 만든 리포트를 버린다(다시 만들려면 28부터). 저장 실패는 토스트 「다시 시도」와 30 유지.
- PDF 템플릿: 머리(아이 이름 · 연령 · 관심사 · 기간 · 만든 날) → 날짜별 목차 → 날짜별 대화 원문(과거 → 최신). 진단 결과가 아님을 명시한다.
- 전문가에게는 보호자가 저장한 PDF를 직접 건넨다. 서비스 안 전송 · 공유 기능 · 전문가 계정 · 수신 확인은 없다.
- 완료 기준: PDF가 저장되고 저장 사실만 이력에 남는다. 저장을 전달 · 수신 완료로 표시하지 않는다. 동의 범위 밖 전사 · 인용이 들어가지 않는다.

### FR7 서버 · 세션 · AI 처리 (담당 B · D · E)

**FR7.1 세션 상태 관리** — Must · 출처 FR-F01, 점검표 3 · 4, G13
- 세션 상태 11개: REQUESTED · PREPARING · DEVICE_ACK · WAITING_CHILD · ACTIVE · CLOSING · ENDED · ENDED_UNCONFIRMED · ABORTED · DECLINED · FAILED. 종료 사유 8개: GUARDIAN_STOP · CHILD_STOP · SILENCE · DISCONNECT · CONSENT_WITHDRAWN · UNCONFIRMED · DECLINED · FAILED. 종료 시각은 요청 · 출력 중단 · 전송 종료 · 공급자 종료를 따로 둔다.
- 계정당 진행 세션 1개. 뒤늦은 진행 이벤트 · 중복 종료 · 복구 이벤트가 종료 상태를 되돌리거나 새 활동을 만들지 않는다. 아동 서비스(Realtime)–보호자 서버(Core) 간 전달이 중단됐다 재개되면 미전달 이벤트가 순서대로 반영된다(Outbox/Inbox).
- 완료 기준: 앱 종료 · 앱만 오프라인 시험 중 정상 기기의 활동 · 기록이 유지되고 재진입 시 같은 세션이 조회된다. 기기 종료 확인 미수신은 미확인으로 유지되고 확보되지 않은 이력을 만들지 않는다. 상태 전이는 상태 기계 표(개발 명세 5절)대로만 일어난다.

**FR7.2 승인 문구 관리** — Must · 출처 FR-F02
- 시작 안내 · 참여 재안내 · 기회 트리거 · 마무리 인사 문구(와 음성)를 버전과 함께 관리하고 해당 상태에서는 생성형 발화 대신 승인 문구만 출력한다(PLAY_APPROVED_CONTENT). 도움(Cue)은 실시간 생성이다.
- 완료 기준: 세션 중 문구 버전이 바뀌지 않는다(세션에 closing 버전이 고정된다).

**FR7.3 전사 · 원음 저장** — Must · 출처 FR-F04, D-06, 점검표 2, G4, G26
- 아이 발화를 GPT-Live 전사로 저장한다(별도 STT 없음, 전사 수정 기능 없음). 의미가 불확실한 구간은 불확실로 표시한다.
- 원음은 항상 저장한다(원음 보관이 필수 동의). 보존은 계정 삭제까지. 저장 위치(EC2 디스크 볼륨 등)는 Infrastructure Design에서 정한다.
- 완료 기준: 전사와 불확실 표시가 저장된다. 세션 조회 응답에 전사가 포함된다(12 말풍선용). 원음 파일이 세션에 연결되어 저장되고 계정 삭제 시 함께 지워진다.

**FR7.4 경험 구조화와 목표 후보 생성** — Must · 출처 FR-F05, FR-F06, 점검표 12 · 21
- 자유대화가 끝나면 등장인물 · 상황 · 상대의 말 · 아이 반응 · 설명을 분리하고 보호자 입력(08 네 칸)/아이 회상 출처를 태깅한다. 아이의 의도 · 감정을 추론해 저장하지 않는다.
- 4요소(행동 정의 · 기회 조건 · 상황 생성 조건 · 판정 기준)를 갖춘 연습 목표 후보를 자동 생성 · 등록한다. 추천 근거는 실제 기록에 연결한다. 기록이 없으면 후보 없음이다(연령 기반 기본 추천은 두지 않는다 — G16).
- 완료 기준: 각 내용이 실제 출처(보호자 입력 또는 아이 전사 구간)로 역추적된다. 08 네 칸 원문은 대화 모델에 전달되지 않고 구조화에만 쓰인다.

**FR7.5 연습 상황 생성과 중복 방지** — Must(생성) / Should(중복 방지) · 출처 FR-F07, FR-F08
- 선택 목표에 맞게 상황을 생성하고 기회 트리거 · 상대 역할 · 언어 부담을 유지하며 소재를 바꾼다. 생성 후 목표 · 트리거 포함 여부와 금지 표현을 자동 확인하고, 통과하지 못하면 1회 다시 생성한다. 그래도 실패하면 연습을 시작하지 않고 보호자에게 안내한다(18).
- 새 상황에는 이전 활동에서 그 아이에게 노출된 적 없는 상황만 쓴다. 노출 이력을 아이별로 보관한다.
- 완료 기준: 확인을 통과하지 못한 상황은 아이에게 제공되지 않고, 두 번 실패하면 시작되지 않는다. 실패를 정상 생성으로 표시하지 않는다. 이전 노출 이력과 겹치는 상황이 선택되지 않는다.

**FR7.6 반응 판정** — Must · 출처 FR-F10, D-05
- 첫 반응 · 도움 후 반응 · 새 상황 반응을 저장된 핵심 기능 정의와 해당 상황의 판정 조건으로 판정한다. 라벨: functional · partial · none · uncertain. 무반응은 NOT_PERFORMED(none과 구분). 판정 LLM은 5초 예산 + 재시도 1회, 실패면 uncertain.
- 판정 기준이 없는 행동은 연습 대상으로 제공하지 않는다. 불확실하면 보류로 기록하고 새 상황으로 넘어간다. 판정 기준 · 프롬프트는 AI 입출력 계약(WBS 1.7.3, 담당 D)에서 정한다.
- 완료 기준: 같은 행동의 판정이 저장된 정의 · 조건을 따른다. 판정값은 저장만 되고 보호자 화면 · PDF에 노출되지 않는다(FR4.3).

**FR7.7 결과 생성 재시도** — Should · 출처 FR-F17
- 활동 기록은 있으나 기록 상세(팁 · 목표 후보) 생성이 최종 실패하면 27 · 17에 실패를 구분해 표시하고 보호자가 「다시 시도」로 생성을 다시 요청할 수 있다.
- 완료 기준: 다시 시도해도 같은 활동의 결과가 한 번만 생성되고 원본 기록은 바뀌지 않는다.

**FR7.8 출력 게이트** — Must · 출처 ADR-004, 점검표 18
- AI 음성 응답을 구간으로 나눠 전사와 대응시키고 금지 표현(NFR1) · 역할 규칙(FR5.3, FR5.5)을 검사한 뒤 승인된 음성만 기기로 보낸다. 12 말풍선에는 승인된 AI 말만 올라간다.
- 아이가 끼어들면 기기가 재생을 멈추고(0.5초 이내) 재생 위치를 보고한다.
- 완료 기준: 금지 표현이 포함된 응답은 기기로 가지 않고 말풍선에도 나오지 않는다. 끼어들기 시험에서 재생 중단이 0.5초 이내다(TS-N04, 11/2 확정).

**FR7.9 대화 공백 판정과 자동 종료** — Must · 출처 FR-F18, D-07, 점검표 6, G12
- 기기 연결 · 음성 모델 연결이 정상인 상태에서 확인 가능한 연속 공백이 4분이면 공백 경고 상태(12 표시 · 기기 안내 1회), 2분 더(6분) 지나면 자동 종료(SILENCE) 처리하고 기기 확인 후 완료한다.
- 완료 기준: 앱만 오프라인 · 보호자 서버 상태 미수신 · 음성 대화 장애 시간을 공백으로 대체한 자동 종료가 없다. 장애/미확인 경계 전후 공백의 연속성이 증명되지 않으면 합산하지 않는다. 17 사유 "말이 없어 자동 종료"로 표시된다.

**FR7.10 웹 푸시 알림과 알림 진입** — Should · 화면 04 · 12 · 17 · 출처 FR-A10, D-17, 점검표 10, `[Q1]`
- 서버가 음성 대화 장애 · 기기 상태 수신 중단 · 기술 문제로 인한 기기 종료 확인을 감지하면 보호자 폰에 웹 푸시를 요청한다(core_push_token). 문구 3종: "대화 중 음성 연결 문제가 발생했어요." / "기기 상태를 확인할 수 없어요." / "연결 문제로 활동이 종료됐어요." 감시는 앱 실행 여부에 의존하지 않는다.
- 푸시를 누르면 04가 최신 세션을 재조회해 진행 중이면 12, 끝났으면 17, 실패면 04 지금 활동 칸 미확인으로 보낸다. 이 재조회 로직은 푸시가 없어도 앱 재진입에서 동작한다.
- 같은 사건의 중복 발송을 막고 발화 원문 · 대화 내용은 넣지 않는다. 발송 요청 · 실패 · 전달 상태를 구분하며 실제 전달을 보장하지 않는다. 앱 닫힘 · 앱 연결만의 장애로는 알림을 만들지 않는다.
- 우선순위: Should. 시연은 Android Chrome에서 장애 · 미확인 1종만 보여도 된다. 7일 안에 못 넣으면 Delivery Planning에서 뒤로 민다. iOS는 보장하지 않는다(NFR10).
- 완료 기준: 앱을 닫고 세 사건을 각각 발생시키면 서버 발송 요청이 올바른 문구 · 아이 · 세션으로 남는다. 알림 비허용 · 폰 오프라인은 실제 전달로 표시되지 않는다. 오래된 알림 문구로 현재 상태를 덮어쓰지 않는다.

## 제약

- **구조**(ADR_2S, 바꾸지 않는다): Core API Spring + Realtime Activity Spring, Next.js 한 앱 두 접점(/parent · /device, PWA 아님), PostgreSQL 1대(core · realtime 스키마), Neo4j(화용 지식), GPT-Live 중계 B안 + 출력 게이트, 내부 HTTP + Outbox/Inbox, EC2 1대 Docker Compose + Nginx(WSS · HTTPS) `[desc]`, G20.
- **외부 의존**: 음성 대화 · 전사는 GPT-Live 하나에 의존한다. 공급자 교체 가능성(NFR-10)은 ADR로 이관되어 요구사항이 아니다.
- **일정 · 팀**: 구현 10/15~27(7일) · 통합시험 10/29 · 결함 수정 10/30 · 동결 11/2 · 문서 11/3 · 제출 11/5. 5인(A 계정 / B 음성 / C 연습 / D AI / E 결과) `[desc]`, G25. Must는 Q6 네 경로에 한정한다.
- **사용자 모델**: 한 계정 = 아이 하나 = 기기 하나. 공동 보호자 · 가족 초대 · 전문가 계정 · 관리자 화면 없음(G2, G22).
- **동의 모델**: 4항목 전부 필수, 철회는 계정 삭제로만(G3). 법적 적합성 검토는 범위 밖.
- **기준 문서 우선순위**: 화면 설계 v1.5j > 개발 명세 1008 > 요구사항 v1.1 > ADR · ERD · WBS. ADR · ERD · WBS와 어긋나는 21곳(점검표 2절)은 Domain Design · Contract Design에서 화면 기준으로 고친다.
