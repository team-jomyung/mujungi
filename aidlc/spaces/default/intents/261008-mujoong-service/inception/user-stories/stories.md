# 무중 사용자 스토리

> 묶는 단위: 화면 설계의 차선(LANE) 여섯 개 = 에픽 US1~US6. 스토리 하나 = 화면 카드 하나(또는 아이 기기의 음성 흐름 하나).
> 수용 기준: 화면 분기표 한 줄을 한 줄로 옮겼다 — `Given` 화면 · 상태 / `When` 단추 · 사건 / `Then` 어디로 · 무엇이 보이나. 화면에 보이는 글은 문구표의 실제 문구를 인용했고, 화면 설계에 상태는 있으나 글이 없는 곳은 "(문구 미정)"으로 표시해 Refined Mockups에서 채운다(B26). 개발 명세의 검증 규칙과 검토에서 추가된 서버 · 접근성 조건은 "검증:" 접두로 적었다. 다른 스토리와 같은 내용은 한 번만 적고 가리킨다(→ ACx.y.z).
> 우선순위: requirements.md와 같다(Must = 11/5 시연 네 경로, Should = 구현하되 시연 필수 아님). Must 스토리 안의 Should 기원 AC에는 `(Should)` 표를 달았다. 페르소나는 personas.md(보호자 P1 · 아이 P2 · 운영자 P3).
> 가정: 검토에서 사람 판단이 필요했던 항목은 멈추지 않고 `B1`~`B26`(끝의 "검토에서 정한 가정" 절)로 적었다. 뒤 단계에서 바꿀 수 있다.

## US1 · 처음 한 번과 홈 (LANE 1 · 1-1)

### US1.1 구글 로그인 — Must · 화면 01 · FR1.1 · NFR9
**보호자**로서, 구글 계정으로 들어와 로그인 상태를 유지하고 싶다. 그래야 매번 다시 로그인하지 않고 아이 활동을 바로 볼 수 있다.

수용 기준
- AC1.1.1 Given 01 대기 When 「구글로 시작」 성공 · 첫 로그인(동의 없음 = 현재 policy_version의 동의가 없음; 약관 개정 재동의는 범위 밖) Then 02로 간다
- AC1.1.2 Given 01 대기 When 「구글로 시작」 성공 · 동의 있음 · 아이 등록됨 Then 04로 간다
- AC1.1.3 Given 01 대기 When 「구글로 시작」 성공 · 동의 있음 · 아이 등록 안 됨 Then 03(처음 등록)으로 간다
- AC1.1.4 Given 01 인증 중 When 취소 · 실패 Then 인증되지 않은 상태로 01에 남고 다시 시도할 수 있다
- AC1.1.5 Given 02 · 03을 끝내지 않고 종료 When 다음 실행 Then 01부터 시작한다
- AC1.1.6 Given 로그인 유지 토큰 만료 When 재로그인 Then 04로 가고, 진행 중 활동이 있으면 지금 활동 칸에 보인다
- AC1.1.7 검증: 01에는 구글 외 로그인 · 회원가입 · 아이디/비밀번호 경로가 없다
- AC1.1.8 검증: 다른 보호자의 아이 · 세션 · 기록 · 리포트 · 목표 id로 조회 · 변경을 요청하면 404 또는 403이고 응답에 그 데이터가 없다(NFR9)
- AC1.1.9 Given 어느 화면(12 폴링 중 포함) When API가 401(로그인 유지 만료) Then 안내 토스트 뒤 01로 간다; 진행 중 세션은 영향받지 않고(기기–서버 사이에서 계속) 재로그인 → 04 지금 활동 진행 중 → 12
- AC1.1.10 Given 01 When 「구글로 시작」 누름 Then 인증 중 상태가 보이고 단추가 다시 눌리지 않는다

INVEST: 독립 · 작음 · 시험 가능. 의존: 없음.

### US1.2 기록 · 동의 안내 — Must · 화면 02 · 02-1 · P5 · FR1.2 · FR1.3
**보호자**로서, 처음 한 번 무엇을 기록하고 누가 보는지 알고 네 항목에 동의하고 싶다. 그래야 아이 음성이 어떻게 쓰이는지 알고 시작할 수 있다.

수용 기준
- AC1.2.1 Given 02 첫 동의(네 개 다 체크 전) When 화면 표시 Then 「동의하고 계속」이 꺼져 있다
- AC1.2.2 Given 02 When 항목의 「자세히 보기」 Then 02-1 약관 시트가 뜬다 — 음성 수집 = 수집하는 것 · 이용 목적 · 보관 · 동의하지 않으면, 보호자 열람 = 보는 사람 · 볼 수 있는 것 · 이용 목적 · 동의하지 않으면, 리포트 = 만드는 것 · 전달 · 보관 · 동의하지 않으면, 원음 = 보관하는 것 · 이용 목적 · 보관 · 동의하지 않으면(C.S-02-1.35 · 41 · 42 · 43)
- AC1.2.3 Given 02-1 When 「확인」 · 바깥 누름 Then 02 보던 자리로 돌아온다
- AC1.2.4 Given 02 When 네 항목 모두 체크 → 「동의하고 계속」 Then 항목별 동의 상태와 약관 버전이 저장되고 03(처음 등록)으로 간다
- AC1.2.5 Given 02 동의 전 When 「←」 · 뒤로가기 Then P5 "동의하지 않으면 무중을 쓸 수 없어요" / "네 항목에 모두 동의해야 시작할 수 있어요. 나가면 로그아웃돼요."(C.P-05.64)가 뜬다
- AC1.2.6 Given P5 When 「로그아웃」 Then 01로, 「계속 동의하기」 Then 02로 간다
- AC1.2.7 Given 02를 끝내지 않고 종료 When 다음 실행 Then 01 → 02다
- AC1.2.8 검증: 동의를 바꾸거나 거두는 화면 · 단추가 없다(거두려면 계정 삭제 US1.6)
- AC1.2.9 검증: 02-1 네 항목 본문 모두에 생성형 AI 고지 문장이 있다(FR1.3) — 문구표 02-1에는 아직 없음 (문구 미정 · 문구표 보완 필요)

INVEST: 작음 · 시험 가능. 의존: US1.1.

### US1.3 아이 정보 — Must · 화면 03 · FR1.4
**보호자**로서, 아이 하나의 이름 · 나이 · 관심사를 한 화면에서 등록하고 나중에 고치고 싶다. 그래야 대화가 아이에게 맞춰진다.

수용 기준
- AC1.3.1 Given 03 처음 등록(제목 "아이 정보를 알려 주세요", 칸 "이름 또는 별명" · "나이" · "관심사 (예: 공룡, 블록 놀이)", 뒤로 없음 — C.S-03.40) When 입력하고 「확인」 Then 04로 가고 기기 칸이 「기기 등록」을 안내한다
- AC1.3.2 Given 03 처음 등록 When 「←」 · 뒤로가기 Then 아무 일도 없다(등록을 마쳐야 넘어감)
- AC1.3.3 Given 03 보기 When 「정보 수정」 → 글자 수정 → 「확인」 Then 03에 바뀐 내용이 보인다
- AC1.3.4 Given 03 수정 중 When 「취소」 Then 원래 내용으로 돌아온다
- AC1.3.5 Given 03 입력 When 이름이 비면 Then 「확인」이 꺼진다; 나이가 6~12 밖이면 오류 글(문구 미정)이 해당 칸 바로 아래에 글로 붙고 색만으로 알리지 않으며 입력 상태가 유지된다
- AC1.3.6 Given 03 When 저장 실패 Then 토스트(문구 미정)가 뜨고 이전 값이 유지된다
- AC1.3.7 Given 03 보기 · 수정 중 When 「←」 Then 04로 간다(수정 중이면 「취소」와 같다)
- AC1.3.8 검증: 이름 또는 별명 1~10자(빈 값 · 11자 이상이면 「확인」 꺼짐), 나이 6~12 정수, 관심사 5개 이하 · 각 10자(초과 입력 막음) — 개발 명세 화면별 명세
- AC1.3.9 검증: 아이 선택 · 추가 · 삭제 단추가 없다. 수정으로 기존 활동 · 기록의 대상 아이가 바뀌지 않는다
- AC1.3.10 Given 03 보기 When 화면 표시 Then 카드에 이름 · "n세 · 관심사" · 기기 상태 줄(「기기 · 안정」 등; 기기 없음 · 불안정일 때 문구 미정) · 「정보 수정」이 보인다(C.S-03.2)

INVEST: 작음 · 시험 가능. 의존: US1.2.

### US1.4 홈 — Must · 화면 04 · FR1.5 · FR2.3 · FR7.1
**보호자**로서, 홈에서 아이 · 대화 기기 · 지금 활동 세 구역을 한눈에 보고 시작할 수 있는지 알고 싶다. 그래야 기기가 안 될 때 헛되이 시작하지 않는다.

수용 기준
- AC1.4.1 Given 04 When 아이 구역 「수정」 Then 03으로 간다
- AC1.4.2 Given 04 대화 기기 안정 When 화면 표시 Then 제목 "{아이}의 오늘", 대화 기기 칸에 상태명 "안정"(초록) + 마지막 확인 hh:mm + 「기기 상태 보기 ›」가 보이고 자유대화 · 연습 탭이 열려 있다(C.S-04.3)
- AC1.4.3 Given 04 대화 기기 불안정(노랑) · 끊김(빨강) · 응답 없음(회색) When 화면 표시 Then 각 상태명 + 문구(안정될 때까지 시작할 수 없어요 / 전원 · 와이파이를 확인해 주세요 / 기기를 다시 켜 보세요 + 마지막 hh:mm)가 색과 함께 보이고 자유대화 · 연습 탭이 잠긴다(판정 조건은 AC2.1.3~2.1.6 · AC2.1.10)
- AC1.4.4 Given 04 연결된 기기 없음 When 화면 표시 Then 대화 기기 칸에 "연결된 기기 없음" + "아이 기기에 뜬 코드로 등록해요." + 「기기 등록」(C.S-04.4.6~8)이 보이고 탭이 잠긴다; 「기기 등록」 Then 05a
- AC1.4.5 Given 04 When 대화 기기 칸 「기기 상태 보기」(어느 상태든) Then 05로 간다
- AC1.4.6 Given 04 지금 활동 없음 · 기기 안정 When 화면 표시 Then "진행 중인 활동 없음 · 자유대화 · 연습 탭에서 시작해요."(C.S-04.66.10~11)가 보인다
- AC1.4.7 Given 04 지금 활동 진행 중(초록) When 화면 표시 Then "{아이} · 자유대화 n분째" + "hh:mm 시작" + 「진행 화면 보기 ›」가 보이고, 누르면 12로 간다(C.S-04.3.12)
- AC1.4.8 Given 04 지금 활동 조회 실패 When 화면 표시 Then 지금 활동 칸에 '미확인' 라벨(문구 미정) + 마지막 확인 hh:mm + 「다시 확인」만 보이고 '진행 중' · '없음' 라벨은 보이지 않는다; 「다시 확인」 성공 시 실제 상태로 갱신된다
- AC1.4.9 Given 04 기기 안정 · 활동 없음 When 하단 「자유대화」 Then 08, 「연습」 Then 18로 간다
- AC1.4.10 Given 04 활동 진행 중 When 하단 「자유대화」 또는 「연습」 Then 새 시작 대신 12(해당 활동)로 간다
- AC1.4.11 Given 04 탭 잠김(기기 불안정 · 끊김 · 응답 없음 · 없음) When 하단 「자유대화」 · 「연습」 Then 이유 토스트(문구 미정) 뒤 05로 간다
- AC1.4.12 Given 04 When 하단 「기록」 Then 26, 「⚙」 Then 설정 시트(US1.5)
- AC1.4.13 검증: 재진입 · 재조회 시 지금 활동 칸은 세션 상태별로 다음과 같다 — REQUESTED · PREPARING · DEVICE_ACK · WAITING_CHILD · ACTIVE → '진행 중' + 「진행 화면 보기」 → 12; CLOSING → '종료 처리 중' + 「진행 화면 보기」 → 17(B1); ENDED · ENDED_UNCONFIRMED · ABORTED · DECLINED · FAILED → '없음'(종료 확인 미확인 표시는 17 · 27에서 한다). 11개 상태를 각각 주입해 확인한다. 앱 닫힘은 장애 · 종료 요청이 아니다
- AC1.4.14 Given 04 지금 활동 없음 · 탭 잠김 When 화면 표시 Then 지금 활동 칸이 "지금은 시작할 수 없어요" + 사유 한 줄로 바뀐다 — 기기 없음 "기기를 먼저 등록해 주세요."(C.S-04.4.10~11), 불안정 "기기 네트워크가 불안정해요. 안정되면 자유대화 · 연습 탭이 열려요."(C.S-04.67.9~10), 끊김 · 응답 없음(문구 미정)
- AC1.4.15 검증: 대화 기기 · 지금 활동 상태는 색 + 상태명 글자 + 사유 문구를 함께 쓰고 색만으로 구분하지 않는다. 잠긴 탭은 보조기기에도 잠김으로 읽히고 누르면 이유가 글(토스트)로 나온다

## US3 · 자유대화 · 활동 진행과 끝 (LANE 3, 연습도 12 · 17을 함께 씀)

### US3.1 자유대화 시작 — Must · 화면 08 · FR3.1 · FR2.3
**보호자**로서, 아이에 대해 아는 것을 네 칸에 적거나 비워 두고 바로 자유대화를 시작하고 싶다.

수용 기준
- AC3.1.1 Given 08 네 칸 전부 비움 When 「자유대화 시작」 Then 12로 간다(비워도 시작 가능)
- AC3.1.2 Given 08(제목 "오늘 아이와 자유롭게 이야기해요") 일부 입력 When 「자유대화 시작」 Then 네 칸 — "알고 있는 내용"(서술) · "관련 상황"(선택 칩: 친구 · 학교 · 가족 · 학원 · 기타) · "정보 출처"(선택 칩: 직접 봄 · 아이에게 들음) · "궁금한 내용"(서술)(C.S-08.10) — 이 세션 문맥(결과 구조화 입력)으로 저장되고 12로 간다. 칩의 단일/복수 선택은 미정(OQ16)
- AC3.1.3 Given 08 When 두 서술 칸 중 하나가 200자를 넘기면 Then 입력이 막힌다(칩 칸은 해당 없음)
- AC3.1.4 Given 08 요청 전송 중 When 화면 표시 Then 「자유대화 시작」이 꺼진다(중복 시작 방지)
- AC3.1.5 Given 08 When 탭 이동 Then 04 · 18 · 26으로 간다
- AC3.1.6 Given 08 When 시작 요청 Then 서버는 진행 중 세션(REQUESTED · PREPARING · DEVICE_ACK · WAITING_CHILD · ACTIVE · CLOSING 중 하나) 있음 / 기기 안정 아님(불안정 · 끊김 · 응답 없음 · 없음) / 동의 없음이면 각각 SESSION_IN_PROGRESS / DEVICE_NOT_STABLE / CONSENT_MISSING으로 거절하고 08에 해당 사유 문구(문구 미정) 하나만 보인다; 종료 상태(ENDED · ENDED_UNCONFIRMED · ABORTED · DECLINED · FAILED) 세션은 새 시작을 막지 않는다
- AC3.1.7 검증: 목적 선택 칸 · 확인 화면 · 녹음 첨부가 없다. 평가 · 판단을 유도하는 입력란이 없다. 네 칸 원문은 대화 모델에 전달되지 않는다(NFR3)
- AC3.1.8 검증: 시작 요청은 idempotencyKey를 가지며 같은 키 재전송(재시도 · 재연결)은 같은 세션 id · 상태를 돌려주고 새 세션을 만들지 않는다; 다른 키로 2건이 겹치면(두 번 탭 · 두 탭) 세션 1개만 생기고 두 번째는 SESSION_IN_PROGRESS로 거절되며 12는 첫 세션이다. 18의 「선택한 N개로 연습 시작」도 같다(AC4.1.10)
- AC3.1.9 검증: REQUESTED가 시간 계약의 시한(B5) 안에 PREPARING으로 넘어가지 않으면 서버가 FAILED로 닫고 08 · 18로 돌아가 이유를 표시한다

INVEST: 작음 · 시험 가능. 의존: US1.4 · US2.1.

### US3.2 활동 진행 보기 — Must · 화면 12 · FR3.2 · FR7.1 · FR7.8 · FR7.9
**보호자**로서, 아이와 무중의 대화를 실시간 말풍선으로 보고 상태(끊김 · 공백 · 미확인)를 구분해서 알고 싶다. 그래야 끼어들지 않고도 안심할 수 있다.

수용 기준
- AC3.2.1 Given 12 자유대화 · 대화 중 When 화면 표시 Then 머리 "자유대화", 부제 "{아이}가 이야기하고 있어요"(참여 기다리는 중이면 "무중이 {아이}에게 말을 걸고 있어요" — C.S-12.11.2 · 12.2), 경과 "hh:mm 시작 · n분째", 말풍선(아이 전사 + 승인된 AI 말, 말하는 중인 발화는 "… (말하는 중)" 꼬리)이 2초 폴링(A2)으로 갱신된다
- AC3.2.2 Given 12 연습 · 연습 중 When 화면 표시 Then 머리 "연습 · n/N번째 목표 · {목표 이름}"(C.S-12.19.1), 부제 "{아이}가 연습하고 있어요", 현재 단계 표시(방식 · 문구 미정, US4.2)가 보인다
- AC3.2.3 Given 12 WAITING_CHILD(참여 기다리는 중) When 아이가 대답하지 않음 Then US3.5(AC3.5.1)를 따른다
- AC3.2.4 (Should · FR3.5) Given 12 PREPARING(기기 응답 대기) When 서버가 시작 명령을 보낸 뒤 20초 안에 기기 응답 없음 Then FAILED로 닫고 08 · 18로 돌아가 DEVICE_NO_ACK 사유 문구(문구 미정)가 보인다
- AC3.2.5 (Should · FR3.5) Given 12 연습 When 상황 생성이 재생성 포함 2회 실패 Then 18로 돌아가 SCENARIO_GEN_FAILED 사유 문구(문구 미정)가 보인다(목표 여러 개일 때의 처리는 AC4.2.1 · B13)
- AC3.2.6 Given 12 When 자유대화 「이야기 끝내기」 · 연습 「연습 끝내기」(C.S-12.11.5 · 19.7) Then P1(US3.3)
- AC3.2.7 Given 12 When 아이 종료 표현 인식 Then 17(사유: 아이가 끝냄)
- AC3.2.8 Given 12 대화 중 When 공백 4분 Then 경과 줄 "hh:mm 시작 · n분째 · 4분째 말이 없어요" + 안내 "2분 더 말이 없으면 활동이 끝나요" + "아이가 다시 말하면 그대로 이어져요."(C.S-12.51.3~6)가 보이고, 6분이면 자동 종료(SILENCE) → 17(사유: 말이 없어 자동 종료). 공백의 정의와 리셋은 AC3.2.18
- AC3.2.9 Given 12 연습 When 목표 전환 · 마지막 목표 끝 Then US4.2(AC4.2.6)를 따른다
- AC3.2.10 Given 12 When 마지막 기기 메시지 뒤 10초 누락 Then (a) 끊김 진행 중 — 점선과 "대화 연결 복구 중"(문구 미정)이 보인다; (b) 복구 뒤 — 대화 흐름 안에 "hh:mm ~ hh:mm 잠깐 끊김" 구간이 남는다(C.S-12.12.7); 40초 복구 실패 뒤 흐름은 US3.4(AC3.4.1 · 3.4.2)
- AC3.2.11 Given 12 When 보호자 서버의 기기 상태 마지막 수신이 B6의 시간을 넘음 Then "기기 상태 확인 불가"(문구 미정) + 마지막 확인 시각이 보이고 '대화 중단' · '종료' 라벨은 보이지 않는다
- AC3.2.12 Given 12 When 앱만 오프라인 Then "실시간 상태를 불러오지 못하고 있어요"(문구 미정) + 마지막 확인 시각이 보이고, 복구 뒤 실제 기록으로만 갱신되며 임의의 중단 구간이 생기지 않는다
- AC3.2.13 Given 12 진행 중 When 하단 탭을 눌러도 Then 12가 유지된다
- AC3.2.14 Given 12 When 푸시 알림으로 다시 들어옴 Then 최신 상태를 재조회한다
- AC3.2.15 검증: 말풍선에는 출력 게이트를 통과한 AI 말만 올라간다. 실시간 발화 · 자막 · 부모 마이크 · 다음 질문 버튼이 없다. 정상 연결에서 아이 무발화 3분 59초를 주입하면 세션 ACTIVE 유지 · 12 "대화 중" 유지 · 종료 사유 없음 · 푸시 발송 요청 0건이다
- AC3.2.16 Given 12 시작 직후 When 세션이 REQUESTED · PREPARING Then "준비 중"; DEVICE_ACK Then "기기 응답 확인됨"; WAITING_CHILD Then "참여 기다리는 중"이 보인다(라벨은 B8 · 문구 미정, 확정은 Refined Mockups)
- AC3.2.17 검증: 12 폴링 조회 응답은 세션 상태 · 종료 사유 · 종료 확인 여부(confirmed) · 마지막 수신 순번 이후의 전사 조각(since)을 돌려준다. 판정값 · 구조화 결과 · 보호자 입력 원문은 들어가지 않는다(A10)
- AC3.2.18 검증: 공백 = 아이의 마지막 확정 전사 종료 시각(또는 활동 시작 뒤 첫 안내 재생 완료) 이후 아이 발화가 없는 시간. AI 재생 · 게이트 대기 · 장애 구간은 세지 않고 시계를 리셋하지도 않는다. 공백 4분 경고 상태에서 아이 발화 전사가 확정되면 경고가 해제되고 "대화 중"으로 돌아가며 시계가 리셋된다(B9). 경계값 3:59 / 4:01 · 5:59 / 6:01
- AC3.2.19 검증: NFR6의 모든 시간 값은 설정 한 곳(WBS 1.7.6 시간 계약)에서 읽히고 시험 환경에서 오버라이드된다(예: 1/60 축소). 상태 전이 타이머는 가상 시계 또는 이벤트 타임스탬프 주입으로 구동할 수 있다
- AC3.2.20 검증: 말풍선의 발화자(아이 · 무중)는 위치 · 색만 아니라 보조기기가 읽을 수 있는 이름으로 구분되고, 폴링 갱신이 보호자의 초점 · 스크롤 위치를 빼앗지 않으며 새 말풍선은 조용히(aria-live polite 수준) 알린다

INVEST: 가치 큼 · 시험 가능(상태 주입 · 시간 규칙). 의존: US3.1 또는 US4.1 · US6.2.

### US3.3 끝내기 — Must · 화면 P1 · FR3.3 · FR7.1
**보호자**로서, 활동을 끝내고 싶을 때 한 번 확인하고 바로 끝내고 싶다.

수용 기준
- AC3.3.1 Given P1(제목 "정말 끝낼까요?" — C.P-01.13) When 「네, 끝낼게요」 Then 17 마무리 중으로 간다; 응답이 '이미 종료됨'(아이 종료 표현 · 자동 종료와 겹친 경우)이면 17에 실제 사유가 보인다
- AC3.3.2 Given P1 When 「아니오」 Then 12 그대로다
- AC3.3.3 Given P1 「네」 When 서버가 종료 요청을 수락(CLOSING) Then 17 마무리 중 — 머리 "오늘 자유대화를 마무리하고 있어요", 본문 "무중이 마무리 인사를 하고 있어요" + "기기가 멈추면 기록을 정리해요."(C.S-17.73), 「오늘 기록 보기」는 보이되 준비 전 — 가 보이고 기기가 일반 출력을 멈추고 승인된 마무리 인사 1회를 재생하고 멈춘다 — 기기 재생 로그 count=1, 재생 콘텐츠 id = 세션에 고정된 closing 버전, 콘텐츠 길이 ≤ 3초
- AC3.3.4 Given 17 마무리 중 When 기기 멈춤 확인 Then 정리 중으로 넘어간다
- AC3.3.5 Given 17 마무리 중 When 서버가 종료 명령을 보낸 뒤 30초 안에 기기 확인 없음 Then 서버가 ENDED_UNCONFIRMED로 처리하고 17에 "기기 응답 없이 끝냈어요" + "기기가 30초 동안 멈춤을 알리지 않아 끝낸 것으로 처리했어요. 다음 시작 전에 기기 상태를 다시 확인해요."(C.S-17.58)가 보인다(보호자 조작 없음). 경계값 29 / 31초
- AC3.3.6 Given 앱만 오프라인 When 「네, 끝낼게요」 Then "전송하지 못함"(문구 미정)이 보이고 종료 요청됨으로 표시하지 않는다
- AC3.3.7 검증: 종료 확정 뒤 이전 응답이 이어서 재생되지 않는다. 종료와 기록 삭제는 별개다
- AC3.3.8 검증: 종료 요청은 세션 id로 하며 멱등이다 — 「네, 끝낼게요」 2회 · 재시도 · 재연결 · 중복 응답에도 종료 요청 1건 · 기기 종료 명령 1회 · 상태 전이 1회. 이미 CLOSING 이후면 현재 상태를 돌려주고 두 번 처리하지 않는다; 종료 가능 상태(WAITING_CHILD · ACTIVE)가 아니면 거절; 다른 계정 세션이면 404
- AC3.3.9 Given 끝내기 요청 중 토큰 만료(401) Then "전송하지 못함" 표시, 종료 요청됨 표시 없음, 세션 ACTIVE 유지 → 재로그인 → 04 → 12

INVEST: 작음. 의존: US3.2.

### US3.4 예상치 못한 종료 — Should · 화면 P2 · FR3.5 · FR5.7
**보호자**로서, 연결이 끊겨 복구되지 않았을 때 무슨 일인지와 기록이 어디까지 남았는지 알고 싶다.

수용 기준
- AC3.4.1 Given 12 연결 끊김 40초 복구 실패(시계는 B10) When 화면 표시 Then P2 "대화가 예상치 못하게 끝났어요"(C.P-02.14)가 뜬다(연습 세션에서의 제목은 OQ16)
- AC3.4.2 Given P2 When 「확인」 Then 17 — 사유 "연결이 끊겨 끝났어요" + "hh:mm 기기 연결이 끊겨 다시 잇지 못했어요. 끊기기 전까지의 기록은 남아요."(C.S-17.71) — 로 간다
- AC3.4.3 검증: 기기 종료 확인이 없어도 결과 정리는 확보된 기록으로 진행되고 정리 끝 · 「오늘 기록 보기」에 도달할 수 있다. 17 · 27은 '종료 확인: 미확인'을 종료 사유와 따로 표시하고 '종료 확인됨'으로 표시하지 않는다. 앱 연결 장애 · 조회 불가를 아이 종료 · 대화 중단으로 표시하지 않는다

INVEST: 작음. 의존: US3.2 · US6.6.

### US3.5 아이 무응답 — Should · 화면 P3 · FR3.5 · FR5.2
**보호자**로서, 아이가 처음부터 대답하지 않아 시작되지 않았을 때 다그치지 않는 말로 안내받고 싶다.

수용 기준
- AC3.5.1 Given 12 참여 기다리는 중 When 20초 무응답 → 재안내 1회 → 20초 무응답(시계는 AC6.3.3) Then P3 "아이가 대답하지 않아 시작하지 못했어요"(C.P-03.15)가 뜬다(DECLINED, 원문 기록 없음 · 종료 사실과 시각만 남음)
- AC3.5.2 Given P3 When 「확인」 Then 04로 간다
- AC3.5.3 검증: 안내 문구는 아이를 다그치지 않고 재촉 · 만류가 없다(NFR2 체크리스트). 원문은 저장되지 않는다

INVEST: 작음. 의존: US3.2 · US6.3.

### US3.6 활동 끝 — Must · 화면 17 · FR3.4 · FR3.3 · FR7.1
**보호자**로서, 활동이 어떻게 끝났는지 한 줄로 알고 기록이 정리되면 바로 보고 싶다.

수용 기준
- AC3.6.1 Given 끝내기 · 종료 표현 · 자동 종료 · 연결 끊김 When 종료 Then 모두 17로 오고 머리에 활동 종류 + 시간 범위("hh:mm ~ hh:mm · n분" / 연습 "hh:mm ~ hh:mm · 목표 n개" — C.S-17.16.3 · 21.3) + 종료 사유 라벨(AC3.6.9 표)이 보인다
- AC3.6.2 Given 17 When 기기 멈춤 확인 Then 마무리 중 → 정리 중("기록을 정리하고 있어요") → 정리 끝(문구 미정 — 그림 21.4가 정리 중과 같은 글) · 「오늘 기록 보기」
- AC3.6.3 Given 17 정리 끝 When 「오늘 기록 보기」 Then 이 활동의 27로 간다(같은 날 여러 활동이어도 해당 세션)
- AC3.6.4 Given 17 정리 실패(문구 미정) When 「기록에서 다시 시도」(문구 미정) Then 27(정리 다시)
- AC3.6.5 Given 17 When 「홈으로」 Then 04; 하단 「홈」 · 「기록」 Then 언제든 04 · 26(정리는 서버에서 계속)
- AC3.6.6 Given 17 마무리 중 When 하단 「자유대화」 · 「연습」 Then 잠김 · 토스트 「끝나는 중이에요」
- AC3.6.7 Given 17 정리 중 · 정리 끝 When 하단 「자유대화」 · 「연습」 Then 08 · 18
- AC3.6.8 검증: 17에는 결과 · 해석 · 추천 · 판정이 보이지 않는다. 준비 중 기록은 준비 상태로 표시된다

- AC3.6.11 Given 세션 ENDED 뒤 When 전사 이벤트가 늦게 도착 Then 발화 시각 < 종료 시각이면 기록에 추가(타임라인 보완)되고 상태는 ENDED 유지; 발화 시각 ≥ 종료 시각이면 저장되지 않음; 중복 ACK · 늦은 heartbeat는 상태 전이 0회
- AC3.6.12 검증: 17 표시는 세션 상태 × 결과 작업 상태로 정해진다 — 마무리 중 = CLOSING; 정리 중 = (ENDED | ENDED_UNCONFIRMED | ABORTED | FAILED) 이고 결과 작업 REQUESTED · RUNNING; 정리 끝 = READY; 정리 실패 = FAILED(자동 3회 뒤). 종료 확인 미확인(confirmed=false) 표시는 세션 상태에서, 정리 상태는 결과 작업에서 따로 온다

## US4 · 연습 (LANE 4, 진행과 끝은 12 · 17 공통)

### US4.1 내 연습 목표 — Must · 화면 18 · FR4.1
**보호자**로서, 담아 둔 연습 목표에서 오늘 할 것을 여러 개 골라 시작하고, 즐겨찾기와 삭제로 목록을 정리하고 싶다.

수용 기준
- AC4.1.1 Given 18 목표 있음 When 화면 표시 Then 제목 "이번에 살펴볼 목표", 묶음 라벨 "★ 즐겨찾기" · "담은 목표"(★ 묶음이 맨 위, 그 아래 담은 순), 줄마다 메타 "m/d 자유대화에서 담음 · 연습 n회 / 아직 안 함"(C.S-18.17.1~10)이 보인다
- AC4.1.2 Given 18 When 목표 줄 누름 Then 선택 ↔ 해제, 단추 「선택한 N개로 연습 시작」(C.S-18.17.11)의 N 갱신, 0개면 단추 꺼짐(0개 라벨 문구 미정)(18 유지)
- AC4.1.3 Given 18 1개 선택 When 「선택한 N개로 연습 시작」 Then 12(연습); 시작 조건 · 거절 사유는 AC3.1.6과 같다
- AC4.1.4 Given 18 여러 개 선택 When 「선택한 N개로 연습 시작」 Then 서버 수락 시 순서(★ · 담은 순 가중 랜덤, A8)를 확정해 realtime_session_goal.sort_order에 저장하고 12(연습 · 차례로)로 간다; 재조회 결과가 같다(결정성). 분포는 고정 시드 또는 1,000회 표본에서 ★ 목표가 첫 자리인 비율 = A8 가중 비율 ±5%p
- AC4.1.5 Given 18 When 별 「☆/★」 누름 Then 즐겨찾기 토글(맨 위 묶음 · 연습 순서 가중치), 18 유지
- AC4.1.6 Given 18 When 목표 줄 오른쪽 「×」 Then 바로 삭제되고 토스트 「되돌리기」(최소 3초 · 토스트에 초점이 가면 사라지지 않음 — B25); 「되돌리기」 Then 줄 복구
- AC4.1.7 Given 18 비어 있음 When 화면 표시 Then "아직 담은 목표가 없어요" + "이렇게 해 보세요" + "① 자유대화 탭에서 아이와 이야기해요 ② 기록 탭에서 그날 기록을 열어요 ③ "연습 목표" 칸에서 담기를 눌러요" + 「자유대화 하러 가기」 → 08(C.S-18.18)
- AC4.1.8 Given 18 When 탭 이동 Then 04 · 08 · 26
- AC4.1.9 검증: 다른 목표 선택 화면 · 연령 기반 추천 목록이 없다. 즐겨찾기 · 담은 순서가 저장된다. 선택만으로 활동이 시작되지 않는다
- AC4.1.10 Given 18 When 「선택한 N개로 연습 시작」을 서버가 거절(SESSION_IN_PROGRESS · DEVICE_NOT_STABLE · CONSENT_MISSING) Then 18 유지 + 사유 문구(문구 미정) 하나; 전송 중 단추 꺼짐; 시작 요청은 idempotencyKey(AC3.1.8)
- AC4.1.11 검증: 「×」 삭제는 되돌리기 창이 지난 뒤 서버에 반영된다(되돌리기면 전송하지 않음); 반영 실패면 줄이 복구되고 오류 토스트가 뜬다; 「되돌리기」 뒤 is_favorite · sort_order는 보존된다
- AC4.1.12 검증: 진행 중 연습 세션에 들어간 목표를 18에서 「×」 · 즐겨찾기 변경해도 진행 중 세션의 목표 · 순서 · 27의 목표 이름에 영향이 없다(AC4.2.9 스냅숏)
- AC4.1.13 검증: 한 줄의 세 조작(줄 선택 · ★ · ×)은 각각 보조기기 이름이 다르고(예: "삭제 — {목표}"), 터치 영역 44px 이상, 「되돌리기」 토스트는 보조기기에 알림으로 읽힌다

### US4.2 연습 세션 진행 — Must · 화면 12(연습) · FR4.2 · FR4.3 · FR7.5 · FR7.6
**보호자**로서, 고른 목표들을 차례로 연습하는 동안 지금 몇 번째 목표의 어느 단계인지 보고 싶다. **아이**로서, 상황을 듣고 먼저 말해 보고 어려우면 도움을 받고 싶다.

경계: US4.2는 보호자 12(연습) 표시와 서버 저장(세션–목표 고정 · 4단계 분리 저장 · 판정 저장)이고, US6.5는 아이가 듣는 음성 규칙(문구 · Cue 내용 · 반복 · 새 상황 소재)이다.

수용 기준
- AC4.2.1 Given 연습 시작 요청 When 서버 수락 Then 선택 목표와 각 목표의 정의 버전이 세션에 고정되고(realtime_session_goal), 첫 목표의 상황만 생성 → 자동 확인(목표 · 트리거 포함, 금지 표현)을 거친다; 실패 시 1회 재생성, 또 실패면 시작하지 않고 FAILED → 18(SCENARIO_GEN_FAILED). 다음 목표의 상황은 이전 목표가 끝날 때 생성하고, 중간 목표가 2회 실패하면 그 목표를 미실시(사유: 상황 생성 실패)로 기록하고 다음 목표로, 남은 목표가 없으면 마무리로 간다(B13)
- AC4.2.2 Given 12 연습 When 목표 진행 Then 머리 "연습 · n/N번째 목표 · {목표 이름}"과 단계 표시(표시 방식 · 문구 미정)가 세션 조회 응답의 current_practice_stage 값과 폴링 1주기 안에 일치한다 — 단계 6개(상황 제시 · 첫 반응 · 도움 · 도움 후 반응 · 새 상황 · 마무리) 각각 주입. 고정 순서 표시나 부모의 다음 단계 · 건너뛰기 버튼은 없다
- AC4.2.3 Given 상황 제시 뒤 When 아이가 먼저 말함 Then 첫 반응이 기록되고 판정(functional · partial · none · uncertain)이 저장된다; 첫 반응 대기 시간(B15) 안에 발화가 없으면 NOT_PERFORMED
- AC4.2.4 Given 첫 반응 판정이 Cue 제안 조건(none · partial; NOT_PERFORMED는 B14) When 아이가 도움에 동의 Then Cue 제공 사실 · Cue 내용 · 동의 응답 · 도움 후 반응 1회가 분리 저장된다; 거부 또는 동의 질문 무응답(B15)이면 거부로 기록하고 도움 없이 새 상황으로 간다. uncertain은 보류로 기록하고 Cue 없이 새 상황으로 간다(음성 규칙은 AC6.5.3 · 6.5.4)
- AC4.2.5 Given 도움 후 반응(또는 도움 없음) When 다음 단계 Then 새 상황 반응이 첫 반응 · 도움 후 반응과 분리 저장된다(새 상황의 소재 · Cue 금지 규칙은 AC6.5.5)
- AC4.2.6 Given 목표 하나 끝 When 다음 목표 있음 Then 12(다음 목표, n+1/N); 마지막이면 17
- AC4.2.7 검증: 판정 LLM은 5초 예산 + 재시도 1회, 실패면 uncertain; 판정 1건의 최대 지연 상한(≈ 10초 + 왕복)을 시간 계약에 적어 단계 전환 시험의 타임아웃으로 쓴다. 첫 반응 · 도움 · 도움 후 반응 · 새 상황 반응이 분리 저장되고 도움 후 반응이 첫 반응을 덮어쓰지 않는다. 미실시 단계는 null + 사유
- AC4.2.8 검증: 보호자 서버의 상태 미수신 · 앱 조회 불가를 연습 멈춤 · 단계 실패로 바꾸지 않는다. 개별 상황 본문은 보호자에게 미리 보이지 않는다. 판정값은 12 · 17 · 27 어디에도 노출되지 않는다
- AC4.2.9 검증: 세션 시작 시 목표 순서(가중 랜덤 결과)와 각 목표의 정의 버전이 realtime_session_goal에 고정 저장된다. 이후 18의 삭제 · 즐겨찾기 변경은 진행 중 세션의 목표 · 순서 · 27의 목표 이름에 영향이 없다
- AC4.2.10 검증: 시간 계약에 (a) 첫 반응 대기 시간(→ NOT_PERFORMED) (b) 도움 동의 질문 무응답 시간 (c) Cue 생성 5초 예산 초과 시 행동을 넣는다(값은 B15, 확정은 AI 입출력 계약 OQ4)

비고: AC4.2.3의 판정은 Cue 제안 여부를 정하므로 음성 경로에 동기다(최대 5초 + 재시도 1회). 판정 대기 동안 기기가 '생각 중'을 보이고 아이에게 어떤 승인 문구를 들려주는지는 Functional Design · AI 계약(OQ4). 화면 그림 C.S-12.19.5의 무중 말풍선 예시("이렇게 말해 볼까? "…"")는 정답 문장을 그대로 주는 도움이라 FR5.5 · AC6.5.3과 어긋난다 — 스토리는 FR을 따르고 그림은 뒤 단계에서 고친다(B24).

INVEST: 가치 큼 · 시험 가능(합성 아동 발화). 의존: US4.1 · US6.5. 단계 값 목록 · 판정 기준 · 프롬프트는 AI 입출력 계약(Contract Design)에서 확정.

### US4.3 연습 목표 후보 담기 — Must · 화면 27 → 18 · FR4.4 · FR7.4
**보호자**로서, 기록에서 서버가 제안한 연습 목표 후보를 골라 내 연습 목표에 담고 싶다. 그래야 아이에게 맞는 것만 연습한다.

수용 기준
- AC4.3.1 Given 27 연습 목표 칸(머리 "연습 목표 N" — C.S-27.25.5) When 화면 표시 Then 4요소(행동 정의 · 기회 조건 · 상황 생성 조건 · 판정 기준)를 갖춘 후보만 "근거 · {관찰 문장} (hh:mm)"(25.8 · 25.11 · 25.13) 꼴의 근거와 함께 보인다; 없으면 후보 없음(문구 미정). 근거 문장은 전사 · 행동 사실로 쓰고 감정 추론("울먹이며" 류)을 쓰지 않는다(B24)
- AC4.3.2 Given 27 When 「담기」 Then 18 목록에 쌓인다(화면 이동 없음), 단추가 「담김 ✓」으로 바뀐다
- AC4.3.3 Given 27 「담김 ✓」 When 다시 누름 Then 담기 취소 → 「담기」, 18에서도 빠진다
- AC4.3.4 검증: 후보 생성 · 등록은 자동이지만 18에 들어가는 것은 「담기」로만. 추천 근거는 실제 기록에 연결되고, 근거 없는 개인화 이유 · 지원되지 않는 목표가 노출되지 않는다
- AC4.3.5 검증: 같은 후보를 두 번 담아도(빠른 2회 탭 · 취소 뒤 재담기) 18에는 한 줄이다. 18에서 「×」로 지운 뒤 27은 「담기」로 되돌아간다(같은 선택 자원을 가리킴)

INVEST: 작음. 의존: US5.2.

## US5 · 기록과 리포트 (LANE 5)

### US5.1 기록 달력 — Must · 화면 26 · FR6.1
**보호자**로서, 달력에서 활동한 날을 찾아 그날의 활동을 고르고 싶다.

수용 기준
- AC5.1.1 Given 26 When 화면 표시 Then 머리 "yyyy년 m월" · 「상담용 리포트 다운」(C.S-26.22.1~2), 달력에 활동한 날 점이 보인다; 「상담용 리포트 다운」 Then 28
- AC5.1.2 Given 26 When 날 누름 Then 머리 "m월 d일 x요일"과 그날 활동 목록 — "hh:mm  종류 · n분" / "hh:mm  연습 · 목표 n개 · n분" / "… · 중간에 끊김"(C.S-26.22.10~13) — 이 아래에 뜬다; 활동 없는 날이면 「활동이 없어요」 한 줄(26 유지)
- AC5.1.3 Given 26 그날 목록 When 활동 한 줄 누름 Then 27로 간다
- AC5.1.4 Given 26 When ‹ › Then 다른 달로 넘어간다
- AC5.1.5 Given 27 When 「←」 Then 26 보던 날이 유지된다
- AC5.1.6 Given 26 When 탭 이동 Then 04 · 08 · 18
- AC5.1.7 검증: 활동 종류 필터가 없다. 같은 날 여러 세션이 구분된다. 날짜 경계는 Asia/Seoul이다. 26 진입 때 선택되는 날은 미정(OQ16)
- AC5.1.8 검증: 26 · 28 목록에 보이는 세션 — ENDED · ENDED_UNCONFIRMED · ABORTED는 27로 연결; DECLINED는 '시작하지 못함 · 시각' 한 줄(문구 미정)만(27 없음, 그날에도 점은 찍힘 — B19); FAILED와 비종료 상태는 보이지 않는다
- AC5.1.9 Given 26 기록이 하나도 없음 When 화면 표시 Then 빈 상태 안내(문구 미정)가 보이고 「상담용 리포트 다운」은 28 자료 부족으로 이어진다
- AC5.1.10 검증: 달력의 점은 보조기기에 "m월 d일 · 활동 n개"로 읽히고, 날 칸은 44px 이상, 선택한 날은 색 외에 머리 글로도 드러난다

INVEST: 작음. 의존: US3.6.

### US5.2 활동 기록 상세 — Must · 화면 27 · FR6.2 · FR6.3 · FR7.4 · FR7.7 · NFR9
**보호자**로서, 활동 하나의 대화 기록 · 생활 팁 · 연습 목표 후보를 한 화면에서 보고 싶다. 그래야 아이가 무슨 이야기를 했고 집에서 무엇을 해 볼지 안다.

수용 기준
- AC5.2.1 Given 27 When 화면 표시 Then 머리 "← m월 d일 자유대화" · "hh:mm ~ hh:mm · n분"(C.S-27.23.1~2)과 개수 달린 탭 "대화 기록 · 생활 팁 n · 연습 목표 n"(23.3~5)이 보이고, 연습 세션이면 머리 "← m월 d일 연습" · "… · 목표 n개"와 묶음 "18에서 고른 목표"(26.1~3 — 화면 번호가 사용자 글에 들어가 있어 라벨 교정은 OQ16)에 고른 목표 이름만(판정 글 없음) 보인다
- AC5.2.2 Given 27 대화 기록 탭 When 화면 표시 Then 아이 전사 · 승인된 AI 말 인용, 보호자 입력 배경, 보호자 입력/아이 회상 출처 구분이 보이고, 불확실 전사 구간(FR7.3)과 장애로 미확인된 구간(FR5.7, "hh:mm ~ hh:mm 끊김" — 23.9)은 서로 다른 표기로 보인다
- AC5.2.3 Given 27 생활 팁 탭 When 화면 표시 Then 표시된 팁(제목 + 본문 — 24.6~9; 적용 조건 · 한계의 표시 방식 미정)의 목표 행동 태그 · 적용 조건 태그가 세션 결과 태그와 교집합 ≥ 1(서버 매칭 로그로 확인); 교집합 0이면 '추가 관찰 필요'(문구 미정)
- AC5.2.4 Given 27 정리 중(문구 미정) When 화면 표시 Then 정리 중 상태가 보이고 자동으로 갱신된다; 정리 실패(문구 미정)면 「다시 시도」 → 팁 · 목표 다시 정리
- AC5.2.5 Given 27 When 뒤로 Then 26 보던 날 유지
- AC5.2.6 검증: 모든 인용 · 출처 · 미실시가 실제 저장 기록과 일치하고 서버 집계에 없는 수치 · 판단 · 점수 · 성공률이 없다. 미승인 팁 · 검색 점수가 노출되지 않는다. 기록 수신 공백을 아이의 침묵 · 거부 · 실패로 쓰지 않는다. 기술 문제가 있었으면 종료 확인 여부와 확보 범위 · 미확인 구간(문구 미정)이 따로 보인다
- AC5.2.7 검증: 「다시 시도」는 결과 작업이 FAILED일 때만 보인다. 연타 · 중복 요청은 새 작업을 만들지 않는다(한 세션에 동시 작업 1개). 이전 결과 버전과 원본 기록은 보존된다(FR7.7)
- AC5.2.8 검증: 다른 보호자의 세션 id로 27 · 세션 조회 → 404/403. 조회 응답 스키마에 판정값 · 구조화 내부 필드 · 08 네 칸 원문이 없다(A10 · NFR9)
- AC5.2.9 검증: 구조화 결과(FR7.4)에 아이 의도 · 감정 추론 필드 · 문장이 없다(스키마 검사 + NFR1 사전 검사)

INVEST: 가치 큼. 의존: US3.6 · 서버 구조화(FR7.4).

### US5.3 리포트 범위 고르기 — Must · 화면 28 · FR6.4 · NFR8
**보호자**로서, 상담에 가져갈 기간과 활동을 골라 리포트를 만들고 싶다.

수용 기준
- AC5.3.1 Given 28 처음 When 화면 표시 Then 빠른 선택 "최근 2주 · 이번 달 · 전체 · 직접"(C.S-28.27.2~4) 중 「최근 2주」(오늘 포함 14일)가 적용되어 달력에 칠해지고, 요약 줄 "m/d ~ m/d · 활동 n개"(27.13)와 활동 줄 "m/d 종류 · n분"(27.14~16), 단추 N이 갱신된다
- AC5.3.2 Given 28 When 「이번 달」 Then 1일~오늘; 「전체 · 직접」 Then 기록 첫날~오늘이 칠해지고 달력에서 날을 누르면 직접 고르기 시작
- AC5.3.3 Given 28 달력 When 첫 번째 날 누름 Then 그날만 칠해지고 "시작 m/d · 끝나는 날을 누르세요"(75.13), 빠른 선택 해제; 두 번째 날 Then 두 날 사이가 칠해진다(앞뒤 바뀌어도 됨); 세 번째 누름 Then 새로 시작
- AC5.3.4 Given 28 달력 When 드래그 Then 같은 결과, 달을 넘으면 ‹ ›로 이어짐, 미래 날은 못 누름; ‹ › Then 고른 기간 유지 (뒤로 밀 수 있는 AC: 두 번 누르기만으로 시연 가능)
- AC5.3.5 Given 28 활동 목록 When 줄 누름 Then 빠짐 ↔ 들어감, 단추 N 갱신; 진행 중인 활동 · FAILED · DECLINED는 목록에 없다
- AC5.3.6 Given 28 기간 안 활동 0건 When 화면 표시 Then "이 기간엔 활동이 없어요" + "다른 기간을 골라 주세요." + N 없는 「리포트 만들기」 꺼짐(76.14~16)(28 유지)
- AC5.3.7 Given 28 N ≥ 1 When 「활동 N개로 리포트 만들기」 Then 만드는 중 "리포트를 만들고 있어요" + "대화 원문을 날짜순으로 묶고 있어요. 몇 초 걸려요." + 「취소」(54.3~5)(화면 머무름) → 성공 시 리포트 id를 들고 30
- AC5.3.8 Given 28 만드는 중 When 「취소」 · 「←」 Then 보호자 앱이 기다리기를 멈추고 고른 범위 그대로 28; 서버 작업은 끝나도 저장 전 상태로 남아 화면에 나타나지 않으며 A4 규칙으로 폐기된다(B21)
- AC5.3.9 Given 28 만들기 실패 "리포트를 만들지 못했어요" + "잠시 뒤 다시 시도해 주세요. 고른 범위는 그대로예요."(55.3~4) When 「다시 시도」 Then 같은 범위로 만드는 중; 「범위 다시」 Then 28(범위 유지); 「←」 Then 26
- AC5.3.10 Given 28 범위 화면 When 「←」 Then 26(고른 범위 버림)
- AC5.3.11 검증: 날 토글이 없다. 생성은 60초 안에 READY, 실패는 3회 재시도 뒤 FAILED(NFR8); 60초를 넘기면 만들기 실패 화면(타임아웃)
- AC5.3.12 검증: 날짜 경계는 Asia/Seoul. 23:59 세션은 그 날짜에 집계된다
- AC5.3.13 Given 만드는 중 When 「만들기」 재탭 Then 작업 1건(중복 없음)
- AC5.3.14 검증: 기간 칠하기는 색 외에 요약 줄 글로도 드러나고, 미래 날은 보조기기에도 비활성으로 읽히며, 드래그 없이 두 번 누르기만으로 같은 결과가 된다

INVEST: 시험 가능(날짜 · 활동 조합). 의존: US5.1.

### US5.4 PDF 저장 전 확인 · 저장 · 공유 — Must · 화면 30 · FR6.5
**보호자**로서, 만든 리포트의 기간 · 아이 · 건수를 확인한 뒤 PDF로 저장하고 상담사에게 직접 보내고 싶다.

수용 기준
- AC5.4.1 Given 30 확인 When 화면 표시 Then 머리 "← PDF로 저장" · "포함되는 내용을 확인해요", 기간 · 아이 · "대화 원문 · n일 · n줄"(C.S-30.29.5), 안내 "AI 요약이나 평가 없이 대화 원문만 날짜순으로 담아요. 전달은 보호자가 직접 해요."(29.6)가 보인다
- AC5.4.2 Given 30 When 「PDF 저장」 Then 저장했어요 — 파일명 "무중_상담용리포트_{아이}_mmdd-mmdd.pdf"(56.3), 안내 "전달은 보호자가 직접 해요. 앱이 자동으로 보내지 않아요."(56.6) — 와 「공유하기 (문자 · 메일 · 메신저)」 · 「파일 열기」 · 「기록으로」가 보인다
- AC5.4.3 Given 30 저장 완료 When 「공유하기」 Then Web Share API에 PDF 파일을 넘겨 OS 공유 시트가 뜬다(Android Chrome); 지원하지 않는 브라우저에서는 단추를 숨기고 다운로드만 된다(NFR10 · B20). 「파일 열기」 Then 같은 PDF 응답을 새 탭에 띄운다(B20). 둘 다 30 유지
- AC5.4.4 Given 30 When 「기록으로」 Then 26; 저장 뒤 「←」 Then 26
- AC5.4.5 Given 30 저장 전 When 「←」 Then 28(고른 범위 유지 · 만든 리포트 버림); 「나중에」 Then 26(만든 리포트 버림 · 다시 만들려면 28부터 — 라벨과 결과가 어긋나는 점은 OQ16)
- AC5.4.6 Given 30 When 저장 실패 Then 토스트 「다시 시도」(문구 미정), 30 유지
- AC5.4.7 검증: 저장 사실만 이력에 남고 저장을 전달 · 수신 완료로 표시하지 않는다. 서비스 안 전송 · 전문가 계정 · 수신 확인이 없다

INVEST: 작음. 의존: US5.3.

### US5.5 리포트 PDF 내용 — Must · R-PDF · FR6.5 · FR7.3 · NFR1
**보호자**로서, 아이 정보와 날짜별 대화 원문만 담긴 PDF를 받고 싶다. **전문가**로서, AI 해석 없이 원문을 보고 싶다.

수용 기준
- AC5.5.1 Given 리포트 생성 When 서버가 만듦 Then 머리 "무중 대화 기록" · "{아이} · n세 · 관심사" · "yyyy.mm.dd ~ mm.dd · 만든 날 mm.dd"(C.R-PDF.60.1~3) → 날짜별 목차 "n. m월 d일 종류 · hh:mm ~ hh:mm"(60.5~7) → 날짜별 대화 원문(과거 → 최신, 발화자 라벨 "무중" / "{아이}", 연습이면 "(목표 이름)" — 60.8~11) 순서다
- AC5.5.2 Given PDF When 내용 검사 Then 저장된 전사(아이 전사 · 승인된 AI 말)만 있고 AI 요약 · 평가 · 판정값 · 점수가 없으며 "진단 결과가 아님" 문장이 있다 — 문구표 R-PDF(60.x)에는 아직 없음 (문구 미정 · 템플릿 보완 필요)
- AC5.5.3 검증: 금지 표현(NFR1) 검사 대상은 서비스가 생성한 텍스트(머리 · 목차 · 안내 · 라벨 · '진단 결과가 아님' 문장)이며 아이 전사 원문은 대상이 아니다. 다른 보호자의 세션을 포함한 생성 요청은 거절 · 제외된다(PDF에 0건). 한글이 깨지지 않는다
- AC5.5.4 검증: PDF는 글자가 선택 · 검색되는 텍스트 PDF다(이미지 아님)

INVEST: 시험 가능(템플릿 검사). 의존: US5.3.

## US6 · 아이 기기 웹 (LANE 6, /device)

### US6.1 처음 켜기 · 코드 — Must · 화면 D0 · FR2.1
**운영자**(준비) · **보호자**(등록)로서, 아이 기기를 처음 켜면 등록 코드가 보이고 보호자가 입력하면 우리 집 기기가 되길 바란다.

수용 기준
- AC6.1.1 Given /device 첫 실행(미등록) When 화면 표시 Then 안내 "보호자 앱에서 이 코드를 넣어 주세요"와 서버가 발급한 8자리 코드가 4자리 · 4자리로("7F3K · 92QD" 꼴, C.D-00.30.2~3) 크게 보이고 등록 대기 상태다
- AC6.1.2 Given D0 등록 대기 When 보호자가 05a에서 등록을 마침 Then 기기가 등록 상태를 폴링해 「등록되었어요」(3초) 뒤 T19 대기로 간다
- AC6.1.3 (Should · 11/5 시연 비필수) Given 등록된 기기 When 브라우저 데이터 삭제 Then 새 코드가 뜬다(D0); 보호자가 새 코드를 등록하는 순간 옛 Device 행이 RELEASED가 되고 옛 토큰의 WSS 접속이 거부된다(그 전까지 04 · 05는 '응답 없음 · 마지막 hh:mm'). 보호자 쪽 재등록 진입 경로는 Refined Mockups에서 확인(B3 · OQ12)
- AC6.1.4 검증: 운영자 사전 시드 · 고정 ID 없이 서버 발급 코드로만 등록된다. 등록 뒤 기기 토큰이 기기 저장소에 남고 WSS 접속에 쓰인다; 토큰 유효 기간은 두지 않는다(B4)
- AC6.1.5 검증: D0 코드는 새로고침해도 같은 코드가 유지된다(기기 저장소에 bootstrap 식별자 보관). 코드 유효 기간 · 헷갈리는 글자(0/O · 1/I) 제외 여부 · 등록 상태 폴링 주기는 Contract Design(OQ13)

INVEST: 작음. 의존: 없음(US2.2와 양끝).

### US6.2 상태 화면 · 켜기 끄기 — Must · 화면 T19 · FR5.1 · FR7.8
**아이**로서, 「켜기」만 누르면 무중이 들을 준비가 되고, 「끄기」로 끌 수 있길 바란다. **보호자**로서, 기기 화면만 봐도 지금 듣는지 말하는지 알고 싶다.

수용 기준
- AC6.2.1 Given T19 꺼짐 When 「켜기」 Then 마이크 · 소리 허용을 받고 기기 연결(WSS) 뒤 대기가 된다; 화면 켜짐 유지(Wake Lock)
- AC6.2.2 Given T19 When 마이크 · 소리 허용 거부 Then "마이크를 허용해 주세요" + "브라우저 설정에서 마이크와 소리를 켠 뒤 다시 「켜기」를 눌러요." + 「켜기」(C.D-19.57)가 보이고 다시 누를 수 있다(연결하지 않음)
- AC6.2.3 Given T19 대기 When 「끄기」 Then 기기 연결이 끊기고 꺼짐이 된다
- AC6.2.4 Given T19 대기 When 보호자가 활동 시작 Then T19 표시 상태가 `?debug=1` 상태 로그의 마지막 상태와 일치하며 대기 → 듣는 중 → 생각 중 → 말하는 중으로 바뀐다 — 글자 라벨(대기 · 듣는 중 · 생각 중 · 말하는 중 · 마무리 · 연결 끊김, C.D-19.31.2~7)과 캐릭터 표정(31.1 "상태마다 표정이 바뀜")이 함께 바뀐다; 상태 8개(+ 꺼짐 · 마이크 허용 안 됨) 각각 주입
- AC6.2.5 Given T19 활동 중 When 아이 종료 표현 · 보호자 끝내기 · 자동 종료 Then 마무리(승인 인사 재생) → 대기(자동)
- AC6.2.6 Given T19 When 연결 끊김 Then "연결 끊김"과 다시 연결 중 표시(문구 미정)가 보이고 복구되면 대기(또는 진행 중 상태)로 돌아간다
- AC6.2.7 Given T19 When 탭이 뒤로 가거나 화면이 꺼짐 Then 연결 유지를 시도하고 끊기면 다시 연결 중
- AC6.2.8 Given T19 When 브라우저 데이터 삭제 · 다른 기기 · 토큰 거부(RELEASED · 계정 삭제) Then D0(다시 등록)
- AC6.2.9 검증: 클릭 요소는 「켜기」 · 「끄기」뿐이다. `?debug=1`이면 상태 로그가 보인다. 승인된 음성만 재생된다(출력 게이트)
- AC6.2.10 검증: 같은 기기 토큰으로 재연결하면 서버가 그 기기의 진행 중 세션에 다시 붙이고 새 세션을 만들지 않는다; 같은 토큰의 두 번째 동시 연결은 이전 연결을 끊고 대체한다(거부로 할지는 Contract Design OQ13)
- AC6.2.11 Given ACTIVE 세션 중 When 아이가 「끄기」 Then 기기 연결 끊김으로 처리되어 끊김 40초 경로(US6.6 · DISCONNECT)로 간다; 별도 즉시 종료 신호는 없다(B16)
- AC6.2.12 검증: 아이가 끼어들면 재생이 0.5초 이내에 멈추고 재생 위치가 서버에 보고된다(FR7.8 · TS-N04, 11/2 측정 로그로 확인)
- AC6.2.13 검증: 「켜기」 · 「끄기」는 화면에서 가장 큰 터치 영역이고, 상태 전달이 글 읽기에 의존하지 않는다(표정 + 음성). 「끄기」는 캐릭터와 떨어진 자리에 있어 뜻하지 않게 눌리지 않는다(그림 31.8 위치)

INVEST: 시험 가능. 의존: US6.1.

### US6.3 시작 안내와 참여 확인 — Must · (음성) · FR5.2 · FR7.2
**아이**로서, 활동이 시작되면 누구와 무엇을 하는지, 그만하고 싶을 때 뭐라고 말하면 되는지 듣고 내가 할지 말할 수 있길 바란다.

수용 기준
- AC6.3.1 Given 기기 대기 When 보호자가 자유대화 시작 Then 승인된 음성 문구로 AI와 대화한다는 사실 · 오늘 활동 · 기록과 보호자 열람 · "무중아 그만할래" 안내 뒤 참여 의사를 묻는다(예: "안녕, 무중이야. 오늘 나랑 이야기할래?" — C.S-12.11.4)
- AC6.3.2 Given 기기 대기 When 보호자가 연습 시작 Then 자유대화와 다른 승인 문구로 안내하고 참여 의사를 묻는다
- AC6.3.3 Given 참여 질문 재생 완료 보고(playbackMark)를 서버가 받은 시각 When 20초 무응답(전사 없음) Then 승인 문구로 재안내 1회; 재안내 재생 완료 뒤 다시 20초 무응답 Then 시작하지 않고 종료(DECLINED, 원문 기록 없음) → 보호자 P3. 경계값 19초 응답 → ACTIVE / 21초 → 재안내; 2차 19초 → ACTIVE / 21초 → DECLINED
- AC6.3.4 Given 참여 질문 뒤 When 아이가 명시적으로 거부 Then 다른 선택지를 1회 제안하고, 다시 거부하면 마무리(DECLINED)
- AC6.3.5 Given 참여 질문 뒤 When 아이가 특정 주제만 거부 Then 다른 주제를 제안하고 종료로 혼동하지 않는다
- AC6.3.6 Given 참여 질문 뒤 When 아이가 응함 Then ACTIVE가 되고 보호자 12가 "대화 중"으로 바뀐다 — ACTIVE는 참여 응답 확인 시점이며 아이의 첫 발화 자체가 아니다(거부 · 주제 거부 발화는 ACTIVE가 아님)
- AC6.3.7 검증: 쉬기 · 건너뛰기 · 재개 명령은 안내하지 않는다. 무응답 재안내 1회와 거부 시 대안 제안 1회는 각각 1회이며 안내는 합쳐 최대 3번(처음 · 재안내 · 대안)이다(B17). 무응답 · 쉬고 싶다는 말만으로 종료를 확정하지 않는다. 문구 버전은 세션 중 고정된다
- AC6.3.8 Given 무응답 20초 → 재안내 When 명시적 거부 Then 대안 제안 1회 뒤 다시 거부면 DECLINED(B17); 불명확 발화(전사는 있으나 의미 불명)는 무응답이 아니며 참여 질문을 되묻는 것으로 처리하고 재안내 1회에 포함한다
- AC6.3.9 검증: 참여 질문 · 재안내 · 대안 제안 문구는 모두 승인 콘텐츠이고 재촉 · 만류가 아닌 중립 톤이다(NFR2 체크리스트 통과)

INVEST: 시험 가능(합성 아동 발화 · 타이머). 의존: US6.2.

### US6.4 자유대화 · 종료 의도 · 마무리 — Must · (음성) · FR5.3 · FR5.4 · FR7.2 · FR7.3
**아이**로서, 무중이 내 이야기를 하나씩 물어 주고, 엄마가 뭐라고 했는지 아는 척하지 않고, 그만하고 싶다고 하면 바로 인사하고 멈추길 바란다.

담당: AC6.4.1~6.4.3 = D(대화 규칙), AC6.4.4~6.4.6 · 6.4.8 · 6.4.9 = B+D(종료 의도 · 게이트), AC6.4.7 = B · E 공통 저장.

수용 기준
- AC6.4.1 Given 자유대화 시작 · 배경 입력 없음 When 대화 Then 프로필 관심사 · 승인된 일상 질문으로 시작하고 마무리까지 진행된다
- AC6.4.2 Given 자유대화 · 배경 입력 있음 When 대화 Then 보호자 입력을 직접 언급하지 않는다 — 전언 사전(보호자 지칭 "엄마가 · 아빠가 · 부모님이 · 선생님이" + 전언 어미 "그러던데 · 그랬다며 · 들었는데 · 말했는데") 일치 0건이고, 08 네 칸에 넣은 canary 문자열이 기기 출력 · 말풍선에 0건; 아이가 꺼내지 않은 입력 사건 키워드 질문은 세션당 2회 이하
- AC6.4.3 Given 대화 중 When AI 응답 Then 합성 대화 세트(20세션 × 10턴)에서 (a) AI 턴당 질문 1개 이하(의문형 종결 자동 검사 100%) (b) 칭찬 사전 표현이 연속 2턴 이상 0건 (c) 추궁 패턴(같은 질문 3회 반복 · "왜 안" · "진짜야") 0건 (d) 평가자 2인 루브릭 합의 통과율 ≥ 90%; 출력 게이트를 통과한 음성만 재생된다
- AC6.4.4 Given 대화 중 When 아이가 "무중아 그만할래" 또는 저장된 추가 표현 또는 그 밖의 명확한 종료 의도 Then 대기 응답을 취소하고 승인된 마무리 인사 1회를 재생하고 멈춘다(CHILD_STOP)
- AC6.4.5 Given 대화 중 When 종료 의도가 불명확 Then 종료라고 단정하지 않고 짧게 확인한다
- AC6.4.6 Given 대화 중 When 역할 속 대사 · 상대 발화 · 주제 거부 · 기기 재생 음성 Then 종료로 처리하지 않는다
- AC6.4.7 자유대화 · 연습 공통: Given 아이 발화 When 저장 Then GPT-Live 전사와 원음이 세션에 저장되고 불확실 구간은 표시된다
- AC6.4.8 검증: 20회 시험에서 종료 표현 오인식 0 · 미인식 1 이하(합성 세트 · Build and Test 시험 전략 항목). 종료 확정 뒤 이전 응답이 이어서 재생되지 않는다. 대화 역할에 판정 기준 · 보호자 입력 원문 · 이전 판정이 전달되지 않는다(NFR3 · canary · 공급자 요청 allowlist)
- AC6.4.9 검증: 종료 의도 확인 질문(AC6.4.5)은 승인 콘텐츠로 고정하고 NFR2 만류 패턴 검사를 통과한다

INVEST: 가치 큼 · 시험 가능(합성 세트). 의존: US6.3.

### US6.5 연습 음성 흐름 — Must · (음성) · FR5.5 · FR5.6 · FR7.5
**아이**로서, 만들어진 상황을 듣고 먼저 말해 보고, 어려우면 "같이 살펴볼까?" 뒤에 힌트를 받고 다시 말하고, 새 상황에서 또 해 보고 싶다.

경계: 아이가 듣는 음성 규칙. 보호자 표시 · 서버 저장은 US4.2, 전사 · 원음 저장은 AC6.4.7.

수용 기준
- AC6.5.1 Given 연습 시작 When 안내 Then 만들어진 상황임과 AI의 역할을 음성으로 알리고 상황과 상대 역할의 말을 들려 준다; 기회 트리거는 승인 대본으로 출력된다
- AC6.5.2 Given 기회 트리거 뒤 When 아이가 먼저 말하기 전 Then 힌트 · 정답 · 시범(Cue)이 나가지 않는다; 같은 말 반복 · 속도 조절은 요청하면 해 준다
- AC6.5.3 Given 첫 반응 판정이 Cue 제안 조건(AC4.2.4) When Then "같이 살펴볼까?"로 동의를 구하고, 동의하면 상대의 말을 다시 짚어주는 단서를 실시간으로 만들어 준다(5초 예산); Cue 텍스트에 판정 기준의 기대 발화 예와 5어절 이상 연속 일치 0건 + 평가자 확인(정답 문장 없음 — 그림 C.S-12.19.5의 예시 대사는 B24); 거부하면 이어가지 않는다
- AC6.5.4 Given Cue 뒤 When 아이가 다시 말함 Then 도움 후 반응은 1회만 받는다(기록은 AC4.2.4)
- AC6.5.5 Given 새 상황 When 제시 Then 소재만 다르고 목표 행동 · 상대 관계 · 기회 조건은 같으며 추가 도움이 없다; 같은 활동 안에서 같은 상황은 재사용되지 않는다
- AC6.5.6 Given 마지막 목표 끝 When 마무리 Then 승인 목록의 마무리 음성이 1회만 재생된다
- AC6.5.7 검증: 단서를 추가하지 않은 반복 · 속도 조절은 Cue로 집계되지 않고, 목표 단서가 추가된 설명은 도움으로 기록된다(FR5.6). 제공한 도움 내용과 동의 응답이 기록된다
- AC6.5.8 (Should · FR7.5) 검증: 아이별 노출 이력을 보관하고 새 활동에서 이전 활동에 노출된 상황이 선택되지 않는다(이력 주입 시험)

INVEST: 시험 가능(합성 세트). 의존: US6.3 · US4.2.

### US6.6 연결 끊김 대응 — Should · (음성) · T19 · FR5.7 · FR7.9 · FR7.1
**아이**로서, 잠깐 연결이 끊겨도 돌아오면 아까 하던 이야기를 이어가고, 안 되면 조용히 끝나길 바란다. **보호자**로서, 그 사이 무슨 일이 있었는지 미확인으로 남는 걸 알고 싶다.

수용 기준
- AC6.6.1 Given 활동 중 When 기기 연결 또는 음성 모델 연결 장애 확인(마지막 기기 메시지 뒤 10초 누락 또는 WS close) Then 기술적 일시 정지가 기록되고 보호자 12에 "대화 연결 복구 중" + 점선, 기기는 다시 연결 중
- AC6.6.2 Given 장애 중 When 마지막 기기 메시지 수신 시각 기준 40초 안에 복구 · 종료 요청 없음 · 복원 가능(기기 WSS만 끊기고 음성 모델 연결과 세션 맥락이 살아 있음 — B18) Then 재개하고 이전 응답 · Cue를 다시 재생하지 않는다
- AC6.6.3 Given 장애 중 When 40초 안에 복구되지 않음, 또는 음성 모델 연결이 끊김(B18) Then 기술 종료(DISCONNECT) → 보호자 P2 → 17, 끊기기 전 기록 보존
- AC6.6.4 Given 복구 뒤 When 기록 보완 Then 확보 기록으로만 타임라인을 채우고 증거 없는 구간은 미확인으로 남긴다
- AC6.6.5 Given 정상 연결 When 아이가 4분 말이 없음(공백 정의 AC3.2.18) Then 공백 경고(보호자 12 표시; 기기 안내 1회 여부는 OQ9 확정 뒤, 하더라도 재촉이 아닌 승인 문구), 6분이면 SILENCE 자동 종료 → 마무리 → 대기
- AC6.6.6 검증: 앱만 오프라인 · 보호자 서버 상태 미수신 · 음성 장애 시간을 공백으로 합산하지 않는다. 종료 요청 중 · 종료된 세션은 복구만으로 재개되지 않는다
- AC6.6.7 Given CLOSING 중 끊김 Then 마무리 확인 30초 → ENDED_UNCONFIRMED가 우선하고 끊김 40초의 DISCONNECT 전이는 없다; 복구돼도 재개하지 않는다(B11)
- AC6.6.8 Given DISCONNECT 확정(ABORTED) 뒤 When 늦은 heartbeat · 복구 이벤트 도착(역전) Then ABORTED 유지, 새 세션 없음, 기기는 대기로(NFR4)
- AC6.6.9 검증: 경계값 — 39초 복구 → 재개 · 이전 응답 · Cue 재재생 0건; 41초 → ABORTED. 끊김 시계는 하나(마지막 기기 메시지 수신 시각)이고 FR2.2의 40초와 같은 시계다(B10)

INVEST: 시험 가능(장애 주입). 의존: US6.4 · US3.2.

## 의존 관계 요약

- 처음 한 번: US1.1 → US1.2 → US1.3 → US1.4(허브). US1.5 · US1.6 · US1.7은 US1.4에서 갈라진다.
- 기기: US6.1(기기 쪽) ↔ US2.2(보호자 쪽)가 양끝. US2.1은 US6.2의 heartbeat에 의존.
- 활동: US3.1/US4.1 → US3.2(12 공통) → US3.3/US3.4/US3.5 → US3.6(17 공통). 음성 쪽 US6.3 → US6.4/US6.5가 같은 세션을 움직인다.
- 결과: US3.6 → US5.1 → US5.2 → US4.3(담기) → US4.1(목표 있음). US5.2 → US5.3 → US5.4 → US5.5.
- 시연 Must 네 경로 = US1.1~US1.4 + US2.1 · US2.2 + US6.1 · US6.2 (처음 한 번) / US3.1 · US3.2 · US3.3 · US3.6 + US6.3 · US6.4 + US5.2 · US4.3 (자유대화 1회) / US4.1 · US4.2 + US6.5 + US5.2 (연습 1회) / US5.1 · US5.3 · US5.4 · US5.5 (기록 · 리포트).
- "연습 1회" 경로는 US4.1 → US4.3 → US5.2 → US3.6(결과 파이프라인 · D 담당)에 묶여 있다. D의 결과 생성이 늦어도 C의 연습 화면을 시험 · 시연할 수 있게 데모 시드(A6)에 담긴 연습 목표 선택 2~3개를 포함한다(B22).

## INVEST 점검

- **Independent**: 화면 카드 하나가 스토리 하나라 각자 시험할 수 있다. 12 · 17 공통 화면은 자유대화 · 연습 두 스토리가 같은 화면을 쓰지만 수용 기준이 겹치지 않게 나눴다(US3.2는 공통 상태, US4.2는 연습 단계 · 저장, US6.5는 아이가 듣는 것). 같은 내용은 한 곳에만 적고 가리킨다.
- **Negotiable**: 수용 기준은 분기표와 문구표를 옮긴 것이라 화면 설계가 바뀌면 같은 줄을 고친다. "(문구 미정)" 약 25곳은 Refined Mockups에서 채운다. 검토에서 정한 가정(B1~B26)은 뒤 단계에서 바꿀 수 있다.
- **Valuable**: 모든 스토리에 보호자 또는 아이의 "그래야 ~"가 있다. 서버 기능(FR7)은 별도 스토리가 아니라 그것이 드러나는 스토리의 "검증:" 줄에 들어 있다.
- **Estimable · Small**: 가장 큰 US3.2(20 AC) · US1.4(15 AC) · US5.3(14 AC) · US2.1(14 AC)도 화면 1장 범위다. Should 기원 AC에는 표를 달았다. 음성 스토리 US6.4 · US6.5와 연습 저장 US4.2는 AI 계약(Contract Design)이 정해져야 추정이 끝난다.
- **Testable**: 모든 AC가 Given/When/Then 또는 "검증:" 한 줄이고, 시간 규칙은 NFR6의 값과 시계 시작점(t0)을 적어 주입 시험한다(AC3.2.19). 접근성 검증 줄(AC1.4.15 · AC2.1.14 · AC3.2.20 · AC4.1.13 · AC5.1.10 · AC5.3.14 · AC6.2.13)은 색만으로 구분하지 않는 화면 설계 원칙을 시험으로 고정한다.
