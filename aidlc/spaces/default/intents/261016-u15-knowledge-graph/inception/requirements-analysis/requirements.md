# U15 지식 그래프 요구사항

## Intent analysis

U15 지식 그래프(u15-knowledge-graph) 구현. 지시 docs/units/u15/brief.md를 정본으로 한다. 인셉션 산출물은 261015-doc-sync-code-update 기록의 것을 그대로 쓴다.

기존 공개 행동 지식 조회를 유지하면서 아동별 화용 구조 맥락을 제공한다. 그래프 장애로 기존 core 기능을 막지 않고, 아동 간 자료 혼합과 삭제 자료의 부활을 막는다. 새 업무 요구사항을 만들지 않으며 아래 원 ID는 261015-doc-sync-code-update 기록을 가리킨다. 사용자는 requirements-analysis-questions.md의 통합 요약을 확인했다.

## Functional requirements

### FR1 아동별 그래프와 포트 — 원 FR9.1, FR9.7, C-DS11

- FR1.1 아동 등록 시 그래프를 초기화하고 실패하면 첫 조회에서 재시도한다. 같은 아동 초기화를 반복해도 씨앗이 중복되지 않는다.
- FR1.2 seedSummaries, skillContext, variantPlan, writeGeneratedSeed, deleteChild 및 필요한 초기화·생성 씨앗 삭제 API에 childId를 필수로 둔다. 다른 아동의 같은 seedId를 조회·수정·삭제할 수 없어야 한다. 호출 경계에서 보호자 소유권을 확인한다.
- FR1.3 기존 findRelatedBehaviorKeys는 공개 행동 카탈로그 전용으로 유지한다. PragmaticsKnowledge의 기존 쓰임과 U5a 시험을 보존한다.
- FR1.4 Neo4j 구현과 같은 원천을 쓰는 메모리 대역을 제공한다. 기본 꺼짐 모드와 씨앗이 채워진 개발·시험 모드는 구분한다.
- FR1.5 U15 서비스 경계는 아동별 조회·생성 시작 전에 소유권·동의·삭제 상태를 확인한다. 동의 철회 뒤에는 해당 아동의 자료나 씨앗을 AI 입력으로 반환하지 않는다. 외부 생성 응답 뒤 저장 직전에 상태를 다시 확인하여 철회 전 요청의 늦은 완료 및 철회 후 재요청이 새 씨앗을 저장하지 못하게 한다(원 AC5.2.4). 확인 불가능 시에도 허용하지 않는다.

### FR2 기본 씨앗과 버전 — 원 FR9.2

- FR2.1 social-comm-poc.zip의 지정 자료에서 기본 씨앗 14개(S1~S10, X1~X4)와 어휘를 적재한다. 원본 ZIP을 수정하지 않고 외부 말뭉치·평가셋·없는 graph_out은 사용하지 않는다.
- FR2.2 아동별 기본 씨앗 복사와 생성 씨앗을 분리한다. 기본 씨앗 판 갱신은 같은 ID의 POC 씨앗을 갱신하고 GENERATED 씨앗을 보존한다. 사용 중단은 enabled=false로 처리한다.
- FR2.3 적재 버전과 출처를 기록한다. 누락·중복·허용 밖 값·손상 파일은 명확히 실패하고 완료 버전을 남기지 않는다. ZIP 경로 탈출을 허용하지 않고 중복 루트의 동일 자료를 두 번 적재하지 않는다.
- FR2.4 core V8에 generated_seed와 그래프 버전 표를 추가한다. 기존 마이그레이션은 바꾸지 않는다. 그래프 재구성은 아동 목록·기본 씨앗과 PostgreSQL 생성 씨앗으로 재현 가능해야 한다.
- FR2.5 seedSummaries와 새 씨앗 생성의 seed_catalog에는 enabled=true인 씨앗만 포함한다. 비활성 씨앗은 ID와 과거 참조를 보존하되 새 생성 입력 목록에서 제외한다.

### FR3 구조 맥락과 변형 계획 — 원 FR9.1, FR9.6, C-DS11

- FR3.1 구조 서명 5필드, 불변 문장, 보존 조건, 아동용 기본 관계·자리와 허용 목록을 반환한다. 생성 씨앗은 씨앗 자체의 보존 조건을 쓴다.
- FR3.2 변형 계획은 한 요소만 바꾼다. 기본 SAME_CONTEXT는 화제·장소·등장인물 중 하나이며 같은 씨앗·관계·자리 3회 노출부터 NEAR로 관계 또는 자리 하나를 바꾼다. FAR는 사용하지 않는다. 최근 노출과 겹치지 않는 선택을 우선하며 선택 순서를 결정적으로 정한다.
- FR3.3 LOW·recoverable=true를 유지하고 관계·자리는 기술명세서 §6.4의 아동용 허용 값만 사용한다. 실제 장면 보존 판정과 노출 자료 연결은 U10 책임이며 U15는 입력 계약과 규칙을 제공한다.

### FR4 생성 씨앗 — 원 FR8.3, C-DS7

- FR4.1 자유대화의 NONE 후보에 대한 생성·검사 서비스를 제공한다. 활동당 생성 상한 2개, 후보별 중복 실행 방지, 연습 활동 미생성을 보장한다. 결과 작업에서 호출하고 후보에 반환된 skillRef를 연결하는 작업은 U14가 맡는다.
- FR4.2 CoreLunaClient의 SEED_GENERATION과 계약 스키마를 사용한다. 전사 인용을 제외한 최소 구조화 입력만 보내며 원문 비교용 자료는 서버 검사에만 사용한다. 스키마 확장과 프롬프트 판을 함께 관리한다.
- FR4.3 허용 값, 개인정보·고유명사·날짜, 활동 전사·배경 정보와 연속 5글자 이상 겹침, 금지 표현, 중복, 불변 문장 한 문장·60자 이내를 검사한다. 4/5글자와 60/61자 경계를 시험한다. 정규화와 글자 단위는 설계에서 명시한다.
- FR4.4 duplicate_of는 해당 아동의 조회된 목록에 있는 ID만 허용한다. 유효한 중복은 새 노드 없이 기존 ID를 반환하고 none_reason은 NONE으로 남긴다. 목록 조회 실패 시 중복 확인이 불가능하므로 생성하지 않는다.
- FR4.5 내용 검사 실패는 최대 1회 재생성한다. U9 기술·스키마 재시도와 같은 요청 예산을 공유해 재시도가 곱해지지 않게 한다. 시한 만료·키 없음·최종 실패는 NONE을 반환하며 result_status를 변경하지 않는다.
- FR4.6 생성 씨앗의 출처·검사 결과·모델·프롬프트 판은 PostgreSQL에 저장한다. Neo4j 쓰기에 실패하면 성공한 generated_seed로 남기지 않는다. 부분 실패·중복 요청·늦은 응답을 복구 가능하게 설계한다.
- FR4.7 씨앗 생성만 독립적으로 끌 수 있어야 한다. 이 설정이 꺼지면 그래프 조회는 유지하되 외부 생성 호출과 생성 씨앗 쓰기는 발생하지 않는다. 설정 키·기본값은 기술명세서 §13과 대조하여 설계에 명시한다.

### FR5 개인정보와 삭제 — 원 FR9.3, FR9.4

- FR5.1 그래프에는 아동 범위 식별자와 검증된 씨앗 구조 필드만 저장한다. 전사·보호자 입력 원문, 세션·후보 출처는 저장하지 않는다. 생성 씨앗은 다른 아동 및 공통 기본 씨앗으로 전파하지 않는다.
- FR5.2 아동·계정 삭제는 해당 아동 그래프와 생성 씨앗을 삭제하고 공통 기본 씨앗·어휘는 보존한다. 기록 삭제는 그 기록에서 만들어진 생성 씨앗만 삭제한다(기술명세서 §6.5). 다른 기록·아동의 데이터는 보존한다.
- FR5.3 삭제를 기존 DeletionParticipant 체계에 연결한다. 삭제가 실패하면 RETRY/기존 실패 재시도로 전달하며 빈 조회 결과로 삼키지 않는다. 반복 삭제는 멱등이어야 한다.
- FR5.4 생성과 삭제가 경쟁하면 삭제가 완료된 뒤 생성 결과가 되살아나지 않아야 한다. 삭제된 씨앗을 참조하는 목표는 NONE으로 처리할 수 있도록 U14와 경계를 명시한다.
- FR5.5 그래프가 꺼져 있고 해당 환경에서 아동 그래프를 만든 적이 없음을 확인할 수 있으면 삭제 참여자는 NOT_APPLICABLE로 종료한다. 이전 생성 이력이 있거나 잔존 여부를 확인할 수 없으면 완료로 표시하지 않고 RETRY로 남긴다(원 AC5.2.3). 생성 이력 보존 위치와 확인 방식은 설계에서 정하며, 꺼짐 설정만으로 기존 데이터가 없다고 추정하지 않는다.

### FR6 장애 시 기본 경로 — 원 FR9.5

- FR6.1 그래프 꺼짐·조회 장애·graph-budget 2초 초과·skillRef NONE은 빈 목록/맥락/계획을 반환한다. 이 응답을 개인화 완료로 표시하지 않는다.
- FR6.2 기동에 실제 AI 키를 요구하지 않는다. Neo4j가 끊겨도 기존 core 기본 경로는 사용 가능해야 하며 복구 후 새 조회는 회복한다. 타임아웃 후 늦은 작업이 결과를 덮어쓰지 않아야 한다.

## Non-functional requirements

- NFR1 지연: 기존 mujoong.timing.knowledge.graph-budget(2초)을 전체 조회 경계에 적용한다. 새 시간 값은 계약 규칙대로 관리하며 AI 생성 시한과 그래프 조회 시한을 혼동하지 않는다.
- NFR2 보안: 모든 아동 자료 경계는 childId로 격리하고 Cypher 파라미터를 사용한다. 비밀은 기존 NEO4J_AUTH·OPENAI_API_KEY 이름만 사용하며 값·요청/응답 원문은 로그나 저장소에 남기지 않는다.
- NFR3 무결성: 기본 적재·초기화·생성·삭제의 반복과 동시 실행을 시험한다. DB와 그래프의 부분 성공을 최종 성공으로 오인하지 않으며 실패 복구 순서를 설계에 명시한다.
- NFR4 검증: u15 태그, backend/coverage-scope/u15.txt 줄 80% 이상, 관련 단위·DB/Neo4j 통합·U2/U5a/U6/U9 회귀·ArchUnit·계약 대조를 통과한다. 전체 scripts/verify.sh를 Build and Test에서 한 번 실행한다. 기존 단언과 커버리지 하한을 낮추지 않는다.
- NFR5 증거: 메모리 대역, Neo4j Testcontainers, 개발 인스턴스, 실호출·실기기 증거를 구별한다. 자동 시험은 가짜 AI만 사용한다. 실제 모델의 개인정보 탐지·분류 품질을 대역 시험으로 입증했다고 주장하지 않는다.
- NFR6 유지보수: U15 설계와 보고서를 docs/units/u15에 남기고 요구사항→설계→시험을 추적한다. 네 구현 묶음(V8/포트/메모리, Neo4j/적재, 생성/검사, 삭제/기본 경로) 순서로 검증·커밋한다.

## Constraints

- core-api 중심 변경이며 realtime-activity와 프런트 구현은 범위 밖이다. 계약에 닿는 변경은 contracts와 함께 반영한다.
- 기존 코드는 main 7e30ee8에서 분기한 unit/u15-knowledge-graph 기준이다. 기존 core 시험 1299개가 통과한 기준선을 보존한다.
- 저장소의 Java 21, JsonCodec 단일 JSON 경계, MujoongClock, EventLog와 삭제 순서를 따른다.
- 사용자 수동 Docker 스택은 변경하지 않는다. 새 검증은 별도 프로젝트·포트·볼륨을 사용한다.
- 배포·main 병합은 이번 push 요청에 포함하지 않는다.

## Assumptions

- U8 스키마는 최소 출력 계약이다. 200자 허용은 업무상 60자 검사와 모순되지 않는다. 필드 추가와 실패/중복 분기는 Functional Design에서 완성한다.
- 생성 씨앗 원장과 출처는 PostgreSQL이며 그래프에는 검증된 투영만 둔다. 결과 삭제보다 뒤의 참가자 순서와 출처 FK 충돌을 설계에서 해결한다.
- 기존 공개 행동키 메서드는 childId가 없는 공개 카탈로그 예외다. 새 아동 질의에 이 예외를 확장하지 않는다.
- DeletionCompleted.counts는 realtime 완료 응답이므로 core 그래프 삭제 때문에 확장하지 않는다. 실제 코드 대조에서 달라지면 편차를 명시한다.
- 원본 ZIP 머리말은 X1~X3이라 쓰지만 실제 두 seeds 배열은 X4까지 14개로 일치한다. 적재 검증은 실제 배열을 따른다.

## Out of scope

U14 목표 후보 생성·결과 파이프라인 호출 연결, U10 실제 상황 생성과 변형 보존 판정, realtime/프런트 변경, 운영 배포, 외부 말뭉치 추가, 실제 아동 데이터 외부 전송, 실모델 품질 및 실기기 성공 보장.

## Open questions

업무상 추가 질문은 없다. DB/Neo4j 보상·재구성 순서, 개인정보 검사의 구체적 보수적 정책, 생성 시한 공유 API, 문자 정규화, 삭제된 참조와 U14 연결은 Functional Design에서 실제 코드에 근거해 결정한다. 정본과 충돌하는 결정은 편차로 남긴다.
