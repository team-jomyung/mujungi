# U10 보안 검증 지침

## Scope

R-F1~15·R-M1~11, NFR3·NFR6과 승인된 개인정보 경계를 지킨다. 실제 비밀·아동 자료·유료 API는 사용하지 않는다. 새로운 비밀 이름이나 취약점 예외를 만들지 않는다.

## Checks

전체 verify.sh의 비밀 검사 A4, 역할/스키마 격리 P1, 로그 위생 P2, 비밀 값 P3, 작업 트리 불변 T를 실행한다. 같은 전체 명령을 이 파일 때문에 중복 실행하지 않는다. u10/전체 Core 시험의 소유권·동의 철회·삭제·이름 치환·공급자 최소 입력·로그 금지 대조를 확인한다.

추가 정적·인프라 검증은 저장소 루트에서 아래 명령으로 수행한다.

```sh
bash infra/bin/infra-validate
bash infra/ci/test-infra-validate.sh
```

PR의 필수 GitHub CI에서 backend/frontend 의존성, 비밀 스캔, 이미지 검사와 관문 음성 대조 결과를 확인한다. 이들은 로컬 명령으로 실행하지 않았으면 CI 완료 전까지 미검증이다. CI 실패를 승인되지 않은 예외나 하한 완화로 숨기지 않는다.

## Evidence

종료 코드와 각 관문 결과, 적용한 예외의 기존 승인 여부를 기록한다. 로그에는 고정 이유 코드·시간·개수만 담고 요청 본문이나 키를 노출하지 않는다. 실제 공급자 약관·동의 검토와 실기기 검증은 수행했다고 주장하지 않는다.
