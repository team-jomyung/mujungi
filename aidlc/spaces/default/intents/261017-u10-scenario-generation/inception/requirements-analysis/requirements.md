# U10 상황 생성 요구사항

## Intent analysis

보호자가 담은 목표로 연습을 시작할 때, 목표와 맞는 장면을 만들고 생성과 분리한 자체 검토 및 서버 검사까지 통과한 대본만 발급한다. 기존 U5b 소비자는 기존 필수 응답을 계속 읽고, U12는 선택 필드로 새 장면을 받을 수 있어야 한다. 새 업무 요구사항을 추가하지 않고 정본의 U10·B7·원 FR2·FR9.5·FR9.6·US3.1을 구현 단위로 다시 묶는다.

기준은 `docs/units/u10/brief.md` 및 원 기록 `aidlc/spaces/default/intents/261015-doc-sync-code-update/`다. 기존 코드 분석의 `business-overview.md`, `architecture.md`, `code-structure.md`는 `aidlc/spaces/default/codekb/mujungi/`에서 읽었다. 특히 새 목표 준비 입구, 첫 대본 전달, 재시도와 그래프 조회의 현재 경계를 반영한다.

## Functional requirements

아래 요구사항은 모두 U10 완료에 필요한 Must다. 대괄호는 시험 증거 종류이며, `[자동-대역]`이 모델의 실제 판단 품질까지 보증하지 않는다.

### FR1 생성과 분리한 자체 검토

- **FR1.1** 그래프 맥락을 선택적으로 조회한 뒤 `SCENARIO_GENERATION`으로 대본을 생성하고, 그 결과에 대해 다른 요청의 `SCENARIO_REVIEW`를 수행한다. 생성 응답 속 자기 승인 문구는 승인 증거가 아니다. 생성·검토의 스키마를 각각 적용한다. 출처: 원 FR2.1, AC3.1.1·AC3.1.7, C-DS5.
- **FR1.2** `APPROVE`만 승인 후보로 취급한다. `REJECT`, `UNCERTAIN`, 응답 누락, 스키마 불일치, 시간 초과는 승인으로 취급하지 않는다. 검토 사유는 최종 확정할 허용 enum만 받으며 J7의 `ANSWER_INCLUDED`, `EARLY_CUE`, `PRESSURE`를 포함한다. 출처: 원 FR2.2, AC3.1.2.
- **FR1.3** 기존 나이 입력을 유지해 생성과 자체 검토에 전달한다. 자체 검토는 목표와의 일치뿐 아니라 나이에 맞는 상황·언어 난도, 이전에 노출된 상황과의 의미상 반복을 검사한다. 검토 입력의 이전 상황은 필요한 최소 범위만 사용하며 개인정보를 제거한다. `AGE_MISMATCH`·`REPETITION` 반려도 승인으로 취급하지 않는다. 출처: 원 US3.1·AC3.1.9, ai-io.md 7절, 기존 검토 스키마.
- **인수 기준** `[자동-대역]`: 정상 대본에는 생성과 별도 검토 요청이 각각 존재한다. 실패 종류별 대본은 ISSUED·EXPOSED가 되지 않고 HTTP/시작 패키지에 포함되지 않는다. 동일 생성 응답에 `APPROVE`라는 문자열이 있어도 별도 검토 없이 통과하지 않는다.
- **추가 인수 기준** `[자동-대역]`: 나이와 최소한의 이전 상황이 정리된 생성·검토 입력에 전달되고, `AGE_MISMATCH` 또는 `REPETITION`으로 반려된 대본은 발급되지 않는다. `[실호출-합성]`: 실제 나이별 언어 난도와 의미상 반복 판단의 품질은 합성 자료로 별도 관측한다. 대역 시험 통과를 그 판단 품질의 검증으로 표시하지 않는다.

### FR2 서버 독립 검사와 재생성

- **FR2.1** 자체 검토가 APPROVE여도 서버는 스키마, 필수 장면·필드, 목표·기회·관계 일치, 금지 표현, 중복 지문을 독립 검사한다. 모델이 준 validation 플래그를 신뢰하지 않는다. 판·필드 길이 및 기존 권한 검사를 유지한다. 출처: 원 FR2.1·FR2.2, AC3.1.3·AC3.1.7·AC3.1.9.
- **FR2.2** 내용 실패와 스키마 불일치를 포함한 재생성은 허용 횟수 안에서만 수행한다. 재생성 결과에도 별도 자체 검토와 서버 검사를 적용한다. 기술 재시도와 내용 재생성을 중첩해 횟수를 늘리지 않는다. 끝내 승인 가능한 대본이 없으면 기존 `SCENARIO_GEN_FAILED`로 끝내며 새 오류 코드를 만들지 않는다. 출처: 원 FR2.3, AC3.1.4, 지시서의 REQUEST_BOUNDED.
- **FR2.3** 실패·취소·마감 후 도착한 결과는 발급하지 않는다. 기존 요청 선점, READY 재사용, 아이별 내용 지문과 저장 경합 처리를 유지한다. 발급 직전에 세션·소유자·동의·삭제 상태와 선점 유효성을 다시 확인한다. 출처: AC3.1.5·AC3.1.9, 기존 ScenarioService 경계.
- **인수 기준** `[자동-대역]`: APPROVE+금지 표현/중복/목표 불일치는 실패한다. 반려→재생성→정상은 승인 대본 하나만 저장한다. 두 내용 시도가 실패하면 발급 0건이며, 늦은 응답·동의 철회·중복 동시 요청에도 승인되지 않은 저장이 없다.

### FR3 새 대본과 레거시 응답

- **FR3.1** `practice-scenario.schema.json`에 `scriptVersion`, `scenes`, `selfReview`, `generation`을 선택 필드로 더하고 `additionalProperties: true`를 유지한다. 장면 설명, 기회 문장, 상황 다시 설명, 집중 연습 요점, 표현 예시, BASE/VARIANT 구분과 장면별 관계·자리·화제를 표현한다. 출처: 원 FR2.4, AC3.1.6, C-DS1.
- **FR3.2** 기존 필수 응답 필드는 첫 BASE 장면에서 서버가 만든다. 상대 역할 지시는 모델에 받지 않고 Core가 고정한다. 기존 U5b 내부 HTTP 응답 및 준비 패키지의 기존 필수 필드를 유지하며 새 선택 필드가 첫 대본 전달 중 유실되지 않게 한다. 출처: B7, Contract Design R-04, 코드 분석의 PreparedPracticePackageMapper.
- **FR3.3** core `V10__u10_scenario_generation.sql`로 새 필드를 영속화하고 다시 읽을 수 있게 한다. 기존 V1~V9 내용은 변경하지 않는다. 기존 행과 구버전 쓰기는 계속 유효해야 한다. 새 제약이 구버전 호환을 제한하면 별도 근거·리뷰 절차를 따른다. 출처: 지시서, R-M2·R-M3.
- **인수 기준** `[자동-대역]`: 선택 필드 없는 기존 응답과 새 응답이 계약을 만족한다. 첫 BASE의 고정 필드와 레거시 값이 일치한다. 재조회에서 장면·판·승인 메타데이터가 유지되며 V9 자료 보존·구버전 쓰기가 통과한다.

### FR4 U14 담은 목표와 실제 연습 시작 연결

- **FR4.1** 아동과 선택 ID에 해당하는 U14 `SavedGoalReader`의 고정 버전을 읽고, 목표 표현·4요소(situation/partner/intent/expression)·skillRef를 생성 입력에 사용한다. 후보 최신 버전으로 바뀌어도 담은 당시 목표는 바뀌지 않는다. 출처: 원 AC4.6.2, C-DS10, 지시서.
- **FR4.2** 새 CANDIDATE 목표가 기존 행동 키 기반 준비 입구에서 잘못 NOT_FOUND가 되지 않도록 준비·고정 목표·생성의 Core 경로를 연결한다. `LEGACY_BEHAVIOR` 목표도 기존 정의 버전으로 계속 사용할 수 있어야 한다. 자동 담기는 하지 않는다. 출처: 원 AC4.6.2·AC4.6.4·AC4.6.5, 코드 분석의 PracticeStartService/FrozenGoal.
- **인수 기준** `[자동-대역]`: CANDIDATE와 LEGACY_BEHAVIOR 각각 준비 요청→첫 대본 생성/전달이 된다. 다른 아이·철회·삭제된 선택은 읽거나 발급할 수 없다. 후보 갱신 후에도 담은 버전의 4요소로 생성한다.

### FR5 U15 그래프 맥락과 기본 경로

- **FR5.1** U15의 실제 아동별 경계 `ChildKnowledgeService.skillContext`·`variantPlan`으로 구조 맥락과 변형 계획을 읽는다. 공개 행동 키용 `KnowledgeGraphLookup`을 아동별 조회로 오용하지 않는다. 모든 조회는 해당 childId·담은 목표에 한정한다. 출처: 원 FR9.5·FR9.6, C-DS11, 코드 분석.
- **FR5.2** 그래프가 꺼졌거나 장애·빈 응답·합계 조회 2초 초과 또는 skillRef=NONE이면 구조 맥락 없는 기본 생성으로 진행하고 `generation.graphContextUsed=false`로 표시한다. 다음 요청은 장애 복구 후 다시 조회할 수 있다. 조회 2초는 전체 생성 15초 안에 포함한다. 출처: 원 FR9.5, AC3.2.1~AC3.2.3.
- **인수 기준** `[자동-대역]`: 정상 맥락만 해당 생성 입력에 들어간다. 각 비활성·빈 값·장애·지연 경계에서 기본 경로가 동작하고 개인화 성공으로 잘못 표시하지 않는다. 다른 아이의 맥락이 섞이지 않으며 장애 복구 후 재기동 없이 조회한다.

### FR6 변형 장면 보존

- **FR6.1** 구조 맥락이 있는 대본의 BASE/VARIANT에는 불변 문장, 보존 조건, 같은 기술, 전이 거리와 바뀐 요소를 판정한다. 기본 장면 실패는 대본 재생성 대상으로 취급한다. 출처: 원 FR9.6, AC3.2.4, 지시서.
- **FR6.2** 변형만 실패하면 허용된 내용 재생성 1회와 15초 안에서 변형 보정을 수행하고 다시 검토·검사한다. 보정 후에도 실패하거나 남은 횟수·예산이 없으면 승인된 BASE만 사용하고 변형을 제외한다. 실패한 변형을 유효 장면으로 내보내지 않는다. 전체 대본 재생성과 변형 보정이 재시도 상한을 우회하지 않도록 설계에서 카운터를 명시한다. 출처: AC3.2.4, 지시서의 재생성 상한·원 FR2.5.
- **인수 기준** `[자동-대역]`: 불변·기술·거리·변경 요소 각각의 실패 대조가 있다. BASE 유효/VARIANT 실패 시 BASE가 유지되고 유효하지 않은 변형은 노출되지 않는다. `[실호출-합성]`: 모델의 의미 보존 판단 품질은 별도로 관측한다.

### FR7 개인정보와 공급자 경계

- **FR7.1** 생성물·자체 검토 결과를 제브로 보내지 않는다. 공급자 입력은 허용된 목표·구조 맥락 및 필요한 최소 정보로 제한하고 이름은 '아이'로 치환한다. 실제 아동·보호자 식별자, 키, 불필요한 전사·자유 입력 원문은 보내지 않는다. 출처: 원 FR2.6, AC3.1.10, R-F13~R-F15.
- **FR7.2** 응답에는 업무상 허용된 식별 참조 외 개인정보, Luna 원문 응답, 검토 사유 원문을 넣지 않는다. 저장·응답에는 허용된 구조화 대본·사유 코드·모델/프롬프트 판만 사용한다. 로그에는 본문을 남기지 않고 필드 이름·허용 코드·시간·개수만 사용한다. 출처: 지시서, 원 FR1.4·AC3.1.7·AC3.1.10.
- **FR7.3** interests 전달은 아직 승인된 것으로 간주하지 않는다. 원 AC3.1.8과 현재 금지 키의 충돌을 Functional Design의 명시적 사람 질문으로 해결하고, 결정에 따라 계약·입력 정리·시험을 일치시킨다. 출처: 지시서의 지정 질문, ai-io.md 7절 열린 점.
- **인수 기준** `[자동-대역]`: 허용되지 않은 ID·원문·키가 요청·응답·로그에 없고, 검토 원문과 제브 호출이 없다. 관심사 입력 시험은 실제 설계 결정으로 확정한다.

## Constraints

- 작업 단위는 U10 하나이며 순차 진행한다. 요약 확인과 Code Generation 계획 승인은 꺼져 있다. 완료 승인·필수 사람 질문에 대한 답을 만들어 넣지 않는다.
- 제품 변경은 Core와 관련 계약에 한정한다. `backend/realtime-activity` 운영 코드를 변경하거나 다른 단위의 시험 단언·커버리지 하한을 약화하지 않는다.
- 기존 U5a의 외부 서비스 UNAVAILABLE/TIMEOUT에 대한 HTTP 오류 계약과 U10의 최종 대본 생성 실패를 구분한다. 실패한 대본을 발급하지 않는 업무 결과를 SCENARIO_GEN_FAILED로 유지하면서, 레거시 503 단언을 바꾸지 않는 경로별 매핑을 설계에 명시한다.
- V8·V9가 main에 병합됐다. U10은 최신 main `48a132b8ebe5a276e9a5d26ddbf35353ddf9fac6`을 반영했고 core V10을 사용한다.
- U12 계약 PR은 조사 시점 목록에 없었다. 기존 C-DS1에 선택 필드를 더하며, 구현 전에 최신 main의 계약과 다시 대조한다. 깨는 변경은 임의로 하지 않는다. 동료 메시지 전송은 현재 요청에 포함되지 않는다.
- 지시서의 네 커밋 순서(V10·계약 → 생성/검토/검사 → 목표·그래프 → 레거시 호환)를 Code Generation 계획에 반영한다. AI-DLC 기록도 함께 커밋하고 U10 PR·CI까지 확인한다. U10 실제 병합·배포는 현재 요청 범위 밖이다.
