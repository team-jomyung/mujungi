# U11 GPT-Live 실호출 증거 요약 (2026-10-16 ~ 17)

> 증거 종류: **[실호출-합성]** 실제 API · 합성 음성(R-M11). 테스트 대역 · 실제 기기 증거가 아니다. 전사 원문 · 음성 · 키는 담지 않는다(R-F14).
> 원본 보고서는 `backend/realtime-activity/build/gpt-live/report.md`(마지막 실행만 남는다). 이 문서는 세 실행의 요지를 보존한다.
> 입력: Windows 음성 합성으로 만든 24kHz 16bit 모노 WAV 4.14초(문장 사이 쉼 포함). 지시 추가 시험은 표식 낱말을 쓰고 보고서에는 예 · 아니오와 시간만 남겼다.

## 공개 문서([S7] live-conversations · voice-websockets)에서 확인한 것
- 자동 응답 · 말 끝(turn detection) 설정 없음("GPT-Live가 듣고 말하는 시점을 알아서 관리", 완전 양방향).
- `session.update`는 Responses 위임 설정에만 쓰고 다른 필드는 `immutable_field_update`로 거절 → 우리(client 위임)는 쓸 수 없음.
- 말 끝 · 입력 전사 완료 · 응답 끝 · 응답 경계 사건 문서 없음(관측과 일치). `session.output_audio.delta`에 시간 정보 없음.
- `session.instructions.append`는 `delegation_id: null`, `content` ≤ 500토큰이고 진행 중인 말을 끊을 수 있다. 확인 사건은 "세션 시간선이 추가 지시의 추정 끝에 닿을 때" 온다. 지속성은 문서 없음(관측: 남는다).
- `response.create`는 Responses 위임 전용. 위임 사건 `session.delegation.created`는 이번 세 실행에서 오지 않았다.

## 아직 모르는 것 (구현은 여유를 두고 하고 Build and Test 실호출로 확인)
- 지시 문장의 "한 번만" 준수가 안정적인지(표본 1).
- 낡은 꼬리 길이가 응답 길이 · 시점에 따라 어떻게 달라지는지(관측 1.2 ~ 1.8초).
- 시간표 어긋남이 긴 세션에서 얼마나 커지는지(관측 상 단계마다 0.2 ~ 0.4초 늘어남).
- 실제 제품 지시문(짧게 말하라 등) 아래의 응답 길이 · 쉼 분포.
- 아이 음성(성인 합성이 아닌)에서의 입력 전사 조각 간격.
