# U5b 연습 Realtime 연결 요구사항

## 의도 분석

U5a가 마련한 목표·상황 생성 기반과 U4a의 활동 시작/조회 경계에 실제 연습 진행을 연결한다. 보호자는 화면 18에서 오늘 할 목표를 선택하고 화면 12에서 현재 목표와 단계를 확인한다. 아이는 상황을 듣고 먼저 반응하며, 동의한 경우에만 단서를 받고 새 상황에서 다시 반응한다. 이 과정의 장면·반응·도움을 분리 보존해 U6에 결과 입력을 넘긴다.

이 문서는 기존 `261008-mujoong-service` 인셉션의 U5 중 U5b 몫을 추린다. 기존 FR·NFR·US·AC ID를 보존하며 새로운 제품 기능이나 전체 인셉션 재설계를 추가하지 않는다. 깊이와 시험 전략은 Standard다.

## 현재 구현과 변경 범위

Core의 `PracticeStart`는 인터페이스만 있고 공개 시작 경로는 자유대화만 제공한다. `ScenarioConfiguration`의 세션/기록 포트 기본값은 SERVICE_NOT_READY다. 화면 18 시작 버튼은 비활성이고 Realtime 진행 응답의 practice는 null이다. U5a의 C10·노출 정산 및 `LiveExtras.practice` 필터는 재사용한다. [RE]

현재 checkout에서 U4b 참여·스냅숏 경로의 완성을 검증하지 않았다. 사용자는 U4b 담당자가 구현을 별도 브랜치에 Push했고 CI 진행 중이라고 전달받았다. 이 전달을 로컬 구현 완료·CI 통과·최종 인터페이스 합의로 바꾸지 않는다. [Q1]

## 기능 요구사항

### FR4.1 내 연습 목표 목록 — U5b 시작 연결 (Must)

화면 18의 기존 목록·선택 기능에 `POST /api/activities/practice`와 `PracticeStart` 실제 구현을 연결한다. 선택 목표의 소유권·유효성, 동의·진행 세션·기기 시작 조건을 기존 U4a 경계에서 검사한다. 요청 전송 중 단추를 비활성화하고 멱등 키를 사용한다. 기존 U5a 목록·별·삭제/복구 기능은 재구현하지 않는다. [brief][R][S]

- **AC4.1.3**: Given 유효한 목표 1개와 시작 조건 충족 When 연습 시작 Then 서버 수락 뒤 화면 12 연습으로 이동한다. 0개 선택은 기존 규칙대로 시작 불가다.
- **AC4.1.4**: Given 여러 목표 When 서버 수락 Then 가중 랜덤 순서를 한 번 정해 세션 목표에 저장한다. 같은 세션 재조회·동일 요청 재전송에서 순서가 바뀌지 않는다. 가중식 확정 후 고정 시드 또는 1,000회 표본으로 A8 가중 비율 ±5%p 기준을 확인한다. A8 자체는 아래 상위 가정으로 보존한다.
- **AC4.1.10**: Given 진행 세션·불안정 기기·누락 동의 When 시작 요청 Then 기존 거절 코드에 대응하는 사유를 화면 18에 표시하고 그 화면을 유지한다. 중복 제출이 두 세션·두 번 상황 재생을 만들지 않는다.
- **AC4.1.12**: Given 시작 때 고정된 목표·순서·정의 버전 When 목록 삭제나 별 변경 Then 진행 중 세션의 목표·순서·표시 이름은 바뀌지 않는다.

### FR4.2 연습 세션 진행 (Must)

PracticeProtocol이 목표별 단계를 진행하고 마지막 목표가 끝나면 U4b 생명주기에 마무리 신호를 전달한다. 시작 시 첫 목표의 상황만 생성하며 이후 목표의 상황은 이전 목표가 끝날 때 C10으로 요청한다. [brief][R][S][C]

- **AC4.2.1**: Given 첫 상황 생성 When 내용 확인이 처음 실패하고 재생성도 실패 Then 시작을 거절하고 422 SCENARIO_GEN_FAILED를 표시한다. 중간 목표가 두 번 내용 실패하거나 전체 15초 예산을 넘기면 그 목표를 SKIPPED와 상황 준비 실패 사유로 기록하고 다음 목표 또는 마무리로 간다. 일시적 미연결 오류와 내용 확인 실패는 C10 계약에 따라 구분한다.
- **AC4.2.2**: Given 유효한 practice 조회 When 단계 변화 Then 화면 12의 목표 이름·n/N·단계가 폴링 1주기 안에 실제 값과 일치한다. stage 값은 SCENARIO_INTRO·FIRST_RESPONSE·HELP_OFFER·CUE·AFTER_CUE_RESPONSE·NEW_SCENARIO_RESPONSE다. 고정 순서 진행 표시나 보호자 다음/건너뛰기 조작을 추가하지 않는다.
- **AC4.2.3**: Given 상황 안내와 기회 트리거 완료 When 첫 반응이 들어옴 Then 반응과 판정을 기록한다. 대기 20초 동안 무반응이면 판정 호출 없이 NOT_PERFORMED로 기록하며 none과 구분한다.
- **AC4.2.4**: Given 첫 반응 partial·none 또는 무반응에 대한 기존 B14 경로 When 도움 제안 Then 동의했을 때만 Cue를 제공한다. 거부·동의 질문 10초 무응답은 각각 DECLINED·NO_RESPONSE로 기록하고 도움 없이 새 상황으로 간다. uncertain은 보류로 기록하고 Cue 없이 새 상황으로 간다.
- **AC4.2.5·AC4.2.6**: Given 도움 후 반응 또는 도움 없음 When 새 상황/목표 완료 Then 새 상황 반응을 별도 저장하고 다음 목표면 n+1/N, 마지막이면 U4b 마무리 뒤 화면 17로 이어진다.
- **AC4.2.8**: Given 보호자 서버 상태 미수신·앱 조회 실패 When 아이 기기 세션은 정상 Then 이를 단계 실패·아이 침묵·연습 중단으로 바꾸지 않는다. 이전 수신값·조회 오류와 실제 기기 상태를 구분한다. 상황 본문·진행 판정은 보호자 응답에 노출하지 않는다.
- **AC4.2.9**: Given 고정 목표/버전 When 목록이나 현재 행동 정의 변경 Then 해당 세션의 고정 원본을 사용한다. 외부 조회를 위해 Realtime 표를 Core에서 직접 읽지 않는다.
- **AC4.2.10**: 첫 반응 대기·도움 동의 질문 무응답·Cue 예산 초과의 시간 규칙은 각각 이 절 AC4.2.3(20초 → NOT_PERFORMED), AC4.2.4(10초 → NO_RESPONSE·도움 없이 새 상황), FR5.5의 AC6.5.3(5초 → Cue 미제공·새 상황)에 대응한다. NFR6이 이 세 경계의 Clock 검증을 맡는다. 아래 추적표는 각 대상을 별도로 연결한다. 이 AC가 도움 후/새 상황 반응에도 20초를 확정한 것으로 해석하지 않는다. [S][C]

**새 상황 생성 실패·시간 초과 경계**: 이미 진행한 동일 목표의 NEW_SCENARIO 생성이 두 번 내용 실패하거나 C10 15초 예산을 넘기더라도 기존 ORIGINAL 장면의 첫 반응·판정·동의·실제 제공한 도움·도움 후 반응과 노출 기록을 보존한다. 다음 목표의 최초 상황 실패 규칙을 자동 적용해 이 기록을 지우거나 목표 전체를 SKIPPED로 바꾸지 않는다. 생성되지 않은 상황의 scenarioId나 노출 시각을 만들지 않는다. [revision][R][C]

새 상황 반응 미실시 사유의 계약 표현, 목표 최종 상태, 다음 목표/마무리 전환은 아래 U5b-J3의 **설계 제안이며 미확정**이다. Functional Design에서 합의된 상태·사유 표현으로 확정하기 전에는 정상 새 상황 완료로 집계하거나 해당 분기를 구현 완료로 주장하지 않는다.

**후속 반응 무응답 경계**: AFTER_CUE_RESPONSE와 NEW_SCENARIO_RESPONSE의 대기 시한·시계 시작점·미실시 기록·전이 제안은 U5b-J4에 명시한다. 대기 종료 시 평가자 호출 없이 NOT_PERFORMED와 사유를 기록하는 원칙은 FR7.6·FR4.3을 따른다. 구체 시한과 U4b SILENCE/기술 일시정지 시계와의 관계는 U5b-J4·J5로 구분하고 합의 전까지 확정 값으로 사용하지 않는다. [revision][R][S]

### FR4.3 연습 반응·도움 분리 저장 — U6 결과 입력 부분 (Must)

`record.practice.goals`에 고정 목표·순서·상태, scenarios에 상황과 실제 노출 시각, responses에 종류·전사 순번·진행 판정·미실시 사유, cues에 동의·제공 내용·시각·정답 문장 포함 여부를 보존한다. 반응과 도움에는 반드시 해당 scenarioId가 들어간다. [brief][R][C][U]

- **AC4.2.7**: Given 같은 목표의 첫 반응·Cue·도움 후 반응·새 상황 When 저장/스냅숏 생성 Then 각각 분리되고 도움 후 반응이 첫 반응을 덮어쓰지 않는다. 무반응·미실시에는 null과 사유가 남고 같은 기회의 재시도를 독립 성공으로 바꾸지 않는다.
- **AC4.2.8**: Given 저장된 진행 중 판정 When 보호자 API/화면 응답 Then label·reason·점수·확률이 노출되지 않는다. U6의 기록용 재판정과 장면 칩 생성을 이 유닛에서 대신하지 않는다.
- **계약 6절 확인**: Given 스냅숏 생성 When PRACTICE의 참여/진행 이력이 존재 Then 각 scenarioId가 동일 목표의 장면에 귀속되고 없는 장면의 참조를 내보내지 않는다. FREE_TALK·DECLINED의 practice는 계약의 null 또는 빈 표현을 사용한다.

### FR5.5 연습 음성 흐름 (Must)

만들어진 상황과 AI 역할을 안내하고 승인 대본의 기회 트리거를 출력한다. 단계별 OutputGate와 VoiceRelay 지시를 확장하되 기존 완결 구간·세대·재검사·취소 경계를 유지한다. [brief][R][S][C][RE]

- **AC6.5.1·AC6.5.2**: Given 상황 안내/첫 반응 전 When 음성 출력 Then 가상 상황·역할 안내와 기회 트리거가 제공되고 힌트·정답·시범은 차단된다.
- **AC6.5.3**: Given 도움 수락 When Cue 요청 Then 상대의 말을 짚는 단서만 제공한다. Cue 브리프는 situationSummary·partnerUtterance·focus이며 정답 문장·판정 기준·보호자 원문을 보내지 않는다. 5초 내 재생을 시작하지 못하면 Cue 미제공을 기록하고 새 상황으로 간다. 합성 세트에서 기대 발화 예와 5어절 이상 연속 일치 0건 및 평가자 확인 기준을 사용하며, fixture 검증을 정식 프롬프트 승인으로 바꾸지 않는다.
- **AC6.5.4**: Given Cue 제공 When 아이가 재반응 Then 도움 후 반응은 1회만 받는다.
- **AC6.5.5**: Given 새 상황 When 제공 Then 소재만 다르고 목표 행동·상대 관계·기회 조건은 같으며 추가 Cue가 없다. 같은 활동에서 같은 상황을 재사용하지 않는다.
- **AC6.5.6**: Given 마지막 목표 완료 When 종료 연결 Then U4b 승인 마무리 음성이 1회만 재생된다. U5b가 별도 종료 상태 기계나 두 번째 인사를 만들지 않는다.

### FR5.6 다시 듣기·속도 조절·설명 요청 (Should)

반복·속도 조절은 같은 내용을 제공하며 Cue로 집계하지 않는다. 목표 단서가 추가되는 설명은 도움으로 기록하고 동의·횟수·단계 제한을 적용한다. 요청 문구만으로 Cue 여부를 결정하지 않는다. [R][S]

- **AC6.5.7**: Given 동일 문장 반복/속도 조절 When 제공 내용 비교 Then Cue 횟수는 증가하지 않는다. 단서를 더한 설명은 동의 없는 출력이 차단되고 실제 제공 시 해당 장면의 도움으로 남는다.

### FR7.6 반응 판정 — 진행 중 판정 부분 (Must)

ResponseEvaluator는 고정된 핵심 기능·판정 조건과 반응으로 functional·partial·none·uncertain을 판단한다. 반응 없는 경우는 호출하지 않는다. 호출당 5초와 재시도 1회를 적용하고 최종 실패는 uncertain이다. 기준이 없는 목표를 연습 대상으로 제공하지 않는다. [brief][R][S][C]

- **AC4.2.7**: Given 첫/도움 후/새 상황 반응 When 판정 Then 장면별 입력과 출력이 연결된다. 5초 초과·공급자 실패·형식 오류·재시도 후 실패를 주입해 최대 두 시도 뒤 uncertain으로 진행하고 영원히 대기하지 않음을 확인한다. 왕복/스케줄링을 포함한 시험 상한은 Functional Design의 시간 계약에 명시한다.
- **무반응 경계**: Given 무반응 When 대기 만료 Then 평가자 호출 0회, NOT_PERFORMED와 사유가 저장된다. 불확실 판정과 무반응이 동일 라벨로 바뀌지 않는다.
- 운영 기본값은 미연결이며 합성 반응·가짜 공급자로 시험한다. 운영 대체 평가자가 임의 functional을 만들지 않는다. 기록용 재판정은 U6 범위다.

### FR7.5 상황 생성·노출 — U5b 연결 부분 (Must, 이력 재사용 방지 Should)

기존 C10을 재사용하고 `PracticeSessionContextPort`·`ScenarioRecordPort` 실제 어댑터를 연결한다. 시작 원본과 활성 세션에서 읽는 고정 목표의 경계를 설계하고 현재 목록을 진행 세션의 허가 원본으로 사용하지 않는다. 첫 상황을 위한 임의 활성 세션을 운영에 만들지 않는다. [brief][prior][C]

- **AC6.5.8 및 실제 노출**: Given 상황 ISSUED지만 재생되지 않음 When 기록 수신 Then EXPOSED로 바꾸지 않는다. 실제 노출 scenarioId·exposedAt가 있는 ActivityRecorded 뒤에만 reconcileExposures를 호출한다. 중복 수신은 노출을 두 번 반영하지 않는다. 다른 아이/세션/목표의 상황 참조는 거절한다.
- **첫 상황 연결**: Given 시작 전 첫 상황 준비와 C10의 활성 세션 조건 When 설계/시험 Then 시작 준비·원본 고정·실패 정리를 명시한 경로로 동작하고 조건 우회나 상대 스키마 직접 접근이 없다. 구체 인터페이스와 멱등성은 Functional Design에서 정한다.

### FR5.7·FR7.1·FR1.6 연습 중간 종료·삭제 — U5b 정산 부분

U4b가 소유하는 생명주기와 종료 사유를 유지하며 U5b는 자기 목표·시도·반응·도움·판정 데이터를 정산/삭제한다. CHILD_STOP·SILENCE·DISCONNECT의 중간 종료에서 남은 목표는 NOT_REACHED다. 동의 철회·재시작·삭제·기타 종료 경로도 U4b 스냅숏/정리 순서와 충돌하지 않게 설계한다. [brief][U][C]

- Given 연습 중 종료 When U4b가 결과 입력을 확정 Then U5b 정산이 먼저 완료되어 도달한 기록은 보존되고 남은 목표·미실시 사유가 반영된다. 늦은 평가/생성 응답은 종료 목표를 재개하거나 재생하지 않는다.
- Given 계정 삭제 When Realtime 삭제 참가자가 실행 Then 연습 표 5종을 세션 행보다 먼저 삭제한다. 재호출·빈 데이터도 성공이며 삭제 후 조회 0건이다. Core의 기존 @Order 150과 상대 생명주기 책임을 변경하지 않는다.
- 실제 Java 확장점·스냅숏 제공 위치·정산/삭제 순서는 U4b 구현 검토와 합의 뒤 확정한다. 그전의 계약 대역은 U4b 내부를 복제하지 않는다. [Q1]

- 다른 담당자의 기록 수정과 외부 메시지 발송. 합의가 필요하면 사람에게 확인할 자료를 제시한다.

지시서에는 배포 두 단계 제외 절차가 있으나 현재 진행 계획에는 아직 deployment-pipeline·deployment-execution이 남아 있다. 이 문서는 제품·구현 요구를 추린 것이며 문서 속 명령으로 진행 계획을 바꾸거나 배포를 승인하지 않는다. 단계 변경은 사람이 요청한 경우 별도로 처리한다.
