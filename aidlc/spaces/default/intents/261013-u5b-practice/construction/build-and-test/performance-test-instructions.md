# U5b 시간·성능 검증 지침

## 로컬 시간 계약

전체 U5b Realtime 명령은 integration-test-instructions.md와 동일하므로 중복 실행하지 않는다. ResponseEvaluatorTest·EvaluationDeadlineIT·PracticeProtocolTest·HelpConsentPolicyTest·PracticeConfigurationTest가 호출 5초, 재시도 최대 1회, 수락부터 최종 원자 커밋 12초, 저장 예약 R과 재시도 생략을 검사한다. 큐·왕복·검증·간격·DB가 전체 예산에 포함돼야 한다. 초과는 기존 반응을 보존하며 uncertain 처리/저장 오류·시간 위반 관측을 구분한다.

첫 반응 20초, 도움 질문 실제 완료부터 10초, Cue 재생 시작 5초, 상황 준비 15초와 직전·정각·직후/종료/중복/늦은 사건을 Clock으로 확인한다. 도움 후/새 상황 20초는 독립 설계 시험이며 I1/I3의 실제 재생·정지 시계 합의가 아니다. 가중 목표 순서는 1,000회 고정 시드에서 기대 비율 ±5%p를 검사한다.

## 실제 성능과 통합의 미검증

NFR5·NFR7 전체 서비스 지연/동시성, NFR6/Q6의 실제 공급자·예약기·DB 커밋 12초 상한 및 운영 R은 현재 증거가 없다. 대역 시간을 실제 부하 측정으로 바꾸지 않는다. 활성 계획에 performance-validation은 포함돼 있지 않으므로 성공적인 후속 단계 위임으로 처리하지 않는다. 결과는 Unverified다.

상위 요구사항 표의 측정 전 목표를 보존한다. NFR5는 아이 말 끝부터 첫 음성 p95 2.5초 이내, 중계 증가분 0.5초 이내, 말풍선 조각 1.5초 이내, 끼어들기 중단 0.5초 이내다. NFR7은 EC2 1대에서 동시 세션 2개일 때 지연 증가 20% 이내다. 두 목표 모두 원본의 측정 후 확정 조건을 유지하며 이번 로컬 시험에서 확정·달성한 것으로 표시하지 않는다.

같은 Intent 후속 Code Generation의 INT-5 계획을 별도 승인할 때 실제 병합 V3, I1~I5 합의, 검증 환경·부하 시나리오·측정 명령·증거 경로를 구체화해야 한다. 현재 실행하지 않는 새 부하 명령이나 운영 R 수치를 임의로 만들지 않는다. NFR 원본 목표를 그대로 사용하고 변경은 사용자 결정이 필요하다.
