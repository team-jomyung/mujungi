# U5b 보호자 화면 연결 설계

## Sources

입력은 `../../inception/requirements-analysis/requirements.md`의 FR4.1·FR4.2·NFR3·NFR4·NFR9·NFR10과 Q1~Q5다. 화면 범위는 기존 인셉션 US4.1·US4.2, S-18·S-12다. 상세 규칙은 rules.md의 BR6.1~BR6.3, 시작 순서는 functional-spec.md WF1이 정본이다. 화면 설계 v1.5j의 문구/배치와 기존 U5a 기능을 유지한다.

## 화면 18 구성과 상태

기존 Practice18의 목표 목록·선택·별·삭제·복구·빈 상태를 재사용한다. 시작 동작만 별도 조정자로 연결하며 목표 행은 시작 성공 여부나 실행 중 순서를 소유하지 않는다.

| 구성 | 입력 | 소유 상태/행동 |
|---|---|---|
| Practice18 | 소유 목표 목록·목록 로딩/오류 | 선택 집합과 시작 오류 표시; 기존 목록 조작 유지 |
| PracticeStartAction | 선택 목표 ID·기존 시작 조건 정보 | 동일 논리 요청의 멱등 키·전송/결과 미확인·수락 결과 |
| StartReason | 기존 거절 코드 또는 결과 미확인 | 선택을 유지한 사유와 재확인 조작; 서버 준비를 성공으로 위장하지 않음 |
| ExistingGoalList | 기존 목표 DTO | 목록/별/삭제의 기존 수용 기준 보존 |

선택은 현재 표시되고 소유가 확인된 목표 ID와 교집합으로 계산한다. 0개면 단추를 비활성화한다. 선택만으로 서버를 시작하지 않는다. 처음 제출할 때 키와 선택 집합을 고정하고 연속 누름은 같은 진행 요청을 공유한다. 서버 수락 뒤에는 기존 화면 12 경로로 이동한다. 첫 상황 생성 실패 422이면 화면 18과 선택을 유지하고 상황 준비 실패를 표시한다.

시작 거절의 SESSION_IN_PROGRESS·DEVICE_NOT_STABLE·CONSENT_MISSING·IDEMPOTENCY_CONFLICT와 통신 오류를 구분한다. 요청 시간 초과는 서버 생성 실패의 증거가 아니므로 선택/같은 멱등 키를 보존한다. 임의 새 키로 자동 재시작하지 않는다. 서버가 준비 중인 요청을 어떻게 확인/재시도할지는 I5 합의 항목이며 새 상태 enum이나 공개 API를 클라이언트가 독자적으로 가정하지 않는다.

## 화면 12 구성과 파서

| 구성 | 입력 | 표시/검증 |
|---|---|---|
| ExistingLive12 | 기존 세션·말풍선·연결/오류 | U4a 자유대화·종료·오프라인 처리 보존 |
| PracticeHeader | goalIndex·goalCount·goalName·stage | 연습 · n/N번째 목표 · 이름과 실제 현재 단계 |
| PracticeStageLabel | 여섯 stage 값 | 중앙 문구의 단계 이름; 완료율/판정/고정 진행 순서 표시 없음 |
| ProgressParser | practice null 또는 객체 | 순번/수 양수 정수, index≤count, 이름 비어 있지 않음, stage 허용 목록 |

practice=null인 자유대화·미참여는 연습 머리를 만들지 않는다. 연습인데 값이 없거나 잘못됐으면 현재 단계 확인 불가를 기존 조회 오류와 구분해 표시하며 임의 FIRST_RESPONSE나 0/N을 만들지 않는다. 알 수 없는 추가 필드는 판정/상황을 화면 상태로 복사하지 않고 무시한다. 알려진 필드의 잘못된 타입은 응답 오류로 처리한다.

유효한 응답은 기존 폴링 1주기 안에 반영한다. 조회 실패 때 기존 마지막 확인값과 갱신 실패를 구분하고 아이 기기의 단계를 바꾸거나 연습 종료를 선언하지 않는다. 순서 역전/다른 세션 응답은 세션 ID·조회 세대 및 기존 상태 버전 정책으로 폐기한다.

## 접근성 및 정보 경계

- 기존 선택/별/삭제의 보조기기 이름과 44px 조작 영역을 유지한다. 전송 중 상태를 disabled와 상태 알림으로 제공하고 오류를 색만으로 구분하지 않는다.
- 12의 단계 변화는 과도한 반복 낭독 없이 현재 값으로 알린다. 재시도·선택은 키보드로 가능하며 오류가 선택을 지우지 않는다.
- 상황 본문·판정 라벨·기준·근거·확률·점수·보호자 원문을 props/상태/DOM/로그에 추가하지 않는다. 표시 DTO는 네 필드의 허용 목록이다.
- 부모에게 다음 목표·단계 건너뛰기·Cue 제공 조작을 추가하지 않는다. 기기 웹은 변경하지 않는다.

## 검증과 통합 상태

독립 시험은 선택 0/1/복수, 전송 중 이중 제출, 거절 시 선택 보존, 시간 초과 동일 키 유지, 422 문구, 유효/누락/알 수 없는 단계/잘못된 순번, 폴링 역전·조회 실패·다른 세션 응답, 금지 필드 미노출, 키보드·상태 알림을 포함한다. 기존 U4a/U5a 시험 단언을 줄이지 않는다.

실제 시작 준비의 응답·재시도/확인 API는 I5 합의 전 통합 보류다. 파서는 확정된 계약을 대역으로 검증하며 미합의 응답을 운영 성공으로 해석하지 않는다. 프런트 코드 변경 시 자기 범위 파일과 기존 줄 커버리지 하한을 적용한다.
