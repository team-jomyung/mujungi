# U5b 코드 계획 추가 확인

## 기준

기능 설계 Q1~Q6와 해당 승인 기록을 재사용한다. I1~I5 및 U5b-J3~J5는 기존 상태를 유지한다. 이미 확인한 질문을 다시 묻지 않는다. 이 파일은 구현 정책의 추가 확인이며, 코드 계획 승인용 code-generation-questions.md는 도구가 관리한다.

## CG-Q1. 첫 반응 무응답 뒤 도움 제안

기능 설계 functional-spec.md의 열린 정책 B14는 코드 계획 전에 사람/계약 확인을 요구한다. 메인 stories.md B14는 NOT_PERFORMED를 AI 계약 확정 전까지 Cue 제안 대상으로 두는 가정이다. 기존 Q2는 도움 후·새 상황 반응의 무응답을 다뤘으며 첫 반응 무응답 뒤 도움 제안 여부를 확정하지 않았다.

첫 반응 20초 만료 시 NOT_PERFORMED/NO_RESPONSE를 보존하고 평가자를 호출하지 않는 원칙은 공통이다. 다음 경로만 확인한다. 어느 선택도 실제 재생·SILENCE·종료 경합 또는 AI 계약의 상대 합의를 대신하지 않는다.

A. 이번 U5b 로컬 구현 제안은 도움 동의를 묻는 경로로 한다. 동의한 경우에만 Cue를 한 번 제공하고, 거부 또는 동의 질문 10초 무응답은 기존 규칙에 따라 도움 없이 새 상황으로 간다. 실제 통합은 기존 I1/I3 및 정식 AI 계약 확인을 전제로 한다.
B. 이번 U5b 로컬 구현 제안은 도움 동의를 묻지 않고 Cue 없이 새 상황으로 가는 경로로 한다. 상위 B14 가정과의 편차를 U5b 계획에 명시하고 기존 메인 문서는 수정하지 않는다. 실제 통합은 관련 계약 확인을 전제로 한다.
C. 이 정책을 계속 보류한다. 첫 무응답 이후 경로는 구현 완료 대상으로 넣지 않고 독립 부품·시험 대역과 나머지 확정 경로만 계획한다. 이 선택으로 전체 연습 통합을 완료했다고 주장하지 않는다.
X. Other (please specify)

[Answer]: A. 첫 반응 20초 무응답을 NOT_PERFORMED/NO_RESPONSE로 기록하고 판정 AI 호출 없이 도움 동의를 묻는다. 동의 시 Cue 1회와 도움 후 반응 기회, 거부/10초 무응답 시 Cue 없이 새 상황으로 진행한다. 기존 Q1~Q6 및 미합의 경계를 유지하고 코드 계획에 상태 전이와 Clock 시험을 포함한다.

**사용자 답변(원문):**

1. 도움 동의 질문을 선택합니다.

첫 반응이 20초간 없으면 NOT_PERFORMED/NO_RESPONSE로 기록하고 판정 AI를 호출하지 않습니다. 이후 아동에게 도움 동의를 질문합니다.

동의하면 Cue를 1회 제공하고 도움 후 반응 기회로 진행합니다. 거부하거나 10초 동안 응답하지 않으면 Cue 없이 새 상황으로 이동합니다.

단, 도움 동의 대기 10초는 기존 계약의 확정값인지 확인하고, 새로 선택한 정책이라면 U5b 설계 결정으로 명시해 주세요.

U4b의 실제 재생 성공·실패 확인, 세션 종료 경합, 새 상황 생성 실패 후 전이 등 미합의 사항은 기존대로 유지합니다.

기존 Q1~Q6 결정은 변경하지 말고 이 경로의 상태 전이와 Clock 경계 테스트를 코드 생성 계획에 포함해 주세요.

## 근거 대조 결과

- 메인 contract-summary.md 7절 practice.help-consent-wait는 10초이며 시작점을 도움 동의 질문 재생 완료로 명시한다. 새로 선택한 수치가 아니다.
- 승인된 U5b requirements.md FR4.2 AC4.2.4와 AC4.2.10(b)/NFR6은 10초 무응답을 NO_RESPONSE로 기록하고 Cue 없이 새 상황으로 이동하도록 명시한다. 메인 시간표의 일반적 표현인 거부와 구분하여 DECLINED/NO_RESPONSE를 보존한다.
- 이번 새 U5b 결정은 미확정 B14 경로를 로컬 구현 방침으로 선택한 것이다. 첫 무응답 기록 뒤 HELP_OFFER로 연결한다. 재생 성공 증거·종료 경합·새 상황 생성 실패 후 전이의 실제 통합 합의는 포함하지 않는다.
