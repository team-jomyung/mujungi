## Q1. 어떤 끝난 세션에 결과 정리(SESSION_RESULT)를 만드나 (C4)

정본의 말이 서로 다르다.
- 지시서: "종료가 확인되지 않은 세션 · DECLINED는 정리하지 않는다"
- 17 화면 수용 기준 AC3.6.12: 정리 중 = (ENDED · ENDED_UNCONFIRMED · ABORTED · FAILED) + 작업 진행
- 컴포넌트 설계: "DECLINED · 기록 없는 활동은 작업을 만들지 않는다"
- 27 끝난 이유 칸(AC5.2.11)은 미확인 종료도 27이 있다고 전제한다.

A. 종료 상태가 된 기록은 모두 정리한다. DECLINED와 발화 0건(ACTIVE 전 종료)만 뺀다(jobStatus NONE). 미확인 종료는 결과 수준 표대로 FULL이 되지 않는다. 지시서 문장은 "종료 전 세션은 정리하지 않는다"로 해석하고 편차로 적는다. (추천)
B. 종료가 확인된 ENDED만 정리한다. ENDED_UNCONFIRMED · ABORTED는 NONE이라 27에 결과 칸이 없다.
C. 모두 정리하되, 종료 미확인이면 결과 수준 상한을 PARTIAL로 둔다(A와 비슷하나 상한을 별도 규칙으로 명시).

## Q3. 리포트 60초 목표를 서버 마감으로 쓸지 (C3)

C. 앱 타임아웃만 60초로 두고 서버에는 마감을 두지 않는다.

## Assumption Confirmation

아래는 정본끼리 부딪히거나 정본에 답이 없지만, 추천안이 정본 문장 · 코드 사실과 바로 맞아 따로 묻지 않은 것이다.
요구사항에 가정으로 적고, 바꾸려면 B를 고르고 번호를 적는다.

- (C1) 텍스트 AI 설정 키: `mujoong.text-ai.*` 아래에 결과 · 리포트 하위 키를 더하고, ai-io 6.1의 `mujoong.ai.*`를 고쳐 편차로 적는다. U5a 키 · 시험은 바꾸지 않는다.
- (C2) 자동 재시도: 시도 3회(최초 + 5초 뒤 + 15초 뒤). 키는 `result.job-attempts: 3`과 `result.job-retry-backoff: [5s, 15s]` 둘로 나눈다. NFR8 "3회 재시도"는 "자동 시도 3회"로 해석해 편차로 적는다.
- (C7) 출처 값: 저장 · 응답은 `GUARDIAN_INPUT` · `CHILD_RECALL`로 통일한다. 구조화 내부 `CHILD_TRANSCRIPT`는 CHILD_RECALL로 사상한다. 리포트 인용의 TRANSCRIPT는 전사 인용용으로 둔다. GUARDIAN_INPUT 인용은 quote 없이 출처 표시만 한다.
- (C11) 미실시 칩 사유: mockups 셋(시간 종료 · 상황 준비 실패 · 활동 끝)에 ai-io의 "반응 없음"을 더한다. 문구는 임시 문구로 사전 검사 대상에 넣는다.
- (C13) 금지 표현 1차 사전: Core에 ai-io 4절 형식 JSON 사전을 새로 두고 결과 · 리포트 검사에 쓴다. U5a txt 정책은 그대로 둔다.
- (C17) 「오늘 기록 보기」 감춤 단언: U1 J120(`done-17.test.tsx:109-112`)과 U4a-J14(`screens-u4a.test.tsx:155`) 두 곳만 "정리 끝(DONE)에서만 보임"으로 바꾸고, 설계에 까닭을 적는다.
- (C18) 폴링: 정리 중(REQUESTED · RUNNING)과 만드는 중(GENERATING)일 때만 `parent.poll-interval`(2초)로 상태 경로를 폴링하고, 끝나면 멈춘다. A2 해석을 편차로 적는다.
