# 제브 어댑터 선 형식 정정 — 성능 시험 지시서

> Standard 전략은 성능 시험 파일을 요구하지 않고, 이 기록에는 측정 대상 성능 목표가 정해진 NFR이 없다. 이 정정은 시간 값(`jev-budget` 800ms · 안전 타이머)을 바꾸지 않는다. 이 파일은 산출 목록을 채우되 무엇을 어디서 잰다만 정직하게 적는다. 부하 시험은 하지 않았다.

## 1. 시간 값 (모두 기존 계약 값, 변경 없음)

| 항목 | 값 | 출처 | 확인 방법 |
|---|---|---|---|
| 제브 한 번의 호출 상한 | 800ms (`mujoong.timing.guardrail.jev-budget`) | `contracts/timing.md` | `JevGuardrailClientTest`의 수동 시계 경계 시험(마감 = 지금 · 시한 직전 · 지난 마감). 실제 제브 지연은 모름 |
| 검사 안전 타이머 | `jev-budget`의 2배 | 앞 기록 구현 결정 | `GuardrailSafetyTimerTest` 4개(변경 없음) |
| 응답 상한 | 64KiB | 앞 기록 어댑터 | 새 형식은 질문 1개 · 라벨 8개의 확률이라 상한 안에 든다(`JevGuardrailClientTest`의 상한 초과 시험) |

## 2. 새 요소가 지연에 주는 영향 (추정이 아니라 확인할 항목)

- 공식 형식의 요청 본문이 이전 가정 형식보다 커졌다(질문 문안 + 라벨 설명 8개). 800ms 안에 들어오는지는 실제 제브로만 안다. `jevLiveTest` 보고서의 지연 열이 입력이다.

## 3. 하지 않은 것과 소유

| 항목 | 상태 | 이유 / 소유 |
|---|---|---|
| 제브 실제 지연 분포(p50 · p95 · p99) | 측정 안 함 | 실제 제브 필요. 사람이 `jevLiveTest`로 지연을 관측한 뒤 800ms가 충분한지 정한다 |
| 동시 세션 부하 | 측정 안 함 | 측정 목표가 정해진 NFR이 없고 이 계획에 `performance-validation` 단계가 없다 |

이 항목들은 `Unverified`가 아니라 **목표값이 없는 관측 항목**이다. 800ms를 바꾸게 되면 R-M5에 따라 `application.yml` · `contracts/timing.md` · 프런트 기본값 세 곳을 같은 커밋에서 고친다.
