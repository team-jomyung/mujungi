## 첫 볼트 적용 범위

Google 보호자 소셜 인증·시험용 아동/동의 조회·자유대화 시작·상태 조회·준비 취소·중도 종료, 고정 ID 시드 기기의 사전 대기 WSS와 시작 push, GPT-Live 주 연결·음성 릴레이·출력 게이트·실제 재생 보고를 연결한다. 자체 아이디·비밀번호 가입/로그인 Endpoint는 구현 범위에서 제외한다. 호출어+종료 명령의 서버 판정도 같은 종료 경로로 연결한다.

연습·결과·추천·리포트 경로는 **후속 후보를 보존**한 것이며 첫 볼트의 구현 완료 조건에 포함하지 않는다. 부분 결과 기능은 유효 기록이 있으면 필요하며 첫 볼트 미구현을 전체 제품 제외로 해석하지 않는다. 쉬기·재개 전체 계약은 후속 범위이며 사용자 연습 건너뛰기를 새 현행 기능으로 추가하지 않는다.

시작 접수·기기/공급자 준비·아동 참여는 서로 다르다. 공급자 `session.started`나 기기 준비 보고만으로 ActivitySession을 `ACTIVE`로 바꾸지 않는다. 참여 의미는 서버와 동료 명세가 판단한다.

## 채널과 권위

| 경로 | 용도 | 원칙 |
| --- | --- | --- |
| `/parent` ↔ Core API Spring, HTTPS REST | 보호자 인증, 활동 준비·시작·종료, 상태·결과·리포트 조회 | 활동 상태 조회는 1~2초 Polling 기존 초기 제안. Core는 Realtime의 활동 계약을 사용하고 ActivitySession을 직접 수정하지 않는다. |
| `/device` ↔ Realtime Activity Spring, `/ws` WSS | 대기 연결·heartbeat, 입력 음성·서버 제어·승인 출력 음성·실제 재생 보고 | 기기 음성·제어 채널이다. 기기는 아동 발화의 의미를 판정하지 않는다. |
| Realtime ↔ GPT-Live API(`gpt-live-1`), 주 WebSocket | 서버 입력 음성 전송·출력 음성/전사 수신·세션 제어 | Realtime이 서버 키로 연결한다. 출력은 임시 버퍼 게이트를 거쳐 전달하며 공급자 상태는 서비스 상태의 권위자가 아니다. |
| Core ↔ Realtime, 내부 HTTP | 즉시 명령·조회, Outbox 이벤트 전달과 수신 확인 | 서비스 인증과 요청 주체·대상·허용 행위를 검증한다. 즉시 명령과 영속 이벤트의 수명·ACK 의미를 구분한다. |

`Realtime Activity Spring`은 우리 앱이며 공급자의 Realtime API와 다른 이름이다. 공급자 API는 GPT-Live다. 브라우저는 프로젝트 키·공급자 연결 자격을 받지 않는다. 기기 제어용 대기 WSS와 유료 GPT-Live 주 연결의 수명을 구분하고, 대기 중이라는 이유만으로 공급자 세션을 유지하지 않는다.

## OpenAPI → TypeScript Client 단계적 적용

REST 계약은 springdoc OpenAPI로 노출하고, 확정된 HTTP 요청·응답 스키마에서 TypeScript 타입·클라이언트를 생성하도록 권고한다. 먼저 실제 Spring Boot 조합에서 `/v3/api-docs` 생성과 인증·오류 스키마를 검증한다. 아래 Endpoint와 Field는 후보이므로 생성 클라이언트의 확정 계약으로 해석하지 않는다. 계약이 안정되면 생성 도구와 CI 불일치 검사를 정한다. `openapi-typescript`·`openapi-fetch`·`openapi-react-query`는 후보이며 Cookie·CSRF 처리 방식은 후속 인증 계약에서 확인한다.

Core의 보호자 REST와 앱 간 HTTP의 공개 범위·스키마를 구분한다. WSS 음성·제어·재생 메시지와 GPT-Live 주 WebSocket 이벤트는 REST 클라이언트 생성 범위 밖이며 별도 계약을 둔다.

## 보호자 REST 경로 후보

Core의 외부 보호자 경로 후보이며 Method·Payload·오류 코드는 API 구현 및 OpenAPI 문서에서 검증한다. `/parent`의 상태·결과 조회에는 TanStack Query를 권고하되 1~2초 Polling은 최종값이 아니다. v10의 `POST /api/auth/login` 후보는 자체 자격증명 로그인으로 구현하지 않고 Google 인증 진입·콜백으로 대체한다. 활동 명령·조회는 Core가 Realtime 내부 계약으로 전달한다.

리소스 요청은 GuardianChild·Session·Report 접근 관계와 작업별 현재 Consent를 검증한다. **필수 동의가 철회됐더라도 종료 요청·현재 동의·최소 종료 상태 확인을 막지 않는 안**은 기존 인증 설계 제안이다. 전사·과거 기록의 열람 허용은 D-08에서 따로 정한다.

### Google 소셜 가입·로그인 — 방향 확정, 상세 계약 Proposed

`registrationId`는 `google`을 쓰는 기존 구현 후보를 유지한다. 위 GET 경로는 Spring Security OAuth2 Login 기본값을 기준으로 한 제안이며 Google Client 등록·Callback URI·개발/시연 도메인 호환성을 검증한 뒤 고정한다. 로그인 실패·동의 거부·기존 계정 연결 충돌의 화면 이동/오류 표현은 **TBD**다. 이 리다이렉트 경로를 REST JSON 로그인 API나 생성 TypeScript Client 로그인 호출로 취급하지 않는다.

1. 보호자가 Google을 선택하면 Core의 Spring Security OAuth2 Client가 Authorization Request와 `state` 등 요청 연관 정보를 관리해 제공자 화면으로 이동한다.
2. Callback에서 요청·응답의 `state` 및 제공자·Redirect URI 연관성을 검증하고 Authorization Code를 서버에서 교환한다. OIDC 연결은 `nonce`와 ID Token의 서명·issuer·audience·만료 등 필요한 검증을 수행한다. Google 설정·속성 매핑은 실연동으로 확인한다.
3. Core `auth`는 검증된 제공자 회원 식별자로 `guardian`의 공개 API/Port를 호출해 내부 보호자 계정을 조회·연결한다. 최초 이용자는 가입 정책에 따라 `guardian`이 `Guardian`과 소셜 계정 연결을 생성한다. Port 이름은 TBD이며 다른 모듈 Repository에 직접 접근하지 않는다. **서비스 약관·개인정보/활동 동의는 제공자 로그인 동의와 별도**다. 가입 완료 시점·필수 프로필·중복 계정·동의 화면, 가입 미완료 Context의 제한 권한과 필요 시 가입 완료 POST/CSRF 계약은 TBD다. 소셜 로그인 성공만으로 아동 접근이나 활동 시작을 허용하지 않는다.
4. 서비스 로그인 상태는 **Spring Session JDBC 내부 Session + HttpOnly Cookie**로 유지한다. 공급자 Access/ID Token을 보호자 API용 자체 JWT로 그대로 사용하지 않는다. Cookie·Session 수명과 설정은 후속 인증 계약에서 검증한다.

OAuth 리다이렉트·Callback의 요청 연관 검증은 Spring OAuth2 Client의 `state`와 OIDC 사용 시 `nonce`/ID Token 검증을 따른다. 이를 이유로 전체 CSRF를 끄지 않는다. **로그인 후 Session을 쓰는 변경 REST·`POST /api/auth/logout`에는 CSRF 방어를 유지**하고 로그인·로그아웃으로 Token이 바뀌면 다시 취득한다. Header·취득 Endpoint·SecurityFilterChain은 구현 검증 후 확정한다.

고정 ID 시드 기기와 보호자 로그인 Session은 서로 다른 관계다. 서비스 Logout, 제공자 로그인 상태 종료, 소셜 계정 연결 해제/회원 탈퇴도 별개다. 기본 Logout은 내부 Session 무효화로 설계하고 제공자 Logout/연결 해제 지원과 보존 정책은 TBD다.

### REST 오류 형태 후보

기존 ADR-002는 Spring `ProblemDetail`과 서비스 오류 코드 추가를 제안한다. 인증 없음/만료 `401`, 권한·CSRF 거부 `403`, 존재 은닉 시 `404`는 기존 구현 후보다. `VOICE_CLIENT_OFFLINE`을 포함한 Code Registry, 동의 부족·상태 충돌·중복·할당 실패의 HTTP Status와 본문은 **TBD**다. 보호자 REST에 HTML 로그인 화면을 반환하지 않는 안을 검증한다. 오류 본문에 다른 계정 정보·비밀정보를 넣지 않는다.

## 기기 `/ws` WSS 음성·제어 계약

사전 시드된 고정 ID 기기가 `/device`에서 Realtime `/ws`에 연결해 대기한다. 실제 기기 ID 값·시드 구성·메시지 필드와 직렬화는 TBD다. 고정 ID는 허용 데모 대상의 식별자이며 비밀 자격증명이나 운영 인증 완료의 증거가 아니다. 통제된 시연 네트워크·허용 Origin·현재 연결·활동 결합을 검사하며 운영용 기기 인증·발급 상세는 후속 인증 단계에서 정한다. 시연에 운영자 발급 UI·QR claim을 필수로 추가하지 않는다.

허용 대상·연결·가용성·할당을 구분한다. 가용성은 **지정한 고정 ID**가 시드된 허용 대상인지, 현재 유효 WSS/heartbeat가 있는지, 이미 점유됐는지, 이번 활동에 원자적으로 할당 가능한지로 판단한다. 전체 Available 기기 수로 다중 사용자 시작 정책을 만들지 않는다. 같은 ID의 중복 연결·연결 교체·동시 시작 경합의 처리·거부 응답은 TBD다. 보호자 시작 접수 뒤 Realtime이 할당된 대기 기기에 시작을 push한다.

WSS Handshake와 연결 후 음성·보고마다 허용 Origin 및 기기·현재 연결·ActivitySession 할당과 현재 이용 권한을 대조한다. 인증 성공만으로 활동 할당이 성립하지 않는다. REST CSRF Header가 WS Handshake에도 그대로 적용된다고 가정하지 않으며 운영용 연결 인증·Token 전달·만료 감지의 상세는 TBD다.

기기 WSS 메시지는 GPT-Live 이벤트를 그대로 노출한 것이 아니다. 기기가 `session.start` 등 공급자 명령을 직접 전송하거나 공급자 키·세션 생성 권한을 받지 않는다. 메시지명 후보 채택·필드·검증·버전·오디오 형식·대기열 한도는 POC와 구현 명세에서 고정한다.

아동의 `CHILD_PARTICIPATED`, `CHILD_STOP_REQUEST`, `PAUSE_REQUEST` 같은 **의미 이벤트를 `/device`가 직접 만들지 않는다**. 서버가 전사·공급자 이벤트·동료 명세 판단을 세션 이벤트 경로로 처리한다. 아동 발화 시작·끼어들기·재생 위치 보고만으로 자동 `ENDING`에 들어가지 않는다.

### 공통 Envelope — 기존 초안 보존

원본 재생 완료 예시의 `type`, `id`, `sessionId`, `payload`, `source`, `playbackId`, `contentCode`는 **기존 후보**이며 직렬화·채택 여부를 구현 전에 정한다. 아래 예시는 새 확정 스키마나 `playbackMark` 최종 payload가 아니다.

```json
{
  "type": "PLAYBACK_FINISHED",
  "id": "message-uuid",
  "sessionId": "session-uuid",
  "payload": {
    "source": "APPROVED_CONTENT",
    "playbackId": "playback-uuid",
    "contentCode": "CHILD_STOP_CLOSING"
  }
}
```

`source`의 기존 후보는 `GPT_LIVE`와 `APPROVED_CONTENT`다. 두 종류 모두 실제 플레이어가 관측한 범위와 관측 신뢰 조건을 확인하며 동일한 관측 능력을 가정하지 않는다. `contentCode`는 예시이고 실제 콘텐츠/버전은 동료 명세와 `content`가 관리한다. `opId`는 서버 작업 최신성용이며 반드시 기기에 노출한다는 결정은 없다.

공통 계약은 메시지 식별·명령 상관관계·세션/할당·현재 연결 시도·중복/순서 검증이 필요하며 최종 필드명은 TBD다. 다른 활동/연결의 보고를 현재 작업의 완료로 반영하지 않는다. 전사 원문·키·비밀정보를 Envelope에 무조건 포함하지 않는다.

## GPT-Live 주 WebSocket과 이벤트 대조

공급자는 GPT-Live API(`gpt-live-1`)다. audit §2.1·§5.1이 확인한 공식 시작 순서는 `wss://api.openai.com/v1/live/sessions`에 Realtime이 접속 → 모델/설정을 담은 `session.start` → `session.started` 확인이다. HTTP 세션 생성 절차를 주 WebSocket 시작 절차로 옮기지 않는다. Java SDK 지원·운영 모델/SDK 버전·시작 실패·재시도·종료/usage/저장 설정의 실제 보장은 **TBD·미검증**이다.

| 목적 | GPT-Live 주 연결 근거 | Realtime 처리·보장 경계 |
| --- | --- | --- |
| 공급자 세션 시작 | `session.start` → `session.started` | Realtime이 확인하고 서버 활동·연결과 결합. 시작 수락은 아동 참여/출력 승인과 다름 |
| 입력 음성 전송 | `session.input_audio.append` | 기기 WSS 입력을 권한·할당 검사 뒤 공급자에 전송. GPT-Live가 발화 시점을 관리하는 계약을 따름 |
| 출력 음성 수신 | `session.output_audio.delta` | 임시 메모리 버퍼로 수신하며 검사 전 기기에 통과시키지 않음 |
| 입력 전사 | `session.input_transcript.delta` | 조각 누적·발화/Turn 조립·누락/불확실 표시의 앱 책임. 단일 전사이며 별도 STT·병렬 비교 보류 유지 |
| 출력 전사 | `session.output_transcript.delta` | 앱 출력 구간과 대응. 조각·전사의 시간 정보만으로 기기 실제 재생을 확정하지 않음 |
| 발화/전사 전체 완료 | 동일한 발화별 output-audio-done 계약을 가정하지 않음 | 구간과 전체 질문/안내 완료 범위를 앱이 정의. VAD 쉼·큐 공백만으로 완료 판정하지 않음 |
| 교정 지시 | `session.instructions.append` 및 수락 | 수락 ACK는 실제 교정 성공·재생 승인과 별개. 새 음성도 다시 게이트를 통과해야 함 |
| 공급자 종료 | 주 연결의 종료/오류/사용량 관측 — 실제 이벤트명·명령·지원 범위 TBD | 소켓 종료와 공급자 마무리/usage, 기기 출력 정리를 구분. 수락·종료 이유·Timeout은 실연동 확인 |

**혼용 방지를 위한 미채택 예시:** Realtime API의 `input_audio_buffer.*`·`response.output_audio.*`·`response.done`을 GPT-Live 입력/출력/음성 한 턴의 완료 계약으로 복사하지 않는다. 수동 오디오 commit·음성 턴 생성 트리거도 옮기지 않는다. `response.create`는 GPT-Live의 Responses delegation 작업 시작/재개에서 별도 역할이 있으므로 이름만 보고 일괄 삭제하거나 일반 음성 생성에 적용하지 않는다.

delegation/KG·GraphRAG 연결은 **확인 항목·미채택**이다. mode·도구·허용 입력·권한·중복·결과 반환은 후속 확인하며, delegation 대기만으로 발화가 정지하거나 B안 게이트·도메인 소유권·정보 제한을 대체한다고 가정하지 않는다.

### 대체된 이전 선택의 종료 사유 참고 — 주 연결 적용 미확정

아래 표는 원본의 이전 연결 선택에 있던 종료 사유 후보를 이력으로 보존한 것이다. 현행 B안 주 연결의 확정 계약이 아니다. 주 연결에서 제공하는 값·필드·SDK 지원을 확인한 뒤 매핑하며 이 표로 새로운 공급자 기능을 확정하지 않는다.

| 기존 `session.closed.reason` 후보 | 원본 의미 | 서비스 매핑에 필요한 근거 |
| --- | --- | --- |
| `close_requested` | 애플리케이션 close/hangup 요청 | 보호자/아동/타임아웃 등 서버 요청 원인. 값만으로 보호자 종료를 확정하지 않음 |
| `expired` | 공급자 세션 길이 제한 | 서비스 최대 길이 정책·예고·정리·현재 상태. 시간값 TBD |
| `content` | 공급자 안전 필터 종료 | 서비스 사유·허용 기록 정책 TBD. 아동 실패/평가 결과가 아님 |
| `remote_hangup` | 주 연결 정상 종료 | 주 연결을 소유한 Realtime의 정리 요청·원인과 기기 로컬 관측을 별도로 확인 |
| `connection_lost` | 주 연결/상위 연결 예기치 않은 단절 | 장애 이벤트·유예·기기 출력 관측. 최종 서비스 매핑 TBD |

현행 서비스 상태/사유 매핑은 ADR-005·D-03·D-06에서 합의해 서버 이벤트 경로로 적용한다. 공급자 종료 관측(실제 이벤트·명령 TBD)은 기기 스피커 무음 증거가 아니며 소켓 종료만 확인했으면 공급자 마무리/최종 usage를 미확인으로 남긴다. 공급자 close 요청만으로 진행 출력이 즉시 중단됐다고 가정하지 않는다. 기기 출력·대기열 중단과 서버 버퍼·공급자 입력/출력·주 연결 정리를 병행하는 순서와 확인·Timeout은 실연동 대상이다.

## 출력 버퍼 게이트 — 전달 조건 계약

Realtime 또는 내부 미디어 Adapter가 공급자 출력 음성을 **임시 메모리**에 보관하고 출력 구간을 분할한다. VAD/noise gate는 앱/미디어 프레임워크 책임이며 직접 알고리즘을 작성한다는 결정은 없다. 구간 경계·음성/전사 대응·답변 전체 완료 기준·구현 라이브러리는 TBD다.

```text
출력 음성 임시 버퍼
→ 앱 출력 구간 분할
→ 해당 음성과 출력 전사 대응
→ 상태·권한·작업 최신성 + 필요한 경량 의미 검사
→ 동일 음성 구간 승인
→ 송신 직전 현재 조건 재확인
→ 기기 WSS 전달
→ 기기 실제 재생 관측
```

검사 수행과 통과는 **기기에 전달하는 조건**이다. 전사 정확성·대응 품질·검사기가 모든 위험을 발견한다는 보장은 아니다. 승인된 바로 그 음성만 전달하고 같은 말을 새로 생성했을 때 이전 승인을 재사용하지 않는다. 일반 출력·Cue·재생성 출력에 같은 전달 조건을 적용한다. 고정 승인 콘텐츠는 활동에 확보·고정한 승인 버전 계약을 따르며 실시간 미검사 출력을 승인 콘텐츠로 바꿔 부르지 않는다.

게이트 안에는 상태·권한·최신성과 필요한 경량 의미 검사를 둔다. 무거운 교육 판정·KG/GraphRAG를 동기 경로에서 분리하는 것은 **우리 설계 권고**다. 필요한 안전 검사를 사후로 미루거나 게이트에서 LLM을 금지한다는 뜻이 아니다. 안전 판단에 추가 근거가 필요하면 준비된 근거를 쓰거나 전달을 보류하며 검사 모델은 제브(Jev) 가드레일이고, 분류·구조화 결과는 AI 동작 명세 v0.2 §10.2, 대상·처리는 기술명세서 v0.3 §7.7을 따른다.

전사 누락·대응 불명확·검사 실패·시간초과·버퍼 포화 시 미검사/미승인 음성을 폐기하고 대체 안내 경로로 전환한다. 버퍼 시간·크기·포화 한도, 대체 안내 콘텐츠·실패·재생성 조건/횟수는 TBD다. 임의 문구·무제한 재생성이나 실패 시 통과 경로를 추가하지 않는다. 중계 실시간 원음은 임시 메모리에서 폐기하며 Outbox·Inbox·DB·일반 로그·디스크에 복제하지 않는다. 기존 승인 안내 음성 파일의 보존 범위와 실시간 원음을 구분한다.

### 취소·늦은 승인·차단 후 회복

| 취소 사유 | 전달·재생과 상태 처리 |
| --- | --- |
| 끼어들기 | 현재 음성 버퍼·기기 대기열을 취소하고 실제 중단/재생 범위를 관측. 대화 말차례 변경일 수 있으며 자동 `ENDING`이 아님 |
| 쉬기 | `PAUSED`로 전이하고 일반 출력 승인·대기 출력·관련 타이머를 무효화. 재개 뒤 기존 음성을 자동 재생하지 않음 |
| 보호자 종료 | 유효 STOP의 종료 우선 경로에서 `ENDING`·일반 출력 차단·버퍼/기기 대기열 취소·실제 중단 확인을 연결 |
| 아동 종료 A안 | 유효 표현 서버 확인 즉시 `ENDING` → 일반 질문/연습/출력 차단 → 버퍼·기기 대기열 폐기·늦은 승인 무효 → 고정 승인 마지막 인사 1회만 예외 → 실제 정리 확인 |
| 동의 철회 | 새 처리·외부 전송·출력 승인·저장 전에 현재 이용 가능성을 확인. 불가/미확인이면 새 이용을 보류·차단하고 출력·대기열 정리. 효력·경합·최종 상태는 후속 계약 |

취소된 구간의 늦은 전사·검사 통과·승인으로 재생 권한을 되살리지 않는다. 아동 종료의 인사 완료는 `ENDING` 선행 조건이 아니며 인사 실패로 일반 출력을 다시 열지 않는다. 실제 중단·서버 최종 상태·공급자 종료는 독립된 사실로 확인한다.

기기에 보내지 않고 폐기한 음성도 GPT-Live 모델 맥락에 남는다. 차단 후 대화를 계속할 때 앱이 작성한 교정 지시를 회복 정책에 따라 `session.instructions.append`로 보낸다. 미승인 사용자/모델 원문을 시스템 지시로 복사하지 않는다. 교정 수락 ACK는 맥락 삭제·실제 교정 완료·재생 승인이 아니며 교정 뒤 새 출력도 전사 대응·검사·재승인을 거친다. 일반 끼어들기·종료·가드레일 차단의 후속 정책·추가 공급자 명령은 TBD다.

## Core ↔ Realtime 앱 간 전달

앱 간 즉시 명령은 내부 HTTP로, 유실되면 안 되는 요청·완료·정책 변경 사실은 **PostgreSQL Transactional Outbox + 내부 HTTP Sender + 수신 멱등성/Inbox**로 전달한다. Broker는 추가하지 않는다. 같은 DB를 써도 상대 앱의 업무 Repository를 직접 수정하지 않으며 일반 프로세스 내부 이벤트가 다른 JVM에 자동 전달된다고 구현하지 않는다. Endpoint·DTO·물리 컬럼·인증 방식·시간/재시도 한도는 TBD다.

### 즉시 명령·조회

활동 생성/준비 취소/종료·현재 상태 조회·허용 자료 조회·목표 등록은 내부 HTTP 계약을 따른다. Core가 검증한 주체·허용 행위·대상·기한을 전달하고 Realtime은 서비스 자격과 기존 활동/기기/주체 결합 및 현재 이용 가능성을 대조한다. 내부 인증은 사용자 인가를 대신하지 않는다.

시작은 Realtime이 짧은 로컬 트랜잭션으로 중복 확인·기기 할당·`PREPARING`·접수 기록을 커밋해 접수 사실을 반환한다. 연결 준비·시작 push·참여는 별도로 진행한다. 응답 유실 시 같은 논리 요청으로 접수 결과를 재조회하며 새 활동/공급자 세션을 임의로 만들지 않는다. STOP은 사후 Result Worker 대기열 뒤에 두지 않고 종료 우선 경로로 처리한다. DB 장애 때 안전 차단 시도와 영속 종료 저장 실패를 구분한다.

Core 장애 중 보호자가 Realtime으로 직접 종료하는 대안은 **미확정**이다. B안 릴레이 채택만으로 Core 경유 의존이 해결됐다고 기록하지 않는다.

### 영속 이벤트와 수신 ACK

1. 발신 앱은 자신의 업무 변경과 Outbox를 같은 로컬 DB 트랜잭션으로 저장한다.
2. Sender는 제한된 개수를 선점하고 DB 트랜잭션 밖에서 내부 HTTP로 전송한다. 한도·선점/lease·재시도 상세는 TBD다.
3. 수신 앱은 이벤트 식별·주체·대상·버전·정책을 검증한다. 업무 반영을 함께 커밋하거나 Inbox를 영속 저장한 뒤 수신 ACK를 보낸다.
4. Inbox 후처리는 업무 상태 반영과 처리완료 표시를 같은 트랜잭션으로 마친다. 각 앱이 자신의 미처리 Outbox/Inbox를 재시작 뒤 복구한다.
5. ACK 유실·중복·순서 역전을 처리하고 동일 업무 효과를 중복 만들지 않는다. 전달 재시도를 새 LLM 호출로 세지 않으며 전달 성공이 업무 후처리·결과 준비 성공을 뜻하지 않는다.

이벤트에는 필요한 ID·버전·최소 참조를 전달하고 원문을 무조건 복제하지 않는다. 실시간 원음은 Outbox/Inbox에 넣지 않는다. 전사 스냅샷·삭제 표식·중복 제거 기록은 보존/삭제 정책의 대상이며 삭제 후 재전송이 자료를 복원하지 않게 검사한다. 내구성·복구 규칙 아래 유실 위험을 줄이는 설계이고 외부 AI 정확히 한 번 실행이나 영구 장애 자동 성공을 보장하지 않는다.

### 상관관계·중복·최신성 — 기존 논리 식별자

| 기존 논리 이름 | 목적 |
| --- | --- |
| `requestId` | 동일 상태 변경 요청 재전송. 주체·동작·대상·내용 해시·처리 기한·결과 재확인과 결합 |
| `eventId` | 영속 이벤트 식별. 네트워크 재전송에서 유지 |
| `activityOpId` / 기존 `opId` | 현재 상황·대화·Cue·판정 최신성. 종료·쉬기에서 효력 무효화 |
| `jobRunId` | 사후 결과 실행. 보호자의 새 수동 재시도와 이전 실행 구분 |
| `candidateId` + `inputVersion` | 목표 등록 후보 중복/입력 버전 검사 |
| `authorizationEpoch` / `policyVersion` | 동의·삭제·권한 변경 후 현재 이용 가능성 검사 |
| `streamVersion` / `expectedStateVersion` | 활동 순서·상태 경합. 이벤트 중복 제거와 별도 |

이 이름은 v0.2의 논리 계약과 원본 후보이며 Java 클래스·wire 필드·DB 컬럼 확정이 아니다. 실제 이름·필수 조합·보존 기간은 TBD다. 종료 때 활동 작업 ID가 바뀌었다는 이유로 정상 사후 `ResultReady`를 전부 폐기하지 않는다. Realtime은 기대 `jobRunId`·입력 버전·결과 대상·현재 자료 권한을 확인해 결과 참조를 연결하며 이전 run이 새 실행을 덮거나 `PARTIAL`/종료 활동을 `ACTIVE`로 되살리지 못한다.

### 현재 권한·철회·앱별 복구

Core는 동의 변경과 철회 이벤트를 함께 저장해 Realtime에 우선 전달한다. Outbox 알림만으로 즉시 반영이 보장되지는 않는다. Realtime과 Core Worker는 새 처리·외부 요청·저장·결과 반영 전 현재 이용 가능성을 검사하고 불확실하면 새 이용을 보류·차단한다. 종료/안전 정리를 동의 재확인 실패로 막지 않는다. 철회 효력 시각과 확인/저장/송신 사이의 경합·권한 fence 또는 동등 원자성 계약은 TBD다.

Core는 자신의 Job/Outbox/Inbox만 복구하며 정상 Realtime 활동을 일괄 오류 처리하지 않는다. Realtime은 자신이 소유한 진행 중 음성 활동을 자동 재개하지 않고 ADR-005의 오류 정리 정책을 따른다. `RESULT_PENDING`/`PARTIAL` 참조와 영속 Inbox를 보존한다. 릴레이 메모리 버퍼를 재시작 뒤 복원하거나 미확인 재생을 성공으로 채우지 않는다. ResultJob lease·이전 실행 차단·체크포인트의 논리 계약은 [result-pipeline.md](result-pipeline.md)에 반영했다. 실제 선점/lease·fencing·체크포인트 구조와 장애 시험은 TBD다.

| Realtime Grace Period | 원본 직접 연결 때 약 6~7초 후보. B안 적용 TBD | ADR-005 |

위 연결 시간값은 **Proposed**다. 무응답 10초·Cue 5초의 합의 초기값과 구분한다. 재연결되어도 이미 종료한 공급자 실시간 세션·기기 대기열·활동을 이어 붙이지 않는다. 실제 중단과 로컬/공급자 연결 close, 최종 상태 저장을 구분하고 확인 불가를 남긴다. 재연결 동기화·현재 할당 조회·종료 확인 Timeout·중복 연결은 TBD다.

## 동적 목표 조회·선택 계약 — 후속 구현안

목표 생성은 [Core result Worker 내부 작업](result-pipeline.md#goal-generation-contract)이며 보호자에게 모델 생성 API를 직접 노출하지 않는다. REST 후보의 목표 조회·선택 의미를 보존하며 오류 코드·DTO는 후속 API 명세에서 연결한다. 아래 필드명은 **기존 Proposed**다.

| 경계 | 최소 계약 |
| --- | --- |
| 목록 항목 | `recommendationId`, `behaviorDefinitionId`, `behaviorDefinitionVersion`, `displayName`, `recommendationReason`, 접근 가능한 `evidenceRefs`. 등록 검사를 통과한 해당 아동 후보만 표시한다. |
| 목록 상태 | 정상 추천 없음과 생성 중/기술 실패를 구분. 근거 부족의 추천 없음만으로 자유대화 결과 전체를 `INSUFFICIENT` 또는 `RESULT_FAILED`로 바꾸지 않음 |
| 선택 요청 | `recommendationId`, 조회한 `behaviorDefinitionVersion`. 아동 소유·현재 이용 가능 근거·등록 검사·버전 검증. 오래된 버전은 재조회가 필요한 충돌로 처리 |
| 선택 응답 | `selectionId`, 선택한 정의 ID·버전. 선택만으로 활동/공급자 세션을 시작하지 않음. 시작 시 선택·근거·동의를 재검사해 활동 버전 고정 |
| 내부 전달 | 상황·평가에는 필요한 정의·기준을 전달하되 GPT-Live 대화 역할에는 전체 정의 패키지의 판정 기준을 보내지 않음. Core는 Realtime의 목표 등록 계약 사용 |

서버가 허용 기록에서 실제 근거 참조를 제공한다. 모델의 가짜 식별자·임의 인용을 그대로 목록에 넣지 않는다. 삭제 근거와 의존 추천은 재검사/무효화하며 [목표 데이터 모델](data-model.md#goal-definition-model)에 저장·중복·버전의 후속 정합성을 연결한다.

<a id="cue-contract"></a>
## 실시간 Cue 입력·출력 계약 — 합의한 구현 기본안

GPT-Live 실시간 생성, 첫 반응 보호·도움 동의·정답 직접 제시 금지·실제 제공 기록은 기존 확정 정책이다. Cue 상태·시간·실패 분기는 [Cue 단계](session-state.md#cue-lifecycle), 소유 책임은 [ADR-007](../ADR-007-module-boundaries.md#goal-and-cue-ownership), 저장 후보는 [Cue 기록 모델](data-model.md#cue-delivery-model)에 연결한다. 책임/데이터 문서에 두 앱 소유권·원격 계약·실제 제공 참조를 반영했으며 실제 필드·구현·검증은 TBD다.

### Realtime 내부 요청과 역할별 정보

Realtime `practice`가 유효한 첫 반응·아동 도움 동의를 확인해 요청을 구성하고 `activity`의 단계/작업 최신성 검사를 거쳐 `voice`가 공급자에 연결한다. 원격 Core 근거/지식 조회가 필요하면 공개 계약을 사용한다. 실제 Port/DTO 클래스·SDK 이벤트 매핑은 TBD다. 기기가 의미를 판단해 Cue 제공을 결정하지 않는다.

| 기존 내부 요청 후보 | 의미·전달 범위 |
| --- | --- |
| `cueId`, `sessionId`, `practiceAttemptId`, `scenarioId` | 서버가 부여/검증한 활동·기회·요청 식별. 모델에게 생성하도록 요구하지 않음 |
| `behaviorDefinitionId`, `behaviorDefinitionVersion` | 선택 정의 버전과 연결. 전체 객체를 대화 모델에 직렬화하지 않음 |
| `firstResponseId`, `consentResponseId` | 이번 기회의 첫 반응·도움 동의 참조. 과거 활동 동의 재사용 금지 |
| `opId`, `connectionAttemptId`, `requestNo` | 작업·연결 최신성·재요청 내부 상관관계. 기기에는 필요한 불투명 재생/할당 식별자만 전달하며 공급자가 서비스 작업 ID를 자동 적용한다고 가정하지 않음 |
| `contextBrief` | 현재 상황·상대 역할·실제 제공한 상대 말·이번 아동 반응의 필요한 정보. 아동 발화는 자료이며 시스템 지시로 실행하지 않음 |
| `supportFocus`, `cuePolicyVersion` | 도움 초점·적용 규칙 버전. 프롬프트/대본은 동료 명세 소유 |

`CueBrief` 허용 내용은 **현재 상황, 이미 제공한 상대의 말, 현재 아동 반응, 허용 도움 초점, 짧은 1~2문장 및 정답 직접 제시 금지 같은 표현 규칙**이다. 판정표·평가 레이블·이전 판정·보호자 원문·타 아동 정보는 제외한다. 부족한 정보를 채우려고 전체 `BehaviorDefinition`/ActivityContext를 보내지 않는다. 역할 지시 변경만으로 기존 세션 맥락이 삭제/분리된다고 취급하지 않는다.

호출 전 도움 허용 단계·첫 반응 유효성·이번 동의·현재 권한·최신성·중복·금지 정보 부재를 검사한다. 출력은 구간 분할→전사 대응→게이트 검사→동일 음성 승인→현재 조건 재확인→WSS 전달을 거친다. 첫 반응 전·새 상황의 목표 Cue, 취소/쉬기/종료/철회 뒤 오래된 출력은 차단한다.

### 출력·실제 제공 보고·실패

GPT-Live를 완성된 도움말 JSON 하나를 반환하는 API로 가정하지 않는다. 공급자 음성/전사 조각과 앱 구간·게이트·기기 재생 관측을 연결한다.

| 관측/보고 | 기록할 의미 |
| --- | --- |
| 공급자 요청 수락·교정/명령 ACK | 처리 수락 사실. 생성·재생 시작·완료 증거가 아님 |
| 도움 전사·게이트 | 생성 내용과 조립/대응·검사·승인 사실. 구간을 Cue와 확실히 연결하지 못하면 보류·폐기하고 실제 제공으로 기록하지 않음 |
| 실제 재생 관측 | 기기 플레이어의 시작·진행·중단·완료·실패·확인 불가. 의미/도움 적절성 판단은 서버 책임 |
| 제공 완료 반영 | 현재 작업·동의·단계와 실제 재생 근거를 함께 검증. 전사·승인·송신 완료만으로 완료 처리하지 않음 |

원본의 `sessionId`, `connectionAttemptId`, `playbackId`, `sequence`, `playbackStatus`, `observedAt`, `playedRange`, `failureReason`는 **기존 재생 보고 필드 후보**로 보존한다. 범위 미확인에 `playedRange=null`과 사유를 두는 기존 예시도 최종 wire 확정이 아니다. `playbackMark`와의 필드 통합·단위·시각 기준·완료 정의는 TBD이며 정확한 단어별 재생 시각을 보장하지 않는다.

필요한 의미 검사와 상태·권한·최신성 검사를 전달 조건으로 적용하며 실패·누락·불명확·시간초과에서 미검사 음성을 전달하지 않는다. 생성 내용을 검사했어도 실제 제공 범위는 기기 관측으로 따로 확인한다. 뒤늦은 부적절 발화 감지에서는 현재/대기 출력 정리·실제 영향 범위·이후 반응의 정상 판정 사용 제한을 기록하고 실제 제공 이력을 삭제하지 않는다.

수락·재생 불명확/부분 재생·총 한도 만료 뒤 자동 재요청하지 않는다. 명확한 미수락·일시 오류·전혀 미제공 확인 시 총 5초 안에서 조건부 추가 요청 최대 1회를 적용한다. 구간 분할·전사·검사·송신·기기 시작 대기를 포함하고 요청 번호 변경·재생성이 최초 시각/동의/활동 유효성을 초기화하지 않는다. 실제 5초 달성과 이미 시작한 재생의 완료/실패 대기는 POC·상세 계약 대상이다.

이전 Cue의 늦은 결과/보고를 새 상황 완료나 아동 성공/실패로 반영하지 않는다. 확인된 제공 내용·미실시·기술 오류를 구분하고 차단 후 교정 ACK가 도움 제공으로 집계되지 않게 한다.

## 대체된 이전 선택·미채택 대안

아래는 원본 선택의 이력이며 현행 구현 규칙이 아니다.

- **직접 WebRTC·SDP Relay·Data Channel·Sideband:** 원본은 `/device`가 마이크/`RTCPeerConnection`·SDP Offer를 준비하고 `POST /api/device/sessions/{sessionId}/rtc`에서 `{ "sdp": "v=0..." }`를 주고받았다. 서버는 공급자 세션과 Sideband를 관리하고 브라우저 Data Channel의 이벤트 Allow List·`session.started`를 사용했다. `START_NEGOTIATION`은 SDP 시작 후보였다. 브라우저 직접 연결과 기기 WSS 비음성·서버 음성 비중계 전제는 B안으로 대체됐으며 이 경로·payload·Allow List·attach 선후·과거 이벤트 시험을 현행 계약으로 쓰지 않는다.
- **공급자 직접 연결 권한:** 원본 브라우저의 공급자 명령/관측 권한 후보는 Realtime 소유 주 연결로 대체됐다. 브라우저용 임시 키·Ephemeral 경로를 새 기본안으로 추가하지 않는다.
- **3개 로그인:** 원본은 카카오·Google·네이버와 `kakao`·`google`·`naver` 등록·Callback·속성 매핑·시험을 포함했다. Google만 제공하는 최신 확정이 그 활성 범위를 대체했다.
- **기기 발급 후보:** 원본은 `/device` 단기 인증 Cookie·운영자 일회용 발급 코드와 발급 POST·TTL·갱신을 후보로 제안했다. 현행 시연은 고정 ID 사전 시드·대기 WSS이며 그 발급 UI를 필수 전제로 삼지 않는다. 운영 인증 상세는 별도 TBD다.
- **전역 기기 수 규칙:** 원본의 Available 0개 차단·1개 사용·2개 이상 차단은 지정한 고정 ID 기기의 허용·현재 연결·점유·할당 검사로 대체했다. 전역 다중 사용자 정책으로 확장하지 않는다.
- **생성 발화 사후 기록 중심 검사:** 원본은 실제 전사·재생을 연결하되 전달 전 버퍼 게이트를 추가 과제로 남겼다. 현행은 검사 통과를 전달 조건으로 삼고 검사 품질·실제 재생 관측을 별도로 검증한다.
- **인사 후 종료 진입:** 승인 인사 완료 뒤 `ENDING`인 과거 순서는 유효 아동 종료 표현 확인 즉시 `ENDING`인 A안으로 대체됐다.
