- 개정 요약 ① 유효한 아동 종료 표현의 즉시 `ENDING`, 출력 버퍼 취소, `playbackMark` 관측과 앱별 복구를 현행 상태 흐름에 반영.
- 개정 요약 ② 인사 재생 뒤 `ENDING`, 직접 WebRTC·Sideband 준비 및 단일 Spring 재시작 정리 전제를 대체된 이전 선택으로 이동.
- 개정 요약 ③ 출력 구간·질문 완료 기준, 재생 보고 세부, 결과 준비 표현·복구 경합, Cue 5초 달성 여부는 TBD.

## ActivitySession 전이

전체 상태도는 **[ADR-005 §2.2](../ADR-005-session-events-timeouts.md#22-세션-상태-전이-기본-구조)**에서 관리한다. 아래는 첫 볼트가 사용하는 분기의 요약이며 새 상태를 추가하는 계약이 아니다.

| 상황 | 현행 전이·처리 | 첫 볼트 확인 기준 |
| --- | --- | --- |
| 보호자 시작 수락 | `PREPARING` 생성 | 소유권·현재 동의·기기 가용성·중복 시작·할당 검사. 시작 전 화면 취소는 세션을 생성하지 않음 |
| 기기 WSS·GPT-Live 주 연결 준비 | 준비 사실만 보고, `PREPARING` 유지 | `session.started` 또는 기기 준비 보고를 아동 참여로 해석하지 않음 |
| 아동 참여 확인 | `PREPARING → ACTIVE` | 동료 명세의 참여 처리 결과를 서버 이벤트 경로로 전달. `/device`가 의미를 판단하지 않음 |
| 참여 거부 | `PREPARING → DECLINED` | 최대 1회 대안 제안·재거부 종료 원칙, D-07 경계 합의. 미참여 응답 원문 미저장 |
| 준비 중 보호자 취소·시작 확인 무응답 | `PREPARING → CANCELLED` | 준비 취소 API·무응답 기준은 계약/시간값 합의 후 검증. 아동 행동 실패로 기록하지 않음 |
| 참여 후 보호자 종료 | `ACTIVE` 또는 `PAUSED` → `ENDING`; 유효 기록이 있으면 `PARTIAL` | 종료 사유와 출력 중단 확인을 구분. 첫 볼트에서 사후 결과 생성·요약 미구현은 전체 제품의 부분 결과 요구를 취소하지 않음 |
| 유효한 호출어+종료 명령 | 확인 즉시 `ACTIVE` 또는 `PAUSED` → `ENDING`; 유효 기록이 있으면 `PARTIAL` | 일반 질문·연습 진행·일반 출력 차단과 버퍼 폐기 후 승인 마무리 인사 1회 예외. 실제 재생/연결 정리를 별도로 확인 |
| 진행 중 무응답 | 실제 재생 완료 → 10초 → 재안내 1회. 이후 상태 전이는 TBD | 유효한 반응 대기 단계만 적용. 재안내 이후 대기·미실시/종료 조건을 합의하며 자동 `PARTIAL` 종료로 고정하지 않음 |
| 복구 불가 연결 장애·Realtime 재시작 | 진행 중 음성 활동의 `ERROR` 정리 경로 | 합의한 장애 조건을 적용. 닫힌 공급자 세션이나 메모리 버퍼를 재개하지 않으며 기술 문제를 행동 실패로 바꾸지 않음 |
| Core 재시작 | 정상 Realtime 활동의 상태 유지 | Core가 소유한 결과 작업·영속 전달만 복구. Realtime 활동을 일괄 `ERROR`로 바꾸지 않음 |

`ENDING`은 내부 상태다. 연습 단계 `CLOSING`과 다르다. `ERROR`는 활동 자체의 기술 실패이고 `RESULT_FAILED`는 활동 기록은 남았으나 사후 결과 생성이 실패한 경우다. `PREPARING`에서 응답 없이 끝난 세션은 `CANCELLED`이며 아동 행동 실패로 기록하지 않는다. 유효 기록의 중도 종료는 `PARTIAL`로 남겨 부분 결과를 처리하되 결과 준비 상태와 구분한다. 결과 산출·준비의 표현과 자료 부족·철회 분기는 TBD이며, 없는 원문이나 점수를 만들어 채우지 않는다.

현재 첫 볼트의 종료 화면은 최소 종료 사실·사유를 다룬다. 시작 전 미참여는 FR-F11의 종료 사실·시각만 보존하고 대화 내용을 남기지 않는다. 참여 이후 중도 종료 기록 보존은 D-08 합의 범위로 제한하며, 미참여 규칙을 중도 종료 전체에 확대하지 않는다.

## 음성 제어와 참여 처리

쉬기·재개·종료 등 현재 허용된 음성 제어는 요구사항 FR-E05의 **호출어+명령어 키워드**로만 처리한다. 키워드 없는 “그만할래”나 역할 대사, 기기 재생 음성은 제어 명령으로 변환하지 않는다. 참여 확인·거부 처리는 FR-E01·E02의 별도 흐름이며 일반 제어 명령 추론으로 대체하지 않는다. 원본의 사용자 연습 건너뛰기는 대체된 이전 선택이며 현재 범위에 다시 넣지 않는다.

서버는 동료 명세의 키워드 처리 결과를 활동 제어 이벤트로 연결한다. 인식 기준·현재 설정 적용 시점·초기값·재유입 배제 방식은 D-04에서 정한다. `KeywordCommand` 같은 코드 이름과 payload는 **후보**이며 여기서 확정하지 않는다. 첫 볼트는 종료 명령을 선택하고 쉬기·재개 등 나머지 허용 제어와 설정 UI는 후속으로 남긴다.

## 상태 변경 경로와 동시성

```text
보호자 요청 / VoiceClient / GPT-Live / ResultWorker
  → SessionEventIngress
  → SessionEventQueue (세션 단위 논리적 직렬화)
  → SessionEventProcessor
  → SessionStateMachine
  → ActivitySession 저장 및 후속 명령
```

`SessionStateMachine`은 현재 상태와 이벤트로 다음 상태·동작을 정하고 Queue를 역호출하지 않는다. Realtime이 ActivitySession의 변경을 소유하며 `voice`와 Core의 `result`는 이를 직접 수정하지 않는다. 실시간 Cue·판정·음성 작업의 작업 식별이 현재 작업과 다르면 늦은 결과를 폐기하고 기록한다. 반면 정상 사후 `ResultReady`는 종료 때 실시간 작업 식별이 바뀌었다는 이유만으로 버리지 않는다. 기대한 결과 실행·입력 버전·결과 대상·현재 자료 이용 허용을 확인해 결과 참조만 연결하고, 닫힌 활동을 진행 상태로 되살리지 않는다. 식별자 물리 필드명은 TBD다. STOP을 일반 실시간 이벤트보다 우선하며 이벤트 저장·Queue 구현 형태(Spring Event 또는 자체 Queue)는 ADR-007 Pending이다.

보호자 종료·서버의 키워드 처리 결과·연결 장애와 후속 `ResultReady`/`ResultFailed`, 삭제 요청처럼 동시에 들어올 수 있는 변경은 같은 세션 처리 경로에서 조정한다. 상태를 바꿀 수 있는 이벤트는 현재 상태·할당·작업 최신성과 중복 처리를 확인한다. 결과 준비 사실은 `PARTIAL`을 `RESULT`나 `ACTIVE`로 바꾸지 않고 별도로 취급한다. 인증 만료·철회 이벤트의 이름·우선순위·상태 매핑과 삭제/결과 완료 경합 규칙은 **TBD**다. 이름이 없는 새 이벤트를 기존 종료 사유에 임의 대응시키지 않는다.

## 출력 버퍼 승인·취소와 끼어들기

[ADR-004 §2.5](../ADR-004-communication-voice.md)의 현행 경로에서는 Realtime이 GPT-Live 출력 음성을 임시 메모리 버퍼에 두고 앱이 정한 출력 구간을 대응 전사와 묶는다. 상태·현재 권한·작업 최신성 및 필요한 경량 의미 검사를 거친 바로 그 음성만 기기로 전달한다. 전사 누락·대응 불명확·검사 실패·시간초과·권한 상실 때는 미승인 구간을 폐기하고 대체 안내 경로를 따른다. 승인 결과가 늦게 도착해도 전달 직전에 다시 현재 조건을 확인한다. 구간 경계, 대체 안내 내용·재생성 한도와 버퍼 시간·크기·포화 처리는 TBD다.

| 입력 | 상태·출력 처리 |
| --- | --- |
| 아동 끼어들기 | 현재 출력 구간의 서버 버퍼·기기 대기열을 취소한다. 마지막 신뢰 재생 범위가 보고되면 수신·검증하고, 보고가 없으면 확인 불가로 남긴다. 말차례 변경 자체는 자동 `ENDING`이 아니다. 이후 발화가 유효한 종료 표현인지는 별도 서버 판정으로 결정한다. |
| 유효한 쉬기 | `PAUSED` 경로와 함께 현재 출력 구간 승인 효력을 취소한다. 재개 시 이전 버퍼나 대기열을 자동 재생하지 않는다. |
| 보호자 STOP·유효한 아동 종료 | 종료를 우선 처리하고 일반 출력 승인 효력, 대기 버퍼·기기 대기열을 취소한다. 아동 종료에 한해 아래 승인 마지막 인사 1회 예외를 둔다. |
| 동의 철회 | 신규 처리·출력 전달을 차단하고 버퍼·대기열 정리를 요청한다. 철회 효력 시각, 경합·최종 상태/사유는 D-08과 자료 계약의 TBD다. |

취소된 구간의 늦은 검사 통과·승인은 재생 권한을 되살리지 못한다. 폐기한 음성도 공급자 모델 맥락에 남는다. 회복이 필요한 경우 앱이 작성한 교정 지시를 별도 경로로 보낸다. `session.instructions.append`의 수락은 교정 완료나 음성 재생 승인이 아니다. 재생 범위 관측을 공급자 맥락 삭제로 취급하지 않는다.

## 실시간 Cue 생명주기 — 2026-10-02 구현 기본안

**기능 정책:** GPT-Live가 도움을 실시간으로 생성하고 음성으로 제공한다(FR-E08·FR-F02). 아동 동의를 받고 정답 문장을 제공하지 않으며, 도움 거절은 새 상황으로 연결한다. 첫 반응 전·새 상황에는 목표 Cue를 제공하지 않는다. **기술 설계:** 아래는 사용자 합의 구현 기본안이며 작업 상태·식별·관측의 상세 표현은 Proposed다. [ADR-005 §10.2](../ADR-005-session-events-timeouts.md#cue-timeout)의 총 5초는 합의한 초기 설정이고 아직 미측정이다. 새 ActivitySession Enum을 확정하는 표가 아니다.

도움은 선택한 행동 버전·현재 상황/기회·연습 단계·작업 `opId`에 묶는다. 상황·도움·판정은 같은 행동 버전을 참조하되, 친구/대화 역할에는 판정 기준·보호자 입력 원문·이전 판정값을 넘기지 않는다. 허용 정보와 전송 계약은 [protocol.md](protocol.md#cue-contract), 이력은 [data-model.md](data-model.md#cue-delivery-model), 목표 생성·버전 조건은 [result-pipeline.md](result-pipeline.md#goal-generation-contract)를 따른다.

| 현재 단계/관측 | 서버 처리 | 다음 단계·기록 |
| --- | --- | --- |
| 첫 반응 전 또는 새 상황 | 목표 Cue 요청·늦은 Cue 출력을 차단 | 해당 반응 단계 유지. 같은 내용 반복·속도 조절을 자동으로 Cue로 집계하지 않음 |
| 도움 필요, 동의 대기 | 아동에게 도움 동의를 구하고 응답을 확인 | 동의 전 생성/재생 금지. 거절이면 거절 사유를 기록하고 새 상황 |
| 도움 동의·상태/연결/버전 유효 | 허용 상황 정보로 GPT-Live에 Cue 요청; 최초 요청 시각·작업 연관 기록. 출력 구간·전사 대응·검사 승인·송신을 거침 | 실제 재생 시작까지 대기. 생성 완료·출력 전사·승인·ACK로 제공 완료 처리하지 않음 |
| 총 5초 이내 명확한 미수락 + 일시 오류 + 전혀 미제공 확인 | 동일 논리 작업의 추가 요청 최대 1회 | 최초 총 한도를 연장하지 않음. 시도 구분과 중복 재생 방지 |
| 실패 처리 중 수락 불명확·일부 재생, 또는 총 한도 초과 | 재발행하지 않고 이전 작업/대기 출력 취소·차단. 늦은 승인을 무효화 | 제공/미제공/일부 제공/확인 불가 사실을 기기 관측에 따라 남김 |
| 실제 재생 시작·완료 확인 | 해당 작업·기회·승인 출력과 기기 관측을 연결 | 실제 제공된 도움 내용·종류·순서·시각·재생 범위를 기록한 뒤 도움 후 아동 반응 1회 수집. 무응답은 [ADR-005 §5.2](../ADR-005-session-events-timeouts.md#no-response-wait) 적용 |

| 부적절 도움 발화 검사 차단 또는 뒤늦은 감지 | 전달 전이면 버퍼 폐기·대체 안내, 이미 재생 중이면 플레이어·공급자 출력 중단/정리. 영향받은 이후 반응은 정상 판정 근거에서 제외 | 기기 관측 범위·실제 재생·검출 시점을 구분. 이후 분기는 위 정리 확인/연결 조건에 따름 |
| STOP·쉬기·단계 변경·오래된 opId | Cue 대기/재요청 취소, 기존·대기·늦은 출력 차단 | STOP은 종료 경로, 쉬기는 PAUSED 경로. 재개해도 이전 Cue 자동 재생 금지 |

**총 5초는 최초 요청에서 실제 도움 음성 재생 시작까지**이며 출력 구간 분할, 전사 대응, 게이트 검사, 송신, 기기 재생 시작 대기를 포함한다. 재생성·조건부 추가 요청 때도 최초 요청 시각을 초기화하지 않는다. 재생 완료 시간·아동 반응 대기 시간은 별개다. 재생 시작 보고가 아직 없다는 이유만으로 미제공을 추정하지 않는다. 한도 만료 뒤 확인되는 늦은 재생·부분 재생은 실제 이력에 남기되 새 요청이나 정상 완료로 바꾸지 않는다. 5초 달성 여부와 이미 시작한 재생의 완료/실패/중단 관측·대기 한도는 POC 및 상세 계약 대상이다.

STOP·쉬기는 모든 표 행보다 우선한다. 유효한 아동 종료 표현이 확인되어 `ENDING`으로 들어가는 즉시 Cue를 무효화하므로 승인 마지막 인사 예외가 이전 Cue를 허용하지 않는다. 단계 변경·동의 철회 등으로 요청 당시 허용 조건이 사라지면 뒤늦은 공급자 응답을 적용하지 않는다. 잘못된 Cue를 제공받은 반응을 `UNCERTAIN` 값 하나로만 덮어 정상 판정 대상으로 복귀시키지 않으며, 실제 제공 사실과 판정 사용 제한을 함께 보존한다.

허용 단계·정보 검사는 GPT-Live 요청 전에도 적용한다. 생성된 출력은 Realtime의 임시 버퍼에서 전사와 대응시켜 필요한 검사를 통과한 구간만 재생 전에 전달한다. 대응 불명확·누락·실패·시간초과에서는 미검사 음성을 전달하지 않는다. 이 게이트는 전사 정확성이나 의미 검사 품질의 보증이 아니며 실제 플레이어 중단, 출력·전사의 연관, 부분 재생/미확인의 기록을 POC에서 검증해야 한다. 프롬프트와 검수 기준 자체는 동료 AI 명세를 참조한다.

## 종료와 재생 완료

- **보호자 STOP**: ADR-005의 종료 우선 원칙을 따른다. 일반 출력 승인과 진행 작업을 즉시 무효화하고 Realtime의 버퍼·기기 대기열 및 공급자 주 연결 정리를 병행한다. 한 경로의 수신 ACK를 다른 경로의 실제 중단으로 간주하지 않는다. 전달·확인·재시도 순서는 [sequences.md](sequences.md)·[protocol.md](protocol.md)에서 합의한다. 네트워크와 무관한 원격 즉시 중단을 보장하지 않는다.
- **아동 종료 A안 — 현행**: 기존 호출어+종료 명령 기준으로 유효한 종료 표현을 확인하면 즉시 `ENDING`으로 전환·기록한다. 이어 일반 질문·연습 진행과 일반 GPT-Live 출력을 차단하고, 대기 버퍼·기기 대기열의 일반 출력을 폐기한다. 활동에 고정된 승인 콘텐츠 버전의 마지막 인사 **1회만 예외**로 전달하고, 실제 출력·연결 정리 여부는 따로 확인한다. 문구·발화 판정은 동료 명세가 소유하며 인사 재생 완료를 `ENDING` 진입 조건으로 삼지 않는다.
- **대체된 이전 선택**: 원본은 승인 마무리 인사 재생 완료 뒤 `ENDING`에 들어가고 즉시 `ENDING` 안은 검토안으로 남겼다. 최신 A안이 그 순서를 대체했다. 과거의 직접 WebRTC·Sideband 기반 출력 중단 설명도 현행 B안의 기기 WSS·서버 버퍼 정리 경로에 적용하지 않는다.
- **무응답 Timer**: GPT-Live의 생성·전사 완료나 버퍼 승인, 잠깐 빈 출력 큐가 아니라 앱이 정의한 유효한 질문/안내 범위의 **기기 실제 재생 완료** 이후 시작한다. 구간 분할·전사 대응·게이트·송신·재생 대기는 아동 무응답 시간에 넣지 않는다. 질문/안내 완료 범위와 기기 보고의 신뢰 기준은 TBD다.

### `playbackMark`와 실제 재생 범위

`playbackMark`는 기기 플레이어가 관측한 승인 음성의 실제 재생 진행·중단·완료 범위를 Realtime에 보고하는 앱 계약의 목적이다. 생성량·검사 승인량·송신량은 실제 재생 범위와 다르며 보고가 없으면 전체를 재생한 것으로 채우지 않는다. 기기 관측은 아동의 청취·이해 증거가 아니다. Cue 실제 제공 범위, 도움 후 반응, 무응답 시작, 종료 정리와 기록·리포트는 확인된 범위에 맞춘다.

끼어들기 뒤 보고는 마지막 신뢰 재생 범위를 알려줄 수 있지만 끼어들기 자체를 종료 명령이나 정상 재생 완료로 바꾸지 않는다. 주기 보고·중단 직후 최종 보고·정상 완료 보고, 대상 식별·위치 단위·중복·역전·구 연결의 늦은 보고·보고 불가 처리는 [protocol.md](protocol.md)에서 TBD다. `playbackMark`를 GPT-Live에 그대로 보내면 미재생 모델 맥락이 삭제된다는 계약은 없다.

HTTP 요청 수락, WSS 수신 `ACK`, 공급자 연결 정리, 서버의 `PARTIAL`/`ERROR`, 기기에서 실제 중단을 확인한 사실은 각각 구분한다. ACK나 공급자 연결 종료만으로 기기 출력 중단을 추론하지 않는다. 서버가 최종 상태를 저장했어도 실제 중단이 미확인이면 그 관측을 별도로 남긴다. 보호자 조회·표시와 확인 대기 종료 조건은 [protocol.md](protocol.md)에서 확정하며 새 DB 표시 상태 Enum을 이 문서에서 만들지 않는다. 확인 근거·시각·타임아웃·늦은 보고 반영은 **TBD**이고 늦은 보고가 종료된 활동을 되살릴 수 없다.

## 인증 만료·동의 철회의 상태 연결 — 제안

[auth.md](auth.md)의 인증·철회 정책과 연결한다. 아래는 첫 볼트에서 기대값을 먼저 정할 예외이며, 새 ActivitySession Enum을 정하지 않는다.

| 입력 상황 | 상태 처리 경로·차단 원칙 | 합의할 것 |
| --- | --- | --- |
| 기기 Credential 만료/폐기 | Available에서 제외하고 새 작업을 차단. 할당된 활동은 이벤트 경로로 안전 종료를 요청하고 기기/공급자 연결 정리를 확인하는 안 | 이벤트명·인증 만료 감지·중단 확인 순서·최종 상태/사유(D-03, ADR-005/008) |
| 진행 중 필수 동의 철회 | 이후 수집·이용 중단 원칙에 따라 새 처리를 차단하고 활동 이벤트로 입력·출력·버퍼·기기 대기열·연결 정리를 요청한다. `consent`는 Activity Repository를 직접 변경하지 않음 | 동시성·이미 수집/지연 도착 자료·기존 기록 및 결과 처리·상태/사유(D-08) |
| 보호자 로그아웃/인증 만료·앱 닫힘 | 로그인 Session과 ActivitySession을 구분. 재로그인 후 상태 확인·허용된 종료는 가능하며 종료 활동 자동 재개 금지 | 자동 활동 종료 여부·앱 닫힘 처리(D-03). 기기 인증 만료와 동일 정책으로 가정하지 않음 |

필수 동의 철회를 `guardian_stop` 또는 `ERROR`로 자동 분류하지 않는다. 종료 요청·최소 상태 조회를 철회 때문에 막지 않는 안은 인증·소유권 검사와 변경 요청의 CSRF 검사를 유지한다. 첫 볼트의 철회 시험은 전체 동의 UI 완료를 뜻하지 않으며 D-08 미합의이면 `Blocked/TBD`로 남긴다.

| 반응 판정 작업 | 5초 Timeout + 1회 Retry | 실패 시 `UNCERTAIN` 후보 | Activity 전체 오류로 전파하지 않음 |
| 실시간 Cue 작업 | 최초 요청~도움 음성 재생 시작 총 5초, 조건부 추가 요청 최대 1회. 합의한 초기값·미측정 | 구간·전사·게이트·송신·기기 시작 대기를 모두 포함. 명확한 미수락·일시 오류·전혀 미제공 확인 시에만 총 한도 내 재요청 | [Cue 생명주기](#cue-lifecycle)의 정리 확인 후 새 상황/기술 종료. 5초 달성은 POC 대상 |

결정 여부와 검증 여부를 구분한다.

- **합의한 초기값·미측정:** 진행 중 무응답 `실제 재생 완료 뒤 10초 → 재안내 1회`, Cue `최초 요청부터 실제 재생 시작까지 총 5초·조건부 추가 요청 최대 1회`. 적용할 기본값은 정했으며 버퍼 게이트를 포함한 실제 성능은 시험 후 조정할 수 있다.
- **미정(TBD):** 재안내 이후 대기 시간·미실시/종료 조건, 시작 참여 확인에도 같은 시간을 적용할지 여부(Q-TIME-01), 세션 최대 길이 등 아직 선택하지 않은 항목.
- **제안(Proposed):** 위 합의값 외의 기존 시간값 후보. 합의 여부와 실측 상태는 각 기준 ADR·결정 로그를 따른다.

v10의 `reason = child_stopped` 표기는 최신 ADR-005의 사유 설계와 대조한다. 무응답이 곧 아동 종료 명령을 뜻하지 않으며 사유 필드·Enum이나 재안내 후 자동 종료를 이 문서의 예시로 고정하지 않는다.

## 연결 장애와 앱별 재시작

기기↔Realtime WSS가 끊긴 동안 Realtime은 기기 출력 관측과 GPT-Live 주 연결 상태를 구분한다. 기기는 합의한 안전 종료 조건에서 자체 출력·대기열을 중단하고, Realtime은 Grace 경과나 복구 불가 조건에서 버퍼·공급자 연결을 정리해 활동의 기술 종료 경로를 밟는다. 종료된 공급자 실시간 세션을 새 세션으로 이어 붙이지 않는다. 서버 영속 상태와 기기 실제 중단 확인은 별개다.

| 재시작 주체 | 소유 범위의 복구 |
| --- | --- |
| Core | 자신의 미완료 ResultJob·Outbox·Inbox와 전송만 복구한다. 정상 Realtime 활동을 일괄 `ERROR`로 변경하지 않는다. 실행 중 결과 작업의 재선점은 소유권·lease 만료와 이전 실행의 반영 차단을 확인하며, 모든 `RUNNING`을 무조건 `PENDING`으로 되돌리지 않는다. |
| Realtime | 재시작 전에 자신이 소유하던 진행 중 음성 활동(`PREPARING`, `ACTIVE`, `PAUSED`, `ENDING`)은 자동 재개하지 않고 `ERROR(server_restart)`로 정리한다. 다른 정상 Realtime 소유자의 활동은 건드리지 않는다. 영속 `RESULT_PENDING`·`PARTIAL` 결과 참조 및 미처리 Inbox는 보존해 현재 실행·권한·버전을 확인한다. |

Realtime의 릴레이 메모리 버퍼와 기기 대기열은 재시작 뒤 복원된 것으로 취급하지 않는다. 생성·승인·송신 사실이나 재시작 전 마지막 보고만으로 미확인 재생 범위를 성공으로 채우지 않는다. 실제 기기 중단 확인 불가와 늦은 보고를 별도로 남기되 닫힌 활동을 되살리지 않는다. 첫 볼트는 ResultJob을 생성하지 않으며 자세한 후속 작업 복구는 [result-pipeline.md](result-pipeline.md)를 따른다.

## 첫 볼트 검증 연결

- [ ] 연결 준비 보고만으로 ACTIVE가 되지 않고, 참여·거부·무응답은 합의한 서버 처리 경로를 따름.
- [ ] 보호자 종료·키워드 종료·중복 종료·늦은 이벤트 시험에서 이전 출력과 상태가 되살아나지 않음.
- [ ] 유효한 아동 종료 표현 확인 즉시 `ENDING`을 기록하고 일반 출력·버퍼·기기 대기열을 취소한 뒤 승인 마지막 인사 1회만 예외로 처리함.
- [ ] 끼어들기·쉬기·종료·철회를 구분하고 각 취소 뒤 늦은 승인으로 출력이 재개되지 않음. 끼어들기만으로 자동 `ENDING`이 되지 않음.
- [ ] 기기 `playbackMark`로 확인된 범위와 생성·승인·송신 범위를 구분하고, 미확인 재생을 완료로 채우지 않음.
- [ ] 서버 최종 상태·수신 ACK·실제 중단 근거를 구분하고 미확인 종료가 완료로 표시되지 않음.
- [ ] 현재 설정 키워드와 키워드 없는 유사 발화·재생 음성 재유입을 구분. 키워드/참여 명세 버전을 기록.
- [ ] 준비 취소·미참여 원문 미저장, 참여 이후 최소 보존 및 철회 경합을 D-08 기대값과 대조.
- [ ] 연결 장애·인증 만료/폐기·Realtime 재시작 시 소유한 진행 중 음성 활동과 버퍼를 정리하고 종료 세션을 재개하지 않음. Core 재시작은 정상 Realtime 활동을 바꾸지 않음.
- [ ] 유효 기록의 중도 종료가 `PARTIAL`이며 결과 준비와 별도라는 계약을 확인하고, 늦은 정상 결과 참조가 활동을 부활시키지 않음. 첫 볼트의 실제 ResultJob·부분 결과 준비 추적은 범위 밖이며 후속 계약으로 남김.

현재 모두 **미검증**이다. 합의되지 않은 전이·시간값·중단 확인 기준은 성공으로 계산하지 않는다.
