- 개정 요약 ① 화면 없는 음성 기기의 대체 `/device`, 고정 ID 사전 시드·대기 WSS·보호자 시작 push·상태 보고와 playbackMark, 서버 릴레이·버퍼 게이트 경계를 반영.
- 개정 요약 ② 브라우저 WebRTC·공급자 직접 연결을 전제로 한 기기 역할과 구형 데모 인증 참조를 대체된 이전 선택으로 이동; 단일 Next.js·두 접점과 서버 최종 판정 원칙은 보존.
- 개정 요약 ③ 운영 기기 인증, 오디오·메시지·playbackMark 필드/단위/보고 시점, 상태 카드 표시 상세와 실제 브라우저·게이트 성능은 TBD.

# ADR-003 아동용 웹 음성 UI 구조

- 상태: **Proposed**. 아래 고정 ID 기기 데모·Realtime 릴레이 B안·아동 종료 A안의 방향은 최신 기준을 적용한다. 화면 상세와 구현 검증은 이 ADR의 미결정 범위를 유지한다.
- 관련: [ADR-002 기술 기본값](ADR-002-technology-defaults.md), [ADR-004 통신·음성 연결](ADR-004-communication-voice.md), [ADR-005 세션 이벤트·종료·타임아웃](ADR-005-session-events-timeouts.md), [ADR-008 인증·접근 제어](ADR-008-auth-access-control.md), [통신 계약](architecture/protocol.md), [시퀀스](architecture/sequences.md)
- 확정 전 확인: 운영자 사전 준비·아동 음성 사용의 구분, 기기의 실제 재생·연결 관측, 보호자 상태 카드의 상세 표현과 실제 브라우저 동작

## Context

최종 서비스에서 아동은 보호자 스마트폰이 아닌 **화면 없는 별도 음성 대화 기기**를 사용한다. MVP에서는 실제 하드웨어를 제작하지 않으므로 그 음성 입출력 접점을 웹 브라우저로 대신한다. `/device`의 화면은 대체 클라이언트의 준비·시험에 필요한 접점이며, 아동에게 화면 조작이나 텍스트 입력을 요구하는 제품 흐름을 뜻하지 않는다.

보호자 화면과 아동의 음성 접점을 하나의 화면에 섞으면 보호자 스마트폰을 아동에게 건네는 사용 흐름이 된다. 또한 브라우저가 연결·재생 상태를 관찰하는 일과 활동의 의미·최종 상태를 판단하는 일은 책임이 다르므로 구분이 필요하다.

## Decision

기존 **하나의 Next.js 애플리케이션에서 `/parent`와 `/device` 두 접점**을 제공하는 구성을 유지한다. 두 백엔드 앱(Core·Realtime)이라는 결정이 프론트도 두 앱으로 분리한다는 결정은 아니다. 프론트 빌드·호스팅의 별도 전환은 이 ADR에서 확정하지 않는다.

### `/parent`

보호자용 화면이다. 아동 선택, 동의, 활동 준비, 목적·상황 입력, 연습 목표 선택, 활동 시작·종료, 상태·결과 조회, 기록, 리포트를 담당한다. 보호자 로그인은 Google만 사용하고 자체 ID/PW 가입·로그인은 제외한다. 내부 Guardian 계정·서비스 세션·동의·리소스 접근 제어는 유지하며 [ADR-008](ADR-008-auth-access-control.md)이 정한다.

REST 조회와 상태 Polling에는 TanStack Query 사용을 권고한다. 조회 대상이 더 변하지 않는 최종 상태에 이르면 해당 Polling을 멈추고 결과 재시도 뒤 관련 조회를 갱신하는 방향으로 검증한다. `RESULT_PENDING`처럼 결과 준비 중인 대상은 계속 조회한다. 활동 `PARTIAL`과 별도 결과 준비·실패·재시도를 같은 상태로 해석하지 않는다. 도구 선택은 [ADR-002](ADR-002-technology-defaults.md), Polling 주기·상태 권위는 [ADR-004](ADR-004-communication-voice.md), 부분 결과 계약은 [ADR-005](ADR-005-session-events-timeouts.md)가 정한다.

보호자는 사전 시드한 고정 ID 기기의 **상태 카드**를 통해 시작 대상의 현재 관측을 확인하고 시작을 요청한다. 카드에는 시작 가능 여부를 판단하는 데 필요한 기기 허용·연결·점유/활동 할당의 관측과 서버 판단을 구분해 연결한다. 표시 문구·전체 UI 상태 목록·갱신 주기·확인 불가의 구체 표현은 TBD다. 표시를 위해 새 `ActivitySession` DB Enum을 추가하지 않는다. 카드의 오래된 표시만으로 시작을 허용하지 않고 서버가 현재 조건을 다시 검증한다.

### `/device`의 준비와 아동 사용

`/device`는 실제 아동용 별도 음성 기기를 대신하는 웹 클라이언트다. **음성 중심**으로 만들고 글자와 조작 버튼을 최소화한다. 보호자 스마트폰을 아동에게 넘기는 구조로 해석하지 않는다.

운영자는 통제된 데모 환경에서 브라우저 접속, 마이크 권한과 플레이어 준비, 사전 시드한 기기의 연결을 준비한다. 구체 준비 UI와 브라우저 재생 조건은 구현 검증 대상이다. 이 운영자 준비와 아동의 음성 사용을 구분한다. 아동에게 로그인·텍스트 입력·기기 선택·연결 시작 버튼을 필수로 요구하지 않는다.

기기는 활동 시작 전부터 Realtime의 `/ws`에 **대기 WSS**로 연결하여 준비·연결 상태를 보고한다. 보호자의 시작 요청을 Core가 검증하고 Realtime이 고정 ID 기기의 허용·현재 연결·점유·원자적 활동 할당을 확인한 뒤 대기 중인 해당 기기에 시작을 push한다. 전역 기기 개수로 실제 다중 사용자 정책을 만들지 않는다. 구체 메시지·오디오 형식·재연결/연결 교체는 [protocol.md](architecture/protocol.md)의 TBD다.

시작 요청의 접수, 기기/공급자 준비, 아동의 실제 참여는 서로 다른 사실이다. 기기의 준비 보고나 명령 수신 ACK를 참여 판정으로 사용하지 않는다. 준비가 완료되어도 아동이 참여했다고 기록하지 않으며, 실제 입력 전사 등 유효 근거를 서버가 판정한다.

### 음성·제어 연결과 출력

기기↔Realtime의 WSS는 **음성 입출력·제어·상태/실제 재생 보고** 경로다. 대기 기기 연결의 수명과 유료 공급자 연결의 수명을 구분한다. `/parent`의 TanStack Query Polling이 이 실시간 연결을 대체하지 않는다.

Realtime은 GPT-Live API(`gpt-live-1`)의 주 WebSocket 연결과 서버 키를 소유하고 음성을 중계한다. 브라우저는 공급자 키나 직접 연결 권한을 받지 않는다. 공급자의 말차례/연결 상태와 서비스 `ActivitySession`의 진행·종료 권한은 별개다. 대상 API·이벤트·시작 계약과 서버 Adapter는 [ADR-004](ADR-004-communication-voice.md)가 정한다.

공급자 출력은 Realtime의 임시 메모리 버퍼에서 **앱 구간 분할 → 출력 전사 대응 → 상태·권한·최신성 및 필요한 경량 의미 검사 → 동일 음성 승인 → 전달 직전 재확인**을 거친 뒤 기기로 전달한다. 기기는 전달받은 승인 범위만 재생하고 취소된 대기 음성을 재생하지 않는다. 전사 누락·대응 불명확·검사 실패·시간초과는 폐기와 허용된 대체 안내 경로로 처리하며 미검사 음성을 전달하지 않는다. 구간 경계·버퍼 한도·검사기·대체 안내의 세부는 TBD다. 검사 수행은 전달 조건이며 모든 위험 발견이나 지연 성능의 보장은 아니다.

기기의 원음과 중계 원음은 임시 처리 범위를 벗어나 DB·Outbox/Inbox·일반 로그·디스크로 우회 저장하지 않는다. 기존 승인 안내 음성 파일과 실시간 원음의 보존 범위를 같은 것으로 취급하지 않는다.

### 기기의 관측과 서버의 판정

`/device`는 연결·플레이어 상태와 실제 재생 범위를 관측하고 Realtime에 보고한다. **아동 발화의 의미, 참여 여부, `ActivitySession`의 최종 상태 결정권은 서버에 둔다.** Realtime은 기기/활동/현재 연결/작업의 결합과 보고 권한을 검증한다. 내부 HTTP의 서비스 인증과 보호자의 사용자 인가도 구분하며 [ADR-008](ADR-008-auth-access-control.md)·[auth.md](architecture/auth.md)가 정한다.

`playbackMark`는 실제 플레이어가 관측한 진행·중단·완료 범위를 기기→Realtime에 연결하는 앱 계약이다. 생성·승인·송신·수신 ACK·실제 재생은 다르다. 이 보고는 아동의 실제 청취·이해를 증명하지 않는다.

| 보고 계약 | 기기 역할과 남은 범위 |
|---|---|
| 관측 주체·수신 | 실제 플레이어가 관측하고 Realtime이 수신·검증한다. |
| 대상 식별 | 활동·현재 연결·승인 음성/재생 묶음을 구별해야 한다. 실제 필드명은 TBD다. |
| 위치 단위 | 플레이어의 재생 위치를 사용한다. 시간·샘플·프레임 등 단위는 TBD이며 공급자 전사/생성 타임라인으로 대신하지 않는다. |
| 송신 시점 | 주기 진행·끼어들기 중단 직후 최종 관측·정상 완료 보고의 관계는 TBD다. |
| 늦은 보고 | 중복·순서 역전·구 연결·현재 작업 변경 이후 보고를 검증한다. 과거 관측을 기록하더라도 출력 승인이나 활동 진행을 되살리지 않는다. |
| 보고 불가 | 확인 불가와 마지막 신뢰 관측을 남긴다. 미보고·불확실 범위를 전체 재생 성공으로 채우지 않는다. |
| 활용 | Cue 실제 제공 범위·도움 후 반응·무응답 타이머·기록에 연결한다. 정상 완료의 범위는 앱 계약으로 정한다. |

보고 자체가 공급자의 미재생 대화 맥락을 삭제하거나 종료 명령이 되는 것은 아니다. 폐기 음성도 모델 맥락에 남으므로 회복 시 Realtime의 교정 정책을 적용하고, `session.instructions.append`의 수락 ACK를 재생 승인으로 쓰지 않는다. 새 출력도 게이트를 통과한다. 공급자 맥락 반영은 [ADR-004](ADR-004-communication-voice.md)·[protocol.md](architecture/protocol.md)의 확인 항목이다.

### 끼어들기·쉬기·종료·철회

끼어들기, 쉬기, 종료, 필수 동의 철회를 구분한다. 각 사유에 따라 해당 출력·서버 버퍼·기기 대기열의 권한을 무효화하고 정리하며 늦은 승인으로 재생을 재개하지 않는다. 단순 끼어들기나 재생 중단 보고만으로 `ENDING` 또는 정상 재생 완료를 확정하지 않는다.

서버가 아동의 **유효한 종료 표현을 확인하면 즉시 `ENDING`**을 기록하고 일반 출력과 버퍼/기기 대기열을 취소한다. 고정된 승인 마지막 인사 **1회만 예외**로 둔다. 인사 재생 완료는 상태 전환의 선행 조건이 아니다. 보호자 STOP과 철회에는 이 아동 종료 예외를 자동 적용하지 않는다. 실제 문구·판정·오디오와 정리 실패/철회 경합은 담당 명세·ADR-005의 계약을 따른다.

기기는 명령 수신 ACK와 실제 플레이어 중단/재생 범위를 각각 보고한다. Realtime의 상태 저장, 명령 접수, 기기 수신, 실제 출력 중단을 하나의 성공으로 합치지 않는다. 연결 장애에서는 안전 정리와 확인 불가를 구분하며 재연결로 종료된 활동이나 취소된 출력이 자동 재개되지 않는다. 재시작 뒤 메모리 버퍼가 복원됐다고 취급하지 않는다.

무응답은 앱이 정한 유효 질문/안내 전체의 **실제 재생 완료 뒤 10초**를 초기값으로 유지한다. 구간·전사·게이트·송신·재생 대기를 아동 무응답으로 세지 않는다. Cue 최초 요청부터 실제 재생 시작까지 **5초 초기 예산**은 게이트 대기를 포함하고 달성 여부는 POC다. 타이머·연결/장애·종료의 최종 정책은 [ADR-005](ADR-005-session-events-timeouts.md)를 따른다.

### 기기 허용과 인증·인가

MVP는 허용 고정 ID를 사전 시드한다. 탐색·페어링·일회용 코드·Credential 발급/갱신 UI를 시작 선행 조건으로 추가하지 않는다. 고정 ID는 **허용 대상 선정의 축약이며 비밀 자격증명이나 운영 인증의 증거가 아니다.** 보호자 로그인 Cookie로 기기를 인증하지 않고 물리 기기 소유권을 증명하지 않는다.

실통신 POC는 통제된 시연 네트워크와 허용 Origin·현재 연결·점유·할당·활동 권한 검사를 적용한다. 인증과 인가는 별개이며 공개 ID를 안다는 사실만으로 활동 제어를 허용하지 않는다. 운영 수준의 기기 인증·등록·페어링은 TBD다. 실제/모의 제품 데모 선택과 실통신 POC 목표도 구분한다.

## Alternatives

### 보호자 스마트폰을 아동에게 전달 — 미채택 대안

채택하지 않는다. 보호자 화면과 아동 음성 접점의 역할이 섞이고 최종 서비스의 별도 음성 기기 구조와 맞지 않는다.

### MVP에서 실제 하드웨어 제작 — 미채택 대안

MVP 범위에서 제외한다. 웹 브라우저로 먼저 음성 상호작용과 서버의 상태 제어 경계를 검증한다. 실제 기기 등록·페어링·하드웨어 인증은 제품화 단계에서 별도로 설계해야 한다.

### `/device`가 활동 상태를 독자적으로 확정 — 미채택 대안

채택하지 않는다. 클라이언트의 연결 및 재생 관측과 서버의 활동 상태 결정이 분리되지 않으면 기기 연결 장애와 활동 종료 같은 서로 다른 상황이 혼동된다. 상태 처리 기준은 [ADR-005](ADR-005-session-events-timeouts.md)에 둔다.

### 대체된 이전 선택 — 연결·데모 인증 참조

원본은 `/device`가 WebRTC와 WebSocket을 다루며, 당시 ADR-004의 브라우저↔공급자 직접 연결을 따랐다. 그 흐름의 SDP·Data Channel·Sideband와 브라우저 공급자 권한은 현행 구현 대상에서 제외되고 Realtime 소유 주 연결·WSS 릴레이 B안으로 대체됐다.

원본이 참조하던 구형 ADR-008의 `/device` 단기 인증 Cookie·운영자 일회용 발급 코드 후보는 고정 ID 사전 시드 데모 흐름으로 대체됐다. 발급/갱신 UI를 다시 필수 범위로 추가하지 않는다. 운영 기기 인증의 미결정 상태는 유지한다.

## Consequences

- 실제 하드웨어 없이도 최종 서비스의 아동 음성 접점과 보호자 화면을 분리해 검증할 수 있다. 운영자 준비와 아동 음성 사용이 구분된다.
- 하나의 Next.js 애플리케이션에서 두 접점을 관리하지만 사용 흐름과 인증 맥락은 구분해야 한다. 두 백엔드 앱의 실행 책임과 프론트 앱 수를 혼동하지 않는다.
- `/device` 구현은 브라우저의 마이크 권한, 대기/활동 WSS, 플레이어와 실제 재생 범위를 정확히 관찰해야 한다. 브라우저와 시연 네트워크에서 동작을 시험해야 한다.
- 출력 검사와 구간·전사 대기로 지연이 늘 수 있으며 부분 재생·미보고·연결 교체에서 실제 제공 범위가 불확실할 수 있다. 이를 재생 성공으로 보정하지 않는다.
- 고정 ID 데모는 운영 인증 완료가 아니다. 제품화 단계에는 기기 등록·페어링·하드웨어 인증 설계가 추가로 필요하다.
- 보호자 상태 카드가 오래되거나 앱 간 전달이 실패할 수 있다. 현재 허용·연결·점유·할당 검사를 서버에 남기며 요청 접수와 실제 준비/출력의 차이를 표시 계약에서 유지한다. Core 장애 중 보호자 직접 Realtime 종료는 미확정 사항이다.

## Pending

- **화면 상세:** `/device`의 최소 글자·버튼, 운영자 준비/시험 표현과 보호자 상태 카드의 갱신·확인 불가 표시를 UI 명세에서 확정한다. 생각중/듣는중 등 전체 UI 상태 목록이나 표시 상태에 따른 새 진행 규칙은 이번에 확정하지 않는다.
- **UI 도구:** UI Library는 화면 담당자가 후보를 제안한 뒤 결정한다. 기존 ADR-002의 미정 항목을 유지한다. TanStack Query의 `/parent` 적용은 별도로 구현 검증한다.
- **기기 계약:** WSS 오디오 형식·메시지·연결 교체, `playbackMark` 필드명·위치 단위·송신 시점·중복/늦은 보고·보고 불가와 신뢰 범위는 TBD다.
- **출력/타이머:** 앱 구간·전사 대응·전체 질문/안내 완료, 버퍼 한도·검사기·대체 안내·교정/취소 적용과 Cue 5초 달성은 POC 대상이다. 무응답 10초는 실제 재생 완료 기준의 초기값이다.
- **다른 ADR의 결정 적용:** 통신은 ADR-004·protocol, 세션·종료/복구는 ADR-005, Google·서비스 세션·내부/기기 인증과 인가는 ADR-008·auth의 현행 계약을 따른다.
- **제품화 범위:** 운영 기기 인증·물리 기기 등록·페어링과 실제/모의 제품 데모 선택은 후속 확인 대상이다. 사전 시드 고정 ID 방향을 미정으로 되돌리지 않는다.

## First Bolt 확인 항목 — 미실행

- 운영자 브라우저 사전 준비와 아동의 화면 조작 없는 음성 사용을 구분한다. 기기 대기 WSS·준비/상태 보고·보호자 상태 카드·시작 push를 시험한다.
- 허용 고정 ID·Origin·현재 연결·점유·원자 할당, 잘못된 대상/구 연결/중복 시작을 확인한다. 공개 ID만으로 권한이 생기지 않는지 검증한다.
- 시작 접수·기기/공급자 준비·서버 참여 판정을 분리하고 기기 수신 ACK를 실제 준비·참여·재생으로 사용하지 않는지 확인한다.
- 출력 구간·전사 대응·검사·동일 음성 승인·전달을 시험한다. 누락/실패/시간초과 및 취소 뒤 늦은 승인에서 미검사·취소 음성이 재생되지 않는지 확인한다.
- 플레이어의 부분/완료/중단·보고 불가, `playbackMark`의 대상·단위·구 연결/늦은 보고를 시험한다. 미확인 범위를 완료로 추정하지 않는다.
- 끼어들기와 유효 종료 판정을 구분한다. 쉬기·종료·철회의 출력/대기열 정리, 즉시 `ENDING`·승인 마지막 인사 1회와 접수/ACK/실제 중단의 차이를 확인한다.
- 브라우저/네트워크 장애와 Realtime 재시작 후 취소 음성·종료 활동이 자동 재개되지 않는지 확인한다. 게이트 대기와 무응답 10초·Cue 5초 예산을 실제 재생 관측에 연결한다.

## 요약

`/device`는 화면 없는 별도 음성 기기를 대신하는 클라이언트다. 고정 ID 사전 시드·대기 WSS에서 보호자 시작 push를 받고 Realtime의 승인 출력만 재생하며 실제 범위를 보고한다. 의미·참여·활동 상태는 서버가 판정한다. 단일 Next.js·두 접점은 유지하고 운영 인증·필드·UI 상세·실통신 성능의 미결정 상태를 보존한다.
