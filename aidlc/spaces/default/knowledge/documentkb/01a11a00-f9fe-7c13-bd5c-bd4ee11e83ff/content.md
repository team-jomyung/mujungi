- 개정 요약 ① 기기↔Realtime WSS와 Realtime↔GPT-Live 주 WebSocket의 음성 릴레이, 출력 전사 기반 버퍼 게이트, 차단 후 회복을 현행 결정으로 반영. ADR-008의 문서 존재 상태를 바로잡았다.
- 개정 요약 ② 브라우저 공급자 직결·SDP·Sideband 및 Spring 음성 중계 미채택은 대체된 이전 선택으로 이동. ADR-008의 (예정) 표기를 제거했다.
- 개정 요약 ③ 출력 구간·완료/전사 대응 기준, 버퍼·대체 안내 한도, 재생 관측 세부, Java/SDK·지연 실연동은 TBD. 문서 연결 완료와 구분해 유지한다.

# ADR-004 통신·음성 연결 구조

- 상태: **Proposed — GPT-Live 연결 B안의 방향은 확정, 구현·성능은 미검증**
- 부분 확정: **MVP GPT-Live 단일 전사 사용 · 별도 STT 보류 Accepted (2026-10-01 팀 회의)**.
- 확정 조건: B안의 First Bolt 실연동·게이트·지연 검증 후 ADR Accepted 여부 결정
- 관련:
  - ADR-002 기술 기본값
  - ADR-003 아동용 웹 음성 UI 구조
  - ADR-005 세션 이벤트·종료·타임아웃
  - ADR-006 시연 서버·배포
  - ADR-008 인증·접근 제어
  - GPT-Live 상세 명세 L-D01~L-D05

## 1. Context

서비스에는 서로 다른 통신 목적과 실행 책임이 존재한다.

1. 보호자가 활동을 준비·시작하고 상태·결과를 조회하는 Core API 경로
2. 기기가 음성·제어·실제 재생 범위를 보내고 받는 Realtime Activity Spring 경로
3. Realtime이 GPT-Live API(`gpt-live-1`)와 대화하는 공급자 주 연결
4. Core와 Realtime 사이의 권한·상태·결과 계약

실시간 대화에는 낮은 지연이 필요하다. 동시에 아동에게 보내기 전 출력 음성을 대응 전사와 함께 검사해야 한다. Realtime이 기기와 공급자 사이에서 음성을 중계하며, 출력 음성은 승인될 때까지 메모리 버퍼에 둔다. 이 경로의 지연·부하는 First Bolt에서 측정한다.

프로젝트 API Key, 보호자·아동·동의 확인, ActivitySession 상태, 승인 콘텐츠, 허용 출력과 중단, 결과·기록·리포트의 책임은 클라이언트나 대화 모델에 넘기지 않는다. ActivitySession의 수정 소유권은 Realtime에 두며 Core와 계약으로 연결한다. 공급자 세션 상태는 서비스 상태의 최종 권위가 아니다.

---

# 2. Decision

## 2.1 보호자 앱 ⇄ Core API Spring

보호자 앱과 Core API Spring은 HTTPS REST를 사용한다.

```text
/parent
   ⇅ HTTPS REST
Core API Spring
```

MVP에서 활동 상태는 별도의 실시간 Push 채널을 추가하지 않고:

```text
1~2초 Polling
```

으로 조회한다.

보호자 앱이 자체적으로 추정한 상태를 권위 있는 상태로 사용하지 않는다.

```text
보호자 화면 상태
← Realtime이 소유하는 ActivitySession 등 서버 서비스 상태
```

Core는 Realtime이 소유하는 영속 ActivitySession 상태와 관련 서비스 상태를 계약으로 조회해 응답하는 것을 기본 원칙으로 한다. `/parent`에서는 TanStack Query로 REST 조회와 상태별 Polling을 구현하도록 권고한다. 조회 대상별 최종 상태에서 해당 Polling을 멈추고 결과 재시도 후 관련 Query를 갱신하는 방식을 검증한다. `RESULT_PENDING` 등 결과 준비 중인 상태는 계속 조회한다. 1~2초 간격, 백그라운드 동작과 오류 재시도는 최종 확정 전이다.

세션 상태의 세부 저장·복구 규칙은 ADR-005와 `session-state.md`에서 관리한다.

---

## 2.2 실시간 음성 경로 — GPT-Live 연결 B안

채택 경로는 기기↔Realtime Activity Spring의 **WSS 음성·제어 연결**과 Realtime↔GPT-Live API의 **서버 주 WebSocket 연결**이다. 이 문서의 `Realtime`은 우리 백엔드 앱 이름이며 OpenAI Realtime API가 아니다. 공급자는 GPT-Live API, 모델 식별자는 `gpt-live-1`이다. 운영 모델·SDK 버전과 Java 지원 범위는 실연동 확인 대상이다.

```text
/device
   ⇅ WSS: 입력 음성·승인 출력 음성·제어·재생 관측
Realtime Activity Spring
   ⇅ GPT-Live 주 WebSocket: 입력 음성·출력 음성/전사·공급자 이벤트
GPT-Live API (gpt-live-1)
```

Realtime은 입력 음성을 공급자로 중계하고, 공급자 출력 음성은 §2.5의 버퍼 게이트가 승인한 **동일한 음성 구간**만 기기로 보낸다. 브라우저는 공급자 세션에 직접 연결하거나 공급자 키·임시 자격을 받지 않는다. 공급자 출력 음성을 수신 즉시 기기로 통과시키지 않는다.

기기 대기용 제어 연결과 유료 GPT-Live 모델 연결의 수명은 구분한다. 각 연결의 생성·유지·해제 시점과 실패 처리는 상세 계약에서 정한다. 이 문서는 대기 연결만으로 공급자 세션이 시작된다고 가정하지 않는다.

---

## 2.3 기기 WSS: 음성과 서비스 제어

같은 기기↔Realtime WSS 경로에서 다음 목적을 구분한다.

- 기기 입력 음성과 승인된 출력 음성의 중계
- 활동 시작·종료, VoiceClient 연결 상태, heartbeat, 서버 명령
- 끼어들기·쉬기·종료·철회에 따른 출력 중단 및 기기 대기열 정리
- 기기 플레이어의 실제 재생 진행·중단·완료 보고(`playbackMark`의 목적; 세부 계약 TBD)
- 연결 장애 및 안전 종료 보고

`/device`는 발화 의미·권한·ActivitySession 상태를 최종 결정하지 않는다. 재생 보고도 실제 플레이어가 관측한 범위이며 아동의 청취·이해를 증명하지 않는다. 호출어·키워드·판정 방식은 GPT-Live 상세 명세 L-D03에서 관리한다.

---

## 2.4 GPT-Live 주 연결과 이벤트 대조

프로젝트 API Key는 서버에만 보관한다. Realtime의 공급자 Adapter가 주 WebSocket `wss://api.openai.com/v1/live/sessions`에 연결하고 `session.start`에 모델·허용 설정을 실어 보낸 뒤 `session.started`를 확인한다. 세션 의존 명령은 시작 확인 이후에 보낸다. 연결과 공급자 세션을 ActivitySession에 연관시키되 구체 식별 필드·오류·재시도 계약은 TBD다. Java SDK가 이 경로를 지원하는지 확인하고, 필요하면 같은 Adapter 경계 안의 Java WebSocket 구현을 검토한다. SDK 타입은 Activity 도메인에 노출하지 않는다([ADR-007](ADR-007-module-boundaries.md)).

| 목적 | GPT-Live 주 연결 기준 | 앱의 책임·주의 |
| --- | --- | --- |
| 입력 음성 | `session.input_audio.append` | 기기 음성을 현재 허용된 활동과 결합해 전송 |
| 출력 음성 | `session.output_audio.delta` | 기기로 직행시키지 않고 임시 버퍼에서 검사 |
| 입력 전사 | `session.input_transcript.delta` | 조각 누적·발화 대응·누락/불확실 처리 |
| 출력 전사 | `session.output_transcript.delta` | 출력 음성 구간과 대응해 게이트에 사용 |
| 교정 지시 | `session.instructions.append`와 수락 이벤트 | 지시 수락과 내용 교정·기기 재생 승인 구분 |

GPT-Live의 발화 시점은 공급자가 관리한다. 앱은 출력 음성·전사 조각과 자체 구간 경계로 진행을 판단한다. 공급자 조각의 잠깐 끊김을 질문/답변 전체 완료로 간주하지 않는다. 주 WebSocket의 출력 오디오에 기기 재생 시각이나 발화별 완료 신호가 있다고 가정하지 않는다. 음성 턴 생성을 위해 수동 오디오 commit·수동 생성 트리거를 이식하지 않는다.

**혼용 방지를 위한 미채택 예시:** OpenAI Realtime API의 `input_audio_buffer.append`/`input_audio_buffer.commit`, `response.output_audio.done`/`response.done`을 GPT-Live 입력이나 음성 턴 완료 계약으로 사용하지 않는다. `response.create`는 GPT-Live Responses delegation의 별도 역할이 있으므로 무조건 같은 뜻으로 취급하지 않는다. delegation 자체는 §8의 확인 항목이다. 실제 Adapter·SDK의 이벤트/수락 계약은 First Bolt에서 검증한다.

---

## 2.5 출력 전사 기반 버퍼 게이트와 차단 후 회복

Realtime은 공급자 출력 음성을 **전달 전 임시 메모리**에 보관한다. Realtime 또는 그 미디어 처리 Adapter가 검사할 출력 구간을 분할하고 대응 전사 조각을 묶는다. 출력 VAD/noise gate를 사용할 수 있으나 알고리즘·라이브러리·구간 길이·완료 기준은 TBD다. 쉼을 답변 완료로 단정하지 않는다. 음성 구간은 해당 전사·검사 결과·활동/현재 작업과 연결해야 한다.

```text
공급자 출력 음성 → 앱이 구간 분할·임시 버퍼 보관
                   → 대응 출력 전사 확보
                   → 상태·권한·작업 최신성 + 필요한 경량 의미 검사
                   → 동일 음성 구간 승인
                   → 전달 직전 현재 활동·권한·작업 최신성 재확인
                   → 승인된 음성만 기기로 송신
```

검사 전이나 승인 효력이 사라진 구간은 기기로 보내지 않는다. 전사 누락·음성/전사 대응 불명확·검사 실패·시간초과 때 해당 음성을 폐기하고 대체 안내 경로로 전환한다. 대체 안내 내용, 재생성 조건·횟수, 실패 시 처리, 구간 경계, 버퍼 최대 시간·크기와 포화 처리 수치는 TBD다. 같은 문장을 다시 생성해도 이전 승인 결과를 재사용하지 않는다. 게이트 통과는 검사 **수행** 조건이며, 전사 정확성이나 의미 검사가 모든 위험을 발견한다는 보증은 아니다.

끼어들기·쉬기·종료·철회는 각각의 서비스 규칙에 따라 구간 승인 효력을 취소한다. 취소된 서버 버퍼와 기기 대기열을 정리하고 늦은 검사 통과·승인 결과로 재생을 다시 시작하지 않는다. 승인 콘텐츠 예외·종료 순서는 ADR-005에서 관리한다.

**우리 설계 권고:** 게이트의 동기 경로에는 상태·권한·최신성 및 필요한 빠른 의미 검사를 두고, 무거운 교육적 판정과 KG/GraphRAG 조회는 분리한다. 필수 안전 검사를 생략하거나 게이트에서 모델 검사를 전면 금지한다는 뜻은 아니다. 안전 판단에 필요한 근거가 준비되지 않았다면 전달을 보류해야 하며 구체 검사 모델은 제브 가드레일(기술명세서 v0.3 §7.7)이고 기준은 AI 동작 명세 v0.2 §10을 따른다.

폐기한 음성도 GPT-Live 모델 맥락에는 남는다. Realtime은 차단 이유와 실제 제공 범위를 구분하고, 대화 회복이 필요한 경우 앱이 작성한 `session.instructions.append` 교정 지시를 사용한다. 이 지시는 과거 맥락 삭제가 아니다. 수락 ACK는 교정 성공이나 음성 재생 승인과 다르며 새 출력도 게이트를 다시 통과해야 한다. 미승인 사용자·모델 원문을 시스템 지시로 복사하지 않는다. 일반 끼어들기, 활동 종료, 가드레일 위반의 후속 처리는 별도 계약으로 구분한다.

## 2.6 상태 결정권

ActivitySession의 수정·최종 상태 결정권은 Realtime Activity Spring에 둔다. Core는 공개 계약으로 연결한다.

외부에서 들어온:

```text
GPT-Live Event
/device 상태
음성 명령 판정 결과
AI 작업 결과
```

는 상태 변경 요청의 입력일 뿐이다.

```text
외부 Event / 판정
        ↓
Realtime Activity Spring
        ↓
Session Event
        ↓
서비스 상태 변경
```

모델 응답이나 공급자 Event만으로 다음을 직접 확정하지 않는다.

- 활동 종료
- 연습 완료
- 아동 반응 평가 완료
- 결과 생성 완료
- 활동 성공·실패

상태 전이 및 종료 우선순위는 ADR-005에서 관리한다.

---

## 2.7 GPT-Live 책임 범위

GPT-Live는 아동과의 **실시간 음성 대화 역할**을 담당한다.

다음 책임은 GPT-Live 대화 역할과 논리적으로 분리한다.

- 활동·세션 상태 결정
- 승인 콘텐츠 관리
- 아동 반응 판정
- 경험 구조화
- 연습 후보 추천
- 결과 생성
- 기록 및 리포트

이 책임 분리는 여러 개의 LLM 또는 여러 개의 서버를 반드시 사용한다는 의미가 아니다.

비실시간 분석·판정·추천·결과 처리에 사용할:

- 모델
- 호출 방식
- 처리 시점
- 검수 방식

은 GPT-Live 상세 명세의 L-D05 및 관련 설계에서 결정한다.

ADR-004에서는 별도 LLM 사용을 강제하지 않는다.

<a id="live-cue-responsibility"></a>
### 2.7.1 GPT-Live의 실시간 도움(Cue)과 서버 제어

**기능 정책은 기존 확정 사항을 적용한다.** 요구사항 FR-E08·FR-F02에 따라 도움은 GPT-Live가 상황에 맞게 실시간으로 생성해 음성으로 제공한다. 승인 대본을 사용하는 시작 안내·기회 트리거·마무리와 구분한다. Cue를 고정 승인 대본으로 교체하거나 생성 주체를 다시 선택하는 결정으로 해석하지 않는다.

상세 메시지·출력 제어·관측 계약은 구현 미검증이다.

- Realtime은 도움 제공이 허용되는 현재 연습 단계, 아동의 도움 동의, 선택 행동 버전, 작업 최신성과 전달 정보 범위를 확인한다. 실제 도움 생성은 GPT-Live가 수행하고, 생성 음성은 §2.5 게이트를 통과한 뒤에만 제공한다.
- 선택한 행동 버전은 상황 생성·도움·판정에서 공통으로 고정한다. 대화 역할에는 도움에 필요한 허용된 상황 정보만 제공하고 **판정 기준 전체, 보호자 입력 원문, 이전 판정값을 전달하지 않는다**. 같은 버전을 참조한다는 이유로 평가 전용 데이터를 복사하지 않는다.
- 첫 반응 전과 새 상황 반응 단계에는 목표 Cue를 차단한다. 도움 거절 시 강제하지 않고 새 상황으로 진행하며, 도움 제공 뒤 아동의 반응 기회는 1회다.
- 공급자 요청 수락·출력 전사 수신·음성 생성은 실제 기기 재생 증거와 구분한다. 게이트 승인도 기기 재생 완료와 다르다. 실제 플레이어의 출력 차단·중단과 재생 관측을 함께 구현·시험한다.
- 부적절한 도움 발화를 발견하면 해당 구간을 차단하고 그 도움 및 영향 아래 받은 반응을 정상 제공·판정 근거로 사용하지 않는다. 검사는 전달 전에 수행하지만 전사·검사 정확도 100%를 보장하지 않는다. 검출 시점과 실제 재생 범위의 한계를 남긴다.

Cue의 지시문·문구·구체 생성/검수 기준은 동료 GPT-Live/AI 명세가 소유한다. 상태·실패 분기는 [Cue 생명주기](architecture/session-state.md#cue-lifecycle), 요청·관측 경계는 [Cue 계약](architecture/protocol.md#cue-contract), 제공 이력은 [Cue 데이터 모델](architecture/data-model.md#cue-delivery-model)을 따른다. 선택 행동 버전의 생성·검증은 [목표 생성 계약](architecture/result-pipeline.md#goal-generation-contract)에서 관리한다.

---

## 2.8 재생 완료와 playbackMark

모델 응답 생성, 게이트 승인, 기기로 송신, 실제 플레이어 재생은 서로 다른 사건이다. 필요한 구간에서 기기가 실제 재생 진행·중단·완료 범위를 Realtime에 보고한다. `playbackMark`는 이 기기 관측 계약의 목적을 가리키며 정확한 필드·단위·시점·중복 처리 방식은 TBD다. 기기 보고가 없으면 생성량이나 송신량을 실제 재생 범위로 채우지 않는다. 이를 아동의 청취·이해 증거로 해석하지 않는다.

실제 재생 완료가 필요한 무응답 Timer, 승인 마무리 확인, 다음 단계 진행은 이 구분을 사용한다. 끼어들기 보고 자체를 활동 종료나 정상 완료로 취급하지 않는다. `playbackMark`가 공급자 맥락을 자동 수정한다고 가정하지 않는다. 상세 계약은 `architecture/protocol.md`, 상태와 타이머는 ADR-005에서 관리한다.

---

## 2.9 연결 장애와 안전 종료

활동 중 기기↔Realtime WSS가 복구되지 않으면 기기는 플레이어 출력과 대기열을 중단하고 자체 안전 종료 절차를 따른다. Realtime은 해당 활동의 공급자 주 연결과 버퍼를 정리하며, 실제 기기 출력 정리 여부와 영속 서비스 상태를 구분한다. 제한 시간·재연결 범위·Grace Period·상태 전이는 ADR-005에서 정한다. 종료된 GPT-Live 실시간 세션을 자동 재개한다고 가정하지 않는다.

---

## 2.10 데이터 저장

서비스 자체에서는 아동 원본 음성을 저장하지 않는다. 중계와 게이트에 필요한 원음은 임시 메모리에서만 사용하고 폐기한다. 원음이 Outbox·Inbox·DB·일반 로그·디스크에 우회 저장되지 않게 한다. 승인된 안내 음성 파일과 실시간 중계 원음의 보존 범위는 구분한다.

공급자 Session 저장 기능을 사용하지 않는 정책을 유지한다. GPT-Live 주 연결의 설정 방식·검증 결과는 First Bolt에서 확인한다. 실제 아동 데이터 사용 전에는 공급자 데이터 처리·보존·동의 조건을 별도로 확인한다.

---

## 2.11 기기 권한 최소화

`/device`는 Realtime WSS의 허용된 음성·제어·재생 보고에 필요한 권한만 가진다. 브라우저에 Project API Key, 공급자 연결 자격, 서버 내부 판정 기준, 보호자 입력 원문 전체, 이전 평가 결과 전체, 다른 아동 정보, 서버 전용 자격증명을 두지 않는다. 연결·활동·권한 결합 및 정확한 기기 인증 방식은 ADR-008과 `architecture/protocol.md`에서 정한다. 기기 ID를 공급자 자격으로 사용하지 않는다.

---

## 2.12 공급자 격리

GPT-Live의 주 WebSocket 연결, `session.start`/공급자 이벤트, 음성·전사 조각, 교정 지시, 공급자 세션 식별·수명주기는 공급자 종속 기능이다. Realtime의 `voice` Adapter 경계에 두고 Activity 도메인에 SDK 타입을 노출하지 않는다. Fake 구현으로 버퍼 게이트·취소·실패를 시험한다. 공급자를 코드 변경 없이 완전히 교체할 수 있다는 보장은 아니다.

---

## 2.13 ADR-004에서 결정하지 않는 것

GPT-Live 상세 명세는 `session.instructions`, Prompt·대본·승인 문구·Cue·종료 문구 내용, 호출어·명령어·키워드 판정, 아동 반응 판정 모델, `functional / partial / none / uncertain` 및 `review_needed`의 세부 기준을 관리한다. 이 ADR은 출력 **전달 전 게이트의 존재와 실패 시 차단**을 결정하며, 가드레일 모델은 제브(Jev), 아동 반응 판정 모델은 GPT-6-Luna로 정했다(기술명세서 v0.3 §5.7·§5.8·§7.3·§7.7). 가드레일 질문·분류는 AI 동작 명세 v0.2 §10을 따르고, 발화 조립·누락 감지 구현은 TBD로 남긴다. 관련 상세 명세: L-D02 승인 음성, L-D03 키워드·명령·전사, L-D04 지식·문맥, L-D05 판정·출력 검수·모델 배치.

## 2.14 MVP 전사 공급원과 별도 STT 보류 — Accepted

- 결정일·근거: **2026-10-01 팀 회의 결과**.
- 현재 MVP: **GPT-Live 1개로 실시간 대화와 해당 경로에서 제공되는 전사를 사용한다. 별도 STT 공급자·독립 전사 경로를 서비스에 추가하지 않는다.**
- 보류 대안: `GPT-Live 1개 + 별도 STT 1개`의 병렬 전사·자동 비교. 추가 STT 선정·연동·비교 시험도 현재 MVP와 First Bolt의 필수 완료 조건에 넣지 않는다.
- 이 결정의 범위는 **실시간 음성·전사 공급원**이다. 경험 구조화·새 연습 상황 생성·반응 평가·결과·리포트의 비실시간 AI 책임과 모델 배치는 §2.7 및 동료 GPT-Live/AI 명세에서 계속 관리한다.

### Context: 전사를 사용하는 곳

아동 발화를 글로 남겨 경험 구조화, 연습 후보 추천과 선택 목표에 맞는 새 연습 상황 생성의 근거로 사용한다. 연습 반응 판정과 보호자 결과·리포트의 인용도 저장된 전사 구간을 참조한다. 따라서 이름·부정 표현·관계·지시어 같은 의미가 잘못 전사되면 이후 추천·판정도 영향을 받을 수 있다.

`AI_대화인형_사회적의사소통_지원서비스_V5.1.pdf` 9·11쪽은 동일하게 처리한 아동 음성을 대화 모델과 Parallel STT Adapter에 전달하고, 두 전사와 사람 검토를 연결하는 설계를 제시했다. 13쪽 M3도 병렬 STT와 비교 실험을 포함한다. 이번 팀 결정으로 **그 설계의 별도 STT·병렬 비교 부분은 현재 MVP에서 보류**한다.

### 별도 STT를 검토했던 목적

| 사용 영역 | 검토했던 목적 | 현재 처리 |
| --- | --- | --- |
| 실제 서비스의 병렬 전사 | 같은 발화를 별도로 전사해 대화 모델 전사와 비교하고, 의미에 중요한 불일치·누락을 발견하면 해당 근거에 의존하는 추천·판정을 보류 | MVP 보류. 현재 서비스는 GPT-Live 전사만 사용 |
| 전사 방식 선정·품질 시험 | 동일 처리 음성과 사람이 확인한 기준 전사를 사용해 후보별 오류·긴 쉼·짧은 답·겹침·소음 등을 비교 | 별도 STT 후보 조사·선정·연동과 비교 시험은 후속 재검토 때 계획. 현재 필수 시험에 추가하지 않음 |
| 한계 | 두 전사의 일치는 정답 증명이 아니고, 불일치만으로 어느 전사가 틀렸는지도 확정할 수 없음 | 별도 STT를 도입하더라도 실제 품질 검증과 불확실 처리 기준이 필요 |

### Reason: 이번에 구현하지 않는 이유

**구현 일정이 부족하다.** 팀은 남은 기간에 GPT-Live 음성 연결·제어·종료와 핵심 서비스 기능을 먼저 완성하기로 했다. 새로운 STT를 조사·선정하고 추가로 연동·검증할 시간을 확보하기 어렵다고 판단했다.

별도 STT에는 공급자·모델 비교, 인증·비용·처리 조건 확인, 동일 음성의 분기·전송, 발화 구간 대응, 두 전사 비교, 지연·실패·불일치 처리까지 추가 작업이 필요하다. 병렬 전사 구현이 끝나도 품질이 좋아졌는지 별도로 확인해야 한다. 이 추가 범위를 현재 일정에 넣지 않기로 했다.

보류 이유는 **일정과 구현·검증 부담**이다. 전사 정확도가 이미 충분히 입증되었거나 별도 STT가 불필요하다는 판단으로 기록하지 않는다.

### Consequences: 현재 MVP에서 남는 책임과 한계

- Realtime `voice`는 GPT-Live 주 연결·공급자 이벤트를 담당하고 `conversation`은 제공되는 전사 조각을 발화·Turn으로 조립한다. 구체 이벤트·조립·누락 처리 계약은 구현 검증과 동료 명세에서 정한다.
- 별도 STT와의 자동 비교가 없으므로 **단일 전사의 모든 오류를 자동으로 발견할 수 있다고 보장하지 않는다.** 저장된 전사를 독립 검증된 정답 또는 검토 완료된 Canonical Transcript라고 표현하지 않는다.
- 누락·중단·조립 실패·의미 불확실 등 확보 가능한 품질 신호를 보존하고 불확실 구간을 표시한다. 불확실한 근거만으로 목표 행동 미관찰·실패를 확정하지 않으며 추천·판정은 충분한 근거 범위에서 수행한다. 세부 기준·필드는 동료 명세와 상세 계약에서 정한다.
- 요구사항 `v0.7.1.xlsx`의 FR-F04·F10에 맞춰 전사 저장과 불확실 표시·판정 보류를 유지한다. 전사 수정 화면과 사람 검토 큐(FR-F16)는 현재 MVP에서 제외된 후속 범위다. 이번 결정으로 해당 기능을 다시 MVP에 추가하지 않는다.
- 현재도 합성·성인 역할극의 발화 원문과 GPT-Live 전사를 대조해 누락·의미 변화·불확실 처리 여부를 시험할 수 있다. 추가 STT 없이 수행하는 시험이며, 실제 아동 전사 정확도 검증 완료로 해석하지 않는다.
- 원음 수집·보관·동의와 공급자 저장 정책은 기존 정책을 따르며, STT 보류를 이유로 보존 범위를 확대하지 않는다.

### Pending: 구현 확인과 후속 재검토

- **구현 확인:** GPT-Live 전사 수신, 발화·Turn 조립, 누락·중단·불확실 구간 표시와 추천·판정의 보류 연결을 검증한다. 품질 신호·필드와 구체 기준은 TBD다.
- **후속 재검토 조건:** 의미에 중요한 전사 오류가 반복되거나 추천·판정 근거의 신뢰도 개선이 필요하고, 추가 조사·연동·시험 일정을 확보할 때 별도 STT를 다시 검토한다.
- **재검토할 내용:** 후보·비용·처리 조건, 동일 음성 확보 및 발화 대응, 비교 기준, 실패·지연·불확실 처리, 필요 시 사람 검토·수정 범위. 재검토 날짜와 담당은 TBD이며 자동 채택하지 않는다.

이 범위 결정의 Source of Truth는 **ADR-004 §2.14**다. V5.1의 병렬 전사 설계나 이전 문서의 전사 공급원 미결정 표현과 충돌하면 현재 MVP에는 이 팀 결정을 적용한다. GPT-Live 지시문·키워드·평가 세부는 동료 명세를 참조하며 여기서 중복 정의하지 않는다.

# 3. Reason

## 3.1 전달 전 검사

서버가 출력 음성을 일단 보관해야 전사 대응과 검사를 거쳐 승인된 음성만 기기로 보낼 수 있다. GPT-Live 안내의 버퍼·검사·승인 후 전달 패턴에 부합하도록 선택한 설계이며, 이 문서가 전사 정확성·검사 품질·지연·모든 위험 차단을 실증한 것은 아니다. 생성 뒤 검사하지만 아동에게 전달·재생하기 전에 검사한다.

## 3.2 서버 통제권

Realtime은 ActivitySession 상태와 현재 작업, 권한, 중단과 허용 출력을 결정한다. Core는 보호자·동의 등 자신의 소유 정보를 계약으로 제공한다. GPT-Live 세션·이벤트는 상태 변경의 입력이며 서비스 상태의 권위자가 아니다. 기기의 실제 재생 보고도 생성·송신·청취를 혼동하지 않게 한다.

## 3.3 자격증명 보호

프로젝트 API Key와 공급자 연결 자격을 서버에만 둔다. 브라우저가 공급자 세션 생성·유지를 맡지 않는다.

## 3.4 책임 분리

GPT-Live의 실시간 대화 역할과 서비스 상태·평가·기록·추천·결과 처리를 분리한다. 필요한 경량 게이트 검사는 실시간 경로에서 수행하되 무거운 교육적 판정과 지식 조회의 동기 의존을 줄이는 것은 우리 설계 권고다.

## 3.5 공급자 종속 범위 제한

주 연결과 공급자 이벤트는 Realtime `voice` Adapter에 격리한다. 구현·SDK 변경과 Fake 검증의 영향을 이 경계에서 관리한다.

# 4. Alternatives와 대체된 이전 선택

## Alternative A. Spring이 음성을 중계 — 현재 채택

원본 문서에서 이 대안은 지연·서버 부담을 이유로 미채택이었다. 최신 사용자 확정의 GPT-Live 연결 **B안**은 Core가 아니라 **Realtime Activity Spring**이 기기와 GPT-Live 사이의 입력·출력 음성을 중계하고, 출력은 §2.5 버퍼 게이트로 통제하는 구조다. 원본의 Alternative A 번호와 최신 B안 명칭은 서로 다른 분류다.

중계량·버퍼·검사 비용과 지연은 실제 단점이다. 출력 전달 전 검사 요구를 만족시키기 위해 이를 수용하고 자원·지연·포화·취소를 측정한다. 단순 통과형 음성 중계로 해석하지 않는다.

## 대체된 이전 선택. 브라우저 직접 WebRTC + 서버 Sideband

원본 §2.2~2.5는 브라우저↔GPT-Live 직접 WebRTC, 브라우저 SDP 교환, 별도 서버 Sideband를 현행으로 두고 Spring이 음성을 중계하지 않는다고 결정했다. 이 선택은 출력 전사 기반 버퍼 게이트 B안으로 대체되었다. 그때의 SDP/Sideband·브라우저 Data Channel 허용 Event 목록과 관련 First Bolt 조건은 현행 구현 지시가 아니다. 낮은 서버 중계 부담은 과거 선택의 이유였지만 현재의 사전 전달 통제 조건을 충족하지 않는다.

## Alternative B. 브라우저가 공급자 Session과 자격증명을 모두 관리 — 미채택

Project API Key 노출 위험, Spring의 Session 통제권 약화, ActivitySession과 공급자 Session 연결 관리의 어려움 때문에 채택하지 않는다. 새 B안의 알파벳과 이 원본 Alternative B 번호를 혼동하지 않는다.

## Alternative C. GPT-Live가 서비스 상태와 평가를 직접 관리 — 미채택

모델 응답이 서비스 상태의 권위자가 되고 승인 콘텐츠·판정·기록 책임이 섞이며, 상태 재현과 시험이 어려워지므로 채택하지 않는다.

## Alternative D. 보호자 상태 화면도 WebSocket Push 사용 — 현 MVP 미채택

기존의 HTTPS REST와 상태별 Polling을 유지한다. 보호자 화면에 음성 수준의 실시간성이 필요하지 않고 연결 관리가 늘기 때문이다. 주기·재시도 최종값은 TBD다.

# 5. Consequences

## 장점

- 검사 전 출력과 취소된 출력을 기기에 전달하지 않는 경계를 세울 수 있다.
- 승인된 동일 음성만 현재 활동·권한·작업과 다시 대조한 뒤 보낼 수 있다.
- Project API Key를 서버에 두고 서비스 상태와 공급자 상태를 분리한다.
- 단일 전사·별도 STT 보류 및 공급자 Adapter 격리 원칙을 유지한다.
- 실제 기기 재생 범위를 생성·승인·송신 범위와 따로 관측할 수 있다.

## 단점

- Realtime이 양방향 음성 중계량, 임시 버퍼, 검사 작업, 공급자 연결을 감당해야 한다.
- 구간 분할·출력 전사 대응·검사 대기로 첫 재생 지연이 늘 수 있다.
- 기기 WSS, 공급자 주 연결, ActivitySession, 출력 승인과 실제 재생 상태를 맞춰야 한다.
- 전사·검사 자체의 오류와 늦은 결과, 차단 후 모델 맥락 회복을 처리해야 한다.
- 보호자 Polling의 반복 요청과 기기 연결 장애 처리가 남는다.

# 6. Risks

## 6.1 공급자·Java 연동

GPT-Live 주 WebSocket 및 이벤트는 공급자 종속이다. `voice` Adapter로 격리하고 First Bolt에서 Java SDK 지원, 시작·이벤트·교정·종료 계약을 실연동 확인한다. SDK가 필요한 주 연결 기능을 제공하지 않으면 같은 경계의 Java WebSocket 구현을 검토한다. 일정 내 Java 구현이 불가능할 때 공급자 연동부만 별도 프로세스로 분리하는 기존 Contingency를 유지하지만, 현재 기본 구조의 세 번째 상시 Spring으로 확정하지 않는다.

## 6.2 버퍼·지연·부하

입력/출력 중계량, 세션별 메모리 버퍼, 검사 작업, DB 풀, 모델 호출 비용을 합산한다. 구간 경계·최대 대기시간/크기·포화 처리·동시 활동 한도는 TBD다. 포화나 시간초과에서 미검사 음성을 흘리지 않고 대체 안내/실패 경로로 전환한다. Cue 최초 요청부터 실제 재생 시작까지의 기존 5초 초기 예산은 게이트 대기까지 포함해 측정하며 달성은 미검증이다.

## 6.3 전사·검사 품질

출력 전사 누락·잘못된 대응·늦은 도착, 짧은 쉼을 답변 완료로 오인하는 위험이 있다. 불확실하면 해당 음성은 전달하지 않는다. 단일 전사가 모든 의미 오류를 자동으로 드러낸다고 보장하지 않으며 검사 정확도와 대체 안내의 적절성은 별도 검증한다.

## 6.4 취소와 모델 맥락

끼어들기·쉬기·종료·철회 중 늦은 승인으로 오래된 음성이 재생될 수 있다. 활동·작업 최신성 확인과 버퍼/기기 대기열 폐기, 승인 효력 무효화를 함께 시험한다. 폐기 음성이 모델 맥락에 남으므로 교정 지시의 수락만으로 실제 제공 범위가 바로잡혔다고 보지 않는다.

## 6.5 연결·실제 재생 상태

기기 WSS, 공급자 주 연결, 서비스 상태가 서로 어긋날 수 있다. heartbeat·장애 감지·안전 종료와 실제 플레이어 관측을 구분한다. 생성 완료·게이트 승인·송신 완료는 실제 재생 완료가 아니다. 미확인 범위를 성공으로 채우지 않는다.

## 6.6 실제 아동 데이터

데모는 합성·성인 역할극으로 시험한다. 원음은 임시 메모리에서 폐기하고 우회 저장을 막는다. 실제 아동 자료 전에는 공급자 정책·보존·동의·외부 전송 조건을 확인한다.

# 7. First Bolt 검증 조건

GPT-Live 연결 B안의 선택은 확정이다. 아래는 구현·성능 검증이며 실패 시 원인과 대안을 기록하고 ADR Accepted 전환 여부를 판단한다.

## 7.1 연결·세션

- [ ] `/device`가 마이크를 쓰고 Realtime WSS로 입력 음성·제어·재생 보고를 보낼 수 있음
- [ ] Realtime이 서버 키로 GPT-Live 주 WebSocket에 연결하고 `session.start` → `session.started` 순서를 확인함
- [ ] 입력 `session.input_audio.append`와 출력 `session.output_audio.delta`, `session.input_transcript.delta`/`session.output_transcript.delta`의 실제 이벤트·순서·누락을 확인함
- [ ] 기기 대기 제어 연결과 유료 모델 연결의 수명·오류를 구분함
- [ ] ActivitySession과 공급자 연결/세션의 결합 및 종료·오류·usage 정보 제공 범위를 확인함

## 7.2 구간·게이트

- [ ] 긴 답변과 말 사이 쉼에서 구간을 분할하되 쉼을 전체 답변 완료로 오인하지 않음
- [ ] 출력 음성·전사 조각을 대응시키고 누락·지연·불명확 사례를 재현함
- [ ] 검사 전 음성은 기기로 가지 않고 승인된 동일 음성만 전달됨
- [ ] 상태·권한·작업 최신성 및 필요한 경량 의미 검사를 수행하고 송신 직전 다시 확인함
- [ ] 검사 실패·누락·시간초과·버퍼 포화 때 폐기와 대체 안내 경로를 검증함
- [ ] 대체 안내/재생성의 조건·한도와 버퍼 시간·크기 기준을 결정할 근거를 측정함

## 7.3 자격증명·데이터

- [ ] Project API Key와 공급자 연결 자격이 브라우저 Bundle·응답·일반 Log에 노출되지 않음
- [ ] 원음이 임시 메모리 외 Outbox·Inbox·DB·일반 로그·디스크에 남지 않음
- [ ] 공급자 Session 저장 미사용 정책의 실제 설정·효과와 데이터 처리 조건을 확인함
- [ ] Java SDK/Adapter의 주 연결·이벤트·교정·종료 지원 범위를 기록함

## 7.4 지연·말차례·타이머

합성·성인 역할극에서 느린 말속도, 긴 쉼, 문장 중간 멈춤, 겹침과 잡음을 포함한다. 아동 실제 성능 검증으로 해석하지 않는다.

- [ ] 발화 종료 관측 → 구간/전사 확보 → 검사 → 송신 → 기기 첫 재생의 각 지연 및 p50/p95를 측정함
- [ ] 안전 대체 안내와 유용한 답변의 첫 재생을 구분해 기록함
- [ ] 아직 말하는 중 AI가 끼어들거나 긴 쉼을 종료로 오판한 사례를 기록함
- [ ] 검사·전사·재생 대기를 아동 무응답으로 세지 않고, ADR-005의 실제 재생 완료 후 무응답 10초 초기값을 확인함
- [ ] Cue 최초 요청부터 실제 재생 시작까지 구간/전사/검사/송신 대기를 포함해 기존 5초 초기 예산을 측정함. 재시도에서 최초 시각을 초기화하지 않음

## 7.5 중단·차단 후 회복

- [ ] 보호자 STOP과 기기 끼어들기·쉬기·종료·철회를 구분하고 서버 버퍼 및 기기 대기열을 정리함
- [ ] 취소 뒤 늦게 도착한 전사·검사·승인으로 재생이 재개되지 않음
- [ ] 폐기한 음성을 GPT-Live가 이미 전달된 말로 전제하는 사례와 대화 회복을 확인함
- [ ] `session.instructions.append` 수락과 실제 교정·새 음성의 게이트 승인·재생을 각각 확인함
- [ ] 종료 뒤 늦은 공급자 출력이 다시 재생되지 않음

## 7.6 실제 재생 관측

- [ ] 필요한 구간에서 생성·승인·송신 범위와 실제 플레이어 재생 진행·중단·완료 범위를 구분함
- [ ] 끼어들기 직후의 `playbackMark` 목적과 미보고·중복·늦은 보고 사례를 확인함
- [ ] 승인 콘텐츠 재생 완료를 서버가 확인하거나 확인 불가로 남길 수 있음

## 7.7 장애

- [ ] 기기 WSS와 공급자 주 연결의 장애를 각각 감지하고 정리함
- [ ] 제한 시간 내 기기 재연결 및 실패 시 출력·대기열의 자체 안전 종료를 검증함
- [ ] 종료된 공급자 실시간 세션을 자동 재개하지 않고 미확인 재생 범위를 성공으로 채우지 않음

## 7.8 결과 기록

시험 환경, SDK/API 버전, 브라우저·네트워크, 연결/이벤트 매핑, 구간·전사 대응, 게이트 실패/차단·교정, 구간별 지연과 p50/p95, STOP·끼어들기·playbackMark, 장애·데이터 보존 결과, 발견된 문제와 필요한 대안을 기록한다. 수치·한도·구체 구현은 시험 전후에도 근거 없이 확정하지 않는다.

# 9. Source of Truth

## ADR-004

보호자 REST/Polling, 기기↔Realtime WSS의 음성·제어, Realtime↔GPT-Live 주 WebSocket, 출력 버퍼 게이트와 차단 후 회복, 공급자 이벤트 대조, 서버 키, 서비스/공급자 상태 분리, 실제 재생과 생성·승인·송신의 구분, 공급자 Adapter, MVP 단일 전사·별도 STT 보류를 관리한다.

## ADR-005

Session 상태·종료·STOP 우선순위·무응답·Cue 예산·연결 장애 상태 매핑·서버 재시작과 승인 마무리를 관리한다.

## ADR-008

보호자·기기 인증, CSRF, Origin, 리소스 접근 권한, 현재 동의·기기 결합의 상세 계약을 관리한다.

## Architecture Protocol

기기 WSS 음성·제어·재생 보고, GPT-Live 주 연결 이벤트 매핑, 앱 간 즉시/영속 전달, 구간·전사·검사·취소·교정 ACK, heartbeat·retry의 상세 메시지를 관리한다.

## GPT-Live 상세 명세

L-D02 승인 음성, L-D03 키워드·명령·전사, L-D04 지식·문맥, L-D05 판정·출력 검수·모델 배치, Prompt·Instructions·대본·Cue·평가 기준을 관리한다.
