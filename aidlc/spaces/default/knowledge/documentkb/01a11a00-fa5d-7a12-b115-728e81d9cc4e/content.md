## 2. 구현할 한 흐름

> 두 앱 기동 → Google 로그인·시험용 아동/현재 동의 → 고정 ID 기기 대기 WSS·상태 카드 → 보호자 시작 접수/기기 push → 승인 안내·참여 확인 → GPT-Live 릴레이·구간 분할/전사 대응/검사·동일 음성 전달 → 기기 재생 보고 → 보호자 종료·실제 정리/종료 사실 확인

1. Core API Spring과 Realtime Activity Spring을 별도 빌드/실행한다. Result Worker는 Core 내부, Sender/Inbox Processor는 각 앱 내부이며 세 번째 Spring·Broker를 추가하지 않는다. 기존 한 Next.js의 `/parent`·`/device`는 **서로 다른 물리 기기**에서 실행한다. 합성·성인 역할극만 사용하고 운영자의 마이크/오디오 사전 설정과 아동 역할의 음성 사용을 구분한다.
2. Google 로그인이 가능한 성인 시험 사용자 **2명**과 각 내부 `Guardian`에 연결할 시험용 아동·관계·동의를 준비한다. 제공자 식별자는 실제 로그인 결과에 연결하며 가짜 비밀번호 로그인으로 대체하지 않는다. 최초 가입·재로그인·취소/실패·다른 계정 접근 거부를 시험하고 시험 사용자 성공과 Google 공개 조건 충족을 구분한다. 서비스 동의·로그인·소유권·현재 DB 동의 검사는 실제 구현한다.
3. 허용 고정 ID Device를 사전 시드하고 기기가 Realtime `/ws` WSS로 대기하여 heartbeat·연결/준비 상태를 보고한다. 보호자는 Core의 허용 조회를 통해 상태 카드를 확인한다. 고정 ID는 통제된 데모의 허용 대상 식별이며 **운영용 인증의 증거가 아니다**. 형식/실제 값·Origin·중복/연결 교체·운영 인증은 TBD다.
4. 보호자 시작 요청에서 Core는 Session·CSRF·관계·현재 동의를 검사하고 인증된 내부 HTTP로 위임한다. Realtime은 검증된 주체/행위/대상과 지정 기기의 허용·현재 연결·점유·원자 할당을 대조한다. 중복 확인·`PREPARING`·접수 기록을 짧은 트랜잭션으로 커밋해 응답하고, 준비/참여를 기다리지 않는다. 응답 유실은 같은 요청으로 재확인하여 중복 활동/시작을 만들지 않는다. 기기에 시작을 push한다.
5. Realtime은 서버 키로 GPT-Live API(`gpt-live-1`) 주 WebSocket을 시작한다. 기기 마이크/플레이어/WSS 준비, 공급자 `session.started`, 승인 버전 안내, 아동 참여는 각각 다른 사실이다. **`PREPARING → ACTIVE`는 아동 참여 확인 후** Realtime 공식 이벤트 처리 경로에서 수행한다. 대기 WSS만으로 유료 모델 연결을 시작했다고 보지 않는다.
6. 기기 입력 음성을 Realtime이 권한/활동 결합 검사 후 공급자로 중계한다. 출력은 **앱 구간 분할 → 임시 버퍼/출력 전사 대응 → 상태·권한·작업 최신성 및 필요한 경량 의미 검사 → 동일 음성 승인 → 전달 직전 재확인 → 기기 송신**으로 처리한다. 실패·누락·대응 불명확·시간초과에는 미검사 음성을 폐기하고 대체 안내 경로를 확인한다. 생성/전달/기기 재생과 실제 청취·이해를 구분한다.
7. 플레이어의 진행/중단/완료 관측 `playbackMark`를 Realtime이 활동·현재 연결·승인 음성/재생 묶음과 대조한다. 보고 불가와 마지막 신뢰 관측을 남기며 미보고 범위를 완전 재생으로 채우지 않는다. 가드레일 차단 후 계속할 권한이 있는 대화는 대체 안내·앱 교정 지시·새 출력 재검사로 회복한다. 폐기 음성의 모델 맥락 잔존과 교정 ACK≠재생 승인을 시험한다.
8. 보호자는 상태 조회/종료 확인을 통해 종료를 요청한다. **참여 이후 유효 기록이 있는 보호자 중도 종료**의 대표 경로는 **`ACTIVE → ENDING → PARTIAL`**이며 사유를 보호자 종료로 구분한다. 원본 `end_reason=guardian_stop`은 기존 코드 후보이고 최종 필드/Enum은 TBD다. 요청 접수·DB 종료·버퍼/기기 출력·공급자 연결 정리·실제 중단 확인을 구분한다. 미확인 정리를 성공으로 표시하지 않는다.
9. 준비 취소·미참여·참여 거부·중복 시작·끼어들기·쉬기·아동 종료·철회·연결 장애·늦은 승인/보고·차단 후 회복은 작은 흐름의 별도 경계 사례로 시험한다. **호출어+종료 명령어**의 실제 원문/인식 기준은 동료 명세에서 확인한다. 유효 종료 표현의 서버 확인 즉시 `ENDING`인 A안은 현행이며 일반 출력/버퍼 취소 → 승인 마무리 인사 1회 예외 → 실제 정리 확인을 시험한다. 보호자 종료에 아동 인사 예외를 자동 적용하지 않는다.

`PARTIAL`은 참여 이후 유효 기록이 있는 활동 중도 종료의 상태이며 Core의 결과 준비/실패와 구분한다. 미참여·자료 부족·철회는 ADR-005의 별도 계약을 따르고 원문이나 결과를 만들어 채우지 않는다. 첫 볼트는 종료 사실·사유와 허용된 최소 기록까지 확인하고, 유효 기록의 부분 결과 요구는 후속 구현으로 연결한다. 첫 종료 화면을 AI 요약·추천·평가·결과 생성 완료로 표시하지 않는다. 기술 POC의 실통신 목표와 실제/Mock 제품 시연 범위(Q-DEVICE-01/G-01)는 구분한다.

## 3. 요구사항에서 선택한 범위

아래는 **관련 요구사항의 일부 구현·검증 범위**다. 이 표만으로 각 FR 전체를 완료 처리하지 않는다.

## 4. 첫 구현에 사용할 계약 후보

### 4.1 HTTP와 화면

아래는 [protocol.md](protocol.md)의 **기존 후보를 연결한 안**이다. 요청/응답·오류·중복/재조회·CSRF 상세를 정하고 OpenAPI에 반영한다. REST·WS·테이블 수를 고정하지 않는다.

| 기능 | 경로 후보·실행 위치 |
| --- | --- |
| Google 로그인 | Core: `GET /oauth2/authorization/google`·`GET /login/oauth2/code/google` — Spring 기본 구현 후보. 자체 `POST /api/auth/login`은 사용하지 않음 |
| Session 조회·로그아웃 | Core: `GET /api/auth/me`·`POST /api/auth/logout` 후보. 변경 REST/로그아웃 CSRF, OAuth state 및 사용 시 OIDC 검증을 구분 |
| 시험용 아동·현재 동의 | Core: `GET /api/children`·`GET /api/children/{childId}/consent` 후보 |
| 자유대화 시작 | Core 공개 `POST /api/children/{childId}/free-talk/sessions` 후보 → 인증된 Realtime 내부 HTTP. 응답은 시작 접수이며 참여 완료가 아님 |
| 상태·준비 취소·진행 종료 | Core 공개 `GET /api/sessions/{sessionId}`·`POST /api/sessions/{sessionId}/cancel`·`POST /api/sessions/{sessionId}/stop` 후보 → Realtime 명령/조회 |
| 기기 음성·제어·보고 | Realtime `/ws` WSS. 오디오 형식·메시지/최종 payload·Origin/인증·현재 연결 결합은 TBD |
| 추가 상세 | CSRF 전달, 허용 기기/현재 활동/상태 카드 응답, 내부 HTTP·서비스 인증·즉시 접수/재조회·공개 내부 경로 차단. 기기 별도 HTTP 필요성/Endpoint는 TBD |

시작 요청 전 준비 화면 취소는 프런트 로컬 동작이며 기기에 시작을 보내지 않는다(FR-B05). `cancel`은 서버 접수 후 `PREPARING` 취소 후보이고 진행 중 `stop`과 상태/응답을 구분한다. 즉시 명령은 사후 Worker 큐 뒤에 넣지 않는다.

보호자 화면은 로그인·아동/기기 확인·준비·진행·종료 확인·사유/미확인 사실을 연결한다. 진행 화면에 실시간 전사·질문 조작을 추가하지 않는다. TanStack Query 상태 조회와 원본 **1~2초 Polling 제안값**을 시험하며 최종 주기·표시 문구/상태는 TBD다. 재진입·백그라운드 복귀·조회 오류, 활동 최종 상태와 실제 정리 미확인을 구분한다. 정리 확인이 남았는데 최종 상태라는 이유로 재확인을 중단하지 않는다. 재조회/Polling 종료 조건·제한 시간은 protocol 담당 계약이다.

### 4.2 기기 제어와 공급자 연결

| 방향/목적 | 메시지·검증 계약 |
| --- | --- |
| Realtime → 기기 | 보호자 시작 push(최종 이름 TBD), 기존 `STOP_OUTPUT`·`CLOSE_TRANSPORT` 후보. 현재 활동/연결·명령 중복·순서·유효성 검사 |
| 기기 → Realtime | 기존 `HEARTBEAT`·`ACK`·`DEVICE_READY`/`TRANSPORT_STATE`·`VOICE_SESSION_CLOSED` 후보. 대기/준비·로컬 정리와 공급자 관측 구분 |
| 승인 콘텐츠·실제 재생 | 기존 `PLAY_APPROVED_CONTENT`·`PLAYBACK_FINISHED` 후보와 `playbackMark` 관측 계약. 생성/승인/송신/수신 ACK와 실제 재생은 별개이며 최종 필드명·단위 TBD |
| 실시간 음성 | 기기↔Realtime WSS와 Realtime↔GPT-Live 주 WebSocket 릴레이. 브라우저는 공급자 키·직접 연결 권한을 받지 않음 |

- 기기는 `CHILD_PARTICIPATED`·`CHILD_STOP_REQUEST` 같은 의미 이벤트를 최종 판정/발행하지 않는다. Realtime이 전사·동료 명세의 참여/키워드 근거를 활동 공식 이벤트 경로로 연결한다. 끼어들기·재생 보고는 자동 `ENDING`의 근거가 아니다.
- 수신 ACK는 실제 출력 중단 증거가 아니다. 종료는 상태/승인 무효·서버 버퍼 취소·기기 현재/대기 출력 차단·공급자 정리를 각각 관측한다. 한 경로의 ACK를 기다리느라 다른 차단을 미루지 않고, 네트워크와 무관한 원격 즉시 종료를 보장하지 않는다.
- `playbackMark`는 기기 플레이어 관측을 Realtime이 검증하는 **앱 계약**이다. 활동·현재 연결·승인 음성 식별, 위치 단위, 진행/중단/완료 보고 시점, 중복/역전/구 연결/늦은 보고, 보고 불가와 마지막 신뢰 관측, Cue/타이머/근거 활용을 시험한다. 공급자 전사 시간과 실제 재생 위치를 동일하게 쓰지 않는다. 공급자에 보고를 보내면 미재생 맥락이 삭제된다고 가정하지 않는다.

공급자는 **GPT-Live API(`gpt-live-1`)**다. Realtime 서버가 `wss://api.openai.com/v1/live/sessions` 접속 → 모델/설정을 넣은 `session.start` → `session.started` 확인을 수행한다. 아래는 audit §5.1의 대조 계약이며 실제 Java SDK/필드·오류·취소·종료·사용량·저장 조건은 미검증/TBD다.

| 확인 대상 | 주 연결 근거·시험 책임 |
| --- | --- |
| 입력 음성 | `session.input_audio.append`. 기기 메시지/권한을 공급자 Adapter에서 변환 |
| 출력 음성 | `session.output_audio.delta`. 즉시 기기로 흘리지 않고 임시 버퍼/게이트로 수신 |
| 입력·출력 전사 | `session.input_transcript.delta`·`session.output_transcript.delta`. 조각 누적·전사/구간 대응은 앱 책임 |
| 발화/전체 안내 완료 | 동일한 발화별 오디오 완료 이벤트를 가정하지 않음. 쉼/큐 공백을 전체 완료로 단정하지 않고 앱 완료 범위/재생 관측 사용 |
| 차단 후 교정 | `session.instructions.append`와 수락을 확인하되 맥락 삭제·교정 성공·재생 승인과 구분. 새 출력도 다시 검사 |
| 공급자 정리 | 실제 종료/오류/usage 이벤트·명령·지원 범위 TBD. 소켓 close, 공급자 마무리, 기기 정리/미확인 구분 |

GPT-Live가 발화 시점을 관리하는 계약을 유지하고 다른 API의 수동 오디오 commit·음성 턴 생성 절차를 가져오지 않는다. delegation/KG·GraphRAG는 **확인 항목·미채택**이며 발화 정지/게이트 대체의 근거가 아니다.

Realtime 미디어 Adapter가 **분할 → 전사 대응 → 상태·권한·최신성+필요 경량 의미 검사 → 동일 음성 승인 → 송신 직전 재확인**을 조정한다. 검사 수행은 전달 조건이고 모든 위험 발견의 보장이 아니다. **무거운 교육 판정·KG 조회를 동기 게이트에서 분리하는 것은 우리 설계 권고**다. 필수 안전 검사를 사후로 미루거나 필요한 근거가 없는 구간을 통과시키지 않는다. 알고리즘/라이브러리·구간/전체 완료·검사기·버퍼 한도/포화·안내/재생성 한도는 TBD다.

차단 음성도 모델 맥락에 남는다. 계속할 권한이 있는 대화는 앱이 작성한 교정 지시/대체 안내로 회복하며 미승인 원문을 시스템 지시에 복사하지 않는다. 교정 수락만으로 취소된 음성의 승인을 복원하지 않고 새 출력도 전사 대응·검사·재승인한다. 같은 말을 재생성해도 이전 승인 결과를 재사용하지 않는다. 일반 대체 안내/재생성 한도는 TBD이며 Cue 재요청은 [Cue 계약](protocol.md#cue-contract)의 남은 총 예산·확인 조건을 따르고 수락/재생 불명확 시 자동 재요청하지 않는다.

| 구분 | 첫 볼트 범위·쓰기 소유권 |

실시간 원음은 **임시 메모리 사용·폐기**이며 DB·Outbox/Inbox·일반 로그·디스크에 저장하지 않는다. 승인 고정 음성 파일과 보존 범위를 무조건 합치지 않는다. 공급자 저장 미사용의 실제 설정/조건은 지원 검증 전 TBD다. `device_client` 같은 테이블명·고정 테이블 수를 새 결정으로 간주하지 않는다. `SessionEvent` 영속 범위·`ActivityContext` 사용/시험용 목적 필드는 담당 계약에서 정한다.

Java **21**·Boot **4.1.x**는 ADR-002의 기존 후보 상태를 유지한다. 두 앱/공통 계약 빌드·component/entity/repository scan·scheduler, Spring Security/Session·Flyway/JPA·Testcontainers·GPT-Live Java SDK/전송 Adapter·springdoc `/v3/api-docs`의 호환성을 확인한다. 도메인/Repository 소유권·공급자 격리·상태 변경 진입점·최소 ArchUnit을 적용한다. OpenAPI→TS는 안정된 첫 HTTP 계약으로 Cookie/CSRF 연동부터 검증하고 도구/CI·전체 생성은 단계 결정한다. 기본 CI는 Fake/Mock Adapter이며 유료 호출은 별도 POC로 구분한다. 배포의 EC2/볼륨/백업/DB 비공개·한 Next.js 두 접점·Neo4j는 ADR-006을 유지한다.

- **호출어+명령어 기반 활동 제어**와 시작 전 참여 의사 확인은 구분한다. 실제 클래스/이벤트명은 TBD이며 `KeywordCommand`를 확정하지 않는다. 키워드 없는 발화(“그만할래” 포함)·기기 재생 재유입을 곧바로 제어 명령으로 처리하지 않는다. 유효 종료 표현의 판단 기준은 동료 명세이고 확인 이후 순서는 ENDING A안이다.
- 아동 유효 종료 확인 즉시 `ENDING` → 일반 출력/진행 차단·버퍼/기기 대기열 취소·늦은 승인 무효 → 승인 마지막 인사 **1회 예외** → 실제 정리 확인. 이 순서를 다시 검토안으로 두지 않는다. 인사 확보/재생 실패·제한 시간·미확인·사유는 ADR-005의 상세 계약을 시험한다.
- 현재 동의/권한을 확인할 수 없으면 새 처리·외부 요청·승인/송신·저장/결과 반영을 보류·차단한다. STOP/안전 정리는 수행한다. 철회 알림 Outbox만으로 즉시 반영을 보장하지 않는다. Core 장애 중 보호자 직접 Realtime 종료(G-02)는 **미해결 대안**, 철회 경합(G-03)은 구현 전 상세 게이트다.

**목표 행동의 동적 정의·근거/4요소 완비와 실시간 Cue 정책은 보존**한다. 원본 FR-C02/F06/F10·2026-10-02 참조를 새 D-01 미정으로 되돌리지 않는다. 후속 [목표 생성 계약](result-pipeline.md#goal-generation-contract)·[정의/버전 모델](data-model.md#goal-definition-model)·[Cue 계약](protocol.md#cue-contract)·[Cue 수명주기](session-state.md#cue-lifecycle)를 따른다. 전체 목표 생성/연습은 후속이며 이번 **합성 상황의 작은 Cue 예산 POC**와 구분한다.

## 6. 완료 조건과 시험 증거

아래는 [ADR-004 §7](../ADR-004-communication-voice.md#7-first-bolt-검증-조건)의 연결·Lifecycle·권한·지연·중단/재생·장애와 audit §5.3을 연결한 **미실시 시험 계획**이다. 현재 전부 미검증이며 미합의 상세는 `Blocked/TBD`, 기대 불충족은 `Fail`로 기록한다. 계획/문서 개정을 시험 통과로 처리하지 않는다.

- [ ] **정상 흐름/두 앱:** 두 Boot의 build·scan/scheduler·쓰기 권한/공통 계약과 두 물리 기기의 §2 흐름을 확인한다. 참여 이후 유효 기록이 있는 보호자 중도 종료에서 `PREPARING → ACTIVE → ENDING → PARTIAL`·보호자 종료 사유, 접수/준비/참여·활동/결과 준비·실제 중단 구분을 기록한다. 미참여/자료 부족 분기는 별도 확인한다.
- [ ] **Google/서비스 세션:** 최초 가입·재로그인·취소/오류, 같은 Google 계정의 동일 Guardian 연결, state 누락/불일치·사용 시 잘못된 OIDC ID Token 거부, 이메일만의 계정 자동 병합 금지를 확인한다. Session ID 변경·CSRF 갱신·Logout/만료·기존 세션 재사용 거부·미로그인 실패와 실제 등록/공개 조건을 남긴다. 공급자 토큰은 서비스 Session과 구분한다.
- [ ] **접근/고정 기기:** 미로그인·다른 보호자·동의 없음/철회·허용되지 않은 ID/Origin·구 연결·다른 활동의 음성/보고·위조 내부 주체를 거부한다. 지정 기기 미연결/점유/할당 경합·중복 시작·준비 취소·응답 유실 재확인·재진입을 시험한다. 고정 ID만으로 운영 인증 완료를 선언하지 않는다.
- [ ] **실제 주 연결:** 마이크/플레이어·대기 WSS/상태 카드·시작 push·Realtime 서버 키의 `session.start → session.started`·입출력/전사 이벤트가 동작하는지 시험한다. 준비 수신 주체·활동/현재 연결 결합·명령 허용·실패 정리와 SDK/API 지원을 남긴다.
- [ ] **출력 게이트:** 분할/전사 대응·상태/권한/최신성·필요 경량 의미 검사·동일 음성 승인·송신 직전 재검사를 확인한다. 텍스트 부족/누락/늦음/오대응·검사 실패/시간초과·버퍼 포화 때 미검사 음성 전달이 없고 폐기/대체 안내로 이어지는지 확인한다. 같은 발화의 재생성에도 이전 승인을 재사용하지 않고 새 음성·전사에 다시 검사/승인하는지 시험한다. 안전성/의미 품질 전부를 검증했다고 표시하지 않는다.
- [ ] **참여/키워드:** 승인 버전 안내·참여·미참여·최대1회 제안/재거부·합의한 무응답 분기, 호출어+종료 명령·키워드 없는 발화·출력 재유입을 구분한다. 미참여 원문을 저장하지 않고 준비만으로 ACTIVE가 되지 않는지 확인한다.
- [ ] **취소/종료:** 끼어들기·쉬기·보호자/아동 종료·철회·중복 종료·늦은 이벤트/승인을 분리 시험한다. 서버 버퍼/기기 큐·승인/타이머 무효화, 아동 즉시 ENDING→승인 인사1회 예외, 기기/공급자 정리·미확인·늦은 재생 금지를 기록한다. 끼어들기만으로 ENDING을 만들지 않는다.
- [ ] **실제 재생/playbackMark:** 생성·승인·송신·ACK·실제 플레이어 관측을 구분한다. 고정 승인 음성/실시간 음성의 부분·중단·자연 완료/불가·중복/역전/구 연결/늦은 보고를 검증한다. 타이머에 쓰는 전체 질문/안내 범위와 마지막 신뢰 관측을 기록하며 미확인 재생을 성공으로 채우지 않는다. 실제 청취/이해를 입증했다고 쓰지 않는다.
- [ ] **차단 후 회복:** 폐기 발화가 이미 제공됐다고 모델이 전제하는 사례, 앱 교정/대체 안내 후 흐름과 새 출력 재검사를 확인한다. `session.instructions.append` 수락을 맥락 삭제·교정 성공·재생 승인으로 처리하지 않고 미승인 원문을 시스템 지시로 복사하지 않는다.
- [ ] **장애/앱별 복구:** 기기 WSS·서버 공급자 링크를 각각 단절시켜 재연결/실패 자체 정리·유예/미확인을 시험한다. 닫힌 음성 세션/종료 활동을 자동 재개하지 않는다. Realtime 재시작은 소유한 진행 음성 활동의 ADR-005 오류 정리·버퍼 비복원, Core 재시작은 자신의 Job/Outbox/Inbox 복구이며 정상 상대 활동을 일괄 변경하지 않는지 확인한다.
- [ ] **내부 전달/후속 복구:** 즉시 명령 응답 유실·같은 요청 재확인·공개 내부 Endpoint 차단/수신 서비스 인증을 시험한다. 영속 경로 구현 시 업무+Outbox 커밋·수신 커밋 전/후 크래시·ACK 유실/중복/역전·Inbox 업무/완료 원자 반영·미처리 복구를 확인한다. ACK는 처리완료/LLM 성공/재생이 아니다. 후속 Worker/run/lease/fencing·원격 등록/checkpoint·이전 실행 차단은 전체 결과 단계의 증거로 남긴다.
- [ ] **기록/삭제/입력 경계:** 합의 최소 보존·데모 자료 정리, 버퍼/DB/Outbox/Inbox/로그/디스크 원음 비저장·Secret 비노출을 확인한다. 빈 배경 정상 흐름과 별도 합성 보호자 입력/가짜 평가 자료로 외부 요청의 역할/필드를 검사하여 보호자 원문·기존 평가·채점 기준·타 아동 자료가 대화 역할에 전달되지 않는지 확인한다. 현재 권한 확인 불가·철회/삭제 후 늦은 저장/송신을 시험하고 G-03 미해결을 남긴다.
- [ ] **지연/자원:** §6.1의 여섯 항목·구간별 시간과 느린 발화/긴 쉼/중간 멈춤·표본 수·상태별 p50/p95를 기록한다. 두 앱 실행기/DB pool·입출력 중계·버퍼/검사·외부 호출/Worker/Sender 합산 부하/포화를 관측한다. 측정 전 처리량·동시 활동 수·지연 달성이나 8GB 후보 적합성을 선언하지 않는다.
- [ ] **기반 호환성:** Java/Boot/SDK·DB·Session/CSRF/재시작 직렬화·Flyway 단일 적용/각 앱 validate·소유 스키마 쓰기·상대 쓰기 차단·springdoc/생성 TS·모듈/ArchUnit·Next.js 두 접점의 결과를 남긴다. 무거운 교육/KG를 동기 게이트에서 분리하는 권고의 실제 경로를 확인한다.

### 6.1 지연 POC — audit §5.3의 여섯 항목

합성/성인 자료로 작은 미디어·대화 검증 경로부터 측정한다. 전체 목표 선택·연습/Cue 제품 기능의 구현 완료는 후속이다. Cue 예산은 허용된 합성 상황·작은 CueBrief 경로로 별도 확인하고 전체 실시간 도움 기능을 구현한 것으로 기록하지 않는다. Mock/실공급자·사용한 정의/승인 버전·동의/권한을 구분한다.

| 확인 대상 | 남길 관측·실패 사례 | 판정/측정의 경계 |
| --- | --- | --- |
| 출력 구간 분할 | 말 사이의 쉼, 길게 이어지는 답변, 조각 도착 지연, 짧은 멈춤 뒤 이어지는 발화 | 쉼/큐 공백을 전체 답변 완료로 잘못 판정하지 않는지. 알고리즘/라이브러리·구간/전체 완료 기준은 TBD |

| 차단 이후 대화 | 폐기한 말을 이미 전달했다고 모델이 전제하는지, 교정/대체 안내 뒤 흐름·새 출력 재검사 | 폐기 음성의 맥락 잔존, 교정 ACK≠재생 승인/실제 교정 성공. 일반 끼어들기/종료/가드레일 차단 회복을 구분 |
| 무응답·Cue 예산 | 전체 유효 질문/안내의 실제 재생 완료 후 **무응답 10초·재안내1회**, Cue 최초 요청부터 실제 첫 재생까지 **5초 초기 예산** | 구간/전사/게이트/송신/재생 대기는 아동 무응답에서 제외하고 Cue 예산에는 포함. 재요청/재생성으로 최초 시각을 초기화하지 않음. 이후 대기/종료 분기·실제 달성은 TBD/POC |

필요한 관측 지점/표본·수용 기준을 합의해 단계별 시간과 실패/미확인을 남긴다. API가 제공하지 않는 완료 이벤트, 기기의 관측하지 않은 재생 시각, 누락된 전사/재생 범위를 지표에 만들지 않는다. 측정 완료와 성능 승인을 구분하며 필수 검사를 줄여 지연을 맞추지 않는다. 범위 추가가 VAD/검사기 채택, 가드레일 정확도 승인, 처리량 보장, 일정 확정을 뜻하지 않는다.

### 6.2 시험 증거와 완료 판정

시험 결과는 이 문서의 후속 개정에 아래 항목을 기록하고, 기존 실제 검증 기록이 있으면 연결한다. 현재 실행/POC 검증 기록은 **없음**이며 이번에 별도 history/review/backup 폴더·결과 문서를 만들지 않는다.

| 필수 기록 | 내용 |
| --- | --- |
| 재현 조건 | 커밋/시험일·두 앱 build/설정·Java/Boot·SDK/API/모델·브라우저/네트워크·합성/성인/Mock·동료 명세/승인 콘텐츠 버전 |
| 사례별 결과 | 연결된 FR/NFR·D-ID·선행 상세, 입력/기대/실제, Pass/Fail/Blocked/TBD, 필수 검증과 후속 미구현의 구분 |
| 증거 | 익명 시험 Session/논리 상관 식별, 상태/버전·구간/전사/검사/승인/송신/재생의 단계별 시각/지연·표본/p50/p95, 중단/불가/마지막 신뢰 관측·폐기/회복·앱별 복구/ACK. 실제 필드/단위 TBD, 원음/키/응답 원문 일반 로그 없음 |
| 후속 조치 | 미해결 문제·재시험 조건·미채택 대안, 원문 연결/논의 담당·정책 결정과 구현 오류 구분 |

필수 연결·게이트·중단·재생·회복·장애 검증이 실패/미결정이면 첫 볼트를 완료로 표시하지 않는다. 특히 ADR-004 Accepted 전환은 해당 ADR 조건/별도 팀 합의가 필요하다. Java 연동 실패는 Adapter 경계 안의 대안/재시험을 검토하며 실패를 숨기는 임시 성공 응답이나 미검사 음성 우회를 만들지 않는다. 합의된 릴레이 방향을 임의로 과거 직접 연결로 되돌리지 않는다.

## 7. 첫 2주 진행 순서 제안

| 순서 | 산출물·확인점 |
| --- | --- |
| 착수 전 | §5의 해당 상세·시험 범위/담당/기대 결과, protocol의 첫 HTTP/WSS·내부 계약, 최소 보존/관측과 단계별 측정 정의 합의 |
| 1주차 | 두 앱/DB/스키마·Google/Session/CSRF·고정 ID 대기 WSS/상태 카드/할당·시작 push·서버 주 연결/입출력/전사·구간/검사/승인 전달, 승인 안내/참여/상태 조회의 작은 흐름 검증 |
| 2주차 | 보호자/아동 종료 A안·취소/늦은 승인·playbackMark·차단 후 회복·각 앱/링크 장애·권한, §6.1 지연/예산·합산 부하, OpenAPI/TS·증거와 미해결 판단 |
| 종료 검토 | §6 필수/POC/후속 구분·실제 결과/Blocked/TBD 검토. 확인한 상세는 담당 문서의 후속 개정에 연결하고 정책 변경은 ADR 결정으로 남김. 다음 볼트 선택 |

기간은 기존 **제안**이며 POC 항목을 적었다고 첫2주 달성을 확정하지 않는다. 핵심 연결/검사/중단 실험이 막히면 후속 기능을 늘리기 전에 원인·대안·재시험을 정한다. 일정 경과로 미검증을 완료 처리하지 않는다.

## 8. 후속 볼트로 남기는 범위

- Core 내부 자유대화 결과/요약/추천·ResultJob 전체 처리·영속 요청/완료·run/lease/fencing·체크포인트·원격 목표 등록·재시도/복구, FR-B08·FR-F05·FR-F12. 유효 기록이면 부분 결과를 요구하고 활동 PARTIAL과 결과 준비를 구분한다. 전달·LLM 기술·내용 수정·보호자 수동 재시도를 분리하며 이전 run이 새 run을 덮거나 활동을 부활시키지 못한다.
- Realtime 목표 선택·상황/연습·평가·실시간 Cue·새 상황·Support Library 전체, Core Neo4j 그래프/지식 구현. Neo4j 채택/운영 PostgreSQL·동적 정의/근거 기반4요소·불변 사용 버전·첫/도움 후/새 상황·실제 제공 범위 정책은 유지한다. 원본 [결정 로그](../decision-log.md#goal-cue-decisions) 연결은 이력/8단계 요약 접점이며 현행 세부는 result-pipeline/data-model/protocol/session-state를 따른다. 전체 제품 구현과 이번 작은 Cue 예산 POC를 구분한다.
- 전체 기록·리포트·공유, 전사 수정·검수/사람 검토 큐 운영 Backlog, 전체 동의/철회/삭제 UI, 키워드 설정/초기화·쉬기/재개 전체 흐름. 삭제된 사용자 연습 건너뛰기를 다시 추가하지 않으며 도움 거절/생략·기술적 미실시는 구분한다.
- 위험 발화 전체 대응/검토 큐(D-11), 운영 기기 인증/영구 페어링, 실제 아동 자료 처리 전 승인(D-14), 전체 운영 배포/백업 자동화·Redis AI Cache. 이번 필수 출력 검사/차단·안전 정리는 후속이라는 이유로 생략하지 않는다.

후속 구현 표시는 MVP 요구의 삭제/우선순위 변경이 아니다. 실제/Mock 제품 시연 범위, 운영 보안/아동 자료, 전체 표시 상태는 미결정/별도 승인 상태를 유지한다. 프론트2앱·Vite·CloudFront·QR claim·delegation을 새 확정 기술로 추가하지 않는다. 첫 종료 화면을 전체 요구사항 완료로 간주하지 않는다.

## 9. 대체된 이전 선택 / 미채택 대안

아래는 원본의 선택/검증 계획 이력이며 **현행 구현/시험 지시가 아니다**. 기존 비충돌 첫2주 제안·작은 수직 흐름·합성/성인·상태/실제 출력 구분·FR/NFR/D-ID·목표/Cue·전사 후속 범위는 보존한다.

- **3개 소셜 로그인:** 원본은 카카오·구글·네이버, `registrationId`의 `google`/`kakao`/`naver`, 각 가입/재로그인/실패, 네이버 개발 시험 사용자/공개 검수 증거를 요구했다. 현행 Google만으로 대체했다. 자체 ID/PW 제외·Guardian·Spring Security OAuth2 Client·Spring Session JDBC·CSRF/Logout·계정 자동 병합 금지는 유지한다.
- **직접 음성 연결/준비:** 원본은 브라우저↔GPT-Live WebRTC 직접 연결, SDP Offer/Answer, `POST /api/device/sessions/{sessionId}/rtc`, `START_NEGOTIATION`, Sideband attach/이전 이벤트·브라우저 Data Channel Allow List·`session.started`를 시험했다. 서버 주 WebSocket 릴레이/기기 음성 WSS·Realtime 구간/전사/게이트·재생 관측으로 대체했다. [당시 WebRTC 참고 링크](https://developers.openai.com/api/docs/guides/voice-webrtc)·[당시 Sideband 참고 링크](https://developers.openai.com/api/reference/resources/live/sideband-websocket)는 원본 2026-09-30 참고 이력이며 현행 주 연결 계약의 검증 근거로 쓰지 않는다.
- **이전 종료/저장·SDK 시험:** 원본 `session.closed` 및 `close_requested`/`expired`/`content`/`remote_hangup`/`connection_lost` 사유, 최종 usage·`store=false`, `openai-java` 세션 생성/Java Sideband 시험은 이전 연결/미확정 참고다. 해당 필드·이벤트를 GPT-Live 주 연결에 있다고 확정하지 않는다. 현행 SDK·종료/오류/usage·저장 미사용 설정은 실연동 TBD다.
- **전역 기기 수·발급:** 원본은 Available 0/1/2+, 1개만 할당·2개 이상 시작 차단과 기기 단기 Credential 발급/TTL/저장 후보를 사용했다. 지정 고정 ID의 허용·현재 연결·점유·원자 할당, 사전 시드·대기 WSS·상태 카드·보호자 시작 push로 대체했다. 브라우저 임시 키·Ephemeral, `/device` 단기 인증 Cookie·운영자 일회용 발급 코드 후보를 현행 첫 흐름에 추가하지 않는다.
- **아동 종료 순서 미정:** 원본은 즉시 ENDING을 검토안/DL-005-11 합의로 남겼고 과거 인사 재생 후 ENDING 순서에 연결했다. 현행은 유효 표현 확인 즉시 ENDING A안과 일반 출력/버퍼 취소·승인 마지막 인사1회 예외·실제 정리로 대체했다.
- **단일 앱 재시작:** 원본 단일 Spring의 진행 활동 오류 정리 시험을 Core/Realtime 각 소유 Job/전달·음성 활동 복구로 구분했다. 메모리 버퍼 비복원·미확인 재생·결과 참조 보존은 현행 계약이다.
- **연습 건너뛰기 후속 후보:** 원본 범위 표/후속 항목에 있던 사용자 연습 건너뛰기는 v0.2 삭제 정책으로 대체했다. 도움 거절/생략과 기술적 미실시를 삭제하는 의미는 아니다.
- **미채택 공급자 절차:** `input_audio_buffer.*`·`response.output_audio.*`를 GPT-Live의 입력/출력·음성 한 턴 완료 계약으로 사용하는 예시, 수동 commit/일반 음성 생성 트리거는 채택하지 않는다. 원본에서 이 이벤트 오류를 발견했다는 의미가 아니라 audit §5.1의 혼용 방지 기준이다. delegation은 확인 항목이며 이름만의 이벤트 치환이나 새 채택을 하지 않는다.
