## 0. 적용 범위와 변경 기준

### 0.1 읽는 방법

이 문서는 변경 내역만 나열한 문서가 아니라 **기존 기능을 포함한 전체 기능명세서**다. v0.1의 이벤트 단위 구성을 유지하며, 각 기능에 화면·관련 요구사항·우선순위·트리거·사전조건·입력·처리·출력·예외·논리 API/데이터를 기록한다. 기존 ID는 가능한 한 유지한다. (근거: S01 §0·§2·§5)

다음 표시를 구분한다.

| 표시 | 의미 |
|---|---|
| 확정 | 이번 사용자가 결정한 범위 또는 변경하지 않은 v0.1의 기능 정책 |
| 잠정 | 구현 논의를 위한 임시값. 성능·사용성 검증이나 팀 최종 합의를 마친 값이 아님 |
| 작성 제안 / 작성 해석 | 빈 부분을 연결하기 위해 제시한 안. 사용자 확정과 구분하며 필요한 확인 항목을 연결 |
| 후속 설계 | API·ERD·인증 설정 등 지정된 후속 문서에서 결정할 항목 |

**우선순위(Must/Should/Could)와 확정 여부는 다른 값이다.** 기존 우선순위는 S01을 계승한다. 새 기능의 우선순위 표기는 초안이며, 사용자가 세부값에 답했다는 이유만으로 관련 기능 전체를 일괄 Must로 바꾸지 않는다.

### 0.4 자료 충돌 처리

최신 사용자 결정이 명시된 주제는 그 결정을 적용한다. 그 외 기능 동작은 S01을 유지하고, 화면 위치·화면 내부 상태는 S02/S03을 참조한다. 사진에 남은 이전 문구가 최신 결정을 다시 덮어쓰지 않게 한다.

| 충돌·차이 | 이번 처리 |
|---|---|
| S02 T01에는 ID/PW 입력이 남음 | T01 구조는 유지하되 소셜 로그인 3개 버튼으로 변경 명세. 자체 가입 화면은 제거 |
| S03의 이름·종료 표현은 이전 이름 | `무중` 및 `무중아 그만할래`로 변경 |
| S01 연습 건너뛰기 기능 | 삭제. 자유대화의 `무중아 넘어갈래` 적용 여부는 후속 범위에서 정하며, 현재 연습 기능에는 포함하지 않음 |
| S05의 기기 일회용 코드·단기 인증 발급 후보 | 이번 고정 ID 데모에서 제외. 완성된 운영 인증으로 주장하지 않음 |
| S05의 PARTIAL 뒤 결과 작업 미생성 | 최신 U-09에 따라 유효 기록이면 부분 결과 작업을 요구. 기술 상태도·Job 설계를 후속 동기화 |
| S05의 기존 제안 시간값 | U-07의 잠정 10/30/5초를 이번 기능 문서 기준으로 표시. 성능 보장치로 승격하지 않음 |
| S01의 원음 선택 보관 vs S05 일부 문서의 원음 미보관 | 이번 사용자 답변은 원음 정책을 바꾸지 않았다. S01을 계승하되 정책 충돌을 Q-DATA-02에 남김. “대화 원문”을 음성파일 보관으로 확대하지 않음 |
| 요구사항 v1.0과 기능명세 결정이 다름 | 연습 건너뛰기 삭제·명령어 문구·T20 범위·T19 아동 화면 4건은 기능명세 결정을 유지하고 §11.1.2에 차이 D-01~D-04로 기록한다(2026-10-01 사용자 확인). 요구사항 명세서는 동결되어 수정하지 않는다 |

S05에서 말하는 **첫 볼트의 좁은 구현 범위**와 본 기능명세서의 **전체 MVP 기능 범위**는 같지 않다. 기능을 명세했다는 이유로 첫 볼트 구현·시험이 완료된 것으로 표시하지 않는다. (근거: S05 각 문서의 첫 볼트/후속 구분)

### 1.1 실제 통신을 사용하는 경우의 책임

보호자↔Spring은 REST, 기기↔Spring은 제어 채널, 기기↔음성 공급자는 실시간 음성, 서버↔공급자는 세션 제어라는 기존 역할을 계승한다. 공급자 API의 구체 지원 여부나 연결 시험 성공을 새로 확인한 것은 아니다. (근거: S01 §1.1; S05 protocol.md 「채널과 권위」)

**HTTP 요청 접수, 서버 상태 저장, 기기 명령 수신, 스피커 출력 중단, 음성 연결 종료는 서로 다른 사실**로 처리한다. 소셜 로그인 세션과 아동 대화 활동도 별개의 수명이다. (근거: S01 §1.1·AUTH-T01-002; S05 session-state.md 「독립 상태 축」)

## 2. 기능 ID와 문서 구조

기존 `<도메인>-<화면/기능>-<번호>`를 계승한다. AUTH·CHILD·CONS·HOME·FREE·PRAC·ACT·HIST·RPT·DEV·VOICE·STOP·SUP·SYS의 영역 구분을 유지한다. (근거: S01 §2)

`AUTH-SIGNUP-001`은 폐기하되 이력은 §12에 남긴다. `AUTH-T01-001`은 소셜 로그인 시작으로 변경한다. 신규 항목은 소셜 인증 완료·자동 로그인·실패 리포트 등 새 정책에 필요한 동작과 S02/S03의 기존 버튼 연결을 분리한 것이다.

공통 정책은 `CR-...`, 결정 대기는 `Q-...`로 식별한다. 기능 표에서 공통 정책을 참조해 시간값·종료 표현·보존 규칙을 반복 정의하지 않는다. 화면의 상태·모달은 별도 페이지 ID를 추가하지 않는다.

`ENDING`은 **종료 처리가 진행 중**이라는 서버 상태 후보이며 최종 완료를 뜻하지 않는다. `PARTIAL`은 중도 종료/부분 경로를 나타내는 기존 표현이고, 결과를 생성하는 Worker의 상태는 별도로 다룬다. 물리 필드·Enum·전이 계약은 U-12/U-13의 후속 설계다. (근거: S01 §4.1~4.2·SYS-SESSION-001; S05 session-state.md 「독립 상태 축」「종료와 재생 완료」)

### 4.2 CR-PRACTICE-01 — 연습 흐름과 건너뛰기 제거

기존 첫 반응→필요한 도움→도움 후 1회 반응→새 상황 흐름을 유지한다. 첫 반응 전에는 목표 단서·정답·시범을 주지 않고, 목표 기능이 나타나면 불필요한 도움 없이 새 상황으로 간다. 불확실하면 실패 확정 대신 보류하고, 도움을 거절하면 강제하지 않는다. (근거: S01 §4.3·PRAC 관련 기능)

U-06에 따라 **아동 명령으로 연습의 현재 상황이나 단계를 건너뛰는 기능은 제거**한다. 요구사항 v1.0의 FR-E05·공통규칙에는 건너뛰기가 남아 있으며, 이 결정은 차이 D-01로 기록한다. 따라서 연습 화면·안내·API 역할·결과 기록에 사용자 건너뛰기를 요구하지 않는다. 다만 도움 불필요·도움 거절·무응답 때문에 일부 단계가 수행되지 않는 경우는 유지한다. 이것은 “연습 건너뛰기” 명령과 다르다.

`무중아 넘어갈래`를 자유대화의 질문/주제 전환으로 쓸지는 사용자 답변에 없다. Q-SKIP-01에서 확인 전까지 연습 제어로 실행하거나 자유대화 동작을 임의 확정하지 않는다.

### 4.4 CR-TIME-01~03 / CR-RETRY-01 — 시간·재시도 잠정값

### 4.5 CR-END-01 — 아동 종료 처리 순서

**확정 정책: A안**

아동의 종료 표현이 유효한 종료 요청으로 확정되면 서버는 **즉시 활동 상태를 `ENDING`(종료 처리 중)으로 전환·기록**한다. `ENDING`은 종료 완료가 아니라 종료 처리가 시작되었음을 의미한다.

```text
아동: “무중아 그만할래” 또는 현재 세션에 등록된 추가 종료 표현
→ 종료 표현 판정 확정
→ ActivitySession을 ENDING으로 전환·기록
→ 새 일반 질문·연습 단계 진행·일반 GPT-Live 출력·관련 무응답 처리 차단
→ 승인된 마지막 인사 최대 1회 재생
→ 기기 출력 중단·Transport 정리·공급자 Session 정리 여부 확인
→ 활동 종료 상태 확정
→ 유효 기록 여부에 따라 전체/부분 결과 또는 실패 리포트 경로로 진행
```

종료 표현은 음성 경로를 통해 GPT-Live까지 전달될 수 있으며, 서비스의 **최종 종료 명령 판정은 서버가 현재 세션에 적용된 종료 표현 설정과 대조하여 확정**한다. `/device`가 아동 발화 의미를 독자적으로 판단하는 구조로 두지 않는다. 종료 명령이 확정된 이후에는 GPT-Live가 생성하려던 일반 대화 응답이 아동에게 재생되지 않도록 기존·대기 출력과 추가 출력을 차단한다.

DB에는 `ENDING` 상태와 종료 요청 사실을 기록할 수 있지만, `ENDING` 저장 자체는 실제 기기 스피커가 멈췄다는 증거가 아니다. 실제 출력 중단·Transport 종료·공급자 정리는 별도 확인값으로 관리한다. 보호자 T08/T09에는 서버 상태를 기반으로 “종료 처리 중”에 해당하는 안내를 표시할 수 있고, 아동 T19에는 내부 상태코드 대신 승인된 아동용 마무리 문구를 표시한다.

종료 명령 후 **5초 시점 확인**은 종료를 5초 뒤에 시작한다는 뜻이 아니다. 종료 처리는 즉시 시작하며, 5초 시점에는 실제 중단 여부를 확인한다. 확인되지 않았다면 종료 완료로 추정하지 않고 미확인 상태로 남긴다.

구체적인 DB 컬럼·트랜잭션 순서·API 이벤트 필드는 API 명세서·ERD·Sequence Diagram에서 확정한다. 기능 정책 자체는 본 절을 최종 기준으로 한다.

### 4.6 CR-RESULT-01 — 부분 결과와 실패 리포트

| 상황 | 제공 내용 | AI 결과 작업 |
|---|---|---|
| 정상 종료, 유효 기록 충분 | 기존 자유대화/연습 결과 | 생성 대상 |
| 중도 종료, 유효 기록 충분 | 수행한 내용만으로 부분 결과. 미실시 단계는 미실시 표시 | **부분 결과 생성 대상** |
| 참여 후 기록은 있으나 분석 근거 부족 | 종료 사실·시각·사유·부족 이유 + 허용된 대화 원문의 실패 리포트 | 없는 분석·평가를 생성하지 않음. 고정 형식 구성 |
| 참여했지만 저장 전사 없음 | 종료 정보, 제공할 원문 없음 | 원문을 새로 만들지 않음 |
| 시작 전 미참여 | 최소 종료 사실·시각 | 원문 미저장·결과/추천 미생성 |
| 기술적으로 결과 작업 실패 | 작업 실패 안내. 허용된 기존 기록은 보존 | 잠정 재시도 후 최종 실패/수동 재시도 |
| 동의 철회·자료 삭제 | 해당 제한을 우선 적용 | 금지된 새 분석·저장·자료 복원 없음 |

근거: U-09/U-11; S01 FR-F11 연결 기능·SYS-RESULT-001·SYS-DATA-001.

“실패 리포트”는 사용자 요청 용어다. **아동의 대화 수행 실패 판정이 아니라 결과를 만들 근거가 부족한 기록**으로 정의한다. “대화 원문”은 저장된 전사를 그대로 보여주는 것으로 해석하며, 원래 음성을 완벽하게 복원한다는 뜻이 아니다. PDF 제공·최종 화면 제목·유효 기록의 구체 기준은 Q-REPORT-01/Q-RESULT-01로 남긴다. 동의 철회나 시작 전 미참여로 저장하지 않은 원문을 리포트를 위해 다시 확보하지 않는다.

### 4.7 CR-DATA-01 — 동의 철회·보존·삭제

철회 전에 정상 저장한 자료는 유지하고 보호자가 별도로 삭제할 수 있다. 철회 후 신규 자료와 늦게 도착한 자료는 새로 저장하지 않는다. 철회 전 발화가 철회 후 도착해도 이번 결정은 **미저장**이다. (근거: U-11)

보존·열람·분석은 구분한다. 기존 자료를 남긴다고 새 AI 분석이나 외부 전송까지 허용하는 것은 아니다. 철회 후 열람 범위, 철회 효력의 서버 기준 시각, 작업 중간 산출물 처리는 Q-DATA-01과 API/ERD 단계에서 정한다. 삭제된 자료가 결과 재시도나 실패 리포트 조회로 되살아나지 않아야 한다. (근거: S01 CONS-T03-002~003·SYS-DATA-001; S05 auth.md·result-pipeline.md 철회 경계)

### 4.8 CR-DEVICE-01 — 고정 ID 데모와 실제 통신

사용자 U-15를 **데모에서 허용 기기 ID를 사전 고정하고 연결 대상 선정 절차를 생략**하는 범위로 반영했다. 검색·기기 등록·페어링·일회용 코드 발급·단기 인증 TTL/갱신은 이번 데모 기능에서 제외한다.

다만 “실제로 연결을 시도하는 게 아닌”이라는 말이 **실제 WSS/WebRTC 통신까지 모두 모의 처리**한다는 뜻인지는 확정되지 않았다. 아래를 구분하며 Q-DEVICE-01에 남긴다.

| 구분 | 설명 |
|---|---|
| 연결 대상만 고정 | 기기 ID는 이미 알고 있으며 사용자가 검색/등록하지 않는다. 실시간 음성·상태 통신은 실제 경로를 사용 |
| 통신까지 모의 | 연결됨/끊김/종료 보고 등도 시험용 값으로 표시. 실제 음성 중단·재연결·heartbeat를 검증한 것으로 기록하지 않음 |

고정 ID는 식별값이며 실제 기기 인증·소유권 검증을 완료했다는 증거로 취급하지 않는다. 보호자 로그인 및 아동·활동 접근 검사는 별도로 유지한다. 외부 공개 운영에 데모 축약을 그대로 적용하는 것은 이번 결정 범위가 아니다. 이는 S05의 인증 경계와 데모 축약을 구분하기 위한 **작성 주의사항**이다.

### 4.9 CR-SAFE-01 — 기존 표시·생성 제한 유지

진단 가능성·사회성/화용 점수·등급·향상률·치료 효과·원인/결함 확정·실제 관계로 일반화·감정/의도 단정·지원 효과 보장·정답 강요·연속 이용 압박을 생성하지 않는다. 실패 리포트에도 같은 제한을 적용한다. (근거: S01 §4.5·SYS-SAFE-001)

## 5. 상세 기능 명세

아래 기능의 `변경 구분`은 v0.1 대비 문서 변경 여부다. 실제 구현 완료 여부가 아니다. `유지` 항목은 명칭 교체를 제외한 기존 동작을 계승한다. `보류 후보`는 확정된 실행 기능으로 세지 않는다.

상세 항목은 **76개**다. 기존 68개 중 자체 가입 1개를 폐기하고 67개 ID를 계승했으며, 새로 분리/추가한 항목 9개 중 1개는 넘어갈래 적용 범위의 **보류 후보**다. 따라서 76개 모두가 확정 실행 기능이라는 뜻은 아니다.

## 7. T20 — 종료 표현 설정 상세

### 7.1 입력·저장 규칙

| 항목 | 규칙 | 상태 |

### 7.2 입력 예시

| 고정 앞부분 | 보호자 입력 | 조합 결과 |
|---|---|---|
| 무중아 | 오늘은 여기까지 | 무중아 오늘은 여기까지 |
| 무중아 | 이야기 끝낼래 | 무중아 이야기 끝낼래 |

예시는 형식을 보여주기 위한 것이며 자동으로 3개가 기본 등록되는 정책이 아니다. 사용자 입력 없이 추가 표현을 임의로 만들지 않는다.

### 7.3 남은 작은 입력 결정

**Q-STOP-01 작성 제안:** 고정 호출어는 별도 읽기 전용으로 두고 뒤 표현만 입력받는다. 앞뒤 공백을 제거한 뒤, 내부 공백을 포함해 1~10자로 세는 안을 제시한다. 사용자 요구에는 공백·유니코드 글자 계산·구두점·연속 공백 처리 기준까지 없으므로 이 세부안은 아직 최종 확정이 아니다. 기본/추가 표현의 동일성 검사도 같은 정규화 규칙을 사용해야 한다.

**Q-STOP-02:** `쉬고 싶어` 또는 `다시 할래`를 종료 표현으로 등록하면 고정 쉬기·재개 표현과 완전히 겹친다. 비슷한 발음을 허용한다는 결정만으로 이 충돌의 허용/우선순위까지 정해지지는 않는다. 같은 전체 명령을 여러 의미로 중복 등록하지 않는 안을 제시하되 최종 정책은 확인이 필요하다.
