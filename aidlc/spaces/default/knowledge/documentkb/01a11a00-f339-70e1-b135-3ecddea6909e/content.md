# 무중 기능명세서

## 1. 계정·아동·동의·홈·종료 표현

### AUTH-T01-001 — Google·Kakao·Naver 소셜 로그인 시작

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A01 |
| 우선순위 | **Must** |
| 트리거 | 보호자가 로그인 화면에서 Google, Kakao, Naver 중 하나의 로그인 버튼을 선택한다. |
| 사전조건 | 비로그인 상태. 선택 공급자의 연동 설정 준비 여부는 기술 설정에서 확인한다. |
| 입력 | 선택한 로그인 제공자. 무중 서비스의 ID·비밀번호는 입력받지 않는다. |
| 처리 로직 | 선택한 제공자의 인증 절차를 시작한다. 인증 완료 응답의 검증과 서비스 계정 처리는 AUTH-OAUTH-001로 연결한다. 소셜 제공자 동의와 아동 활동·기록에 대한 서비스 동의를 구분한다. |
| 정상 출력 | 선택 제공자의 로그인·인증 화면으로 연결. 검증 완료 후 서비스 로그인으로 이어진다. |
| 예외 케이스 | 사용자 인증 취소 → 로그인 화면 유지; 제공자 오류·응답 지연 → 실패 안내와 다시 선택; 중복 클릭 → 같은 로그인 절차 중복 시작 방지. 제공자별 응답 형식·오류 코드는 미확정이다. |
| 주요 검증 기준 | 로그인 화면에 Google·Kakao·Naver 선택이 있고 자체 ID/PW 입력·자체 가입 화면이 없다. 인증 취소 시 로그인 상태가 되지 않는다. |

### AUTH-OAUTH-001 — 소셜 인증 완료·서비스 계정 처리

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A01 |
| 우선순위 | **Must** |
| 트리거 | 소셜 제공자의 인증 결과가 서비스로 돌아온다. |
| 사전조건 | 서비스가 시작한 인증 절차와 응답의 유효성을 검증할 수 있어야 한다. |
| 입력 | 선택 제공자와 검증된 외부 사용자 식별 정보. 무중 자체 비밀번호는 생성하지 않는다. |
| 처리 로직 | 인증 응답을 검증하고 처음 방문한 사용자는 서비스 보호자 계정을 생성하며, 동일한 제공자 계정으로 재방문하면 기존 계정을 조회한다. 이어 Spring Session JDBC 기반의 서비스 로그인 상태를 만든다. 최초 성공 직후 다시 로그인하도록 요구하지 않는다. 최초 로그인 후 아동 미등록·동의 미완료이면 아동 등록·동의 절차로, 준비 완료이면 홈으로 연결하는 안은 미확정이다. 제공자가 다른 계정의 통합·연결 정책도 미확정이다. |
| 정상 출력 | 서비스 로그인 완료. 이용 준비 상태에 따라 아동 등록·동의 또는 홈으로 이동. |
| 예외 케이스 | 검증 실패·취소된 인증·재사용 응답 → 계정/로그인 생성 금지; 계정 또는 세션 저장 실패 → 성공으로 표시하지 않음. 동일 이메일이라는 이유만으로 타 제공자 계정을 자동 병합하지 않는 안은 미확정이다. |
| 주요 검증 기준 | 최초 유효 인증 후 별도 자체 가입 없이 서비스 계정과 로그인 상태가 생성된다. 취소·검증 실패에서는 생성되지 않는다. |

### AUTH-AUTO-001 — 재접속 시 로그인 상태 복원

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A01 |
| 우선순위 | **Must** |
| 트리거 | 보호자가 앱에 다시 접속하거나 브라우저를 다시 연다. |
| 사전조건 | 이전에 소셜 로그인에 성공했고 서비스 로그인 상태가 아직 유효해야 한다. |
| 입력 | 브라우저에 남은 서비스 로그인 식별 정보와 서버의 현재 인증 상태. |
| 처리 로직 | 서버가 로그인 유효성을 확인한다. 유효하면 소셜 로그인 절차를 반복하지 않고 앱 이용 화면으로 이동한다. 최초 로그인 직후 로그인 완료와 이후 재접속의 로그인 유지를 모두 지원한다. 무기한 로그인이나 제공자 토큰 무기한 갱신을 뜻하지 않는다. Cookie 유지 기간과 세션 만료 조건은 미확정이다. |
| 정상 출력 | 유효한 세션이면 로그인 화면을 건너뛰고 이전 이용 준비 상태에 맞는 화면으로 이동. |
| 예외 케이스 | 세션 만료·로그아웃·저장 정보 삭제 → 로그인 화면에서 다시 로그인; 서버 조회 실패 → 로그인 성공으로 추정하지 않음; 재로그인으로 종료된 활동 자동 재개 금지. |
| 주요 검증 기준 | 유효 세션 재접속은 제공자 로그인을 반복하지 않는다. 로그아웃/만료 후에는 자동 복원되지 않는다. |

### AUTH-T01-002 — 보호자 로그아웃

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A01 |
| 우선순위 | **Must** |
| 트리거 | 보호자가 로그아웃을 요청한다. |
| 사전조건 | 로그인 상태 |
| 입력 | 현재 보호자 인증 Session |
| 처리 로직 | 서비스의 서버 인증 Session을 무효화하고 자동 로그인에 사용한 브라우저 정보를 정리한 뒤 로그인 화면으로 이동한다. 서비스 로그아웃은 제공자 계정 자체의 로그아웃·연결 해제와 구분한다. 앱·브라우저를 닫는 것은 활동 종료 요청이 아니다(FR-B07). 로그아웃 시 진행 중 활동을 종료할지 여부는 미확정이다. |
| 정상 출력 | 로그인 화면으로 이동. |
| 예외 케이스 | 이미 Session 만료 → 비로그인 상태로 정리; 서버 무효화 실패 → 성공으로 표시하지 않음; 진행 활동 존재 → 활동 상태를 임의 종료 처리하지 않음 |

### CHILD-T02-001 — 아동 등록

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A02 |
| 우선순위 | **Must** |
| 트리거 | 보호자가 아동 등록을 저장한다. |
| 사전조건 | 보호자 로그인 |
| 입력 | 이름 또는 별명, 연령, 관심사 |
| 처리 로직 | 진단명·검사 결과 필드는 받지 않는다. 저장된 아동은 현재 보호자와 접근 관계를 가진다. |
| 정상 출력 | 등록된 아동 목록에 추가 |
| 예외 케이스 | 필수 입력 정책 위반 → 저장 금지(세부 규칙 미확정); 중복 제출 → 동일 아동 중복 생성 방지; 타 보호자 관계 변경 시도 → 거부 |

### CHILD-T02-002 — 활동 대상 아동 선택

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A02, FR-F01 |
| 우선순위 | **Must** |
| 트리거 | 보호자가 아동 카드를 선택한다. |
| 사전조건 | 보호자 로그인, 접근 가능한 아동 존재 |
| 입력 | childId |
| 처리 로직 | 선택한 아동을 이후 자유대화·연습·기록 조회의 현재 대상에 연결한다. 진행 중 세션의 childId는 아동 선택 변경으로 바꾸지 않는다. |
| 정상 출력 | 선택한 아동을 기준으로 홈을 갱신한다. |
| 예외 케이스 | 진행 중 활동 존재 → 해당 활동 대상 아동은 유지; 접근권한 없는 childId → 거부; 삭제/비활성 대상 → 선택 불가 |

### CHILD-T02-003 — 아동 정보 수정

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A02 |
| 우선순위 | **Must** |
| 트리거 | 보호자가 아동 카드의 정보 수정 버튼을 선택하고 저장한다. |
| 사전조건 | 로그인 상태이며 해당 아동에 대한 접근권한이 있다. |
| 입력 | 이름 또는 별명, 연령, 관심사. 입력 제한의 상세는 미정이다. |
| 처리 로직 | 현재 값을 불러와 수정·저장한다. 진단명·검사 결과를 추가 수집하지 않는다. 활동 중 아동 식별자를 바꾸지 않는다. 진행 중 세션에 프로필 수정값을 즉시 반영할지 여부는 미확정이며, 임의로 현재 세션 조건을 교체하지 않는다. |
| 정상 출력 | 저장된 아동 정보를 아동 등록·선택 화면 및 이후 조회에 반영. |
| 예외 케이스 | 저장 실패 → 이전 값 유지; 취소 → 변경 없음; 권한 없음 → 거부. |
| 주요 검증 기준 | 아동 정보 수정 버튼에서 기존 값 조회·저장·취소가 연결된다. 진행 세션의 대상 아동은 바뀌지 않는다. |

### CONS-T03-001 — 최초 동의 저장

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A03, FR-A04, FR-A05 |
| 우선순위 | **Must** |
| 트리거 | 보호자가 동의 항목을 선택하고 저장한다. |
| 사전조건 | 보호자 로그인, 대상 아동 선택 |
| 입력 | 음성 수집(전사를 위한 처리)·전사 저장(필수), 보호자 열람(필수), 리포트 생성·외부 전달(선택), 원음 보관(선택) |
| 처리 로직 | AI 기반 서비스임을 로그인·이용 동의 화면과 약관에 고지한다. 아동 대상 고지는 VOICE-START-001(FR-E01)이 담당한다. 동의 범위 밖의 수집·저장·이용은 하지 않는다(FR-A03). 항목별 동의를 저장하되 소셜 제공자 동의로 아동 활동·기록 동의를 대신하지 않는다. 필수 동의 없이는 활동을 시작하지 않는다. 원음은 선택 동의에 따라 보관한다. 실패 리포트의 대화 원문은 저장된 전사이며 음성파일 보관 동의가 자동 추가되는 것이 아니다. |
| 정상 출력 | 동의 상태 저장, 첫 이용 시 보호자 안내 문구 1회 표시 가능 |
| 예외 케이스 | 필수 동의 누락 → 활동 시작 차단; 저장 실패 → 이전 동의 유지; 선택 동의 거부 → 해당 기능/저장만 제외; 타 아동 동의 변경 → 거부 |

### CONS-T03-002 — 동의 변경·필수 동의 철회

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A08, FR-A03 |
| 우선순위 | **Should** |
| 트리거 | 보호자가 기존 동의 항목을 변경한다. |
| 사전조건 | 보호자 로그인, 대상 아동 접근권한 |
| 입력 | 변경할 동의 항목과 새 상태 |
| 처리 로직 | 필수 동의 철회를 별도 확인한 뒤 서버에 반영한다. 이후 새 수집·이용을 차단하고 진행 활동은 안전 종료한다. 철회 전에 정상 저장된 자료는 자동 삭제하지 않고 보호자가 별도 삭제할 수 있게 유지한다. 철회 후 늦게 도착한 자료는 철회 전 발화라도 새로 저장하지 않는다. 기존 기록을 보존하는 것과 열람·새 AI 분석을 허용하는 것은 다르며, 철회 후 기존 기록의 열람 범위는 미확정이다. |
| 정상 출력 | 새 동의 상태 반영, 필요한 경우 진행 활동 종료 처리 |
| 예외 케이스 | 시작·철회 경합 → 현재 동의 재검사; 진행 중 철회 → 출력 중단 확인과 서비스 종료를 분리; 철회 후 늦은 전사·AI 응답 → 신규 저장/이용 금지; 철회 저장 실패 → 완료로 표시하지 않음. 철회 효력 시각의 서버 처리 경계는 미확정이다. |
| 주요 검증 기준 | 철회 이전 정상 저장 기록은 남고 별도 삭제가 가능하다. 철회 이후 신규·지연 도착 전사는 저장되지 않으며 새 활동이 차단된다. |

### CONS-T03-003 — 기록 삭제 요청

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A08 |
| 우선순위 | **Should** |
| 트리거 | 보호자가 삭제 대상을 선택하고 최종 확인한다. |
| 사전조건 | 보호자 로그인, 대상 아동 접근권한 |
| 입력 | 삭제 대상: 원음/전사/리포트 등 선택 |
| 처리 로직 | 대상 선택 → 영향 안내 → 최종 확인으로 진행한다. 해당 자료에서 파생된 추천·요약·리포트를 조회·집계에서 제외한다. 새 실패 리포트의 전사 조회도 같은 삭제 경계를 따른다. 동의 철회만으로 이 삭제 요청을 대신하지 않는다. |
| 정상 출력 | 삭제 완료 상태와 영향 범위 표시 |
| 예외 케이스 | 확인 전 취소 → 삭제 없음; 일부 파생 데이터 처리 실패 → 전체 완료로 표시하지 않음; 이미 삭제됨 → 멱등하게 처리; 진행 중 결과 작업과 경합 → 삭제 자료를 다시 생성하지 않도록 차단 |

### HOME-T04-001 — 홈 정보 조회

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-A07 |
| 우선순위 | **Must** |
| 트리거 | 로그인 후 또는 홈 탭 진입 |

| 입력 | `무중아 넘어갈래` |
| 처리 로직 | 이 표현으로 연습 단계·상황을 넘기는 실행 기능은 제공하지 않는다. 자유대화에서 질문·주제 전환으로 사용할지 또는 표현 자체를 사용하지 않을지는 미확정이다. |
| 정상 출력 | 미확정 항목. 연습 제어 명령으로 실행하지 않는다. |
| 예외 케이스 | 자유대화의 질문·주제 전환 동작은 미확정이다. 도움 거절·무응답으로 생기는 미실시 분기는 별도로 적용한다. |
| 주요 검증 기준 | 연습 안내·기능·결과 기록에 아동 명령으로 단계를 건너뛰는 기능을 제공하지 않는다. |

### VOICE-STOP-001 — 종료 표현 인식·아동 종료

| 항목 | 명세 |
|---|---|
| 관련 요구사항 | FR-E05, FR-E10, FR-F14 |
| 우선순위 | **Must** |
| 트리거 | 아동이 기본 종료 표현 또는 현재 세션에 적용된 추가 종료 표현을 말한다. |
| 사전조건 | 활동 진행 중이며 세션 시작 시 종료 표현 설정 버전이 고정되어 있어야 한다. |
| 입력 | `무중아 그만할래` 또는 현재 세션에 적용된 추가 종료 표현의 판정 결과. |
| 처리 로직 | 서버가 음성 경로로 전달된 전사·이벤트를 현재 세션의 종료 표현 설정과 대조하여 유효한 종료 요청을 확정한다. 아동 기기가 발화 의미를 독자적으로 판단하지 않는다. 종료 요청 확정 즉시 `ENDING`으로 전환·기록한다. 이후 새 일반 질문·연습 단계 진행·일반 GPT-Live 출력·관련 무응답 처리를 차단하고 기존·대기·추가 일반 응답이 재생되지 않게 한다. ENDING 상태에서 승인된 마무리만 최대 1회 제공한다. 마무리 후 기기 출력 중단·Transport 종료·공급자 Session 정리 여부를 각각 확인하여 종료 및 결과 처리로 진행한다. ENDING 기록 자체를 실제 중단의 증거로 판단하지 않는다. 진행 중 종료 표현 설정 변경은 다음 활동부터만 적용한다. |
| 정상 출력 | 종료 요청 확정 즉시 `ENDING`. 마무리·기기 정리 후 아동에게 중단 마무리 상태를 표시하고 보호자 결과 처리로 연결한다. |
| 예외 케이스 | 기기 자체 재생 음성·역할 대사 → 오인 종료 방지; 중복 종료 → 종료·마무리 중복 방지; 마무리 실패 → 종료 의사를 취소하지 않음; 5초 뒤에도 중단 증거 없음 → 완료로 단정하지 않음. 인식 허용 오차는 별도 명세. |
| 주요 검증 기준 | 세션 시작 시 고정된 종료 표현을 사용하며 설정 저장 후 현재 세션 표현은 바뀌지 않는다. 종료 표현 확정 즉시 `ENDING`으로 전환되고 일반 대화 출력이 차단되는지 검증한다. |
