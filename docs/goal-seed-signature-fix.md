# 새 기술 생성 구조 정보 누락 보완

## 확인한 문제

‘놀이 의견 묻기’ 목표는 실제 아이 발화에 근거해 생성됐지만, 연결 기술은 `NONE`, 구조 정보는 `null`로 저장돼 있었다. 새 기술 생성기는 구조 정보가 있어야 실행하므로 이 목표에서는 새 기술 생성 요청이 시작되지 않았다.

과거 AI 응답 원문은 보관하지 않아, AI가 항목을 생략했는지 명시적으로 null을 반환했는지 또는 검증 중 제외됐는지는 확정할 수 없다. 확인한 구현상 문제는 지시문이 구조 작성을 요구하는 반면, 공급자 응답 규격은 생략을 허용해 요청이 엄격한 구조화 출력으로 실행되지 않았다는 것이다.

## 수정

- 공급자에게 보내는 목표 후보 응답 규격에서 `structureSignature` 키를 필수로 요청한다. 모든 객체가 닫히고 필수 속성이 명시돼 엄격한 구조화 출력을 사용한다.
- 과거 응답 및 기존 계약 자료를 읽는 서버 계약은 유지한다.
- 기존 기술이 없다는 판단과 새 기술 구조를 추상화하는 판단을 구분하도록 지시문을 보완했다. 이미 잘한 행동도 다시 연습할 구조를 가질 수 있다.
- 근거가 불명확한 경우 명시적인 null은 계속 허용한다. 상수로 구조를 채우거나 실제 발화를 그래프에 복사하지 않는다.
- 출처·정확 인용·금지 표현 검사, 새 기술 개인정보/원문 중복 검사, 중복 기술 재사용, 소유자·동의·삭제 검사 및 Jev 경로는 유지한다.

## 검증

응답 규격, Luna 호출, 목표 후보 검증, 후보 재전달, 실제 PostgreSQL/Neo4j를 이용한 새 기술 생성·연결·상황 생성 및 관계·장면 검증 시험 115개가 실패·오류·생략 없이 통과했다. 이 시험의 AI는 대역이며 실제 저장 대화 재분석 결과와 구분한다.

## 실제 저장 대화 검증

2026-10-21 15:48 자유대화의 저장 전사를 재분석했다. 기존 결과·원문·이미 담은 목표의 버전은 보존했고 새 결과의 후보를 생성했다. 목표에 대한 사람의 임의 기술 ID 지정 없이 정상 작업자가 분석·정확 인용·안전 검사·새 기술 생성·원문/식별자 중복 검사·Neo4j 저장을 수행했다.

- 재분석 1회 성공, FULL 결과. 분석 작업 약 20.4초.
- ‘놀이 의견 묻기’ → 새 기술 `seed:G0002`.
- ‘함께할 방법 제안’ → 새 기술 `seed:G0003`.
- Neo4j에는 기존 POC 14개와 생성 기술 2개가 활성 상태이며 두 생성 작업은 COMMITTED다.

첫 실제 상황 검증에서는 상대가 원하는 놀이를 이미 말해 질문할 기회가 부족한 장면이 독립 검토에서 INCOMPLETE_SCENE로 거절됐다. 검토 기준을 낮추지 않고, 조건 문자열을 덧붙이는 대신 실제 가상 맥락을 구성하고 목표의 질문이 필요한 순간을 남기도록 생성 지시를 보완했다. ‘같이 놀 친구’라는 목표의 관계 이름도 기존 친구 코드와 동등할 때만 변환하며 교사 등 다른 관계로 바꾸지 않는다.

재검증은 실제 새 후보의 고정 목표·구조 정보와 실제 Neo4j 기술을 읽어 운영 상황 생성기·독립 검토기로 실행했다. 결과는 약 10.8초, graphContextUsed=true, 기술 seed:G0002, 그래프 버전 poc-v1, BASE 1개, 검토 APPROVE다. 실제 AI 요청 2회이며 모의 응답이 아니다. 이 검증은 별도 진단 실행으로 상황을 앱 DB에 저장하거나 노출 이력을 만들지 않았다. 변형 장면이나 브라우저에서 연습 음성을 재생한 결과로 해석하면 안 된다.

화면 테스트는 사용자가 나중에 진행하기로 했다. 이전에 담은 NONE 버전 목표는 자동 갱신하지 않으므로 새 분석의 후보를 담아 사용해야 한다. AWS Terraform 수정과 main 병합은 하지 않는다.
