# 연습 음성 재생 순서와 승인 대본 복구

## 수정 이유

2026-10-22 17:31 테스트에서 AI 안내가 아이 답변보다 먼저 생성됐지만 나중에 재생됐다. 기존 화면은 생성 조각 수신 순서인 seq를 표시 순서로 사용했다. 또한 승인 대본 불일치 두 번 뒤 전체 연습이 출력 실패로 종료됐고, 기록 화면은 이를 연결 끊김으로 표시했다.

## 동작

- 수신·증거 참조용 seq는 유지한다. AI 텍스트는 안전 검사를 통과해 전송된 뒤에도 표시를 보류하고, 연결된 기기의 STARTED 수신 때 확정한다. AI startedAt은 이 재생 확인의 서버 수신 시각이며, 생성 지연 지표는 기존 별도 지표에 남는다. 아이 startedAt은 기존 입력 전사 시작 시각이다.
- 진행 화면과 기록 화면은 이 시각으로 정렬하고 동률은 seq로 정한다. 웹 표시가 음성보다 늦어도 대화 순서를 우선한다. 서로 다른 기기/서버 시계를 직접 비교하지 않는다. 네트워크 지연 및 음성 인식 지연만큼 시각 오차는 남을 수 있다.
- 재생 시작 없이 실패·취소된 음성, 종료 때까지 재생 확인이 없는 음성은 표시하지 않는다. 늦거나 중복된 재생 표식으로 폐기된 글을 다시 승인하지 않는다.
- 대본 불일치 때 같은 승인 본문을 한 번 재시도한다. 다시 불일치하면 폐기된 출력 대신 승인 자료만으로 새 안내를 생성한다. 이 복구 음성은 생성형 경로의 기존 출력 안전 검사와 Jev ALLOW가 필요하다. 재생 완료 후에만 원래 단계가 진행된다.
- 무제한 재시도는 하지 않는다. 복구도 실패하거나 안전 검사를 통과하지 못하면 기술 실패로 끝내고 성공으로 기록하지 않는다. 종료·휴식 처리는 기존 우선 경로를 유지한다.
- 종료 이벤트의 termination에 허용된 endDetail만 보존한다. 기록 API도 허용된 두 값만 읽으며 원본 termination은 노출하지 않는다. 출력 실패는 ‘음성 안내를 준비하지 못해 연습이 중단됐어요’로 표시한다.

## 검증

- Realtime 관련 656개, Core 기록 관련 29개, 웹 관련 229개 통과.
- 웹 타입 검사·변경 영역 lint·프로덕션 빌드, Core/Realtime bootJar 통과.
- 실제 GPT-Live의 합성 상황 복구 안내: 음성 268800바이트 생성, Jev ALLOW(247ms). 실제 사용자 마이크와 기기 스피커를 통한 전체 흐름 성공을 뜻하지 않는다.
- 추가 기록 저장 통합 시험과 로컬 적용 결과는 작업 종료 보고에 기재한다.

## 적용 범위

기존 대화 기록의 시각과 순서를 임의로 다시 쓰지 않는다. 새 종료 사유 필드가 없던 기록에도 원인을 추정해 채우지 않는다. 새 테스트 세션부터 변경 동작을 검증한다. AWS Terraform 변경 및 main 병합 없음.
