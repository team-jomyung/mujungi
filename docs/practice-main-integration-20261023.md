## 충돌 조정

11개 충돌 파일에서 최신 서비스 정책·출력 권한·승인 음성·스트리밍 게이트와 로컬 연습 흐름을 함께 유지했다.

- 연습 음성의 이전 응답 대기, 요청 전송, 첫 출력, 수집, 기기 재생 시한을 분리한다.
- 대기 후 새 생성 세대로 전환할 때 출력 권한도 새로 발급한다. main의 프레임별 권한 재검사는 유지한다.
- 연습의 대화 표시만 기기 STARTED 확인을 기다린다. 자유대화는 main의 표시 규칙을 유지한다. 여러 스트리밍 단위를 한 응답으로 합치는 기록도 올바르게 정산한다.
- 서비스 판정 프롬프트의 기존 동의·종료 구분에 로컬의 연습 도움·진행 방법 질문·역할 대화 마무리 기준을 더해 `prompt-service-v2`로 기록한다.
- main에서 제거한 종료 확인 경로를 복구하지 않는다. 명확한 연습 휴식 요청은 출력을 즉시 중단하고 기존 `REST_REQUESTED` 확장 사건으로 전달한다.
- 종료 사유를 기록 조회 응답의 허용 필드에 추가한다. 허용 값은 기존 두 코드로 제한한다.
- 바이트 해시로 검증하는 서비스 정책 파일은 Windows에서도 LF를 유지한다. 해시 검증을 완화하지 않는다.
- 서버 안전 검사와 Jev 경로·실패 시 차단을 유지한다. 실제 실행 중인 비교용 STUB 설정은 변경하지 않는다.

## 남은 실패와 검증 한계

첫 GitHub CI의 `infra-validate`는 Terraform이 아닌 로그 속성 대조 도구에서 `AttrKey.AUDIO_STAGE` 해석 실패로 중단됐다. 정본의 한정 이름을 해석하고 새 진단 2종의 고정 속성을 반영했으며, 위 44개 로컬 시험으로 검증했다. 수정 후 GitHub CI 재실행의 최종 결과는 별도 확인해야 한다.

기존 로컬 기준에서도 실패한 두 항목은 제외하거나 성공으로 바꾸지 않았다.

1. `PracticeProgressMappingTest.everyStageOnAVariantAndNextGoalPathFoldsIntoTheSixValuesAndNeverLeaksTheNewStageNames`: 변형 단계 표시가 `NEW_SCENARIO_RESPONSE` 대신 `AFTER_CUE_RESPONSE`인 경로.
2. `PracticeExecutorIntegrationTest.addedAdviceIsDiscardedAndCannotBecomeScenarioExposure`: 승인 대본 불일치 뒤 확장 사건 처리와 옛 FAILED 사실 기대값의 불일치. 거절 음성은 재생되지 않지만 실패 사실 정산 기대는 미해결이다.

실제 대화 품질 후속 문제도 남아 있다.

- 이전 이야기 질문에 원본 대화를 근거로 답하지 않고 새 장면으로 넘어가는 경우.
- 목표 달성 뒤 친구가 제안에 동의했어도 아이의 추가 답만 기다려 마무리가 불분명한 경우.
- 아이가 생각하며 침묵하는 시간을 미완료·시간 초과와 구분하는 경험.

이번 통합본은 실행 중인 로컬 서버에 적용하지 않았으므로 마이크 겹침·실제 음성·실제 Jev 판정 재검증은 미완료다. 이전 로컬 버전에서 사용자가 음성 누락 없이 전체 재생을 확인한 사실과 이번 통합본의 증거를 구분한다. 위 항목이 남아 있으므로 검토용 초안으로 다룬다.
