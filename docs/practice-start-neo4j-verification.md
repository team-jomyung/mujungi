# 연습 시작 오류와 Neo4j 연동 검증 (2026-10-21)

## 수정한 원인

1. **서버 Java 실행 환경 차이**: 연습 목표 순서를 고르는 `RandomGenerator.getDefault()`가 `jdk.random` 모듈을 요구했다. 실제 서버 JRE에는 이 모듈이 없어 AI 호출 전에 예외가 발생했다. `java.base`에 포함된 `java.util.Random`으로 순서만 추첨하도록 변경했다. 가중치·소유권·중복 검사·기존 순서 재사용은 유지한다. 암호·토큰 생성에 사용하는 난수기는 변경하지 않았다.
2. **검토 요청 형식 거절**: 상황 검토의 원본 JSON Schema는 최상위 `anyOf`로 승인과 거절의 조건을 나눈다. 실제 공급자는 이 최상위 형식을 HTTP 400 `invalid_json_schema`로 거절했다. 공급자에게 보내는 공통 객체 사본에서만 최상위 `anyOf`를 제외한다. 원본 서버 검증에는 그대로 남겨, 사유가 붙은 APPROVE·알 수 없는 사유·잘못된 응답은 계속 거절한다.
3. **생성 지시의 모호함**: 모델이 기회 조건을 바꿔 쓰거나 아이가 할 답을 장면에 포함했다. 상대 대사와 아이 답을 분리하고, 기회 조건·관계 유지·장면 안 대사 포함·정답과 코치 예시 분리·그래프 좌표 규칙을 명확히 했다. 기본 장면과 실제 변형 장면의 검토 범위도 구분한다.
4. **변형까지 만들다 전체 마감 초과**: 첫 생성·검토에서 실제 소비한 시간을 바탕으로 다음 BASE+VARIANT 생성과 재검토 비용을 비교한다. 예산이 부족하면 이미 AI 검토 APPROVE와 서버 검사를 모두 통과한 BASE만 발급한다. 거절·불확실·서버 검사 실패인 BASE는 발급하지 않는다. 전체 상황 생성 상한 15초와 호출 횟수 제한은 그대로다. 이 추정은 완료 시간을 보증하는 공식이 아니며 최종 마감 검사는 계속 적용한다.

검토의 추론 강도는 `none`에서 `low`로 바꿨다. 생성·검토를 합치거나 검토를 생략한 것이 아니다. 실제 모델의 내용 검토 결과는 호출마다 달라질 수 있고, 거절·시간 초과는 성공으로 취급하지 않는다.

## Neo4j를 언제 사용하는가

연습 목표의 `skillRef`에 유효한 seed가 연결돼 있으면 `StructuredScenarioFlow` → `ScenarioGraphContext` → `ChildKnowledgeService`가 현재 소유권·동의·그래프 상태를 확인한 뒤 Neo4j에서 구조를 읽는다. AI 요청의 `structureContext`에 기술·추론 구조·불변 문장·보존 규칙을 제공하며, BASE의 실제 좌표를 얻은 다음 `variantPlan`을 만든다. 변형이 있으면 실제 내용과 계획의 일치 여부도 검사한다.

`skillRef=NONE` 또는 조회 불가라면 그래프 없는 경로가 존재한다. Neo4j 설정이 true라는 사실만으로 모든 목표가 seed와 연결되는 것은 아니다. 연결된 목표가 없는데 임의의 seed를 붙이면 다른 기술을 연습하게 되므로 그렇게 수정하지 않았다.

## 실제 연결 검증

- 로컬 Neo4j의 활성 POC seed 14개와 그래프 버전 `poc-v1`을 확인했다.
- 실제 저장 목표 ‘놀이 멈추기’는 `skillRef=NONE`이다. 이 목표를 이용한 실제 AI 호출에서 생성과 별도 검토, 서버 검사를 통과했다. 이 결과를 Neo4j 활용 성공이라고 계산하지 않는다.
- 별도 **합성 검증 목표**를 seed:S2(상태 진술에서 행동 요구 읽기)에 연결해 실연동을 검증했다. 실제 애플리케이션의 소유권·동의 검사, PostgreSQL 이력 조회, Neo4j 읽기, 실제 AI 생성·독립 검토·서버 검사를 사용했다. 목표·활동·상황을 사용자 DB에 새로 저장하지 않는 독립 점검이다.
- 결과: 9,216ms, BASE 1개, 실제 모델 `gpt-6-luna`, 생성/검토 2회, `graphContextUsed=true`, `kgVersion=poc-v1`, 검토 `APPROVE`.
- 앞선 시험에서는 불변 구조 불일치·불완전 장면·15초 초과가 발생했다. 이를 통과로 바꾸지 않았으며 생성·검토 지시와 마감 내 BASE 보존 처리를 보완한 뒤 위 결과를 얻었다. 모든 seed·모든 대화의 생성 품질을 보증하는 결과는 아니다.

## 유지·제외한 범위

- GPT-Live 음성 안전 검사와 Jev 코드·정책·승인 경로는 변경하지 않았다. 상황 생성의 별도 검토는 Luna이고, 실제 음성 출력의 Jev와는 다른 단계다.
- 인증·소유권·동의·개인정보 치환·서버 내용 검사·검토 거절 처리를 유지한다.
- DB 초기화나 마이그레이션은 없다. AWS Terraform은 변경하지 않았다.
- 이 작업의 GitHub push·PR·main 병합은 수행하지 않는다. 로컬 개발 브랜치와 실행 이미지에 적용한다.
- 실제 마이크로 연습 대화를 끝까지 수행하는 시험과 별개로, 이 문서는 상황 생성과 시작 경로의 검증을 다룬다.

## 웹 확인 결과

최종 로컬 이미지 `guardian-025934a`에서 기존 로그인 세션으로 목표를 선택해 시작했다. 생성 요청 3,887ms, 별도 검토 3,010ms 후 연습 참여 확인 화면으로 전환했다. PostgreSQL에서 준비 상태 READY 1건과 상황 ISSUED 1건, 검토 APPROVE를 확인했다. 이 실제 목표의 skillRef는 NONE이므로 저장 상황의 graphContextUsed는 false다.

실제 아이·보호자의 마이크 답변을 대신 넣지는 않았다. 따라서 이번 검증용 활동은 참여 확인 무응답으로 종료됐고, 진행 중인 활동이 없음을 홈 화면에서 확인했다. 이는 상황 생성 실패와 다른 단계다. 앞선 실패 준비 이력은 삭제하지 않았다.

Core·Realtime·공통 계약의 커버리지 기준도 통과했다. 전체 실행은 10분 36초였고, 마지막 Core 보완 뒤 Core 전체 1,742개와 커버리지를 다시 실행하여 6분 10초에 통과했다. 이전 전체 실행의 테스트용 PostgreSQL 연결 오류는 숨기지 않고 재실행으로 해소 여부를 확인했다. 새 회귀 시험은 `java.base`만 제공하는 하위 JVM에서 기존 구현이 실패하고 수정 구현이 통과함을 검증한다. 시간 부족 시 승인 BASE만 발급하고 거절 BASE는 저장하지 않는 사례도 추가했다.

프런트엔드 소스는 이번 수정에서 바뀌지 않았다. 로컬 7개 서비스 정상, 로그인 URL HTTP 200, Neo4j ACTIVE/poc-v1을 확인했다. 임시 진단 코드는 최종 이미지에 넣지 않았다. 이 작업에서 복사한 임시 런타임 비밀값 파일은 삭제했고 기존 env 원본은 유지한다.

검증에 사용한 최종 코드 커밋은 `025934aa2a4b8e2a0244ec8fdae051e4fe0570d6`이며, 실행 이미지 태그는 `guardian-025934a`이다. 이후 설명 문서 커밋은 실행 코드 변경이 아니다. 서버는 켜 둔 상태이며 `/parent/practice`에서 기존 목표를 골라 다시 시험할 수 있다. 참여 확인에는 사용자가 실제로 대답해야 한다.
