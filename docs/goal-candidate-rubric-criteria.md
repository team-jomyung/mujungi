## 4. 측정용 기준 문안 초안 (v2에 더할 내용)

**[A] 관찰된 지원 필요 — 대화 반응 기준** (v2 "1." 지원 필요 목록에 추가)

```
- 응답: 상대(AI 역할 포함)가 아이에게 질문·요청·제안을 했는데, 아이가 그에 답하지 않고 관련 없는 말을 했다.
  되묻기, 전제에 대한 반박, 짧은 답, "몰라", 거절은 반응한 것이다. 상대 말에 질문·요청이 없던 턴은 해당하지 않는다.
- 화제: 상대가 이어 가던 화제가 끝나지 않았는데, 아이가 연결이나 알림 없이 자기 화제로 바꿨다.
  상대의 마무리·화제 제안·대답 대신 질문 같은 신호 뒤의 전환, 짧은 대화에서 화제가 하나뿐인 경우는 해당하지 않는다.
- AI가 같은 말을 반복하거나, 끊기거나, 부자연스럽게 질문한 바로 뒤의 무응답·전환은 근거로 쓰지 않는다.
- 한 대목만으로도 후보가 될 수 있지만, 근거 인용은 그 대목의 CHILD 발화이고 바로 앞 상대 발화가 질문·요청·진행 중 화제였음을 reasonText에 말로 설명한다.
```

**[B] 씨앗으로 확인** (v2 skillRef 문단 보강)

```
seedSummaries의 각 seed는 아이가 연습할 화용 기술의 정의다. 지원 필요로 고른 대목이 어떤 seed의 invariantSentence(무엇이 일어났는지)와
signature.requiredInference(무엇을 알아차려야 했는지)에 맞으면 그 seedId를 skillRef로 쓰고, 그 정의에 비추어 근거가 맞는지 다시 확인한다.
맞는 seed가 없으면 NONE이다. seed에 맞추려고 관찰된 어려움이나 목표를 바꾸지 않는다.
```

열린 점(측정으로 정함): [A]를 "한 대목"으로 할지 "두 번 이상 관찰"로 할지. 두 판(A-1회 · A-2회)을 나란히 측정한다.

| ③ AI 쪽 문제 | 합성: AI가 같은 말을 반복한 뒤 아이가 화제를 바꿈 | 0개 |
| ④ 의견 차이 · 반박 | 합성: 질문 전제를 반박하며 대답 | 0개 |
| ⑤ 짧은 답만 | 합성: "응", "몰라"가 이어짐 | 0개(v2는 짧은 답을 어려움으로 보지 않음) |
| ⑥ 질문 여러 번 무시 | 합성: 질문마다 답 없이 자기 이야기 | 후보 1개(X4) |

- 판: v2 원판 / v2 + A + B(1회 기준) / v2 + A + B(2회 기준). 사례마다 3회. 실호출 약 6 × 3 × 3 = 54회.
- 보고: 후보 수 · 이름 · 근거 seq · skillRef · 서버 검사 결과(`serverValidation`에 `KEPT` 또는 `NUMBER_GUARD(REASON_TEXT)` 같은 탈락 코드).
- 합성 사례는 성인이 쓴 합성 대화만 쓴다(R-F15). 새로 쓴 합성 사례도 `docs/goal-candidate-rubric/`에 같은 모양으로 둔다. 결과는 "실호출 · 합성" 증거로 보고하고 실기기 결과와 섞지 않는다(R-M11).

### 입력 만들기

입력 파일은 결과 작업 입력과 같은 모양이다: `{"transcript":[{"seq","speaker":"CHILD|AI","text","uncertain"}], "structured":{…}|null, "endReason":"CHILD_STOP", "scenes":[], "seedSummaries":[…]}`. 저장소 밖(scratchpad)에 둔다.

- ① 진돗개: `docs/goal-candidate-rubric/jindo-input.json`을 그대로 쓴다(씨앗 15개 포함). 씨앗 없이 재려면 `seedSummaries`를 빈 배열로 바꾼 사본을 쓴다. 원본은 실키 로컬 DB(`mujoong-live`) `realtime.realtime_transcript`의 세션 `a95c848d…` 행이다.
- `seedSummaries`: Neo4j에서 그 아이의 `U15Seed` payload를 읽어 `{seedId,label,signature,invariantSentence}`만 남긴다(`GoalCandidateGateway`가 보내는 것과 같은 모양). 없으면 `social-comm-poc.zip`의 `skill_family_seeds.json` 14개로 같은 모양을 만든다(seedId는 `seed:` 접두).

### 실행

```bash
set -a; . ~/.config/mujoong/live.env; set +a   # 키 값은 출력하지 않는다(R-F3 · R-F13)
cd backend
GOAL_PROBE_INPUT=<입력.json> GOAL_PROBE_REPORT=<보고서.json> GOAL_PROBE_PROMPT=<지시문 사본.txt> \
  ./gradlew -q :core-api:lunaLiveTest --tests '*GoalCandidateProbeLiveTest'
```

`GOAL_PROBE_PROMPT`를 빼면 저장소의 v2를 쓴다. `lunaLiveTest`는 `check` · 기본 `test`와 분리된 수동 전용이다(R-F1).
