# PR #61 CI 실패 4종 후속 수정

## 원인과 수정

1. **변형 단계 시험 순서**: 목표 달성 뒤 친구 답변이 추가됐는데 시험이 그 음성과 변형 제안의 재생 완료를 구분하지 않았다. 입력을 받기 전 J4 결과를 넣어 무시되는 상태였다. 친구 답변과 제안 완료를 각각 전달한 뒤 변형·다음 목표의 원래 단계 및 장면 기록을 검증하도록 고쳤다. 제품의 판정 수락 조건이나 기대 단계를 완화하지 않았다.
2. **대본 불일치의 확장 호환성**: 복구 기능이 없는 확장에도 `approved-text-mismatch` 사건만 보내 실패 사실이 전달되지 않았다. `handlesAudioRecovery()`가 참인 확장만 상관 ID가 있는 복구 사건을 받고, 그 밖에는 기존 `Playback.FAILED`를 전달한다. 두 경로 모두 거절 음성을 재생하지 않는다. 복구 확장 시험과 기존 실패 사실 시험을 함께 유지한다.
3. **상황 생성 Spring 시험 구성**: 실제 서비스에 추가된 `EventLogger` 의존성이 작은 시험 컨텍스트에 등록되지 않았다. 시험에 로거 대역을 등록했다. 생성·검토를 별도로 호출하는 실제 어댑터, 거절 시 재시도·미발급·구형 gateway 미호출 단언은 그대로 유지한다.
4. **로그 위생 통합 시험**: 공급자 오류를 연결 끊김과 구분한 뒤에도 옛 `ProviderDisconnected` 로그를 기다렸다. 고정된 `ProviderUnclassifiedError` 관측으로 바꿨다. 또한 완성된 스트리밍 단위를 내보내고 나서 '미완성 음성'이라 가정하던 자료를 수정했다. 음성 꼬리가 도착하지 않은 전사 구간을 공급자 오류와 함께 보내며, 출력 0바이트·미승인 전사 비공개·전사 및 공급자 오류 원문 비출력 단언을 유지한다.

`FakeProviderWsServer.emitSpeechPrefix`는 시험 전용이다. 운영 게이트·금지 표현·승인 대본 일치·Jev 검사를 변경하지 않는다. Terraform과 main을 변경하거나 실행 서버를 교체하지 않는다.

## 추가로 발견한 시험 자료 오류

전체 실행에서는 정책 JSON을 잘못된 내용으로 바꾸는 시험 두 개가 Windows 줄바꿈(CRLF) 때문에 의도한 변형을 만들지 못했다. 시험 자료를 읽는 도우미에서만 LF로 통일했다. 운영 정책 파일, 해시 검증, 기동 거부 조건은 변경하지 않았다.

## Jev 정책 기준

사용자 확인에 따라 최신 main의 Jev v3 정책(PROFANITY/PASS)을 기준으로 한다. PR의 Jev 구현과 정책 자원은 통합 main과 동일하다. 원래 실행 서버의 비교용 STUB 설정은 이 PR 검증 과정에서 변경하지 않았다.
