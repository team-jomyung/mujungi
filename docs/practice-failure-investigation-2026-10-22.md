# 연습 시작 실패와 안내 중 종료 조사

## 확인한 사실

2026년 10월 22일 16:03~16:04(KST)의 로컬 시험을 확인했다.

- 첫 연습 준비는 약 14.36초 뒤 FAILED가 됐다. 상황 생성·별도 검토 API는 각각 두 번 정상 응답했다. 보완 생성 후에도 최종 승인 조건을 충족하지 못해 사용되지 않았다. API의 정상 응답은 내용 승인과 다르다.
- 재시도는 약 7.5초 뒤 READY가 됐다. 목표 안내와 돌아보기 제안 음성은 Jev ALLOW였다.
- 아이의 계속 진행 발화 뒤 돌아보기 참여 판단 J4가 시간 초과로 보류됐다. 설계상 이때는 선택적인 돌아보기를 건너뛰고 새 상황 안내로 이동한다.
- 이후 공급자 Error 이벤트가 발생했고, 서버가 수집 중인 음성을 불완전 출력으로 폐기했다. 연습 흐름은 PRACTICE_OUTPUT_FAILED로 종료됐다. 종료·휴식 의도로 판정된 기록은 없다.
- 실제 소켓 끊김 처리의 PROVIDER_LOST 종료와 다르다. 기존 로그의 ProviderDisconnected라는 이름만으로 실제 연결 끊김을 확정하면 안 된다.

## 아직 확정하지 못한 부분

첫 생성물이 어느 내용 검사에서 탈락했는지, GPT-Live가 왜 Error를 반환했는지는 기존 기록에 남지 않았다. 저장되지 않은 오류 원문을 사후 복원할 수 없다.

시험용 합성 음성으로 목표 안내 → 돌아보기 제안 → 계속 진행 발화 → 상황 안내 순서를 두 번 호출했다. 두 번째에는 해당 세션에 저장된 실제 상황 안내문과 역할 자료를 사용했다. 두 시험 모두 상황 안내 음성을 받았고 공급자 오류는 재현되지 않았다. 이 결과는 실제 기기 재생이나 전체 연습 흐름의 성공을 뜻하지 않는다.

## 이번 진단 보완

- 공급자 오류 응답을 실제 연결 끊김과 다른 분류로 기록한다. 요청 값 거절·요청 형식·속도 제한·할당량·입력 길이·공급자 내부 오류 등을 서버의 고정 분류명으로 구분한다.
- 알려지지 않은 오류 코드, 공급자 오류 메시지, 아이 발화, 부모 메모와 키는 진단 로그에 복사하지 않는다.
- 상황 생성에서는 서버 검사 결과와 별도 검토의 사전에 정해진 거절 항목을 남긴다. 원본 생성문과 자유 사유는 기록하지 않는다.
- 진단 기록 실패가 생성 결과를 바꾸지 않도록 한다.
- 안전 검사·Jev·엄격한 승인 문장 대조·종료 및 휴식 처리에는 변경이 없다. Jev가 원인이라고 확인되지 않아 비활성화하지 않았다.

## 다음 확인

진단 보완본으로 실제 기기 시험을 다시 수행해 오류가 재발하면 고정 분류를 확인해야 한다. 아직 특정 공급자 원인을 확정하거나 연습 문제가 해결됐다고 판단할 수 없다. AWS Terraform 수정과 main 병합은 하지 않는다.
