# 연습 시작 안내와 행동 돌아보기

대조 기준: 2026-10-30 main `08eb7cb0`. 현재 구현은 [PracticeInstructions](../backend/realtime-activity/src/main/java/kr/mujoong/realtime/practiceflow/PracticeInstructions.java)의 `goalBrief`, `goalRecap`, `factualNotice`와 [PracticeConversation](../backend/realtime-activity/src/main/java/kr/mujoong/realtime/practiceflow/PracticeConversation.java)를 따른다.

## 시작

한 번의 시작에서 목표는 1개만 선택한다. 여러 목표를 잇는 코드가 남아 있어도 [PracticeStartRequest](../backend/core-api/src/main/java/kr/mujoong/core/practice/start/PracticeStartRequest.java)가 2개 이상을 거절한다.

참여 확인 뒤 ‘잠깐 상상 놀이를 같이 해 보자. 하다가 막히면 내가 도와줄게. 쉬고 싶거나 그만하고 싶으면 언제든 말해.’라는 활동·도움·중단 범위를 안내한다. 추상적인 목표 이름은 읽지 않고, 별도 참여 답변도 요구하지 않는다. 이후 새 상황 안내와 상대 역할 대화로 간다. 이전 대화 돌아보기는 현재 흐름에서 제외됐다. [세부 흐름](adaptive-practice-dialogue.md)을 참고한다.

## 마무리

상대 역할 답변 뒤 수행·도움·중단 사실을 구분해 짧게 돌아본다. 목표명을 읽거나 자유롭게 칭찬을 생성하는 방식이 아니다.

| 서버에 확인된 사실 | 안내 문장의 구분 |
| --- | --- |
| 수행 확인 | ‘네 말로 해 봤어’ |
| 코치 도움 후 수행 | ‘도움을 받은 뒤 네 말로 해 봤어’ |
| 확인 질문 뒤 수행 | ‘상대가 다시 물었을 때 필요한 뜻을 전했어’ |
| 수행과 도움 경험이 함께 있음 | 두 사실을 함께 말함 |
| 수행 미확인, 도움 제공 | ‘도움을 받으며 연습해 봤어’ |
| 수행·도움 모두 미확인 | ‘연습하다 여기서 마무리하게 됐어’ |
| 수행했지만 중간 정리 | 끝까지 하지 못한 사실과 해 본 부분을 구분 |

현재 문구는 위처럼 제한된 수행 유형을 표현한다. 아이가 말한 구체적인 내용을 인용해 맞춤 칭찬하는 기능까지 구현됐다고 설명하지 않는다. 판정값·기준·아이 발화 원문을 이 안내용 지시문에 덧붙이지 않으며, 확인되지 않은 향상이나 성공을 추측하지 않게 한다.

## 출력·중단 처리

서버가 문장을 정하고 생성 음성으로 요청한다. 이 안내는 승인 낭독 우회가 아니며 기존 Jev 출력 검사 경로를 거친다. 실제 Jev 또는 STUB 선택은 실행 설정 문제이고 이 문서 변경에서 바꾸지 않는다.

기기 재생 완료와 생성 요청 수락은 구분한다. 종료·휴식 요청, 보호자 종료나 연결 장애 때 돌아보기를 강제하지 않는다. 재생 실패와 수행 여부를 혼동하지 않고 기록을 확인한다. [시작 안내 겹침 보고서](practice-introduction-input-overlap.md)는 이전 수정 당시의 검증 기록으로 참고한다.

## 현재 수동 점검 항목

목표 1개로 시작해 활동 범위·새 상황 안내를 듣고, 직접 수행·확인 질문 후 수행·도움 후 수행·중간 종료를 별도 시도로 확인한다. 상대 마무리 답변과 돌아보기, 공통 종료 인사, 결과의 수행·도움·종료 사유를 대조한다. 이번 문서 변경에서 이 실기 시험을 다시 실행한 것은 아니다.
