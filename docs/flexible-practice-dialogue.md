# 아이가 듣기 자연스러운 안내와 유연한 연습대화

## 바뀐 진행 방식

이전에는 분석용 상황 설명을 읽고, 아이의 답변을 판정한 뒤 같은 대사를 재생하거나 도움·종료로 넘어갔다. 목표 표현을 말해도 친구의 답을 듣고 협의할 기회가 부족했다.

이제 새 상황을 만들 때 두 가지 글을 구분한다.

- `sceneDescription`: 내부 검증용 설명. 목표 조건과 상대 대사 원문, Neo4j를 사용한 경우 보존해야 하는 구조를 확인하는 데 사용한다.
- `spokenIntroduction`: 아이에게 직접 들려줄 안내. 같은 사실·관계·단서를 유지하며 “너는 ~하려고 해”, “친구는 ~하고 싶대” 같은 말투로 쓴다. “~하고 있다”, “~라고 말한다”, “~다를 때”라는 조건 꼬리를 낭독하지 않는다.

새 안내문도 상황 생성·독립 검토·금지 표현·정답 노출·이름과 연락처 검사 대상이다. 검토를 통과한 원문을 GPT-Live가 읽는다. 읽은 내용이 다르면 기존과 같이 재생을 막는다. 임의로 바꾼 안내를 승인 대본으로 취급하지 않는다.

이 필드가 없는 과거 대본은 분석용 설명을 즉석에서 해석하지 않고 짧은 고정 가상 상황 안내를 사용한다. 자세한 새 안내를 보려면 새 연습을 시작해 대본을 생성해야 한다. 기존 DB 열을 삭제하거나 과거 기록을 초기화하지 않는다.

## 역할 대화

시작 안내와 상대의 첫 대사 뒤에는 아이가 한 말에 맞춰 상대 역할의 답변을 생성한다. 첫 대사를 계속 반복시키지 않는다.

예시 흐름:

1. 친구: “나는 다른 놀이를 하고 싶어.”
2. 아이: “무슨 놀이를 하고 싶어?”
3. 친구: 자신이 원하는 놀이를 답한다.
4. 아이: 장소 제약을 말하거나 다른 놀이를 제안한다.
5. 친구: 그 내용에 맞춰 반응하고 필요한 경우 한 가지 질문을 한다.
6. 서로 합의하면 친구가 짧게 받아들이고 장면을 마무리한다.

위 문장들은 설명용 예시이며 고정 대본이 아니다. 상대 역할은 아이의 질문에 먼저 답하고, 제안·거절·수정에 맞춰 반응한다. 상황 안내·정답을 반복하거나 아이의 대사·감정을 지어내지 않도록 지시한다. 명시적으로 도움을 요청할 때는 기존 코치 전환과 동의·예시 제한을 유지한다.

## 수행 판정과 마무리 판정의 구분

목표 표현을 수행하면 그 사실을 세션 메모리에 유지하되 종료하지 않는다. 이후에는 현재 상황이 정리됐는지 따로 관찰한다. 이때 검사기가 아이의 이전 말뿐 아니라 기기에 전달된 승인 상대 발화도 최근 맥락으로 받는다. 상대가 무엇을 제안했는지 없이 “응”만 보고 합의를 추정하지 않는다.

내부적으로 기존 J2는 목표 수행 판정에, J3와 `ROLE_DIALOGUE_CLOSURE` 기준은 수행 후 상황 정리 판정에 사용한다. 새 `prompt-v3`는 이 J3 요청을 기존의 ‘되묻기 해결’과 구분한다. J1 참여·J4 동의·J5 도움 뒤 수행·J6 종료의 기존 의미는 유지한다. 상황 정리 J3를 `REASK_RESOLVED`라는 사실로 잘못 저장하지 않는다.

질문·반대·조건·새 제안에는 대화가 더 필요하다. 합의나 상황 정리가 확인되면 마지막 친구 답변을 생성하고, 안전 검사·Jev 승인과 기기 재생 완료 뒤 기존 변형 제안·다음 목표·종료로 넘어간다. 상황 마무리 판정이 보류되면 목표 수행을 지우거나 성공을 만들어내지 않고 역할 대화를 이어간다.

## 안전과 한도

- 즉흥 역할 발화는 모두 기존 `speakGenerated` 경로와 PRACTICE_PEER/PRACTICE_COACH Jev 검사를 거친다.
- 생성형 발화는 승인 대본 원문 일치로 Jev를 생략할 수 없다.
- 아이 발화 원문·판정 라벨·확률·판정 기준은 GPT-Live의 추가 역할 지시문에 넣지 않는다. 같은 음성 세션의 대화 맥락을 사용한다.
- 명시적 종료·휴식, 출력 실패·차단, 기존 목표 10분·도움 90초·슬롯 한도를 유지한다. 무응답 첫 안내는 첫 대사 반복 대신 편할 때 말해도 된다는 짧은 안내를 사용한다.
- 기록에는 목표 수행 시점을 유지하면서 실패·시간 초과 등 별도 사실도 남긴다. 수행했다는 판정과 정상 완료는 같은 의미가 아니다.
- 실제 앱 설정과 기본 생성자는 유연한 흐름을 사용한다. 이전 흐름은 명시적 `flexibleDialogue=false`로 회귀시험과 구형 호출의 동작을 검증할 수 있게 남겼다.

## 검증 범위

자동 통합시험에서 안내·대화·합의·마지막 답변의 검사와 기기 재생 완료·DB 저장을 확인한다. 공급자와 기기는 시험 대역이다. 별도 실호출에서는 새 안내 생성과 독립 검토, 실제 음성 생성과 Jev 판정, 마무리 판정을 점검한다. 실제 마이크·스피커를 통한 자연스러움 평가는 별도 확인이 필요하다.

Neo4j를 참조할지는 기존 목표의 기술 연결과 생성 경로가 결정한다. 이 변경으로 NONE 목표가 자동으로 그래프 기반 목표로 바뀌지는 않는다. 그래프를 사용하지 않은 상황을 그래프 기반 변형이라고 표시하지 않는다.

AWS Terraform과 main 병합은 변경 범위에서 제외한다.

## 2026-10-22 적용 전 검증 결과

- 관련 자동 시험: Core 131개, 실시간 서버 519개, 합계 650개 통과(실패·오류·시험 건너뛰기 0).
- 실제 AI 호출: 자연스러운 상황 안내 생성·독립 검토 통과. 상황 마무리 판정 5개 사례에서 질문·제안·반대와 합의를 구분했다.
- 실제 음성 API에 합성 질문 음성을 입력한 시험에서 “그럼 무슨 놀이를 하고 싶어”에 “음, 나는 술래잡기 해보고 싶어!”라는 음성과 텍스트가 생성됐다. Jev는 ALLOW, 검사 지연은 273ms였다.
- 위 음성 시험은 실제 브라우저·마이크·스피커 재생 시험과 구분한다. 사용자가 로컬 적용 후 전체 흐름을 직접 확인한다.
- 기존 승인 대본 일치 검사와 생성 발화의 Jev 검사를 유지했다. AWS Terraform 변경, 원격 push와 main 병합은 수행하지 않는다.
