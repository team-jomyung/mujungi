V10의 선택 대본 저장, 담은 후보/기존 행동 목표의 시작 연결, 생성과 분리한 Luna 자체 검토, 서버 독립 검사,15초 공유 마감·재시도·취소, 개인정보 치환, 실제 노출 최근3건의 의미 반복 입력, U15 구조 맥락·변형 보존과 기존 C10/C8 응답 호환을 구현했다. 운영 경로는 구조화 공급자 능력을 감지해 새 흐름을 선택한다. 첫 BASE의8필수 값과 선택 대본을 재조회/첫 전달에도 유지한다.

`candidate:<candidateRef>`는 실제 행동 카탈로그가 아닌 명시적 운반 이름 공간이다. typed 종류·고정 버전/4요소를 함께 보존한다. 편차는 contracts/deviations.md `(U10-a)`다. 구버전 INSERT/기존 행 읽기는 지원하지만 과거 앱이 새 후보 기능까지 지원한다고 주장하지 않는다.

## 구현 해석과 한계

U15 계획은 자유문을 임의의 구조 값으로 추측하지 않기 위해 실제 생성된 BASE를 받은 뒤 대조한다. skillContext와 모든 variantPlan의 소비시간 합계2초를 공유하며 전체15초도 줄어든다. 모델 응답 대기는 그래프 실행시간에서 제외하지만 전체 마감에는 포함한다. 후속 계획 조회 실패·빈 값·시간 초과 때는 남은 내용 수정1회로 그래프 입력 없는 새 BASE-only를 생성·별도 검토한 뒤에만 graphContextUsed=false로 발급한다. 슬롯/전체 예산이 부족하면 실패한다. 이미 구조 맥락을 사용한 BASE에 false만 붙이지 않는다. 정상 그래프에서 단순 변형 내용 실패인 경우만 기존 BASE 별도 검토/true를 유지한다.

사람이 허용한 공통 시험4파일의 정확 기대값·fixture만 갱신했다. R-F7에 따른 설정 잔여시간 Future.get의 정확 단위 변환1조각은 별도 allowlist 메타데이터로 등록했으며 검색식·단언·시간값·하한은 유지했다. RT 운영·프런트·V1~V9 SQL·수동 스택은 건드리지 않았다.

추가로 사람의 별도 한정 승인(rt-test-review.md)에 따라 RT 삭제 시험 두 사례의 sendAudio→emitTurn 사이에 실제 입력 수신 확인1줄씩만 추가했다. 단언/10초 한도는 유지했지만 녹음 개수 실패는 해결되지 않았다. 관측 로그와 추측의 한계는 validation-notes.md에 남겼다. 목표 동일 순위는 종류 무관 selectionId 순서이며 같은 종류 순위 중복은 별도로 거절한다. 별칭이 불투명 후보/기존 키 일부와 같아도 원본 키·판을 유지하고 의미 텍스트만 정리한다.
