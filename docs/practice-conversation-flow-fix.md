# 연습대화 흐름 개선 — 2026-10-22

## 문제와 바뀐 동작

실제 시험에서 재설명 도중 들어온 "무슨 놀이를 하고 싶어"는 저장됐지만 판정되지 않았다. 재설명이 끝나면 같은 상대 대사를 다시 읽었고, 이후 "무슨 놀이를 하고 싶은지 물어봐야 하는 거야"라는 진행 방법 질문을 목표 달성으로 판정해 종료했다.

- 재설명 중 확정된 답변을 보관하고, 재생이 끝나면 같은 J2 또는 J5 판정으로 넘긴다. 기존처럼 가장 최근의 확정 답변 하나를 보관하며, 여러 말을 무제한으로 쌓지 않는다.
- 재설명 직후 상대 대사를 바로 반복하지 않고 답변을 기다린다. 이미 들어온 답변이 있으면 바로 판정한다. 코치 도움 뒤의 재설명도 추가 코치 발화나 재시도 횟수 증가 없이 J5로 돌아간다.
- 새 `judgment/prompt-v2.txt`는 실제 역할 대사와 연습 방법 질문을 구분한다. v1은 이력으로 보존하고 새 세션의 판정 기록에는 prompt-v2를 남긴다.
- 명확한 한국어 방법 질문에 대해 추가 방어를 둔다. 모델이 FULL·DELIVERED·COPIED로 잘못 분류해도 연습 흐름은 도움 요청으로 처리한다. 모델이 반환한 원본 판정 기록은 덮어쓰지 않는다. 이 방어는 J2·J3·J5에만 적용하며, 모든 한국어 표현을 판별하는 일반 언어 분류기는 아니다.
- 같은 "음, 이제 들어봐"를 매번 읽는 대신 상황 도입은 "지금부터 상상 속 상황이야", 상대 대사는 "이런 말을 건넸어", 재설명은 "다시 설명해 줄게", 역할 안내는 "잠깐 안내해 줄게"로 구분한다. 대본 본문은 그대로 유지한다.

## 유지한 안전 장치

재설명 출력이 실패하면 보관한 답변으로 성공 처리하지 않는다. 이전 슬롯의 늦은 중복 사건도 판정을 반복시키지 않는다. 사용자 종료, 시간 한도, 무응답 재안내 상한, 승인 대본 원문 검사, 낭독 불일치 한 번 재시도, 생성형 역할 발화의 Jev 검사를 유지했다.

허용하는 앞 문구는 해당 슬롯에 서버가 지정한 고정 안내 또는 그 끝부분뿐이다. 본문 누락·새 문장 추가·다른 단계 안내는 통과시키지 않는다. 앞 안내를 완전히 뺀 실제 AI 실험은 첫부분이 잘려 3건 모두 원문 검사에 실패했으므로 채택하지 않았다.

## 검증 근거

- Core 129개·Realtime 498개, 합계 627개 회귀 시험 통과. 실패·오류·건너뜀 0. 두 실행 파일 빌드 통과. 중단 전 통과한 결과가 보존됐고, 재개 후 동일 변경 파일과 시험 결과를 확인했다.
- 재설명 중 답변 인계, 중복 완료 사건, 답변 없이 듣기 복귀, 재설명 실패, J2·J3·J5의 방법 질문 오분류 방어, 일반 역할 질문의 정상 완료를 시험했다. 기존 Jev·종료·실패 경로 시험도 포함한다.
- 실제 AI 음성 시험: 단계별 안내를 적용한 도입·상대 대사·재설명 3건 모두 승인 원문 일치 및 음성 생성 통과. 실제 스피커 청취 확인은 아니다.
- 재개 후 실제 `LunaJudgeClient → RealtimeLunaClient → 공급자` 경로를 앱과 같은 4초 제한·신뢰도/차이 문턱으로 호출했다. 앱 컨텍스트나 사용자 세션을 생성하지 않고 합성 문장만 판정했다.
  - "무슨 놀이를 하고 싶은지 물어봐야 하는 거야" → HELP, 확정, 3676ms.
  - "어떤 놀이 하고 싶어라고 말하면 되는 거야?" → HELP, 확정, 2582ms.
  - "무슨 놀이를 하고 싶어?" → FULL, 확정, 1928ms.
  - "무슨 의미인지 잘 모르겠어" → NOT_UNDERSTOOD, 확정, 2384ms.

## 적용과 한계

변경 대상은 로컬 Realtime 서버다. AWS Terraform과 main 병합은 대상에 포함하지 않는다. API 키·데이터 볼륨·Core·Web 실행 이미지를 유지한다. 실제 AI 판정 4건의 통과가 모든 표현과 지연을 보장하지는 않는다. 첫 사례는 4초 제한에 가까웠다. 앱에서 직접 마이크로 재설명 중 답하고, 방법 질문 뒤 도움으로 이어지는지 확인하는 시험은 적용 후 별도로 필요하다.
