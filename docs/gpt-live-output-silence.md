# GPT-Live 연속 무음과 음성 출력 구간

## 문제가 생긴 이유

실제 GPT-Live 연결은 발화가 끝나도 PCM16 무음 조각을 계속 보낸다. 2026-10-20 합성 시험에서는 4,800바이트(24kHz 모노 100ms) 조각이 이어졌고, 말이 없는 상태에서도 약 25초 동안 1MB 이상의 출력이 도착했다. 본문·음성·키를 저장하지 않고 사건 수·길이·샘플 크기만 관측했다.

기존 서버는 음성 조각이 도착할 때마다 구간 완료 대기를 다시 시작했다. 그 결과 무음이 계속 오는 동안 구간이 닫히지 않았고, 20초 상한 초과 또는 불완전 구간으로 폐기돼 Jev 검사와 기기 재생까지 도달하지 못했다.

## 수정한 흐름

1. 공급자 응답 해석기는 길이가 양수·짝수이며 모든 바이트가 0인 PCM만 `OutputSilenceDelta`로 구분한다. 작은 소리의 음성에는 임계값을 적용하지 않는다. 빈 조각·홀수 길이 자료도 정상 무음으로 간주하지 않는다.
2. 무음도 공급자 오디오 시계에는 더한다. 지시 확인 시각과 새 발화의 시간선을 맞추는 기존 검증은 유지한다.
3. 무음은 발화 완료 대기를 다시 시작하거나 새 발화 구간을 열지 않는다. 발화 조각과 전사가 기존 완료 대기 시간 동안 오지 않으면 기존 방식으로 구간을 확정한다.
4. 발화 사이의 짧은 무음은 다음 음성이 도착할 때 구간에 포함해 말의 쉼을 보존한다. 끝의 무음은 버린다. 임시 무음 길이는 상한으로 제한하며, 내부 쉼도 실제 구간 길이 상한에 포함한다.
5. 구간 완결성·전사 존재·PCM 형식·금지 문장·현재 출력 세대 검사와 Jev 승인을 모두 통과한 음성만 기기로 보낸다.

## 유지되는 제한

- 20초 음성 구간 상한과 구간 완료 대기 설정은 변경하지 않는다.
- 참여 확인 전 출력 보류와 낡은 응답 차단을 유지한다.
- Jev 차단·실패·시간 초과 시 음성을 내보내지 않는 동작을 유지한다.
- 무음과 분류할 수 없는 낮은 소리·노이즈가 계속 도착하면 여전히 안전하게 폐기될 수 있다. 임의의 에너지 기준으로 이를 제거하지 않는다.
- Docker·Compose·CI·Terraform·배포 및 비밀값 주입 파일은 수정하지 않는다.

## 검증 방법

- 응답 해석 시험: 완전한 무음, 작은 음성, 잘못된 PCM 길이를 구분한다.
- 오디오 시계 시험: 무음 25초가 들어와도 마지막 발화 시각은 바뀌지 않고 전체 시계는 진행한다.
- 구간 시험: 내부 쉼 보존, 긴 끝 무음의 메모리 제한, 기존 크기 상한을 확인한다.
- 실행기 회귀시험: 음성 뒤 연속 무음이 도착해도 구간을 닫고 Jev 승인 전에는 아무것도 재생하지 않는다. 승인 후에만 출력하며 금지 문장은 계속 차단한다.
- 로컬 실연결: 성인 또는 합성 입력으로 참여 확인 → ACTIVE → Jev 승인 → 기기 음성 송신 → 재생 시작·완료를 확인한다. 물리 스피커에서 들리는지는 사용자의 청취 확인이 필요하다.

공식 연결 안내: [OpenAI WebSockets](https://developers.openai.com/api/docs/guides/voice-websockets). 연속 무음의 구체적인 패킷 모양은 문서의 보장으로 가정하지 않고 위 실연결 관측과 회귀시험으로 확인했다.
