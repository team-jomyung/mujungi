# 연습 상황 생성의 관계 값 연결 보완

## 확인한 문제

목표 후보는 상대를 `친구`처럼 읽기 쉬운 이름으로 저장한다. 지식 그래프의 변형 계획은 `FRIEND_CLOSE`, `FRIEND_CASUAL` 같은 정해진 관계 코드를 사용한다. 서로 다른 표현을 그대로 전달하면 그래프 조회가 성공해도 변형 계획을 만들지 못해 그래프 없는 기본 생성으로 돌아갈 수 있었다. 추가 생성·검토가 15초 전체 한도를 넘기는 사례도 재현했다.

## 변경

- 그래프에서 실제로 조회한 관계 코드와 동등한 것으로 정한 표시 이름만 생성 요청의 관계 코드로 맞춘다.
- 저장된 목표 원문은 바꾸지 않는다. 다른 상대 관계나 알 수 없는 이름은 임의로 바꾸지 않는다.
- 생성 요청과 서버 검증에 같은 관계 값을 사용한다.
- 그래프를 사용하는 새 가상 상황은 허용된 장소·주제 안에서 만들도록 지시를 보완했다.
- 상태 진술에서 행동 요청을 추론해야 한다면, 눈에 보이는 상황 단서를 넣되 정답과 행동 해설은 먼저 말하지 않도록 했다.

## 유지한 경계

기존 독립 AI 검토, 서버 내용 검사, 15초 전체 한도, 그래프 장애 시 처리, Jev 음성 검사, 출처 구분을 유지한다. AWS Terraform과 비밀값은 수정하지 않는다.

## 검증

- 실제 저장된 `뜻을 짚어보기` 목표로 읽기 전용 검증: Neo4j 맥락 사용, 그래프 판 `poc-v1`, AI 검토 `APPROVE`, 기본 장면 1개, 약 8.6초. 이 검증 자체는 상황을 DB에 저장하거나 기기로 음성을 재생하지 않는다.
- 회귀시험은 관계 일치·불일치, 저장 목표 불변, 생성 요청과 검증 값 일치, 기존 그래프 장애·변형·안전·생성 경로를 확인한다.
- 정상 로그인 웹 경로의 상황 저장과 실제 기기 연습 시작은 별도로 확인한다. 위 읽기 전용 검증을 실제 마이크·스피커 시험 성공으로 간주하지 않는다.

## 기록별 상태 구분

- 13시대 자유대화 재분석: 목표 후보 2개 생성. 그중 `뜻을 짚어보기`를 저장해 위 검증에 사용했다.
- 14:43~14:44 자유대화: 분석 작업은 첫 시도에 완료됐으나 새 목표 후보는 0개다. 이 기록에서 새 연습 상황이 생성됐다고 표시하면 안 된다.
