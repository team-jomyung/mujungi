# 결과 분석·리포트의 JSON 요청 형식 보완

## 증상

실제 AI 키를 연결한 로컬 환경에서 자유대화 음성은 재생되지만 결과 분석과 상담용 리포트가 `PROVIDER_ERROR`로 실패했다. Core의 OpenAI 호출 기록은 `RESULT_TEXT / REQUEST_REJECTED`였다. PDF 파일을 만드는 단계보다 앞에서 실패한 것이다.

## 원인 확인

개인정보 없는 합성 자료로 같은 JSON 모드 요청을 보내자 HTTP 400과 `input` 오류가 재현됐다. 입력에 JSON 출력 안내를 포함하면 같은 키·모델·설정으로 HTTP 200과 completed가 반환됐다.

기존 요청은 JSON 출력 안내를 별도의 `instructions`에 두고 `input`에는 정리된 데이터만 보냈다. 실제 공급자의 JSON 모드 입력 검사에는 이 형태가 충분하지 않았다.

## 보완

기존 JSON 모드 요청의 `input`을 두 메시지로 구성한다.

1. 고정 developer 메시지: `Return a valid JSON object.`
2. user 메시지: 기존 개인정보 정리를 거친 JSON 데이터 문자열.

업무별 지시문은 기존 `instructions`에 유지한다. 고정 형식 안내와 사용자 데이터를 합치지 않으며, 계약 스키마를 사용하는 요청은 기존 형태를 유지한다. 모델·토큰·시한·재시도·저장 금지와 결과 검증을 변경하지 않는다.

## 연습 화면과의 관계

‘아직 담은 목표가 없어요’는 장면 생성 오류 화면이 아니다. 연습은 자유대화 기록의 ‘연습 목표’에서 목표를 담은 뒤 시작한다. 자유대화 결과 분석이 실패하면 이 목표 후보를 얻는 앞 단계가 막힐 수 있다. 결과 분석을 복구한 뒤 기록에서 후보 생성 여부를 확인하고, 사용자가 목표를 선택한 다음 장면 생성을 시험해야 한다.

기존에 실패한 결과·리포트는 서버를 교체했다고 자동 성공으로 바뀌지 않는다. 화면의 다시 시도로 정상 서비스 경로를 통해 재요청한다. DB 상태를 임의로 성공으로 바꾸지 않는다.

참고: [OpenAI JSON 모드 안내](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat). 이 작업에서는 공식 안내와 별도로 실제 합성 요청의 400→200 변화를 확인했다.
