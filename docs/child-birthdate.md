# 생년월일 등록·수정 규칙

아이 정보 화면은 년·월·일 선택으로 입력합니다. API는 `birthDate: YYYY-MM-DD` 하나를 받고 DB의 `core.core_child.birth_date` DATE 열에 저장합니다. V11은 기존 age 열을 삭제하지 않는 추가 마이그레이션입니다. 기존 자료에 임의의 생일을 채우지 않습니다.

- 최초 등록일은 아이 정보의 변경되지 않는 created_at을 한국 날짜로 변환해 사용합니다.
- 최초 등록과 생년월일 수정 모두 최초 등록일 기준 만 6세 이상~만 13세 미만인지 확인합니다.
- 등록 후 만 13세가 되어도 계속 이용할 수 있습니다. 실제 나이는 매번 생년월일과 현재 한국 날짜로 계산합니다.
- 2월 29일 출생자는 평년에 3월 1일부터 나이가 증가합니다. 실제 없는 날짜는 거절합니다.
- 등록일 기준으로 선택 가능한 8개 출생연도를 보여주고, 경계 연도는 월·일까지 선택한 뒤 검증합니다. 수정 화면은 현재 연도 대신 최초 등록 연도를 사용합니다.
- 프로필·홈·대화 문맥의 나이는 실제 나이입니다. 연습 콘텐츠 생성 나이는 최대 12로 제한하고 GPT-Live에도 주제·난이도는 최대 12세 수준이라는 지시를 줍니다. 기존 안전 검사와 Jev는 유지합니다.
- 생년월일 원문은 GPT-Live 요청에 추가하지 않습니다. 기존처럼 이름·계산한 나이·관심사만 전달합니다.

기존 age는 호환 열입니다. 생년월일이 없는 이전 자료는 저장된 age를 조회하고, 정보 수정에서 실제 생년월일을 입력할 수 있습니다. 이 개발 건의 로컬 시험 데이터는 사용자 승인에 따라 초기화하지만 원격 DB는 변경하지 않습니다. 실제 운영 적용 시에는 기존 이용자의 생년월일 보완 절차가 별도로 필요합니다.

AWS Terraform은 변경하지 않습니다. 이 브랜치는 검증 후 로컬 적용 및 PR 생성 범위이며 main 병합은 인프라 담당자에게 맡깁니다.

## 배포 검토 사항

V11 적용 후 서버와 웹을 함께 배포해야 새 입력 계약을 사용할 수 있습니다. 이전 클라이언트가 age만 보내는 등록 요청은 새 API에서 거절됩니다. 이전 서버로 롤백하면 13세 이상 이용자의 대화 시작에 구버전 나이 제한이 적용될 수 있습니다. 운영 DB의 기존 이용자 자료는 이 작업에서 삭제하거나 임의 생년월일로 변환하지 않습니다. 운영 초기화는 이 PR에 포함하지 않습니다.
