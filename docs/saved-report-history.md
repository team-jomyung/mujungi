# 저장한 상담용 리포트 다시 보기

## 사용 방법

1. 보호자 화면에서 **기록** 탭을 엽니다.
2. 달력과 활동 기록 아래의 **저장한 상담용 리포트**에서 기간·활동 수·저장일을 확인합니다.
3. **리포트 다시 보기 · PDF 다운로드**를 누르면 기존 리포트 본문이 열립니다.
4. **PDF 다시 다운로드**를 누르면 같은 리포트를 다시 받습니다. 새 AI 생성 요청이나 추가 저장 처리는 하지 않습니다.

저장일이 최신인 순서로 20개씩 보여 줍니다. 목록이 길면 이전·다음으로 이동합니다. 생성만 하고 PDF 저장을 끝내지 않은 리포트는 이 목록에 나오지 않습니다. 불러오기 실패 때 다시 시도할 수 있습니다.

## 코드 흐름

- `RecordsScreen` → 공통 `SavedReports` 화면 → `GET /api/reports?page=0`
- 서버는 현재 로그인한 보호자의 상태를 확인하고, 그 보호자가 소유한 `SAVED` 리포트만 읽습니다.
- 목록에는 리포트 번호, 대상 기간, 활동 수, 저장 시각만 전달합니다. 아이 이름·원문·인용은 전달하지 않습니다.
- 다시 보기는 기존 `/parent/reports/{reportId}` 경로를 사용합니다.
- PDF는 기존 `/api/reports/{reportId}/pdf`를 사용합니다. 서버에 저장한 본문으로 다시 만들며 소유권 검사를 그대로 거칩니다.
- 보관·계정 삭제 정책, Google 로그인, 리포트 신규 생성, 음성·Jev, AWS Terraform은 변경하지 않습니다. DB 구조 변경도 없습니다.

## 변경 위치

- 백엔드 `ReportRepository`, `ReportController`: 본인 저장 목록 조회와 페이지 분할
- 프런트 `parent/common/components/SavedReports.tsx`, `parent/common/api/reports.ts`: 목록 표시·조회
- `RecordsScreen`, `ReportScreen`: 목록 배치·PDF 재다운로드 버튼
- `shared/copy/result.ts`: 화면 문구
- `contracts/parent-api.yaml`, `report-list-response.schema.json`: 새 조회 계약

## 검증 항목

- 저장한 리포트만 노출, 최신순, 페이지 경계, 빈 목록
- 다른 보호자 목록·PDF 접근 차단, 로그인 필요, 삭제 접수 계정 차단, 잘못된 페이지 거절
- 목록에 본문·아이 정보가 섞이지 않는지와 응답 계약
- 목록에서 본문 이동, 실패 후 재조회, PDF 재다운로드 때 새 생성·저장 요청이 없는지
- 기존 프런트 전체 회귀, 리포트·분석 백엔드 회귀, 타입·린트·운영 빌드

이 변경은 로컬 적용용 별도 브랜치 `feat/saved-report-history`에 작성했습니다. 실제 로컬 확인 결과는 작업 결과 문서에 기록합니다.
