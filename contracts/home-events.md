# 보호자 홈 변경 알림 — JIRA-274

홈(`/parent`)과 기기 상태 상세(`/parent/device`)는 같은 SSE 재조회 동작을 사용한다.
`GET /api/home/events`는 보호자 세션으로 인증하는 같은 출처의 SSE 연결이다.
`GET /api/home`과 같은 활성 계정 검사를 사용한다. 보호자 ID를 요청 파라미터로 받지 않는다.
인증되지 않았거나 삭제 중인 계정은 기존 API 오류 정책대로 거절한다.

## 이벤트

| 이름 | 데이터 | 웹의 처리 |
| --- | --- | --- |
| `ready` | `{}` | 연결·재연결 시 홈 재조회 |
| `home-changed` | `{}` | 홈 재조회, 기기 상태와 시작 잠금 함께 갱신 |
| `heartbeat` | `{}` | 연결 유지, 홈 재조회 없음 |

대화·아이 정보·보호자 ID·기기 ID를 SSE 데이터에 담지 않는다. 알림 자체를 상태 판정으로 사용하지 않으며,
활동 시작 시 기존 서버 권한·연결 검사를 유지한다. 응답은 `Cache-Control: no-store`,
`X-Accel-Buffering: no`를 사용한다. 전송 heartbeat는 10초, 한 연결의 수명은 최대 2분이다.
재연결마다 세션과 활성 계정을 다시 확인하며, 보호자당 동시 연결은 4개로 제한한다.

## 서버 전달

Inbox 이벤트와 내부 주기 보고는 기존 조건부 연결 상태 UPDATE를 공유한다. 성공한 UPDATE와 같은 SQL/트랜잭션에서
PostgreSQL `pg_notify('mujoong_home_changed', guardian_id)`를 실행한다. 보고 시각이 같거나 오래돼 버린 보고에는
알림이 없다. 상태뿐 아니라 마지막 보고 시각·품질 정보도 홈 데이터이므로, 적용된 주기 보고 역시 재조회 신호를 낸다.
PostgreSQL은 커밋 후에만 알리고 롤백에서는 알리지 않는다. 기존 Inbox/Outbox와 처리 멱등성은 유지한다.
테이블·컬럼·스키마·트리거·마이그레이션은 추가하지 않는다.

각 Core 서버는 풀 연결 1개를 `LISTEN` 전용으로 유지한다. 같은 DB에 연결된 모든 Core가 신호를 받아 자신의
보호자 SSE 구독자에게만 전달한다. 다른 보호자의 스트림에는 전달하지 않는다. 종료 시 연결을 해제하며,
DB 수신 연결 장애 시 SSE도 닫아 웹이 정상 연결로 오인하지 않게 한다.

## 유실·복구

NOTIFY/SSE는 영구 이벤트 로그가 아니다. 이벤트 재생 대신 `ready` 시 재조회한다.
정상 연결 중에는 `mujoong.timing.parent.home-reconcile-interval`(기본 30초)로 알림 유실,
보고 노후화, 등록·해제나 활동 상태 등 연결 보고 이외의 변경도 보완한다.
SSE 장애·미지원 시 `mujoong.timing.parent.poll-interval`(기본 2초)로 복구 조회한다.
탭이 숨으면 SSE를 닫고 주기 조회를 멈추며, 복귀하면 연결과 조회를 다시 시작한다.
401·403·404에는 연결과 자동 조회를 멈춘다. 진행 중 GET보다 늦게 들어온 신호도 이전 응답 뒤에 다시 조회한다.
